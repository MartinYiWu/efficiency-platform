## 1 统一原则与决策闭合

岗位规则及评分策略在Java数据库配置并发布，Agent/LLM判断简历事实和逐项语义要求，Java验证证据并确定性算分。保留本项目岗位、简历、匹配、面试、人才、配置、工作台全部范围，不以旧项目代码能力裁剪产品。

“设计不留不确定项”指开发规则不能悬空；候选人材料的UNKNOWN/NEEDS_REVIEW是有明确处理动作的事实状态，不能为了得到确定分数而猜测事实。

| 决策 | 固定处理 |
| --- | --- |
| D-01 未提及硬条件 | UNKNOWN→待核验，不等于明确不符合；不进入正式评分排名，不放入“明确失败”的过滤统计 |
| D-02 人工修正与历史 | 新事实、新结果，旧结果SUPERSEDED；默认显示切换，不物理覆盖，不能在刷新时重算 |
| D-03 加分 | 只用第五维，不另加最多5分或其他隐藏bonus |
| D-04 整维未知/空配置 | 非零维度必须有可执行标准才能启用；运行整维无可评结果时总分null、待核验，不自动调权 |
| D-05 缺证据 | UNKNOWN不计0，降低覆盖率；明确反证EXPLICIT_NOT_MET计0且计入已知覆盖 |
| D-06 JD与职级 | 上下文独立版本；只有采用为评分标准才更新规则版本。评分模型不接收未采用的JD附加要求 |
| D-07 日期精度 | 保留年/月/日精度，用上下界区间判断；跨阈值待核验，禁止把推算月份当已知事实 |
| D-08 经验超上限 | 采用原区间公式；不推测薪资/动机。仅超上限扣分导致跌入最低档时转人工复核，总分不篡改 |
| D-09 自动继续/重试 | 低置信超时继续不解除待核验门禁；没有有效预算不触发收费；总实际尝试最多3次，非3次额外重试 |
| D-10 格式与原件 | 全部产品格式均纳入交付；面试官只得到清洗结构/安全附件，不附原始含隐私原件 |
| D-11 覆盖门禁 | 普通正式分档最低覆盖80%，强烈推荐最低90%，关键项必须已知；岗位可提高、不能降低该底线 |
| D-12 角色与存储 | 服务端角色/数据范围/独立DTO强制控制，浏览器隐藏不是权限；保留与清理按不可变截止快照执行 |

全部设计参数在本版有默认值、范围、失败处理和责任方；“需要真实样本校准”属于验证任务，不是实现时再自由选择规则。

## 2 角色、资料范围与禁止项

| 角色 | 可以做 | 不可以做 |
| --- | --- | --- |
| 招聘负责人 | 管理授权岗位、确认事实、匹配/预演、允许的放行、面试与导出、分配面试官、复核删除 | 越租户/越部门读候选人；放行不可放行条件；修改历史 |
| 招聘专员 | 被分配岗位的上传/事实校正/匹配/安全导出；在授权范围查询 | 发布岗位规则、修改全局配置、人工放行、删除候选人，除非单独授予对应权限 |
| 用人经理 | 分配岗位的配置协作、结果与理由、独立预演标注 | 未授权联系方式、跨岗位候选人、全局规则 |
| 面试官 | 仅指派且有效期内的候选人结构化简历、核实点与题集、独立记录 | 分数、分档、维度分、排名、证据强度徽标、匹配亮点/缺口、联系方式及原始私密附件 |
| 配置管理员 | 维护岗位族模板、词典、全局配置、角色授权、审计 | 默认读取候选人正文/联系方式；配置权限不隐含招聘数据权限 |

每次读写核验租户、组织数据范围、岗位授权、候选人授权和字段权限。ID列表先按权限过滤再分页统计，不能先全量检索再在浏览器隐藏。未认证401、无范围403；不可见对象返回404，不泄漏其是否存在。开发环境也要使用显式测试身份及授权，不能把“dev用户”当无限HR权限。

16项禁止属性沿用原规格，不能解析为结构化字段、进入规则、评分、排序、模型评估或面试题。身份证/银行卡丢弃；手机号/邮箱加密存储，列表脱敏。临时查看完整联系方式需独立权限、二次确认、记录审计、30秒后重脱敏，服务端grant有效30秒、不可缓存到持久浏览器存储。招聘原件按原件权限访问，不进入通用知识库或跨业务RAG。

## 3 岗位与配置：HR-01至HR-12

### 3.1 岗位与向导（HR-01）

岗位族固定九类：技术研发、产品、设计、运营、市场、销售、职能支持、管理岗、应届生。岗位族创建后不可修改；部门内去首尾空白、全半角归一后的名称唯一（不区分大小写），编码由部门稳定编码＋六位自增号生成，用户填写编码也须租户内唯一。

基础信息作为向导前置步骤；随后四个页面为硬条件、软要求、权重与分档（含特殊标记）、预演与保存。原规格的“单独特殊标记一步”合并进权重页，保留现有五屏UI，不丢功能。每步服务端保存草稿及lastStep，version乐观锁冲突409不覆盖。状态DRAFT/ACTIVE/DISABLED；只有已发布有效配置的ACTIVE岗位可在上传目标中选择。停用后不接受新自动匹配，已有结果可查；已经冻结的在途任务允许完成。

启用必须具备：至少1条硬条件、1项核心技能、五维合计100%、三阈值严格递减、每个非零维有评分标准、语义锚点完整、无禁用属性、有效词典/Prompt/模型绑定。缺一拒绝并返回字段级原因，不能前端验证通过后绕过后端。

### 3.2 JD草案（HR-02）

接受粘贴或doc/docx/pdf/txt，20MB、保留前20000字并提示；少于100字不发模型。提取硬条件、技能、年限、项目要求，必须有JD原句定位。全部候选默认未采用；用户逐项采用后进入草稿，不能直接发布。归一失败保留原名、进入待处理词典；禁用属性候选不输出，给安全提示。无原句候选拒绝。JD只作解释和面试上下文，更新上下文版本；采用其规则候选才更新评分版本。

### 3.3 八类硬条件与容差（HR-03至HR-05）

条件独立全量判断，不短路。同类型只能一条；技能/证书/地域/语言类型可在一条内配置多个原子要求，匹配方式ALL/ANY必填，避免“只允许一条”变成只能配一个技能。超过5条黄色提示，不阻断。

| 类型 | 实际值与达标 | 容差 | 默认人工放行 |
| --- | --- | --- | --- |
| 学历 | 已确认最高学历序列：中专/高中=1、大专=2、本科=3、硕士=4、博士=5；其他/未知待核验 | 最多下降1级，整级，不适用30% | 允许 |
| 工作年限 | 非实习工作区间并集，月为单位，实际≥阈值通过 | floor(阈值月数×30%)，向下放宽 | 允许 |
| 必备技能 | 明确自述仅满足“已声明”；要求实际使用时须有项目/工作证据；语义熟练度由冻结锚点评估 | 无 | 不允许 |
| 工作地域 | 候选人明确期望/接受城市与要求集合交集非空；当前城市不能代替意愿 | 无 | 允许 |
| 资质证书 | 标准证书ID、有效期与岗位要求匹配；写“待考”不算已持证，状态不明待核验 | 无 | 不允许 |
| 语言能力 | 词典中同体系等级比较，跨考试体系仅用已发布对照表，不能LLM自行换算 | 等级整数≤floor(阈值×30%)，阈值很小时只能0 | 允许 |
| 项目规模 | 岗位声明指标/单位/周期，候选人在同指标的明确项目规模≥阈值 | floor(阈值×30%)，固定指标精度 | 允许 |
| 团队规模 | 明确本人管理人数（不含本人），≥阈值；仅项目总人数不等于管理人数 | floor(阈值×30%)，整数人数 | 允许 |

PASS、BORDERLINE、FAIL、UNKNOWN、NEEDS_REVIEW、OVERRIDDEN六类展示期望、实际、原文与原因；临界也按通过，但汇总必须单列。未提及为UNKNOWN；明确“无该证书/仅2年”等才FAIL。硬条件FAIL且未放行进入FILTERED，不计算正式五维分，总分null显示“—”。未知项进入待核验，不给“未具备”文案；如同时有FAIL和UNKNOWN，主状态FILTERED但全部项仍展示，人工处理已知失败后若仍有未知仍待核验。

项目规模必须配置QPS/日订单/用户量/数据量等指标及单位，禁止跨口径直接取最大值；单位转换表随规则版本冻结。不能以简历宣称的数字证明真实性，只能证明材料中有该主张。

### 3.4 软要求、岗位族参考及版本（HR-06/08/09/11/12）

核心技能重要度1至10，标准技能ID唯一，不能与加分重复；1至2项、超过10项提示，最多30项，技能过多转加分必须显式确认。经验/项目/学历要求各有原子ID、权重、期望和档位锚点；软性“必须相关专业”仅影响学历分，不产生硬过滤。

五维权重0至100整数，合计100；滑块实时示例由Java同一评分函数预览，不用前端另一套公式。维度>60%提示；学历>10%提示，应届生>30%提示，均不阻断。按比例调整用最大余数法：先floor归一后的比例，余数按小数部分降序补齐100，平局按五维固定顺序；全0无法归一。

| 岗位族 | 技能/经验/项目/学历/加分初始权重 |
| --- | --- |
| 技术研发 | 40/25/25/5/5 |
| 产品 | 20/30/40/5/5 |
| 设计 | 30/20/45/5/0 |
| 运营 | 25/30/35/5/5 |
| 市场 | 20/35/35/5/5 |
| 销售 | 15/40/35/5/5 |
| 职能支持 | 30/35/20/10/5 |
| 管理岗 | 20/40/30/5/5 |
| 应届生 | 25/5/35/30/5 |

模板只作为复制起点，核心技能候选默认不选；从模板创建后完全独立。系统九族模板不可原地编辑/删除，仅可复制；组织模板可编辑但发布为新版本，历史引用不变。另存模板不含JD、简历或结果；预演独立标注样本≥10、一致率≥85%可标“已验证（样本N/日期）”，不能标模型准确率。

五个标记始终计算存储，开关只影响展示：低置信/关键缺失→需人工复核；容差→临界；时间/文本结构观察→质量提示；候选相似度≥85%且未确认不同→疑似重复；有明确跨界/创业事实且处于低档→特殊背景关注。标记不能直接改分或推断性格、诚信、离职风险。

初始评分版本v1.0。硬条件任一变化主版本+1且次版本归0；其他影响评分或标记展示配置次版本+1；名称/部门/职级/JD变化仅更新上下文版本，不隐含改锚点。保存草稿不占发布版本；发布事务生成不可变配置及hash，旧发布转归档。结果保存完整配置值快照＋引用＋hash。修改不自动重算，当前与历史清晰分离。

### 3.5 预演（HR-10）

取10/20/50份授权候选人，可随机（冻结种子与ID）、指定或新上传；不足取全部并显示N。冻结未发布草稿，单独存sandbox结果，不写正式匹配历史、不更新档案匹配记录。已有事实/判断可复用，不重复解析；收费前展示最大新调用与总授权，预算不足直接阻止，不缩样本后悄悄执行。

分布诊断分母是本次业务成功产出状态的N，不含系统失败；优先级：过滤>50%→硬条件过严；已评分中的暂不推荐>70%→评分过严；已评分中的两高档>80%→过松；全部有效结果同档→无区分度；其他→分布合理。N=0不显示合理；有待核验先附“材料覆盖不足”，不能仅看已评分小样本宣布合理。每条硬条件过滤率按明确失败人数/N计算，>40%提示。

HR独立标注四档或硬过滤/待核验，提交前隐藏系统分档，提交后显示对照；一致率=相同标签数/有效双标注数，未标注不计分母；一致率<85%提示，不阻断岗位启用。差异原因六类沿用原规格，备注≤200字。样本不足10只显示试跑结果，不授予“已验证”模板标签。

## 4 简历全流程：HR-13至HR-18

### 4.1 格式、上传与安全边界

全部支持pdf/doc/docx/jpg/jpeg/png/txt/md/html、zip/rar/7z以及文本粘贴；原规格的jpg包含jpeg别名。单文件20MiB、单压缩包100MiB、每批最多100个文档条目；粘贴≤50000个Unicode字符，<200提示不阻断。授权每批重新确认，记录操作者/时间/告知文本版本/用途/保留策略；未确认不能开始。目标只能选启用岗位，或明确“仅入库不匹配”。

按魔数/MIME而非后缀校验。压缩包一次展开、不支持嵌套；展开总量≤500MiB、单文件≤20MiB、解压比例≤100倍、路径深度≤8、100文件，拒绝路径穿越/绝对路径/符号链接/加密包/损坏包，超额整包拒绝不截断。系统临时目录隔离，完成/失败1小时内清理临时副本；不执行宏、脚本或外部引用。

PDF逐页文本＋必要页OCR，最多200页；doc/docx段落/表格抽取；jpg/png先校验像素（最大40MP），<600px宽提示但允许OCR；txt/md/html按UTF-8优先、检测编码后抽取可见正文，HTML不执行JS/不加载远端资源。单简历可见文本≤100000字符，超出不静默截断，返回TEXT_LIMIT_EXCEEDED并要求裁剪后重传。PDF/DOCX页块/图片坐标均冻结，文本没有精确页码时展示段号而不伪造位置。

页面边界600px、20MB等以实际配置单位清晰显示；页数/像素/字符超限属于格式处理失败，不是候选人不达标。公共上传返回安全错误码和单文件操作建议，不回显文档正文。

### 4.2 解析、证据与置信分

事实包含基本信息、教育、工作、项目、技能、证书语言，及原始值/标准值/块ID/精确原文引用/日期精度/来源类型。姓名/联系方式在本地CPU识别并由Java加密保存，不能为识别姓名而把全身份信息传给模型；无明确标注的姓名只作待确认候选，完全缺失暂停人工确认。LLM只处理已去身份的职业事实，不得生成原文不存在的经历或数值。块引用必须存在，标准化冲突送复核；抽取不到有效文本先走OCR（适用类型），仍为空则UNREADABLE，不调用事实解析LLM。原始照片和禁用属性不生成结构化字段。

技能强度：至少2个不同工作/项目职责或成果来源为强；1个职责/成果或技术栈来源为中；仅专业技能栏为弱。证据以块hash和经历ID去重，同一段多次出现不增加独立来源。证据强度不自动等于熟练度；技能实际达标还需按岗位锚点逐项评估。

字段质量分使用确定性`quality-policy/1`，不采用模型自报概率：有精确引用、唯一归一且无冲突=100；有引用但缺时间精度/别名歧义/范围不明=60；冲突或OCR关键字低可靠=40；无有效引用/未识别=0。人工明确确认且留下来源/修改理由=100。OCR字符平均识别分<0.85或关键字段字符<0.70即归“需确认”，这个OCR分仅用于该引擎识别质量，不称事实真实概率。

整体质量分：姓名10%、工作30%、项目25%、技能20%、教育10%、证书语言5%；每组以实际存在的事实字段平均，明确“不适用”的空组按该组不适用剔除并重新归一，有要求但缺信息的组按0。姓名缺失直接暂停。整体<70，或任意硬条件所需事实中≥2项质量<85，暂停该条待确认；不能阻塞其他条。页面将历史“置信度”标为“解析质量分”，展示口径说明。

工作日期按月并集统计至冻结的asOfDate（北京时间当天）；使用time-policy/natural-months-1：已明确工作的起止自然月均计入，内部区间[startMonth,endMonth+1)去重，同月出现多段只计1月，不满一月也计该自然月，页面明确“按有工作记录的自然月计”，不称法定逐日工龄。原文只写总年限且有冲突时间线时送核验，不用总年限覆盖矛盾。“至今”只在明确原文且任职状态未冲突时取asOfDate所在月，不能计未来月。

年精度日期的可能起点为当年1至12月、终点为当年1至12月，先按合法start≤end及asOfDate截断。每段生成“必然覆盖区间”[最晚可能开始月,最早可能结束月+1)（空则记空）和“可能覆盖区间”[最早可能开始月,最晚可能结束月+1)，分别求并集月数得到安全下界minMonths/安全上界maxMonths；不枚举所有经历的日期组合，排序合并复杂度O(n log n)。这两个是保守边界，不声称都是可同时实现的精确极值。下界已达阈值可PASS，上界仍低可FAIL，其余UNKNOWN。没有任何合法单段区间返回时间冲突NEEDS_REVIEW。实习明确标识才排除，实习身份不明送核验。跳槽/平均任职/空窗>3月/时间重叠仅事实提示，不直接计分；空窗按前段结束月与后段开始月之间未覆盖自然月数计算，不精确时仅报告确定存在的下界。全日制未提及留null；团队人数无法确定是否含本人留区间并核验。

### 4.3 人工确认与自动继续

质量<85的字段展示原文/原因/编辑；修改创建新事实快照，不改原输出。派生字段不可直接改，只能改来源并重算。跳过须二次确认并记录未确认项；采集时按全局1至30天配置冻结waitUntil，默认72小时，到期标AUTO_CONTINUED，已有等待不因全局修改延长或缩短；均不把未知事实变为已知，仍执行硬条件/覆盖门禁。自动继续仅在有效批次预算/截止仍允许时发新请求；否则BLOCKED_BUDGET并待办，不授权新预算。

新事实版本提交事务立即把所有岗位中依赖被改事实的结果标STALE并移出默认正式排名；只对本次明确选择的目标岗位按已授权事件建新任务，其他岗位显示需重算、不自动发模型。新结果完成后旧结果标SUPERSEDED；新任务失败时旧结果仍为STALE，不回退成有效旧分。仅联系方式校正且未进入任何评分/解释输入时，不让无关分数过期，但联系人授权/导出缓存必须失效。

### 4.4 去重与合并

相同租户且用户可访问的SHA256相同文件复用解析，目标岗位不同只新匹配。身份信号由加密联系方式＋服务端HMAC检索：至少一个明确高质量手机/邮箱相同、无任何其他非空高质量联系方式冲突，才自动关联候选人并新建简历版本；共享联系方式标记、其他冲突、低质量联系方式均转人工建议。姓名＋学校＋毕业年相似只提示，不自动合并。

相似度算法冻结为resume-dedup/1：输入为剔除身份/联系/禁止字段后的可见文本，Unicode NFKC＋casefold，去全部Unicode空白及隔离的零宽/控制字符，保留其他标点；两个文本归一后较短者长度≥20时两者都用字符5-gram，否则两者用n=min(3,较短者长度)。gram按Unicode码点取集合，Jaccard=交集数/并集数；任一空串或空集合返回0，绝不空串匹配100%。相似度原始值≥0.85仅标疑似重复，不参与评分；展示百分数不决定是否命中。不可见档案不泄露匹配身份。确认“不同人”后记录这对候选人＋事实版本，不反复提示。

手动合并需选择主档；身份主档可合并，材料/用途/岗位ACL及expiresAt不合并扩权或延长。每一份来源材料、结果、题集始终保留originCandidateId/originResumeVersionId和原授权策略。用户只看到自己有权的来源，主档名/联系方式也从可见来源装配，不得因主档身份暴露其他部门信息。冲突联系方式不自动选“最新”为可信，保持分源待核验。

合并后新上传须选择被授权的来源归属；新结果/题集继承所用材料来源和授权交集，非源主档任意并集。混合多来源产物需要操作者对全部源有权并记录provenance，不能借合并跨用途使用。7×24小时内可撤销：来源不变的旧/新增版本与产物回归各自原候选人；混合产物标STALE并保留原授权，只可由对全部来源有权者查看，重新选择单源后重算。普通UI超过7天不提供撤销。删除合并主档全体须有全部来源删除权；否则拒绝该“删除候选人”动作，不能静默部分删除或泄露无权来源的数量。

质量检查只记录可观察时间矛盾、文本结构和可疑隐藏指令；不存在AI生成概率、性格或忠诚度结论。隐藏文本先隔离，不进入模型；招聘有权限者可在安全隔离区查原文。不因模板或量化数字比例直接降分。

## 5 完整评分制度：HR-07/19/20

### 5.1 原子判断与标准分

每项语义要求冻结业务描述、适用性、关键性、期望级别、强/满足/部分/明确不足锚点和有效证据类型。LLM批量返回requirementId、level、evidenceIds、简短依据与reasonCode，不能输出权重/总分/分档；集合恰好覆盖输入，已知判断必须有1至5条有效引用，UNKNOWN可以无引用且不得编造。结构错误最多消耗该逻辑操作3次实际HTTP总尝试，失败不得伪装成候选人低分。语义原子项数按硬条件＋软性全部需求去重后最多60，最多4批×15，不能只计软项；所有确定性及语义要求总数最多100，启用时校验。

| 原子状态 | 标准分 | 条件 |
| --- | ---: | --- |
| STRONG_MATCH | 100 | 有证据达到强档锚点，显著高于岗位基准 |
| MATCH | 80 | 有证据达到岗位基准 |
| PARTIAL_MATCH | 50 | 有证据只达到部分锚点 |

### 5.2 子项公式与初始标准

所有子项权重由岗位配置冻结；启用时每个非零维至少1个适用项，维度内权重合计100，技能使用1至10重要度比例，加分等权。关闭某子项是在岗位配置中显式移除，不是在候选人运行时根据缺信息关闭。

### 5.3 聚合、覆盖、舍入与门禁

```text
维度分S_d = Σ(已知适用项w_i×s_i)/Σ(已知适用项w_i)
维度覆盖C_d = Σ(已知适用项w_i)/Σ(全部适用项w_i)
总分T = Σ(维度权重W_d×S_d)/100
覆盖C = Σ(W_d×C_d)/100
```

明确不满足0分是已知、有证据的判断，计入覆盖；UNKNOWN/NEEDS_REVIEW不作0，压低覆盖。覆盖是“足以判断”，不是满足率。整维没有已知项且W_d>0时T=null、待核验。零权重维仍计算可得参考分，分母为空显示“未配置/无可评材料”，不填100。

计算用十进制，中间至少12位小数；最终分数及覆盖百分比HALF_UP到1位，分档和80/90覆盖门禁都用这一位的值比较。原始计算值一并保存供审计，79.94%→79.9%不达80，79.95%→80.0%达80；89.95%→90.0%达90，UI不与后端使用不同精度。阈值整数0至100严格递减。总分0至100；所有错误/空值不得自动当0。

决策顺序固定：明确硬FAIL且未放行→FILTERED；硬未知/关键未知/证据冲突/整维未知/总覆盖<80→REVIEW_REQUIRED；否则按阈值评分，T≥高线且C≥90→强烈推荐，T≥高线且80≤C<90→待核验，不擅自高档；中线≤T<高线→推荐，低线≤T<中线→建议复核，T<低线→暂不推荐。关键要求无论权重多少都须已知；岗位可设更高覆盖门槛但不能低于80/90。

REVIEW_REQUIRED和四档中的REVIEW是不同原因状态：前者不进正式分档统计与排名，后者是已充分评估的50至65分档。具备部分分数时前者显示“参考分83.5，待核验”，明确不是正式排名分。FILTERED完全不产生五维正式分。人工放行属于程序性例外，新结果至多显示“建议复核（已人工放行）”，不自动授予两个高档。

经验超上限例外：另算取消超上限扣分的T_base；若T<低线且T_base≥低线，主业务状态REVIEW_REQUIRED、原因EXPERIENCE_OVERQUALIFICATION_REVIEW，保留T与T_base，不把T强改50。不能推断薪资、动机、忠诚度。

参考例：五维分80/90/80/80/100、技术族40/25/25/5/5→83.5；覆盖100、硬条件全部已知通过、无人工放行时强烈推荐。只有部分证据导致相同83.5且关键项未知，必须待核验。64.95→65.0，与65分档一致。加分权重5%且所有加分项UNKNOWN时，即使其他四维全部已知、潜在总覆盖95%，也因整维未知令T=null并待核验；不能以覆盖门槛绕过D-04。岗位不需要加分维时须在发布配置设0并显式重分配权重，而不是每候选人动态降权。

### 5.4 重算与比较

只改权重/阈值，复用原子证据判断，Java重算，不发LLM；改期望等级/锚点/事实/词典/Prompt/模型，重新评估受影响要求。幂等键＋完整输入快照hash防重复；刷新/翻页/断线恢复只读结果。当前配置版本、计分主版本与评价语义契约相同且基于各自当前有效事实的结果可以比较；不同候选人的事实ID自然不同，不要求事实ID相同。跨岗位不统一排名。

语义判断本身存在模型变化可能，复用的是已持久快照，不承诺重发LLM仍输出相同。缓存按租户、候选人、事实hash、要求/锚点hash、词典/Prompt/模型版本隔离。

所有语义、题集、预览、导出缓存读取都重新核验当前授权；复用生成结果不意味着复用访问权限。派发撤销/到期/源材料删除/联系方式变更立即使相关grant和缓存不可读。导出缓存还包含导出DTO版本、角色投影类型、内容选项/联系授权版本，不得HR版与面试版共用。缓存命中只免重复计算，不跳过输入版本校验。

禁止题型校验先确定性禁用属性/词语，再结构与来源核验；命中只修复当前题组，最多同操作3次HTTP，仍失败CONTRACT_FAILED，不循环到合规为止。手工新增也过相同校验。编辑/删除/排序保存题集新版本；单题重生仅替换该题的产物版本，保留其他题。

面试官授权绑定候选人、题集版本、有效期（默认7天，负责人可设1小时至30天），撤销立即生效。独立API/DTO/DOM不含评分/档位/排名/强中弱徽标/匹配亮点与缺口，不返回再靠CSS隐藏；核实问题措辞不提“AI认为/评分低”，源标记改为“岗位要求/简历待核实”。HR角色导出也不能把AI分数放入面试指南。

PDF/Word及A4预览调用同一安全导出模型；默认不含联系方式，可对招聘负责人单独生成审计的联系版，但该版不可通过面试官链接下载。面试版附件是已清洗可读简历，禁用字段/评分/联系方式按面试官DTO排除；不能直接嵌原件。每题后空白记录页及三档参考，页脚保留AI辅助免责。下载链接一次性、10分钟过期，不进公共COS。

## 8 人才库、全局与工作台：HR-30至HR-35

候选人档案保留版本/事实/所有岗位匹配/题集/修正/放行日志；身份和材料属于租户及授权用途。搜索结构化筛选先权限，技能用冻结词典，语义命中展示原句和“检索相关度”而非达标概率，相关度仅用于检索排序，不进入匹配总分。默认每页20条、可选20/50/100；稳定排序＋游标/页码一致，返回有权限范围内总数。排除已匹配某岗位按授权岗位和非撤销结果判断，不泄露其他部门。

档案>30天未更新提示较旧，保留不足30天提示（展示32天示例错误纠正）；只有新授权简历版本或有依据的保留延期改变截止，不因浏览/修改标签/重算而延长。保留默认从合法采集/新上传起12个自然月，Java保存consentPolicyVersion和expiresAt；租户首次启用必须完成告知文本/保留政策配置并由有权负责人确认，未完成可配置岗位、不能真实上传。该配置门禁是固定行为，不是开发待决项。全局变更只作用新采集，历史截止不追溯；显式延期需要新的依据和审计。

到期或人工删除先立即撤销可见性/链接，进入DELETING；清理向量/索引→业务关联事实/结果/题集→私有原件及缓存/暂存，24小时内完成。跨存储无分布式原子承诺：任一步失败保持不可见，有限重试1分钟/5分钟/30分钟/2小时/6小时，之后告警待人工，不标DELETED；补偿任务只做删除，不恢复可见。完成后DELETED不可恢复；共享原件按租户授权引用计数，仍有合法引用不删底层对象，只删本候选人引用。日志不含可逆联系信息、正文或证据原句。

审计记录发布/修正/放行/撤销/导出/查看联系方式/删除/词典/权限变化，append-only、不允许业务用户修改删除；保留3年后转不可变归档7年，期满按审计策略清理，仅保留非个人化统计。删除候选人不删除必要无正文审计，个人标识使用不可逆墓碑ID。

词典七类、标准名/别名唯一范围、歧义上下文规则版本化；多规则冲突/无命中保留未归一，不由模型选最方便答案。词典建议仅为草案，发布后影响新事实归一，历史不自动改，显式重算才用新版本。导入CSV/XLSX≤10MiB/10000行，先预检冲突清单、整批原子采用；导出仅词典，不夹带简历。

全局配置固定项及边界：保留1至60月默认12；人工确认等待1至30天默认3；模型总尝试1至3默认3；失败条目保留1至90天默认30（仍须早于候选人expiresAt）；默认阈值80/65/50；告知文本版本；文件安全上限只可降低、不可由业务HTTP提高；禁止属性只读。默认值只作用新对象，不能修改已有岗位或续授权。

工作台只显示实际授权数据：低置信待确认、明确过滤待查看、未完成岗位、未归一技能、30天内到期五类待办。未到自动继续期限的按创建时间排序，到期/权限撤销实时消失；某待办数量0不虚构条目。指标使用北京时间本周一00:00至当前，与上周相同时长比较，分母0显示“无可比数据”而非无限增长。岗位进展区分四档/过滤/待核验/运行失败，>40%过滤橙色提示；活动用业务事件，不用模型编造。

## 9 任务、费用、重试与异常

完整业务任务硬上限100元、60次实际付费HTTP、10分钟，单逻辑操作最多3次总HTTP尝试；解析、语义、解释和嵌入均计入统一总账。批次另有总授权，不能每份自动领100元。中途人工等待关闭当前执行占用，后续用户动作创建新任务但继续受批次及全局累计上限；不能更换taskId/预算ID绕过。

无预算/价格未核实/模型不明/账本异常发送前拒绝；402持久熔断，429按已授权阈值；取消、unknown保留预留，不自动退额或续期。计划在请求前冻结工作量，合法用量结算后释放已证实未使用部分；不把“当前尚有余额”视为本批授权。

文件抽取（免费本机）失败可1次有界重试，付费模型/网络/schema修复共享3次，后台不再开新的外层重试。人工点击重试创建显式任务并展示已有占用，未修正输入且同一失败操作不能无限重发。取消后取消排队/在途任务及响应流，迟到事件不改变终态。单条失败不取消其他条，但批次授权熔断/用户取消批次阻止全部后续收费。

事件单调序号、断线按Last-Event-ID续读，只重放已存事件，不触发生成。客户端只看到公开阶段，不输出隐式推理/Prompt/凭据。关键安全错误码有权限、输入、材料、配置、模型、预算五类，不将系统异常映射为候选人能力缺口。

## 10 验收与交付标准

35项需求均有产品规则、Java契约、Agent边界（需要时）、UI状态、可执行用例和真实验收范围。交付分开发顺序，不删除任何格式/页面/功能；在全部通过前模块标“试用”，未接页仍标演示。阶段交付不能宣称35项已全部完成。

确定性评分由固定事实黄金用例精确复算；语义校准使用至少2个岗位、每岗位50份授权脱敏样本，两位独立标注、分歧仲裁，20%锁定回归集不参与调Prompt。上线门禁：精确引用有效率100%、受保护字段泄露0、明显未提及误判FAIL 0、允许高档的关键要求逐项一致率≥90%、六种业务状态与仲裁一致率≥85%；不足保持试用/人工复核，不修改阈值伪报通过。这是需要执行的测试，不代表已经取得样本或真实准确率。

真实材料/数据库DDL/供应商调用仍按已有授权边界执行；没有样本时停在合成与离线验收，不伪造“真实通过”。设计不依赖未知业务选择，但不能替用户编造法律依据、数据授权或供应商价格证明。
