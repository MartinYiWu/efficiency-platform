## 1.4 三个必须在 UI 上体现的设计判断

这三条不是视觉偏好，是产品边界的界面化表达。

**判断一：分档色不用红色**

```
强烈推荐面试   绿  #16A34A
推荐面试       蓝  #2563EB
建议复核       橙  #F59E0B
暂不推荐       灰  #94A3B8   ← 不是红色
```

红色暗示"淘汰/错误"，灰色表达"暂时排后"。**AI 没有淘汰权，界面上就不能出现淘汰的视觉语言。**

**判断二：面试官视角必须物理隔离**

不是"权限控制不显示分数"，而是**面试官角色进入时整个页面结构不同**——没有分数区块、没有维度得分、没有排序位次，只有结构化简历 + 待核实点 + 面试题。UI Prompt 里会单独画这个视角。

**判断三：证据必须可点击跳转**

匹配理由里的每条证据，点击后跳到原简历对应位置并高亮。这是 HR 在 15 秒内判断"AI 是否理解正确"的唯一途径。做不到这一点，可解释性就是空话。

## 第二部分：UI 生成 Prompt

## 全局设计系统前缀（每次必带）

```text
你是一位资深企业级 SaaS 产品设计师。请为「AI 效能平台 - AI 人事助手」
设计高保真 WEB 端 UI 界面。

## 一、输出要求
- 输出可供评审的高保真桌面端设计稿，不限定前端实现技术
- 画布 1440×900，桌面端优先
- 所有文案使用中文，包括标题、按钮、占位符、提示语、状态标签、空状态文案
- 使用真实业务文案，严禁 Lorem ipsum、"标题1""内容2"这类占位内容
- 图表用纯 CSS 或内联 SVG 绘制，不引入图表库
- 头像用带姓氏首字的圆形色块，不引用外部图片

## 二、产品定位
面向企业内部 HR、招聘官、用人经理、面试官的简历智能分析与面试准备工具。
核心能力：简历解析、岗位匹配评分、匹配理由与建议、面试题生成。
明确不做：入职办理、候选人状态流转、面试安排、Offer、自动淘汰、
向候选人发送任何信息。

## 三、设计系统（严格遵守）

基础色彩：
- 主色 primary        #2563EB
- AI 紫 accent        #7C3AED
- 成功 success        #16A34A
- 警告 warning        #F59E0B
- 危险 danger         #DC2626
- 信息 info           #0EA5E9
- 页面背景            #F8FAFC
- 卡片背景            #FFFFFF
- 边框               #E2E8F0
- 分割线             #F1F5F9
- 主文字             #0F172A
- 次级文字           #475569
- 弱化文字           #94A3B8

★ 匹配分档专用色（固定不变，不得调整）：
- 强烈推荐面试  #16A34A（绿）
- 推荐面试      #2563EB（蓝）
- 建议复核      #F59E0B（橙）
- 暂不推荐      #94A3B8（灰）★ 必须用灰色，禁止用红色
  设计意图：AI 不做淘汰决策，"暂不推荐"是意见不是判决，
  界面上不得出现淘汰、驳回、失败的视觉语言。

★ 证据强度专用色：
- 强（HIGH，多项目支撑）    #16A34A
- 中（MEDIUM，单项目支撑）  #2563EB
- 弱（LOW，仅技能栏列出）   #94A3B8

字体与字号：
- 中文无衬线字体栈：system-ui, "PingFang SC", "Microsoft YaHei", sans-serif
- 页面标题 20px/600  区块标题 16px/600  正文 14px/400
- 辅助文字 13px/400  标签与徽标 12px/500  分数数字 32px/700

间距（8px 基准）：
- 卡片内边距 20px  区块间距 20px  卡片间距 16px
- 表单项垂直间距 16px  表格行高 52px

圆角与阴影：
- 卡片 12px  按钮 8px  输入框 8px  标签 6px  弹窗 12px
- 阴影仅用 0 1px 3px rgba(15,23,42,.06)，不使用重阴影

## 四、框架布局（所有页面统一）
- 左侧固定导航栏 宽 220px，白色背景，右侧 1px #E2E8F0 分隔
- 顶部栏 高 64px，白色背景，底部 1px #E2E8F0
- 主内容区 背景 #F8FAFC，内边距 24px

左侧导航结构（当前模块高亮，其他一级菜单收起）：
  工作台

  知识中心
  素材中心

    │   ├ 岗位管理
    │   ├ 简历中心
    │   ├ 匹配结果
    │   ├ 面试准备
    │   ├ 人才库
    │   └ 配置中心
    ├ AI行政助手
    ├ AI内容运营助手
    └ AI财务助手
  组织中心
  权限中心
  系统管理
  数据中心

选中态：浅蓝底 #EFF6FF + 左侧 3px #2563EB 竖条 + 文字 #2563EB

顶部栏：
- 左侧：面包屑「AI人事助手 / 当前页面」
- 中间：全局搜索框，占位符「搜索候选人、岗位」
- 右侧：消息铃铛 + 用户头像 + 用户名「沐白」+ 角色标签「招聘负责人」

## 五、视觉风格
现代企业级 SaaS + 轻 AI 科技感。专业、克制、信息密度适中。
不要过度赛博朋克，不要霓虹发光，不要营销官网风，不要传统老旧后台风。
AI 相关入口可用蓝紫渐变（#2563EB → #7C3AED）点缀，用量克制。

## 六、必须包含的状态
- 正常态（有数据）
- 至少一处空状态（含插画位、说明文案、引导按钮）
- 至少一处加载态或进度态
- 危险操作的二次确认表达
- AI 生成内容必须带「AI 辅助生成，仅供参考」标注

## 七、明确不要出现
- 不要"自动淘汰""批量拒绝""发送拒信"等任何淘汰或对外发送功能入口
- 不要候选人状态流转（待沟通/面试中/已录用）相关 UI
- 不要面试安排、日程、Offer 相关 UI
- 不要"建议录用""不建议录用""薪资建议"等表述
- 不要性别、年龄、婚育、籍贯、照片等字段的展示或筛选入口
- 不要英文按钮和英文占位符
- 不要虚假指标（如 99.9% 准确率）

────────────────────────────────
以上为全局规范。以下是本次要设计的具体页面：
```

## 第三部分：使用说明

## 3.1 基本用法

```
每次生成 = 【全局设计系统前缀】 + 【某个页面的 Prompt】
```

## 3.2 建议生成顺序

| 顺序 | 页面 | 验证目的 |
|:---:|---|---|
| 1 | PAGE-00 组件规范 | **先定组件，后面全部复用** |
| 2 | PAGE-12 匹配详情 | 最复杂的信息结构，早暴露问题 |
| 3 | PAGE-11 匹配结果列表 | 验证分档色与表格密度 |
| 4 | PAGE-09 人工修正 | 验证左右对照 + 高亮框 |
| 5 | PAGE-03 岗位向导 | 验证多步表单与权重滑块 |
| 6 | PAGE-17 面试题编辑 | 验证嵌套卡片结构 |
| 7 | 其余页面 | 按域顺序补齐 |

**第 1 步不要跳过。** 后续生成时可追加一句：「组件样式请严格复用已生成的组件规范页」。
