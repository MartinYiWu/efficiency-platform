# 运营助手质量完善真实验收矩阵

## 1. 统一判定规则

- 所有业务场景从 Java `/api/operations/**` 发起，不直连 Agent 伪造业务成功。
- 研究场景必须访问真实公开来源并发生真实模型调用；文章场景必须由真实模型基于已验证引用闭包生成。
- 每个场景同时保存 HTTP/SSE、Java MySQL、Agent MySQL、Java 日志和 Agent 日志证据。
- 测试类、Mock、fixture、静态检查和编译结果只作开发辅助，不计入本矩阵通过证据。
- 原始证据写入 `.local-acceptance/operations-mvp/<timestamp>/`，不提交 Git；报告只记录脱敏摘要和证据路径。
- HTTP 非预期、SSE 缺失、数据库状态不一致、日志出现未分析异常或结果语义不满足时，场景均判定失败。

## 2. 场景矩阵

| --- | --- | --- | --- | --- | --- |

## 3. 完成报告格式

每个场景必须记录：执行时间、请求摘要、HTTP 状态、conversation ID、Java run ID、Agent run ID、真实终态、内容语义指标、数据库只读查询结论、日志文件与扫描区间。未执行、失败或结果不达标的场景必须原样写明。
