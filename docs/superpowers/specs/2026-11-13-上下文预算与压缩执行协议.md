## 1. 三种信息、三类职责

| 对象 | 负责模块 | 目的 | 不可混用 |
| --- | --- | --- | --- |
| 存储中的权威信息 | Java业务/消息/记忆管理 | 保存来源、版本、确认、保留和撤销 | 不因可存储就全量送模型 |
| 任务恢复状态 | Java业务状态＋Agent运行回执/LangGraph Checkpoint | 判断已做什么、在何处等待、哪些动作不能重发 | 不由LLM摘要宣布工具成功或业务批准 |
| 本次模型输入 | Python ContextBuilder及各入口适配器 | 从授权集合中选当前节点必要内容，计数、裁剪、压缩和准入 | 不直接把完整会话/Checkpoint/所有专家轨迹当Prompt |

MemoryContextPacket是Java允许使用的内容集合；ContextView是当前节点选择后的输入；ContextManifest记录这个View的模型、版本、数量和安全依赖。Python只可缩小授权集合，不能把省略理解为删除原存储，也不能靠引用展开扩大来源权限。

术语沿总方案：session是会话，task是跨天业务目标，execution/run是单次有限授权执行，thread只服务该execution的可恢复状态。ctx_revision表示NOT_SENT操作的输入准备修订，不等于packet授权刷新revision或业务对象版本。

## 2. 模型容量、节点政策与执行授权三道门禁

### 2.1 模型元数据

发布模型适配器固定provider/model/version、接口类型、总窗口W、独立输入上限I、最大输出、reasoning占窗/计费方式、tokenizer/序列化版本、工具和输出Schema开销、图像/PDF等模态计数规则、核实来源及日期。没有独立输入上限的模型，该I项不参加min；不得猜测一个很大的值替代未知总窗口。

本地计数优先使用匹配tokenizer或经过校准的保守上界。字符数/4不能直接作为中文/代码/JSON硬准入。模型适配器计数完整实际序列化请求，覆盖system/developer、消息角色/分隔符、工具定义/参数、tool_call/tool_result、输出Schema及供应商确认占窗的附件内容；不重复扣除本来未进入模型的HTTP协议字段。

远程官方token计数默认关闭；若后续启用，也是数据外发，必须取得用途/来源准入并经统一受控传输。若收费，纳入同账本；未知价格不能发。不得把每次发送变成无记录的额外外部请求，也不得用它绕过现有本地费用上界。

### 2.2 窗口公式与费用准入分开

```text
O = 本次输出占窗预留，按供应商定义计入reasoning，不重复计算
S = 安全余量，初值 min(2048, max(256, ceil(W × 5%)))
P = 已发布的当前节点输入上限
H_ctx = min(I, W − O − S, P)
T = 完整序列化实际输入token上界
F = 本次不可省略的必需内容token上界（已包含在T中）
R = max(0, H_ctx − F)
```

窗口门禁：H_ctx>0且T≤H_ctx；若F>H_ctx，删光可选内容也无解，返回CONTEXT_REQUIRED_INPUT_TOO_LARGE。系统/Schema/工具开销已经计入T/F，不能再从H_ctx重复减一次。

费用门禁独立检查本次T、O、reasoning、请求bytes、价格上界、调用数、inflight、原绝对截止及task历史累计，并在外发前原子reserve。可计算I_auth作为当前授权允许的输入上界，供界面预检和有界选择参考，但**物理窗口占用率始终用T/H_ctx**；费用不足不能伪报模型窗口溢出，更不能隐式发起另一次压缩或自动升级大窗口模型。

最终发送必须同时满足：身份/来源/包有效、窗口合格、请求bytes合格、当前操作回执允许、有效费用原子预留成功。Provider守卫的保守token上界若更严格，则最终以更严格口径准入；不能为让窗口看似装得下而改低原费用保护。

供应商缓存命中影响价格，不让T从窗口消失。输出预留O不得为塞入更多历史而低于业务输出合同；reasoning按接口定义分配，不重复占用/扣算。窗口、金额/token累计、供应商usage分别记录，不能共用一个含糊的“剩余token”值。

### 2.3 必保与可选预算

必保：系统/安全指令、当前用户明确要求、当前业务必要证据、对象/规则/冻结日期、仍待完成工具关联、已确认否定条件和必要运行回执。任何字段是否必保由发布节点策略及Java/运行事件确定，不能让摘要模型删改。

| 可选槽位 | 初始上限 | 装配约束 |
| --- | --- | --- |
| 已确认长期记忆 | min(2048, floor(H_ctx×20%))；偏好核心块≤512 | 权限/时效先过滤，再按相关性选；不是额外窗口 |
| 最近完整交互 | 最多12条完成消息且≤6000 token | tool_call及对应结果按完整组；与摘要覆盖去重 |
| 分段摘要 | 总≤1000 token，每段≤500 | 选择仍合法且相关段，不全量累加 |
| 恢复胶囊 | 当前步骤注入默认≤1000 token | 必需部分计F，其余不凑满；必要字段超限则有界业务拆分或停止 |
| 案例/可选研究片段 | 剩余R及其业务证据上限 | 不挤掉必需证据，不拿案例当事实 |

以上为上限，不保证每类分到足额；互相重叠内容只保留一个实际输入副本并记录覆盖关系。当前请求超过分类规划额度时先重新分配，不截断用户要求；若必需内容仍超总上限再明确阻断。

## 3. 每次模型发送的执行顺序

```text
当前授权/来源投影
→ 节点内容选择和完整消息组校验
→ 确定性去重/工具投影/聚合/分页
→ 已有合法摘要与近期历史有界选择
→ 模型适配器完整计数及增长压力判断
→ 有条件使用唯一derive生成摘要候选
→ 结构/来源/关键状态/实际收益验证
→ CAS提交可用摘要段，形成最终ContextView/Manifest
→ 总方案AuthorizationGate
→ 发送前再计数、查packet/deadline/操作回执、费用reserve
→ Dispatch及回执
```

必须覆盖首次发送、工具返回后、Supervisor派发前、专家汇总后、每次重试前、恢复后、模型/Prompt/工具Schema切换后、packet刷新或内容准备修订后，以及摘要模型自身发送前。前面的预算通过不能替代最终序列化后的硬准入。

纯授权刷新保持同一语义输入hash/operationId；选择/摘要导致的内容变化只在NOT_SENT准备阶段产生新ctx_revision。已SENT/UNKNOWN的业务请求不换摘要或新ID自动重试；恢复先核对原回执。LangGraph interrupt重跑节点的处理沿总方案安全门禁，不把压缩写在副作用节点之后随意恢复。

## 4. 工具完整结果与模型可见投影

工具拥有者先以程序完成字段筛选、授权过滤、聚合和分页。完整结果沿原业务保留策略存储或保留引用；不为“完整结果”另建无期限敏感副本。模型只取得当前步骤的投影。

| 字段 | 类型/语义 | 约束 |
| --- | --- | --- |
| data | 工具发布Schema的最小字段 | 不传未授权字段；金额、判定状态等由业务/程序计算，不由LLM代算 |
| completeness | COMPLETE/PARTIAL/UNKNOWN | COMPLETE指当前query/projection_schema/snapshot与授权范围内结果完整，不指整个数据库 |
| total_count | 非负整数或null | 仅为当前有权范围且可可靠计算；未知用null，不猜0，不泄漏其他租户/部门数量 |
| returned_count | 非负整数 | 与本次data条目数一致 |
| truncated | boolean | 本次是否因限额省略原合法结果；正常业务过滤不叫截断；无法证明完整时不能把false解释为全部结果 |
| truncation_reason | 受控枚举或null | TOKEN_LIMIT、RESULT_LIMIT、FIELD_PROJECTION等；不回显敏感正文 |
| next_cursor | 不透明游标或null | 绑定tenant/principal/query/snapshot/用途/期限，使用时重新鉴权；不是允许扩大范围的凭证 |
| snapshot_ref/version | 原结果引用 | 明确快照与业务版本，不能把几次查询拼成不存在的同一时点结果 |
| projection_schema/version、query_scope_ref | 投影字段定义和授权查询范围引用 | 明确完整性/数量的口径；受控不透明引用，不向模型暴露任意查询或内部SQL |
| safety_dependencies | 来源版本集合 | 从实际工具输入/结果投影继承，不由模型省略 |

若total_count已知则returned_count≤total_count；数据没有下一页不自动证明complete，可能是源能力不支持继续。UNKNOWN/PARTIAL必须在模型视图保留提示，不能把前20条总结为“总共20条”。全局统计/百分比的分母必须来自同授权query或专用聚合工具，不从可见样本猜总量。

工具发布`model_visible_token_upper_bound`及投影版本。原始bytes超过工具限制时按工具安全规则拒绝；已满足bytes限制但投影仍太大时继续有限字段/行选择，禁止截断JSON。分页继续属于显式原任务工具操作，消耗原工具/费用/截止额度，不自动无限翻页。

## 5. 多Agent上下文复制控制

Supervisor下发SpecialistContextSlice：子任务ID、目标、确定约束、必要source refs/版本、相关偏好、允许工具、输出合同、节点窗口policy与父task执行预算引用。不得复制完整会话、其他专家轨迹或全部Checkpoint消息；数据授权范围仍由Java包限定。

专家返回SpecialistResultProjection：结论、证据引用、未解决问题、风险、建议及其状态、产物引用、是否部分完成与覆盖范围、完整安全依赖。详细结果保留受控产物引用，不把全文串接到父Prompt。

每个专家按自己的模型和节点P重新计窗，父聚合按父模型再计窗。11个专家的每个请求都合格，不代表11份输出合并后仍合格；父节点先投影/去重/选择。结论只代表该子任务覆盖的范围，不能把PARTIAL结果汇总成全任务完成。

详读产物或补充证据遵守总方案追加/暂停合同；首期动态追加关闭，不隐式再调专家或增加付费。费用是父task累计，不给每个专家另一套100元/60次。实际进入子模型的依赖由子节点manifest记录，父节点实际使用该结果时继承其传递安全依赖。

## 6. 摘要语义合同与确定性任务胶囊

### 6.1 不可变分段

仅从仍可授权的原始已完成区间生成，不从“摘要的摘要”无限滚动。分段落在完整交互/工具组边界；单次源区间≤2000 token、输出≤500 token，同时满足摘要模型自身H_ctx，系统/Schema不在这两个源/正文额度外免计。

来源消息有更正或新版本，候选旧摘要标STALE，不能覆盖新水位。CAS按session/source revision提交，允许并发新消息追加但不错误声称摘要覆盖新消息。总注入≤1000 token，选择相关合法段并与原文历史互斥覆盖；省略旧区间明确记录，不假称完整历史仍在窗口。

### 6.2 结构字段

| 字段 | 作用 |
| --- | --- |
| covered_sources / watermark | 消息ID、版本、跨度及完整组覆盖，不是只有“第1—20条”的自由文本 |
| goal | 该阶段目标，附来源 |
| confirmed_constraints | 已确认约束及明确确认依据 |
| decisions | 决策内容、状态、依据事件/版本 |
| rejected_options | 已否决方案及有据原因；无明确原因记录“原因未记录”，不得编造 |
| open_questions | 未解决问题，不能压成已解决 |
| important_refs | 仍需原文/对象核验的证据引用 |
| uncertainties | 未确认、相互矛盾或证据不足事项 |
| source_dependencies | 所有实际摘要输入及其传递安全依赖、用途与最早截止 |

各条目携`content_origin`：USER_REQUIREMENT、BUSINESS_FACT、MODEL_SUGGESTION、UNCONFIRMED_INFERENCE；决策携`decision_status`：PROPOSED、CONFIRMED、REJECTED、UNRESOLVED。二者不是总方案item/proposal生命周期。没有可核对的用户确认/Java事件，不允许把MODEL_SUGGESTION提升成CONFIRMED；模型输出的标签不能自行制造确认事件。

Java根据来源回填/核验确认与业务事实状态；LLM只提议叙述及引用。明确否定要求与已否决方案是必保语义，不能为了省token删除。没有明确结构化确认映射时保留未确认，而不是用摘要“猜已经决定”。

### 6.3 恢复胶囊

复用现有TaskState/运行回执，维护current_goal、confirmed_constraints、entity/version refs、completed_steps/receipt refs、pending_steps、open_questions、blocking_conditions和watermark。工具成功来自执行回执，业务批准来自Java事件，用户约束来自明确确认；模型不能把“建议发送”记为“已发送”。

胶囊只选择当前步骤必要字段进入模型，默认≤1000 token且计入T/F；完整恢复状态仍存运行态。上下文裁剪不会把UNKNOWN变成SUCCEEDED，不清除operationId、已用额度或deadline，也不通过恢复再次执行已成功工具。

## 7. 四步压缩与实际收益判定

### 7.1 先选择

在源权限/有效期/抑制规则通过后，选择当前节点相关内容；排除无关历史、重复检索、被摘要覆盖的原文、无关工具定义及其他专家轨迹。改变工具可见集合必须在允许工具白名单子集内，不能删安全合同后调用原本未允许的工具。

### 7.2 再确定性缩减

使用字段白名单、可靠程序聚合、分页与片段选择；保留完整工具消息组、数据覆盖提示、数字/日期/否定/对象版本、执行回执和必要证据。不能在token边界任意切JSON、工具参数或引用句。

### 7.3 最后有界语义摘要

只有M2开启、输入用途准入、原task derive机会/费用/调用/截止均允许时，才发一次逻辑derive。只压缩已完成叙述，不能把必需HR事实/制度条款/当前指令交给模型自由改写。摘要与长期提炼必须满足总方案BOTH准入，否则选一种用途，不能暗拆第二次调用。

### 7.4 效益与提交

记录CPU选择后的基线ContextView，在相同模型、序列化/Prompt/工具Schema版本和相同必保内容下，计算替换前后完整请求T_before/T_after。比较包含摘要包装、引用和消息角色开销，不仅比较正文；目标来源覆盖与省略项逐项对应，不能靠额外丢掉必要内容制造压缩收益。

仅当`T_after < T_before`、关键约束/来源/用途/状态验证通过时，才将新段提交为可用压缩结果。正文更短但完整请求未缩小，也判SUMMARY_NOT_BENEFICIAL；候选不激活、不重试“再压短”，仅保留无正文失败元数据。阶段记录是否需要另行保留不属于压缩成功，沿原业务政策处理。

压缩的自由文本不可能只靠Schema证明语义等价；确定性字段和原文证据保留，模型建议不升级成事实。摘要保留期限从所有输入依赖取最短，信任等级不高于来源。源删除后不能回退到曾经合法的旧摘要。

### 7.5 仍然超窗

先移除可选案例与低相关历史，再缩小可选检索；必需内容仍超窗，只能按既有受权有界工作流拆分/分批，或由Java请求明确缩小材料范围。没有已启用、获授权拆分能力就返回CONTEXT_REQUIRED_INPUT_TOO_LARGE；不循环摘要、不自动换昂贵模型、不创建新task绕费用累计。

## 8. 阈值与下一步增长压力

R4保留R3的初值：u=T/H_ctx≤70%为NORMAL；70%—85%执行CPU TRIM；u>85%且存在可压缩合法历史才COMPACT_ELIGIBLE。压缩目标为尽量回到70%以内，但T≤H_ctx且所有必需内容完整时，不为达目标继续压缩。80%/60%可作为后续A/B候选，当前不直接替换；任何参数都不是行业标准。

下一步增长仅使用已发布工具/专家`model_visible_token_upper_bound`等可验证合同。计算保守增长G及其来源版本：若下一步追加T+G>H_ctx，可提前对**现有可选内容**做CPU选择；在满足全部M2条件时允许消费唯一derive，但不得摘要尚未产生的结果或因此获得额外调用。G未知就标UNKNOWN，不凭模型估一个数字预装正文；结果物化后必须重新计数。

ContextManifest将ACTUAL_PRESSURE与PREDICTED_PRESSURE分开；记录G/模型/投影版本，不能把预测量计为已发送token或账本实际usage。已知未来增长大于整个窗口时，提前选择有界工具投影/业务拆分，不先花钱压缩一个根本无法容纳的必需结果。

## 9. 源冻结、候选校验与CAS提交

压缩身份由task、原execution、derive operationId、来源ID/版本集合、完整区间、用途、policy、摘要模型/Prompt、目标上限组成；同输入只得到同幂等结果。freeze_source_revision→derive候选→校验→Java session CAS提交→更新后续ContextView。并发确认/更正/遗忘优先，旧候选不覆盖。

候选必须满足：来源存在且当前有权、区间准确、关键字段/状态不提升、decision依据存在、Schema/token合法、完整工具关联、最早源截止、全输入安全依赖、实际压缩收益。失败不改变原TaskState、原文、ACTIVE长期记忆或已成功工具回执。

输入依赖与展示引用分开：摘要看过A但只列B仍依赖A；摘要影响回答R后R继续继承A。原文删除或忘记抑制后，摘要、R历史投影、恢复胶囊和整个受影响thread按总方案禁用/清理，不能因当前Prompt已被裁剪就宣称旧Checkpoint已清理。

## 10. 费用、刷新、重试与失败

每task最多一个derive逻辑机会、至多3次原操作总尝试，跨execution关联不重置；前置压缩已消费机会，回答收尾不再调用摘要/候选提炼。query Embedding与索引预算沿总方案，不从上下文模块另开额度。

所有业务/摘要请求都经过同一Provider费用守卫；总体100元/60次、execution最长10分钟及更严格当前授权保持。无预算只做CPU处理不代表可以发原业务模型；原业务本身仍需其有效授权。压缩失败已发生的费用保留，不因未采用摘要退款或清零。

| 情况 | 结果 |
| --- | --- |
| 无预算/调用耗尽/deadline不足 | 不发derive；已有合法上下文若同时满足窗口与业务授权可继续，否则明确阻断 |
| 提炼/摘要输入用途不兼容 | 摘要或候选二选一，最多一次生成，不混输入 |
| 摘要结构/来源/状态/收益不合格 | 新段不采用，CPU选择既有合法段；不额外发“继续总结” |
| 必需内容超窗 | CONTEXT_REQUIRED_INPUT_TOO_LARGE，发送前停止 |
| 模型容量/计数规则未核实 | CONTEXT_CAPACITY_UNVERIFIED，不采用猜测窗口 |
| packet过期 | 沿总方案wait_event/revision/原operation有界刷新，不重新压缩或新建操作 |
| 源撤销/更正或用户撤权 | SOURCE_REVOKED/SOURCE_CHANGED/ACCESS_REVOKED；按作用域停用，不偷偷删源继续原操作 |
| 已SENT/UNKNOWN后想换模型/摘要 | 拒绝输入变更，先依原回执核实，不以新ID逃避重试 |
| Provider返回context_length错误 | 记录CONTEXT_COUNT_DRIFT并停止当前操作，核对tokenizer/序列化/Schema元数据后复验，不自动升级模型 |
| 压缩模型自身输入超窗 | 缩小原始完整源区间，仍不容纳则跳过/停止，不递归调用压缩模型 |

业务状态、付费授权和恢复快照三种生命周期不变；第二天审批不恢复过期执行，授权链未实现时明确拒绝付费续执行。低风险流/敏感缓冲发布以及最终Java全依赖核验仍适用，压缩不弱化输出治理。

## 11. ContextPolicy与ContextManifest

### 11.1 Policy

版本化字段至少包括：适用domain/Agent/node；模型容量元数据引用；节点P/输出合同；tokenizer/serialization；余量；70%/85%触发与目标；槽位上限；必保字段；工具投影/可见输出上界；摘要模式/最大区间/输出；远程计数允许性；费用父范围；失败/省略提示策略。用户HTTP只能缩小允许范围；模型不可改policy。

不为每个策略概念新增一张表。ContextPolicy作为发布资产/记忆策略关联配置，TaskState复用现有运行模型，Manifest接合现有操作事实；需要新增持久字段时在实施计划明确所有者和迁移，不另建第二套运行真相库。

### 11.2 Manifest

每个实际请求记录：task/execution/operation/node/attempt；model/prompt/tool/output-schema/tokenizer/serialization/policy版本；packet_id/revision与ctx_revision；来源/摘要/工具投影ID及版本；完整安全依赖；实际选择和排除原因；各类及总T、F、H_ctx、O/S；预测G及依据；CPU前后与摘要前后T；关键字段校验摘要；摘要CAS/采用状态；费用reservation/usage引用；canonical request HMAC。

Manifest不复制完整Prompt、凭据、私有全文或隐藏推理；请求hash应按tenant分离且不向无权用户提供可枚举内容指纹。来源ID/计数诊断本身也受权限保护。排除的内容不属于模型实际输入依赖，但能以无正文原因说明为何没使用；摘要的传递来源不因仅保留引用而消失。

用它可回答：哪项内容占窗口、为何压缩、为何未使用某记忆、哪些历史被省略、来源撤销会影响哪些结果。用户视图与内部运维视图区分，配置管理员不附带正文权限。

## 12. 分阶段落地

| 阶段 | 交付及门禁 |
| --- | --- |
| M0 | 总方案R2恢复/遗忘协议与本协议共同复评；现有普通Direct、客服、HR和专家实际请求路径逐一登记 |
| M1-A 上下文先行 | 每次发送整包计数、节点P、工具投影/完整性、专家输入输出切片、任务胶囊、Manifest及费用最终门禁；CPU选择，无LLM压缩 |
| M1-B 私有偏好闭环 | 保存/精确读/更正/忘记＋历史血缘/抑制/Checkpoint禁恢复；依赖M1-A，不部署向量或项目共享管理 |

M1-A包括所有真实发送入口的治理覆盖；某入口尚未接合统一计数/Manifest时，必须维持原受控功能并标记未通过此阶段，不以已有Provider费用保护冒充上下文协议已完成。不能仅新建ContextBuilder类而让Direct或HR另行拼Prompt绕过。
