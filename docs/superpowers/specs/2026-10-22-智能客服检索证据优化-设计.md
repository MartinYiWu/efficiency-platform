# 智能客服检索与证据处理优化设计

> 状态：方案已确认，书面设计待复核
>
> 适用范围：公司内部独立智能客服；不改变运营助手
>
> 更新日期：2026-10-22
>
> 前置设计：[父子切片与证据组装](2026-10-22-智能客服父子切片与证据组装-设计.md)

## 1. 目标、边界与现状

本设计完成八项能力：相似片段去重、同文档相邻证据合并、旧版本排除、相关度排序、超长叙述性资料的可追溯压缩、完整条款保护、Rerank 重排和分阶段 TopK。八项能力必须共享同一份冻结的证据快照；回答、引用、调试和回放不能各自重新挑选证据。

当前代码已经具备子片段向量/全文召回、RRF、Rerank、父片段展开、完全相同文本去重和上下文预算。Java 发布新索引时以指定版本替换同一文档在索引快照中的旧版本。尚无语义相似片段的安全合并、相邻不同父片段的受控组装、叙述性长内容的可追溯抽取，以及版本/冲突取舍的完整调试事实。真实接口曾出现中文全文候选为零，因此本设计不能把现有双路召回视为质量已经达标。

Java 仍是文档版本、知识库类型、索引发布和 Agent Release 绑定的真相源；Agent 负责检索、模型判断和证据装配。Prompt、RAG 策略继续版本化存于管理端，不将可调规则写死在代码。旧索引和历史运行保持可读；新逻辑通过新的发布版本生效，不原地改写已发布数据。

## 2. 方案选择与不可同时满足的约束

| 方案 | 取舍 | 结论 |
|---|---|---|
| 所有长内容先让模型摘要，再送入回答 | 上下文开销低，但会遗漏适用条件，摘要不能替代制度原文 | 不采用 |
| 所有命中一律取完整父原文 | 引用边界清楚，但长叙述材料会挤掉其他证据 | 不作为唯一策略 |
| 受保护条款保留全文；经明确允许的叙述材料只抽取原文片段 | 兼顾完整条款与预算，仍须校验抽取位置和证据充分性 | 采用 |

“压缩”仅指选择并组合原文中完整的句段，不接受模型改写后的摘要作为公司事实证据。模型可以选择句段编号，不能生成替代原文。制度或流程中的单个完整条款若超过可用上下文，不能同时满足全文入模和压缩；此时尝试已配置且可用的更大上下文模型，仍放不下则返回证据不足，不截断后作答。

## 3. 数据与发布契约

### 3.1 版本来源

- 新问答只检索当前激活 Agent Release 明确绑定的 `index_release_id`；不得按数据库中最大的 `version_no` 或最新日期自行越过绑定。历史 Run 保留原索引和 Agent Release ID。
- Java 的单个索引快照中，同一 `document_id` 只能有一个 `document_version_id`。发布新版本继续沿用现有“移除该文档旧成员、加入新版本、验证后激活”的流程。若 Agent 同时收到同一 `document_id` 的两个版本，视为发布契约错误，不按相关度择一。
- `effective_date` 表示版本生效日期，不等于不同文档间的效力优先级；知识库绑定 `priority` 也不是制度优先级。不同文档相互矛盾时不得依这两个字段静默淘汰一方。
- 不同知识库里的文档编号只在各自知识库内唯一。没有明确的跨知识库逻辑文档标识时，不能认定两个文档是新旧版本关系。

### 3.2 原文片段元数据

现有 `document_parent` 和 `document_chunk` 的版本、顺序、原文、哈希、页码及子父位置继续作为引用真相。新增父片段的结构类别 `block_kind`，取值为 `NUMBERED_RULE`、`LIST`、`TABLE`、`CODE`、`PARAGRAPH`；解析无法确定时按受保护内容处理，不推测它是可压缩叙述。已发布父子记录不可原地改写；新字段仅随新文档版本重新入库。

Java 文档版本增加 `evidence_mode`：`FULL_ONLY`（默认）或 `EXTRACTIVE_NARRATIVE`。只有 `PRODUCT_DOCUMENTATION`、`TECHNICAL_DOCUMENTATION` 可由后台人员在上传或创建新版本时选择后者；`COMPANY_POLICY`、`BUSINESS_PROCESS` 强制 `FULL_ONLY`。Java 入库请求把此值传给 Agent，Agent 将其随不可变的父片段版本记录保存；查询只读取已绑定索引中的冻结值，不回查可变的管理配置。旧版本未带该字段时按 `FULL_ONLY` 读取。`EXTRACTIVE_NARRATIVE` 也仅允许 `PARAGRAPH` 父片段执行原文抽取；编号规则、列表、表格和代码始终完整保留或整段排除。

## 4. 查询流水线与八项能力

```text
意图判断与查询改写
→ 按激活 Release/索引版本过滤
→ 向量 TopK + 全文 TopK
→ 按 chunk_id 和同版本完全相同原文去重、RRF 融合
→ Rerank TopK
→ 同版本相似候选核验分组
→ 批量展开父片段、同父去重
→ 受控相邻组装、按最终证据 TopK 形成待装配集合
→ 待装配集合内的跨文档冲突核验
→ 完整原文/可追溯抽取的预算选择
→ 充分性与冲突判断
→ 回答、引用闭包、回放
```

### 4.1 相似片段去重

完全相同的原文继续按“同一文档版本 + 内容哈希 + 原文”去重。语义相似不能直接删除：先在 Rerank 结果中，仅对同一 `document_version_id`、同一标题路径的候选计算向量相似度并筛出候选对；再由版本化 `equivalence` Prompt 判断是否表达同一个事实，并明确比较否定、数字、时间、适用对象、前提和例外。模型只返回候选 ID、`EQUIVALENT`/`DIFFERENT`/`UNCERTAIN` 与依据原文位置；位置不合法或判断不确定时保留两项。跨文档、跨版本不做语义去重。

候选相似度使用索引中已保存的子片段向量，不为候选两两比较再次调用 Embedding 服务。确认为等价时只向回答模型送分数更高的一份父证据，保留被合并候选 ID、来源和判断原因供调试。等价分组不改变原索引，不删除父子数据。相似度仅负责筛选待比较候选，不单独决定合并。候选对数量同时受 Rerank TopK 和 `similarity_pair_limit` 限制，先比较相似度最高的候选对；模型判定失败时保留原候选并记录降级，不伪称已经去重。

### 4.2 同一文档相邻片段合并

同一父片段的多个子命中继续只展开一次。对不同父片段，仅当 `document_version_id` 相同、`parent_no` 连续、标题路径相同、两者均被本次 Rerank 命中，且均为 `PARAGRAPH` 或同一表格的连续行组时，建立一个 `EvidenceGroup`；组成员数量不超过 `adjacent_group_max_parents`。不得跨编号条款、标题、代码块或版本拼接。组装只影响给模型的呈现顺序和共享上下文，不产生新的“合成引用”；每个成员仍有独立 `parent_id`、原文、页码和引用定位。

若组装后的完整内容超预算，优先保留排序更高的完整父片段；不能将两个父片段各截一半。被舍弃的成员仍在调试结果中显示 `BUDGET_EXCLUDED`。

### 4.3 旧版本与跨文档冲突

进入 RRF 前先执行 Release/索引成员过滤；不在当前绑定索引内的旧版本根本不能成为新运行候选。切换新索引须发布并激活新的 Agent Release；仅在 Java 知识库发布新索引、但 Agent Release 仍绑定旧索引时，管理页显示“绑定索引落后于知识库当前发布索引”，不在运行时擅自切换。

不同文档的潜在冲突在父证据展开并取到待装配集合后核对：仅比较集合内与问题相关的跨文档父证据对，必要时逐对调用版本化 `conflict_screen` Prompt，避免一次装入全部长文。Prompt 返回涉及的证据 ID、同一适用范围判定、相反原文的精确位置和 `CONFLICT`/`NO_CONFLICT`/`UNCERTAIN`。Agent 校验来源位置、版本及入选状态；有已确认冲突或仍无法解释的关键不确定项时，两侧证据都不能因 Rerank 分数或预算而静默消失，回答模式为 `INSUFFICIENT_EVIDENCE`。只有明确可由原文证明适用对象、条件或时间不同，才能作为非冲突继续回答；模型不得凭标题推断哪份制度效力更高。TopK 之外的资料不在本次证据范围，必须通过召回评测检查此类漏召，不能宣称系统已排除所有冲突。

### 4.4 排序、Rerank 与 TopK

现有 `vector_top_k`、`fts_top_k`、`fusion_top_k`、`rerank_top_k` 保持各自职责：召回数量、RRF 融合候选数量、Rerank 返回数量。`rerank_top_k` 在相似分组之前生效，不能直接当作最终送模型的父证据数量。RAG 策略新增 `final_evidence_top_k`，限制进行冲突核验、预算装配及最终回答的独立父证据数量；相邻组内每个父片段都计一个名额。默认值为 8，允许范围 1–20；上线前用固定真实问题集比较不同值，发布时冻结最终策略版本。

Rerank 服务失败仍按现有错误治理返回可识别失败；除非另有经发布的降级策略，本次不把 RRF 顺序冒充重排结果。调试页分别显示原始召回分数、RRF 分数、Rerank 分数及各阶段名次。

### 4.5 超长内容与完整条款

预算先计入实际所需的共享 Prompt、充分性或回答阶段中较大的模板、问题、必要会话上下文、输出预留和安全余量；不得只按父片段文本估算。`FULL_ONLY` 或非 `PARAGRAPH` 父片段必须整体入选或整体排除。

仅对 `EXTRACTIVE_NARRATIVE` 的 `PARAGRAPH`，在完整父片段放不下时才启用版本化 `evidence_extract` Prompt。Agent 先把父原文按原始顺序标成不可跨段的完整句段及起止偏移；模型只能返回句段 ID，不返回摘要。单个父片段连抽取阶段的模型输入也容纳不下时，不发送截断原文，而是整段排除。确定性代码按原文顺序拼接选中句段，保存每段的 `parent_id`、`start_offset`、`end_offset` 和哈希，并校验逐段与原文完全一致。选择结果为空、偏移不符、无法可靠断句或抽取后仍超预算时整段排除。回答 Prompt 明确说明所见内容是原文节选，不能据此推断未提供的背景；充分性判断与回答使用同一份节选快照。

Agent Release 可选绑定一个已发布的 `large_context_model_policy`，该绑定和策略内容一起进入 Release 校验和；为空时绝不临时切换。只有受保护的单条完整原文超过主模型可用证据预算、且备选策略确有更大输入上限时，才对本次运行的充分性与回答阶段一并使用该策略并重算预算。备选策略仍放不下时返回证据不足。引用节选时展示准确原文段落和位置；引用完整条款时保持完整父原文，不把节选伪装成全文。

### 4.6 冻结的证据契约

`EvidencePack` 是同一次运行中充分性、冲突判断、回答与回放共同使用的不可变快照；每个条目至少含 `parent_id`、文档/版本/索引 ID、Rerank 名次、原文哈希、`FULL_PARENT` 或 `EXTRACTED_SPANS`、实际送入模型的原文、原文偏移列表及命中子片段 ID。相邻 `EvidenceGroup` 只保存有序成员 ID，不制造新的父 ID。最终 `Citation` 增加引用类型及原文偏移列表；`FULL_PARENT` 必须逐字等于完整父原文，`EXTRACTED_SPANS` 的每段必须逐字等于对应原文区间。两类引用均保留原文版本、索引和页码定位。

调试与回放另存各阶段候选、等价分组、版本排除、相邻组、压缩取舍、冲突判断、预算及选用模型策略的事实。公开回答不包含内部判断链；历史回放从当时冻结事实读取，不使用当前规则重新计算。

## 5. 配置、Prompt 与界面

RAG 策略新增 `final_evidence_top_k`（默认 8，范围 1–20）、`similarity_candidate_threshold`（默认 0.96，范围 0.85–1.00，仅筛选待比较候选）、`similarity_pair_limit`（默认 20，范围 1–50）和 `adjacent_group_max_parents`（默认 3，范围 1–5）。这些字段进入 Java MySQL 策略表、Agent Release 契约、校验和及管理页。Agent 版本/Release 增加可选 `large_context_model_policy` 绑定，并在后台展示其模型名与输入上限。现有四个 TopK 和上下文上限沿用原字段。配置在发布版本中冻结；调参创建新策略版本，不修改历史 Release。

新增 `equivalence`、`conflict_screen`、`evidence_extract` 三个 Prompt 阶段，分别具有独立的 SYSTEM 与 USER 消息、输入字段说明、输出 JSON 契约及版本号，遵循现有 Prompt 管理与绑定流程。字段含义和校验如下：

| 阶段 | USER 输入 | 必须返回的结构化字段 | 确定性校验 |
|---|---|---|---|
| `equivalence` | `question`：原问题；`left`、`right`：候选 ID、同版父原文、标题路径、页码与原文哈希 | `left_chunk_id`、`right_chunk_id`：输入候选 ID；`verdict`：`EQUIVALENT`/`DIFFERENT`/`UNCERTAIN`；`left_quote`、`right_quote`：支持判定的原文精确摘录；`differing_conditions`：不同的限制条件列表 | ID 必须属于输入且同版同路径；两处摘录必须逐字出现于各自父原文；只有 `EQUIVALENT` 且限制条件列表为空才能合并 |
| `conflict_screen` | `question`；`evidence`：同一待比较证据对的父证据 ID、文档/版本/索引、完整父原文及位置 | `pairs`：数组，每项含 `left_parent_id`、`right_parent_id`、`same_scope`、`verdict`（`CONFLICT`/`NO_CONFLICT`/`UNCERTAIN`）、双方原文精确摘录及说明 | ID 必须属于本次证据；摘录逐字匹配相应原文；关键证据对返回冲突、不确定或契约错误时，不能生成确定的公司事实回答 |
| `evidence_extract` | `question`、`parent_id`、有序 `sentences`（每项 `sentence_id`、原文、起止偏移）、`available_tokens` | `parent_id`；`selected_sentence_ids`：要保留的句段 ID；`reason`：选择理由，仅供调试，不作为回答证据 | 只能选择输入 ID；按原文顺序输出；每段必须与父原文偏移逐字一致；总量不得超预算 |

三个阶段的 SYSTEM 消息分别声明角色、禁止事项和字段语义，USER 消息只承载本次不可信问题与候选资料。`evidence_extract` 禁止模型改写原文；选择理由不进入回答。`equivalence` 与 `conflict_screen` 的模型结论不能越过确定性的 ID/摘录/偏移/版本校验。阶段缺失、输出契约不合法时，分别执行“保留相似候选”“拒绝有争议的公司结论”“不压缩并按预算取舍”的安全处理，记录真实错误码。

后台 `RagPolicyPage` 在现有 TopK 区域增加“最终父证据 TopK”“相似候选阈值”，展示各阶段含义，不把阈值描述为自动去重率。文档上传和新版本表单在产品/技术文档下展示“证据处理：全文优先 / 允许叙述性原文节选”，制度/流程只能全文优先。`RagDebugPage`、`RunReplayPage` 展示每阶段名次、等价分组和未合并原因、相邻组成员、旧版过滤计数、冲突证据、原文节选位置、预算与最终引用；员工聊天页只显示回答、必要的“原文节选”标记及引用，不展示内部评分和 Prompt。

## 6. 错误、不变量与验收

- 子父版本、索引成员、原文偏移或哈希不一致时，不继续给出公司事实回答。模型输出不可直接充当校验依据。
- 相似度高不意味着事实相同；任何不确定的去重或冲突判断都不得静默丢弃候选。冲突证据若不能一起容纳，直接证据不足。
- 受保护内容的任何原文截断、节选作为全文引用、跨版本合并、依据相关度淘汰相反制度，均属发布阻断问题。
- 原文节选只用于经允许的叙述段落；历史运行仍按创建时的策略、Prompt、索引和证据事实回放。
- 运行日志记录阶段、耗时、候选数、错误码和运行 ID；不打印文档全文、用户敏感输入或凭据。

验收先建立真实且经人工标注的问题集，覆盖四种知识类型、相似但条件不同、同父多子、相邻叙述、同文档新旧版本、跨文档冲突、长叙述、超长完整条款、无答案和中文关键词。每条标注允许的文档版本、父证据、关键条件和回答模式。对旧策略与新策略分别通过 Java→Agent 真实接口运行，保存关键响应及 Java/Agent 日志；核对 Recall@K、Rerank 后正确父片段覆盖率、错误合并率、节选原文一致率、引用支持率、冲突误答率、延迟和模型调用量。关键制度与流程题须人工检查原文，不以单一自动分数宣布通过。

发布门槛：固定问题集中不得出现旧版本进入新运行、条件不同条款被当成等价合并、受保护条款被截断或压缩、节选与原文不一致、无证据公司事实回答或已确认冲突仍给出确定结论；这些项目任一失败即不发布。正确父片段召回不得低于本次固定基线，耗时和调用量须记录并解释回归；阈值调优必须生成新的 RAG 策略版本和完整的真实接口重测记录。

没有真实相互冲突的现行公司文档时，该场景保持“未完成真实验收”，不得编造样本或结论；没有真实跨页 PDF 时同样不能宣称页码验收通过。测试类验证算法契约，但不替代真实接口及日志验证。当前中文全文检索零候选须单独诊断；本设计不把换分词器或新增检索服务隐含纳入这八项改造。

## 7. 参考实现与边界
