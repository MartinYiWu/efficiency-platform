# 前端完整重构设计稿

## 目标与边界

重构 `ai-efficiency-platform-ui` 当前 48 条路由（含首页重定向和兜底页）的页面结构与视觉体系。用户选定“企业控制台”方向：横向一级导航、模块内局部导航、宽内容画布，以及以信息层级和行分隔为主的内容组织。此次是页面重构，不沿用原有“所有模块共用左侧长菜单、内容反复套卡片”的结构。

## 全局框架

1. 桌面顶部一级导航高度 64px：`工作台`、`AI 助手`、`知识中心`、`AI 管理`。菜单项只指向现有路由；没有路由的“素材中心、组织中心、权限中心、系统管理、数据中心”不作为可点击入口展示。
2. 一级导航之下才出现模块内导航。知识中心采用左侧分类筛选；AI 管理采用 220px 功能导航；人事助手采用 220px 工作流导航；对话页将左侧空间交给会话历史。各模块共用视觉 token，不共用不适合该场景的页面骨架。
3. 顶栏不放无实际搜索行为的搜索框、无实际数据的通知入口或伪造的登录身份。现阶段未实现登录，身份区使用中性的“内部用户”展示；后续接入身份接口时再替换。
4. 内容区在 1440px 桌面宽度下留 24px 外边距；长文阅读列控制在约 760px；列表和表格使用可用宽度。导航、标题、筛选、主体左边界对齐。
5. 窄屏一级导航改为菜单抽屉，局部筛选改为抽屉或横向可滚动标签；页面本身不得横向溢出，宽表格只在表格容器内滚动。

## 视觉规范

- 主色保留蓝色，用于选中状态和主操作；正文深蓝灰，背景近白，状态色只表达状态。
- 标题层级：页面 28px，区块 20px，列表标题 16px，正文 14–16px，辅助信息 12–13px；同一页面只设一个页面主标题。
- 间距以 8px 为基础，常用 8/16/24/32px；圆角以 8px 为主。优先用留白、对齐和行分隔组织信息，减少卡片套卡片和大面积空白。
- 保持表单标签、按钮高度、状态标签和表格行高一致；长名称换行或省略，并提供完整文本可见方式。
- 使用现有图标库；各助手可以有独立名称和小型识别标记，不使用夸张机器人头像。

## 页面模板与路由归属

### 对话工作区

路由：`/ai-assistants/customer-service/chat`、`/ai-assistants/operations/chat`、`/ai-assistants/hr/chat`。

桌面为“会话历史 / 消息阅读 / 按需打开的引用或产物详情”布局。消息区与输入区同轴，宽回答使用段落、列表和引用入口；处理过程使用可折叠摘要，不展示模型私有推理。客服保留现有新建、切换、删除历史、流式回答、反馈和引用详情。运营助手的内容产物只在相应生成任务中显示；资料汇总直接在消息流中阅读。人事助手保留现有入口及对话行为。手机端仅显示消息主区，历史与引用各用抽屉打开。

### 知识中心

路由：`/knowledge-center/knowledge-bases`、`/knowledge-center/knowledge-bases/:baseId`、`/knowledge-center/knowledge-bases/:baseId/imports`、`/knowledge-center/documents/:documentId`。

列表采用左侧四类知识类型筛选和右侧单一结果表，不以同尺寸卡片重复展示每个知识库。详情采用“知识库信息 / 目录与文档 / 索引版本和处理任务”分区；文档页采用“版本记录 / 处理状态 / 原文与引用信息”结构。上传、批量导入、手工更新版本沿用现有接口和权限。概念稿中的额外分类、文档数量和禁用按钮不进入实现，除非对应能力已存在于接口契约。

### AI 管理

路由：`/ai-center/agents`、`/ai-center/agents/:agentId`、`/ai-center/prompts`、`/ai-center/model-policies`、`/ai-center/rag-policies`、`/ai-center/rag-debug`、`/ai-center/rag-evaluations`、`/ai-center/rag-evaluations/:datasetId`、`/ai-center/rag-evaluations/runs/:runId`、`/ai-center/runs`、`/ai-center/runs/:runId`、`/ai-center/feedback`。

Agent 页用“对象列表 / 已选对象详情”替代孤立单卡；版本与证据绑定分成清晰表格，长列表分页。Prompt 页用“Prompt 列表 / 版本与角色内容编辑 / 预览”结构，明确系统提示词和用户提示词。模型、RAG 策略页使用分组表单；调试和评测页采用输入、执行状态、证据结果的工作台结构；运行回放依时间顺序呈现公开阶段、答案与引用。保持当前 API 字段与操作语义，概念稿中的“设为当前、绑定凭证、解除绑定”等按钮不实现。

### 人事助手

路由：`/ai-assistants/hr/workbench`、`/ai-assistants/hr/positions/**`、`/ai-assistants/hr/resumes/**`、`/ai-assistants/hr/matching/**`、`/ai-assistants/hr/talent/**`、`/ai-assistants/hr/interviews/**`、`/ai-assistants/hr/settings/**`、`/ai-assistants/hr/component-states`。

工作台采用紧凑指标带、待办优先列表、岗位进展表，替代两层快捷卡加指标卡。职位、简历、匹配和人才列表统一为“标题与主操作 / 筛选 / 结果”；详情统一为“主信息 / 证据或配置 / 辅助操作”。岗位创建继续使用分步流程，步骤和保存操作保持连续。现有部分人事页面使用演示数据，设计稿中的人数和活动不表示真实服务数据；实现时必须如实保留演示属性。

### 其余路由

`/` 继续使用当前重定向；`*` 使用同一视觉体系的兜底页。导航只暴露可达页面，不改变现有 URL 和对外接口。

## 交互与验收

- 完成后逐条打开全部 48 条路由，抽查关键状态、真实接口返回、页面错误和 1440/1024/390px 布局；动态详情用真实 ID 打开。
- 对话验收包含空会话、长回答、流式阶段、引用详情、历史删除；知识验收包含空列表、导入任务、文档版本；AI 管理验收包含单 Agent、长版本列表、Prompt 与 RAG 调试；人事验收包含工作台、列表、详情和分步表单。
- 设计稿仅提供视觉方案。若真实接口缺少图片中的数据或操作，页面展示真实状态，不编造成功、数量或来源。
- 运行类型检查、Lint、构建和相关测试；浏览器视觉检查以实际渲染结果为准。
