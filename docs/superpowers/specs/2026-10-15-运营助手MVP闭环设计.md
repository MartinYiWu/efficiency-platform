# 运营助手 MVP 闭环设计

> 状态：已确认，待实施计划
>
> 负责人：效能平台项目组
>
> 适用范围：Java、前端、Agent 及三端契约
>
> 更新时间：2026-10-15
>
> 决策类型：跨工程产品与技术设计

## 1. 背景与目标

当前项目已具备 Java 多模块骨架、前端运营助手页面和 Agent 离线研究基础，但尚未形成开发环境可验收的三端业务闭环。下一阶段选择“运营助手 MVP 闭环”，以一条可连续对话的真实链路作为交付目标：

1. 用户用自然语言要求收集当天 AI 热点。
2. Agent 识别意图，从批准的公开来源获取真实数据，完成筛选、去重、排序和摘要。
3. 用户在后续轮次中引用整份榜单或第 N 条热点，要求生成微信公众号或小红书内容。
4. 系统生成完整、排版规范的内容制品，并支持预览、复制和下载。

本设计追求固定开发身份、真实模型、真实公开来源和真实基础设施条件下的可验收 MVP，不将登录鉴权、高可用、多租户商业化或生产级运维能力纳入首期范围。

## 2. 已确认的产品决策

### 2.1 核心场景

MVP 同时支持两类连续对话：

- 整榜创作：`收集今天 AI 热点前 10 条` → `把这 10 条写成公众号周更`。
- 单条改写：`收集今天 AI 热点前 10 条` → `把第 3 条改写成小红书`。

后续创作必须绑定上一轮已经完成的研究结果；除非用户明确要求刷新，或者原研究结果已失效，否则不得重新搜索并悄悄替换素材。

### 2.2 首期渠道

- 微信公众号
- 小红书

系统只负责生成、格式化、预览、复制和下载内容，永久不自动发送或发布到任何平台。本期不建设平台账号授权、定时发布、草稿箱同步或平台发布回执。

### 2.3 输出形态

Markdown 是文章的唯一规范原稿。系统基于同一份 Markdown 派生：

- 对话内结果摘要；
- Markdown 预览；
- 可下载的 `.md` 文件；
- 经过服务端转换和安全净化的微信富文本；
- 面向小红书的结构化排版文本。

正常回复只向用户展示结果。来源研究任务、使用的热点条目、引用闭包、版本和中间推理属于内部元数据，不在回复中主动披露；用户明确要求查看来源时，才展示可公开的来源信息。

## 3. 意图与对话行为

### 3.1 MVP 意图集合

首期只实现以下四类意图：

1. **热点研究**：收集、筛选、去重和排序指定主题的近期热点。
2. **跨轮创作**：基于上一轮整份榜单或指定条目创建内容。
3. **平台成稿**：生成微信公众号或小红书的完整排版稿。
4. **内容修改**：对已有文章执行缩写、扩写、改标题、换风格或调整结构。

意图无法可靠判断时，系统只追问一个决定性问题，不创建研究任务、不调用外部来源，也不调用模型生成猜测性结果。

### 3.2 热点研究输出

研究结果按照热度和内容价值排序，每条至少包含：

- 排名；
- 标题；
- 一句话摘要；
- 发生时间或发布时间；
- 热点类型；
- 选择理由。

“前 10 条”是最大目标数量，不是必须凑满的数量。有效材料少于 10 条时返回实际条数，并说明数据不足，不生成虚假条目。

### 3.3 微信公众号成稿

用户未指定篇幅时，默认生成约 3000～4000 个中文字符的完整文章，至少包括：

- 可直接使用的标题；
- 导语；
- 清晰的一级、二级小节；
- 编号事实与必要的背景说明；
- 段落之间的过渡；
- 总结和自然收尾。

回复中不展示内部“处理要点”、研究任务 ID、引用闭包或版本号。文章必须可直接阅读，而不是仅返回提纲。

### 3.4 小红书成稿

小红书内容以移动端阅读为目标，至少包括：

- 标题；
- 开场钩子；
- 分段正文；
- 适量的符号或表情排版；
- 结尾互动句；
- 与正文相关的话题标签。

不得仅把公众号长文机械截短，也不得使用与事实无关的夸张标题。

## 4. 架构与职责边界

### 4.1 前端

前端只调用 Java 公共接口，负责：

- 会话和历史消息展示；
- 用户输入及任务状态展示；
- SSE 流式响应消费与断线恢复；
- 榜单、文章和错误状态渲染；
- Markdown 预览；
- 微信富文本复制；
- Markdown 文件下载。

前端不得直接访问 Agent 地址，不得持有模型或数据源密钥，也不得把远端任务状态镜像到本地状态仓库作为真相源。

### 4.2 Java

Java 是身份、权限、会话、任务、消息、业务结果和最终制品的真相源，负责：

- 在开发阶段从服务端固定注入 `userId=1`、`tenantId=dev`；
- 创建会话并持久化消息；
- 创建、取消和查询运行任务；
- 调用 Agent 内部接口并代理 SSE；
- 校验 Agent 最终结果契约；
- 持久化热点榜单和文章制品；
- 将 Markdown 确定性转换为安全微信富文本；
- 保证所有业务数据均绑定服务端确定的开发身份，客户端不能覆盖身份字段。

客户端不得通过请求字段覆盖用户身份、会话归属或任务归属。

本期不实现登录、JWT、权限管理或用户注册。数据模型仍保留 `user_id` 和 `tenant_id`，为后续接入真实身份体系保留兼容入口。

### 4.3 Agent

Agent 是研究和内容生成执行端，负责：

- 意图识别和参数提取；
- 研究计划编排；
- 已批准数据源适配；
- 页面抽取、正文清洗和来源健康记录；
- 相关性筛选、重复项合并、热度排序和事实摘要；
- 基于指定素材生成公众号或小红书文章；
- 检查点、研究事实、来源尝试、引用关系和预算记录。

Agent 不直接读取 Java 业务库，不拥有用户身份和最终业务状态，也不得绕过 Java 向浏览器返回内部地址或敏感信息。

### 4.4 数据来源

数据来源通过 Agent 的批准适配器访问。首期优先采用无需用户平台授权的公开来源，例如官方 RSS、官方博客、公开发布页、Hacker News 和 GitHub Releases。

每个适配器必须定义：

- 来源名称与允许访问的域名；
- 获取方式和超时；
- 时间范围；
- 原始字段到统一事实模型的映射；
- 限流、重试和熔断策略；
- 来源失败时的降级行为；
- 内容使用和保留边界。

任意用户输入 URL 和抓取结果均视为不可信内容，必须防止 SSRF、Prompt Injection、恶意重定向和超大响应。

### 4.5 开发环境基线

开发环境直接使用项目现有的真实数据库、Redis、模型和 Embedding 配置，不要求额外建设 Docker Compose，也不以本地容器化作为开发前置条件。服务端口固定为：

- 前端：`5190`；
- Java：`8080`；
- Agent：`8090`。

前端只访问 Java `8080`；Java 通过内部配置访问 Agent `8090`。数据库、Redis、模型和 Embedding 连接信息在开发阶段允许明文保存在配置文件中，但任何响应、日志、文档和验收证据均不得输出密钥或完整连接串。

## 5. 接口设计

### 5.1 浏览器到 Java

首期公共接口定义为：

- `POST /api/operations/conversations`：创建会话。
- `POST /api/operations/conversations/{id}/messages`：发送一条用户消息并创建运行任务。
- `GET /api/operations/runs/{runId}/events`：订阅 SSE 事件。
- `POST /api/operations/runs/{runId}/cancel`：取消运行任务。
- `GET /api/operations/conversations/{id}/messages`：读取会话历史。
- `GET /api/operations/artifacts/{id}`：读取文章制品及预览信息。
- `GET /api/operations/artifacts/{id}/download`：下载 Markdown 原稿。
- `GET /api/operations/artifacts/{id}/wechat-html`：获取净化后的微信富文本。

创建消息请求必须带客户端生成的 `requestId`。Java 以“用户 + 会话 + requestId”保证幂等，重复请求返回原任务，不重复调用 Agent。

### 5.2 Java 到 Agent

Java 复用 Agent 现有会话、运行、SSE 和取消契约，并在实施前冻结三端共享字段。内部调用至少携带：

- Java 生成的运行标识；
- 会话上下文摘要；
- 当前用户消息；
- 允许引用的研究结果或文章制品标识；
- 允许使用的工具与来源范围；
- 时间、数量和模型预算。

Java 的 Agent 客户端采用固定开发配置：Agent Base URL 指向 `http://127.0.0.1:8090`，连接超时 5 秒，普通读取超时 30 秒，SSE 读取不设置固定总时长但受任务预算和取消信号约束。连接错误不做无限重试；创建任务只允许在幂等键保护下重试一次。

“第 N 条改写”只向 Agent 传递被选中的条目及其内部引用闭包，不传递无关榜单全文或全部会话历史。“整榜周更”则传递已经确认的整份榜单快照。

### 5.3 SSE 事件

SSE 至少包含以下稳定事件类型：

- `run.started`
- `run.progress`
- `message.delta`
- `artifact.ready`
- `run.partial`
- `run.completed`
- `run.failed`
- `run.cancelled`

事件必须带单调递增的事件序号。前端断线后使用 `Last-Event-ID` 续接；无法续接时查询 Java 已持久化的运行状态和消息，不创建新的运行任务。

## 6. 数据归属与持久化

### 6.1 Java MySQL

Java 业务库保存：

- 会话；
- 用户消息和助手消息；
- 运行任务及状态；
- 热点榜单快照；
- 最终 Markdown；
- 派生的微信富文本；
- 制品版本与当前有效版本；
- 最终错误摘要和重试关联。

Java 在调用 Agent 前，以同一事务保存用户消息和 `PENDING` 任务；获得 Agent `runId` 后建立绑定。只有最终响应通过结构和引用完整性校验后，任务才能进入 `SUCCEEDED`。

### 6.2 Agent MySQL

Agent 运行库使用现有真实 MySQL 数据库 `ai_efficiency_platform_agent`，保存：

- LangGraph 检查点；
- 研究事实；
- 来源尝试和来源健康；
- 去重与排序中间结果；
- 引用关系；
- 模型和工具预算；
- 临时运行状态。

这些数据用于可恢复执行和内部审计，不直接作为用户界面数据源。实施时需要为现有 Port 提供 MySQL Repository，并交付 MySQL 方言的迁移、索引、唯一约束和回滚脚本；现有 PostgreSQL Repository 不能通过替换连接串直接复用。

### 6.3 Agent 向量数据库

Agent 向量数据库使用项目现有的 PostgreSQL + pgvector 真实配置，负责保存文档、Chunk、Embedding 元数据、向量索引和检索数据。Java 不直接连接该数据库，向量检索统一通过 Agent 能力边界完成。

### 6.4 Redis

Redis 只用于短期任务协调、SSE 临时事件、取消标志和限流，不保存唯一业务事实。Redis 数据丢失后，Java 和 Agent 必须能分别从各自持久化存储恢复稳定状态。

开发环境复用现有真实 Redis 配置。Java Key 统一使用 `aiep:java:` 前缀，Agent Key 统一使用 `aiep:agent:` 前缀；运行事件默认保留 24 小时，取消标志默认保留 2 小时，幂等键默认保留 24 小时。具体业务键不得使用无前缀的全局名称。

### 6.5 原始网页内容

原始网页正文仅在 Agent 侧按运行需要临时保留，并设置明确的大小和保留期限。Java 只保存允许长期保留的摘要、来源信息、结构化热点和最终制品，不默认复制完整网页正文。

## 7. 状态、失败与恢复

运行任务至少包含：

- `PENDING`
- `RUNNING`
- `PARTIAL`
- `SUCCEEDED`
- `FAILED`
- `TIMED_OUT`
- `CANCELLED`

处理规则如下：

- 单个来源失败时隔离失败并继续处理其他来源。
- 部分来源成功时返回 `PARTIAL` 和实际有效条目，不凑数。
- 全部来源失败时明确失败，不允许模型凭空补充热点。
- 模型失败、超时或预算耗尽时保留已经完成的上一次稳定结果，并允许用户显式重试。
- 取消操作幂等；取消后的迟到结果不得覆盖 `CANCELLED`。
- 契约、引用闭包或结构校验失败时关闭式失败，不得保存为成功结果。
- 同一个重试任务必须关联原任务，但形成新的运行记录，不能篡改原始失败记录。

## 8. 安全与内容边界

- 开发阶段所有请求均绑定 Java 服务端固定注入的开发身份；前端传入的身份字段不得生效。
- 模型密钥、数据源凭据和内部 Agent 地址只存在于服务端配置。
- 外部网页正文进入模型前必须与系统指令隔离，明确标记为不可信数据。
- 抓取器必须执行协议、域名、DNS 解析结果、重定向次数、响应大小和超时限制。
- 模型生成的 HTML 不得直接返回。微信富文本必须由服务端从 Markdown 转换，并移除脚本、事件属性、危险 URL 和不允许的样式。
- 日志不得记录密钥、Cookie、完整原始正文或用户敏感信息。
- 所有公开来源必须遵守其访问规则、许可证和合理请求频率。

## 9. 开源借鉴门禁

每个实施功能包在编码前必须完成一次有记录的 GitHub 对比，至少包含 3 个相似项目，并记录：

- 仓库地址；
- 实施时选定的 Tag 或 Commit；
- 项目活跃度和成熟度；
- 许可证及复用限制；
- 可借鉴的具体机制；
- 明确不采用的部分；
- 对现有 Java、前端和 Agent 架构的映射；
- 新依赖、安全和后续维护影响。

优先借鉴成熟、活跃、许可证兼容的机制，不整体搬入陌生框架。AGPL 等强 Copyleft 项目在未经专项批准前只允许借鉴产品流程和架构思想，不复制、修改或链接其代码。

本轮已确认的首批研究基线：

## 10. 验收标准

满足以下条件才可判定 MVP 闭环完成：

1. 用户输入“收集今天 AI 热点前 10 条”，系统正确识别为热点研究任务。
2. Agent 通过批准的真实公开来源获取数据，并使用真实模型完成筛选、去重、排序和摘要。
3. 有效条目不足 10 条时返回实际数量，不虚构补足；用户可按需查看来源。
4. 用户继续输入“把这 10 条写成公众号周更”，系统绑定上一轮榜单，不在未说明的情况下重新研究。
5. 用户输入“把第 N 条改写成小红书”时，只使用指定条目及其引用闭包。
6. 公众号默认返回约 3000～4000 个中文字符的完整成稿，而不是提纲。
7. 同一文章可获得一致的 Markdown 预览、Markdown 下载文件和安全微信富文本。
8. 会话、任务和制品在页面刷新及服务重启后仍可恢复。
9. SSE 断线不会重复创建任务，取消、超时、部分成功、失败和重试状态可被正确展示。
10. 所有会话、任务和制品均写入固定开发身份，前端伪造 `userId` 或 `tenantId` 不会改变数据归属。
11. 契约或引用完整性不满足时，任务不会被错误标记为成功。
12. 代码和网络行为中不存在自动发布到微信公众号、小红书或其他平台的接口与调用。

## 11. 验证分层

实施后的证据必须分层报告，不能用单一测试结果代替完整验收：

- **契约验证**：三端字段、状态机、幂等和 SSE 事件兼容。
- **组件验证**：意图识别、去重排序、Markdown 转换和 HTML 净化。
- **集成验证**：Java、Agent、MySQL、PostgreSQL 和 Redis 的真实联调。
- **浏览器验收**：连续对话、历史恢复、预览、复制、下载和异常展示。
- **真实外部验收**：至少一个真实模型和一组批准公开来源的受控端到端运行。

“代码已实现”“离线测试通过”“服务可启动”“真实来源可用”和“端到端验收通过”必须分别记录，禁止相互替代。

## 12. 非目标

本期明确不做：

- 自动发布或定时发布到任何内容平台；
- 登录、JWT、用户注册和权限管理；
- 微信、小红书等平台账号授权；
- 商业付费热点数据源；
- 多租户计费与配额销售；
- 高可用集群和跨地域容灾；
- 通用工作流搭建器；
- 视频、语音、图片生成和媒体素材自动上传；
- 为未确认场景提前建设复杂插件市场或通用编排平台。

## 13. 实施顺序建议

详细任务拆分由后续实施计划确定，原则顺序为：

1. 冻结三端契约、状态机和数据归属。
2. 完成开源项目对比与首批来源适配器选择。
3. 建立 Java 会话、消息、运行任务和制品持久化。
4. 接通 Java 到 Agent 的运行、SSE 和取消链路。
5. 完成真实来源研究、去重排序和引用闭包。
6. 完成整榜创作、单条改写及 Markdown 规范原稿。
7. 完成前端连续对话、预览、复制、下载和历史恢复。
8. 分层执行集成、浏览器和真实外部验收。

本设计仅确定目标、边界和验收口径，不代表上述能力已经实现或验证。
