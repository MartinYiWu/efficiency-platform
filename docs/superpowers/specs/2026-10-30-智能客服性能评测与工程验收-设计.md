## 设计与取舍

沿用 Java 业务接口 → Agent → 现有模型、知识索引及数据库的链路。选择先取得同题真实基线，再对已测量瓶颈做最小修改；不采用降低证据校验或将阶段提示当答案的方案。首进展、首正文和完成耗时分别报告，保留逐事件时间及逐阶段日志。

评测保留原固定集与原始结果；增加逐条显式完整等价表述配置，原事实之间仍为 AND，不能为单题硬编码答案。此功能仍是字符串匹配，不声称自动判断语义或否定关系。新增开放问法、多轮和知识缺口验收，以实际文档原文、引用版本及公司事实/通用建议边界人工复核。

真实基线确认充分性阶段思考等待明显，故仅该阶段关闭思考，冲突判断保持原配置。人工复核发现身份背景误判成专项制度、Windows 操作混入其他平台命令、未利用已有会议纪要规范；通过数据库版本化 Prompt 修复并保留旧版本和失败回答。费用控制的互补条款已召回却被综合问句重排挤出，因此对多个冻结查询并发重排后公平合并。最终RAG策略将父证据上限与已有12条子命中对齐，避免第二次TopK丢掉第11条互补证据；token预算、版本、冲突及引用校验不变。额外重排、冲突调用和延迟成本必须报告。

工程验收先审计旧 E2E 端点与隔离边界，阻止离线 UI 测试漏到真实服务；真实业务验收另通过明确的真实接口进行，不使用 fixture 作为产品结果。处理相关测试失败，运行规定门禁。真机软键盘只有连接实际设备后才可验收，浏览器模拟结果独立标记。

真实审计发现 Agent 重启后历史终态 SSE 返回 500。终态从 Java 持久化步骤只读重放，保留序号和较大续传游标；运行中维持原 Agent 流。新步骤以原 JSON 载荷增加事件类型元数据，旧步骤只还原可确定的公共事件，内部快照不外泄，不凭 Run 状态捏造终态，不重复写库。

## 交付标准

真实接口报告包含服务版本、冻结配置、问题、实际回答、引用、SSE、耗时、日志结论及失败。优化是否有效依据同题前后数据；固定集自动结果与人工核对分开。无法执行的真机或外部链路明确列出原因，不能声明全部完成。
