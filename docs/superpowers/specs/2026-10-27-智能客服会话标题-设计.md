# 智能客服会话标题

- 状态：按用户明确需求与小范围自主决策授权实施
- 负责人：智能客服开发与验收
- 更新日期：2026-10-27
- 范围：智能客服首轮标题、手工重命名与同用户未删除会话标题唯一性

## 行为

空标题会话显示“新对话”。首次意图识别同时从第一条用户消息提炼不超过 24 个字符的简短主题标题，不增加模型调用；标题字段的说明由数据库中的版本化意图 Prompt 提供。旧 Prompt 没有输出标题时保持问答兼容。手工标题最多 80 个字符，不允许空白。后续问答不重写标题；明确提供或手工修改的非空标题始终优先。

历史列表的桌面与手机入口都提供重命名。重名时保留输入、显示明确错误，原标题不变。列表刷新不得用过期响应覆盖刚保存的名称。删除后的标题可重新使用；未删除的归档会话仍参与重名判断。

## 跨层接口

Agent `IntentDecision.conversation_title` 为可选字符串，旧响应可省略。标题单独规范化为单行并限制到 24 个字符，空白或非字符串结果作为无标题处理，不能因为附属标题不合规使核心意图识别失败。仅历史为空的第一轮、且字段非空时，通过 Graph 的可选 `on_conversation_title` 回调发出内部 `conversation.title` 事件，载荷包含 `stage=conversation_title`、`public_summary=会话标题已更新` 与可选 `conversation_title`。原阶段事件与答案顺序不变。

Java 内部事件 DTO 增加可选 `conversation_title`，保留已有 Payload 构造兼容。投影实际首次处理该事件时，用 Run 的 userMessageId 校验其属于会话第一条 USER 消息，并只在标题仍为空时分配自动标题；数据库条件更新防止覆盖并发手工改名。自动重名追加“（2）”“（3）”等序号。事件继续映射为不带 phase 的普通 run.progress，不把模型标题当进展正文；员工前端收到 conversation_title 阶段后刷新真实历史列表。

手工修改复用 `PATCH /api/customer-service/conversations/{id}` 的 title 字段。创建显式非空标题与修改标题都检查唯一性，并将数据库重复键转换为 HTTP 409、`CUSTOMER_SERVICE_CONVERSATION_TITLE_DUPLICATE` 和“会话名称已存在，请使用其他标题”。空白与超长标题返回明确的 400 业务错误。服务端校验为最终依据，不能只检查前端已加载的一页历史。

## 数据库

在 `ai_efficiency_platform.ai_customer_service_conversation` 增加虚拟生成列 `title_unique_key VARCHAR(255)`：未删除且标题去除首尾空格后非空时取 `LOWER(TRIM(title))`，否则为 NULL。唯一索引为 `(tenant_id,user_id,title_unique_key)`，沿用数据库现有不区分大小写排序规则。多个尚未命名的会话不受唯一索引限制。正文、消息、引用表不变。

只读预检发现 1 组重名、4 条多余记录。用户已明确授权迁移并为这 4 条历史重名追加序号。执行前备份原名与 ID，保留每组最早记录，重命名其余记录时避开现有后缀标题；再次检查无重名后才加唯一索引。保存回滚 SQL 与原名备份。该开发库授权不扩展到其他数据库或业务表。

## 验证与交付

真实接口验证首次提问自动提炼、第二轮不改名、手工标题不被自动结果覆盖、普通及并发重名拒绝、自动撞名加序号、同名自身修改、删除后复用。核对 SSE、持久化、真实前端客户端和 Java/Agent 日志；失败如实记录。必要的组件/契约检查用于防回归。完成后按既有授权合并并推送 main，从主目录重启服务，清理本轮工作树并验证物理目录不存在。
