# 前端整体迁移 Vue 与旧版视觉复刻设计

日期：2026-11-03。状态：用户已批准实施；44个页面的Vue实现、默认浏览器43项及三宽132次检查已通过，全量206项测试通过，已完成正式目录切换，详见最终验收记录。

本版根据用户最新要求替代原先“保留 React”的方案：整个前端迁移 Vue，采用旧项目技术体系和实际视觉风格，允许直接复用旧版页面的展示部分。用户后续明确要求按详细计划全量实施并保留现有功能。

## 1. 当前事实与目标

- 当前前端为 `ai-efficiency-platform-ui`，React 19、React Router 7、Ant Design React 6、TypeScript、Vite 6、pnpm；React 是已有架构，并非本次新增。
- 参考工程为 `D:\work-place\jjcy-ai-platform\ai-platform-web`。锁文件中的核心版本为 Vue 3.5.26、Vue Router 4.6.4、Pinia 3.0.4、Ant Design Vue 4.2.6、Vue 图标 7.0.1、Vite 5.4.21、TypeScript 5.9.3、Tailwind 4.1.18。
- 当前按 `*Page.tsx` 统计为 44 个页面文件：人事 25、AI 管理 12、知识中心 4、客服 1、运营 1、404 1。页面文件数不等同于独立路由数，向导子页和详情页也在其中。
- 当前共有 117 个 TSX 文件（含测试）、55 个单元/组件测试文件、7 个 E2E 文件；生产纯 TS 文件约 40 个，其可复用性仍需逐文件确认。
- 当前人事部分页面使用本地演示数据；客服、运营、知识、AI 管理存在独立真实接口和运行状态逻辑。迁移保留各模块现有数据来源，不顺带补建人事后端。

交付目标是一个独立运行、单路由树、单构建产物的 Vue 前端；生产入口和页面不再依赖 React。现有功能、URL、接口与付费保护行为保持可追踪的迁移对应关系。

## 2. 迁移路径比较

| 路径 | 优点 | 代价与判断 |
| --- | --- | --- |
| 推荐：提取旧版 Vue 基础壳和展示组件，接入当前项目业务契约 | 能复刻现有旧版风格，业务行为可逐模块核对 | 需要改写 React 组件与 Hooks，但迁移边界清晰 |
| 整个旧工程复制后大幅删改 | 立即拥有大量 Vue 页面 | 带入旧权限、菜单、API、历史模块及构建豁免；容易功能倒退，整体适配成本更难控制 |
| React 与 Vue 在同一应用长期混跑 | 可逐页切换 | 双运行时、双路由和样式冲突，且不满足完整 Vue 重构目标，不采用 |

实施期间可独立预览新旧两个应用，最终只交付 Vue 生产入口。临时并行用于迁移核对，不采用微前端或 React 嵌入 Vue。

## 3. 目标技术体系

| 领域 | 目标方案 | 迁移说明 |
| --- | --- | --- |
| 框架 | Vue 3.5、Composition API、`script setup`、TypeScript 严格模式 | 业务组件为 `.vue`，纯业务模型和 API 保留 `.ts` |
| 路由 | Vue Router 4 | 路由懒加载；保留当前 URL、参数、重定向和 404 行为 |
| 状态 | Pinia 与 Vue composables | Pinia 管导航偏好等跨页面状态；请求、页面表单和流式订阅按业务隔离 |
| UI / 图标 | Ant Design Vue 4、`@ant-design/icons-vue` | 与旧版一致，替换当前 React 组件与图标 |
| 样式 | 旧版设计令牌、`v1-layout.css`、`v1-components.css`，业务组件 scoped 样式 | 复用页依赖 Tailwind 工具类时保留 Tailwind 4 支持；不照搬全部历史全局选择器 |
| 网络与校验 | 保留当前 fetch / Axios 契约与 Zod 校验 | 框架迁移不强制改写已验证的请求函数，不引入旧版认证拦截器 |
| Markdown | 复用旧版基于 markdown-it 的 Vue 渲染器并核对安全配置 | 替换 React Markdown；拒绝原始 HTML 和危险链接，保留代码块与表格展示 |
| 图表 | 已有页面需要时复用旧版 ECharts 方案 | 仅按需引入；不因旧版安装了图表库就增加当前页面没有的图表 |
| 构建 | Vite + pnpm 10 | 建议保留当前 Vite 6.3.5，换 Vue 插件并做兼容验证；采用相同技术栈不等于降级到旧版每个历史版本 |
| 测试 | Vitest、Vue Test Utils / Vue Testing Library、MSW、Playwright | 纯 TS 测试优先保留；React 组件测试迁移至 Vue；浏览器请求隔离沿用 |

当前代码中 TanStack Query 仅发现 Provider 装配，未发现业务 `useQuery/useMutation` 调用，因此不默认增加 Vue Query。当前已有 Axios、Zod 不为匹配旧版历史版本而降级。Vue 生态依赖的具体版本、许可证和构建体积在基础工程阶段核验并写入 pnpm 锁文件，不复制旧版 npm 锁文件。

用户本轮技术栈要求优先于前端 AGENTS、开发规范和架构设计中的 React、React Ant Design、禁止 Tailwind 等旧技术条款；实施时必须同步更新这些条款，其余安全、测试、数据边界规则继续生效。

| `src/views/home/index.vue` 和 `components` | 复刻页面分区与对齐 | 其首页总览接口、角色数据和业务入口不可直接用于当前人事工作台 |
| `src/views/ai/chat/index.vue`、`src/components/ai` | 复刻对话布局、消息和证据展示 | 当前客服与运营协议不同，重接各自 API、状态机、取消和恢复逻辑 |

| `src/views/ai/hr-assistant` | 复刻上传、候选人详情、分析和面试展示部分 | 旧版候选人评估模型和当前岗位/简历/匹配流程不是同一套模型，不整页替代 |

- 页面标题 22px、区块标题 16px、正文 14px；保留旧版在具体页面中使用的合理差异，优先复刻同类页面的实际排版。

- 客服会话侧栏、运营交付物面板属于业务区，保留各自功能；统一视觉不强行统一业务状态模型。
- 在相同视口、相同状态下保存对照截图，核对导航、字体、边距、卡片、表格、弹层和消息排版；列表字段按当前业务展示。

## 6. 保持行为与接口兼容

- 当前客服 API 为 `/api/customer-service/*`，知识为 `/api/knowledge/*`，管理为 `/api/aihub/*`，运营为 `/api/operations/*`；各自请求体和响应解析继续由现有契约约束。
- 旧版常见的 `/v1/ai/*`、`code === 200` 及动态菜单权限不能替换当前 `code === 'SUCCESS'` 等模块契约。
- 客服 SSE 使用 `afterSequence`、事件序号及终态；运营流还有 `run.stream.event/1` envelope 和另一组事件名。保留二者现有分块解析、去重、断线续读和终态处理。
- React Hooks 改为 composables 时保留请求世代隔离、取消信号、会话切换清理、刷新恢复、URL 会话标识和订阅释放；重新订阅不能重复提交生成请求。
- 保留引用来源、证据抽屉、反馈、澄清、知识激活、交付物预览/复制/下载及付费预算拒绝提示等现有能力。
- 人事演示页保持演示标识、交互和数据范围；不将本轮迁移描述为人事真实业务接通。

## 7. 文件与回滚策略

先在同仓库新增 `ai-efficiency-platform-ui-vue` 独立应用，便于保持当前未提交 React 工作区可运行、可比较。沿用 `app/pages/widgets/features/entities/shared` 的业务边界；页面与组件由 TSX 替换成 Vue，路由仍集中在 app 层。

现有纯 TS 的实体模型、Zod、SSE 解析、归约器、API 和展示转换按依赖检查后复用。Vue 页面对外只依赖当前项目的业务契约，不引用参考工程的绝对路径。

全部迁移且通过验收后，Vue 应用承接正式 `ai-efficiency-platform-ui` 入口。最终交付不保留 React/Vue 混合运行。原 React 代码和未提交工作必须先保留可恢复副本；任何目录删除、覆盖或移动按项目安全规则单独检查执行条件，本轮不执行这些操作。

5. 默认验收全部使用离线 fixture / Mock；所有未拦截 API 必须阻断。真实生成、Embedding、rerank 不在本轮授权内。

7. React 组件测试迁移到 Vue；纯 TS 契约测试继续有效。不得用删测试、缩小覆盖范围或全局 stub 绕过门禁。
8. 格式、lint、`vue-tsc`、单元测试覆盖率、生产构建和默认 Playwright 全部通过。旧项目 tsconfig 排除多批页面，不继承这种豁免；全部迁移业务源文件纳入类型检查。
