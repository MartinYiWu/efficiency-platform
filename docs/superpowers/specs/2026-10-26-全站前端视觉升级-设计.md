# 全站前端视觉升级设计

## 目标与范围

覆盖 `ai-efficiency-platform-ui` 的全部 48 条路由，包括平台框架、知识中心、AI 中心、智能客服、内容运营助手和人事助手。升级布局、视觉层级、排版与窄屏适配；保留现有业务流程、接口与数据语义。验收以实际页面截图和交互为准。

## 现状依据

2026-10-26 在 1440×900 浏览器中检查了人事工作台、岗位管理、知识库列表、Agent 管理和内容运营对话。观察到：页面标题、首屏留白和内容宽度不一致；岗位表格末列拥挤；知识库卡片展示原始英文状态及类型代码；Agent 管理页内容稀疏；不同助手对话页采用不同容器与头像规则。多个 CSS module 内存在未限定页面作用域的 `main`、`aside`、`footer` 选择器，可能影响其他页面。

## 设计方向

采用简洁、克制的企业工作台视觉。保留蓝色作为主操作色，其余内容使用中性色；状态色只表达状态，不用于装饰。桌面采用固定左导航与统一内容画布，窄屏切换抽屉导航。主内容宽度随页面类型变化：阅读/表单页限制行长，表格/工作台页可使用可用宽度，对话页保证消息列和输入区同轴。

## 全站规范

- 间距按 4、8、12、16、24、32 像素使用；页面外边距桌面 24 像素、窄屏 16 像素。
- 页面标题 24 像素，区块标题 18 像素，正文 14 像素，辅助文本 12 像素；同一页面只保留一个主标题。
- 页面顶部统一为标题、说明、主操作区；筛选紧随其下；列表、卡片、详情内容对齐同一左边界。
- 卡片统一边框、圆角和轻阴影；避免多层边框套叠。表格操作列保证可见，横向内容超宽时只在表格区域滚动。
- 状态使用中文标签，原始枚举和技术标识仅在确有必要的详情/调试区域显示。
- 空状态包含下一步操作；错误状态保留可见错误信息，不用仅靠颜色表达。
- 对话页统一消息宽度、头像尺寸、引用入口、进度区域和输入区位置；各 Agent 的名称与能力说明保持各自语义。
- 组件的样式只作用于组件自身；全局 CSS 仅保留重置、字体和基础 token，消除裸 `main`、`aside`、`footer` 等选择器造成的串样式。

## 页面类型

1. 工作台：标题与首要操作位于顶部；指标卡等高、数字和标签对齐；待办和趋势并列，窄屏纵向排列。
2. 列表与管理：标题区、筛选栏、结果区采用统一节奏；搜索、状态筛选、批量操作有稳定位置；表格/卡片按信息优先级展示。
3. 详情与表单：主信息、操作、分组内容和辅助信息层次清楚；表单标签与控件列对齐；抽屉内引用或说明采用可阅读排版。
4. 对话：独立会话区、历史导航、消息、引用与输入区；长回答、流式过程和窄屏视口均保持可读。

## 验收

对全部 48 条路由进行桌面截图与无水平页面溢出检查，并抽查关键路由的 390 像素窄屏布局；逐类检查标题、对齐、表格操作、状态文案、空状态与对话内容。运行前端 typecheck、lint、build 和现有测试。动态内容通过真实页面和接口观察，不能用静态断言替代视觉验收。
