# 智能客服真实评测闭环详细设计

## 1. 目标与范围

本阶段在现有独立 AI 智能客服、知识库、RAG 调试、运行回放和用户反馈能力上，新增可重复执行的真实评测闭环：

1. 管理员维护评测数据集和人工标注用例；
2. 评测批次冻结 Agent 版本、RAG 策略和知识索引版本；
3. 每条用例复用现有真实 RAG 调试链路，真实调用检索、Rerank 和大模型；
4. 系统持久化原始回答、引用、延迟、错误和确定性指标；
5. 管理员查看批次汇总、失败原因和用例明细，并对两个批次进行对比；
6. 使用用户提供的三份 DOCX 完成首轮真实知识导入和评测验证。

本阶段不修改普通员工对话流程，不引入自动发布，不使用测试桩冒充真实调用，不把 LLM 自评结果当作唯一质量判断。

## 2. 已确定的架构选择

采用 Java 控制面编排、Agent 执行真实 RAG 的方案。

- Java 拥有数据集、用例、批次、结果、权限边界和发布版本引用；
- Agent 继续拥有意图识别、检索、父子证据组装、充分性判断、回答和引用生成；
- 评测批次调用现有 `/internal/v1/customer-service/rag-debug-runs`，不创建员工会话；
- Agent 调试响应补充最终引用快照，使评测可以核验引用闭包、文档和版本；
- 一个批次内串行执行用例，避免评测同时打满外部模型服务；批次通过独立后台执行器运行，HTTP 创建接口立即返回；
- 评测结果保存冻结事实，不在查询时重新计算历史结果。

未采用 Agent 自建评测业务表，因为数据集和发布门禁属于平台管理业务；未采用离线脚本作为主方案，因为离线结果不能证明真实 Java—Agent—向量库—模型链路可用。

## 3. 数据模型

### 3.1 评测数据集 `ai_rag_eval_dataset`

| 字段 | 含义 |
|---|---|
| id | 数据集 ID |
| name | 数据集名称 |
| description | 说明 |
| agent_key | 所属 Agent，本阶段为 `customer-service` |
| status | `DRAFT`、`ACTIVE`、`ARCHIVED` |
| created_by / created_at / updated_at | 审计字段 |

### 3.2 评测用例 `ai_rag_eval_case`

| 字段 | 含义 |
|---|---|
| id / dataset_id / case_no | 用例身份和数据集内稳定编号 |
| question | 真实提问 |
| expected_answer_mode | 预期回答模式 |
| expected_facts | 回答必须包含的关键事实数组 |
| prohibited_facts | 回答不得包含的错误事实数组 |
| expected_document_titles | 预期命中的文档标题数组 |
| expected_document_version_ids | 可选的精确版本约束数组 |
| min_citation_count | 最少引用数 |
| tags | 分类标签数组 |
| enabled | 是否参与新批次 |
| created_at / updated_at | 审计字段 |

关键事实按归一化后的包含关系确定性核验；每条事实是人工标注的最小原文事实，不要求整段逐字相等。禁止事实用于检查旧版本泄漏、错误制度和越界补充。

### 3.3 评测批次 `ai_rag_eval_run`

批次保存数据集、Agent 版本、RAG 策略、知识绑定、状态、总数、通过数、失败数、汇总指标、开始和完成时间。知识绑定保存为冻结 JSON，批次运行中不读取新的“当前版本”。状态为 `PENDING`、`RUNNING`、`SUCCEEDED`、`PARTIAL_FAILED`、`FAILED`。

### 3.4 用例结果 `ai_rag_eval_case_result`

每条结果保存对应调试 Run ID、执行状态、耗时、回答模式、回答正文、引用快照、指标明细、错误码和错误信息。原始事实用于详情展示，汇总指标用于批次比较。

## 4. 指标定义

所有分母只包含本批次已执行的启用用例。

| 指标 | 判定方式 |
|---|---|
| execution_success_rate | Agent 调试返回 `SUCCEEDED` 的比例 |
| answer_mode_accuracy | 实际回答模式等于人工标注模式的比例 |
| expected_fact_recall | 必须事实中被回答覆盖的比例 |
| prohibited_fact_rate | 禁止事实出现在回答中的比例，目标为 0 |
| source_recall_at_k | 预期文档标题在最终引用快照中出现的比例 |
| citation_compliance_rate | 引用数达到下限，且所有引用属于本次冻结索引和最终证据包的比例 |
| version_accuracy | 配置精确版本时，引用全部命中预期版本的比例 |
| case_pass_rate | 用例的执行、模式、事实、禁止事实、来源、引用和版本检查全部通过的比例 |
| latency_p50 / latency_p95 | 真实 Java 到 Agent 调试调用耗时分位数 |

当用例未配置某项预期时，该项记为 `NOT_APPLICABLE`，不进入该指标分母。HTTP 200 只表示接口成功，不等于用例通过。

## 5. 接口设计

基础路径：`/api/aihub/rag-evaluations`。

### 5.1 数据集与用例

- `GET /datasets`：数据集列表；
- `POST /datasets`：新建数据集；
- `GET /datasets/{id}`：数据集及用例；
- `POST /datasets/{id}/cases`：新增一条用例；
- `PUT /datasets/{id}/cases/{caseId}`：更新一条用例；
- `POST /datasets/{id}/cases/import`：批量导入 JSON 用例；返回新增和更新数量。

批量导入以 `caseNo` 为幂等键，同一数据集重复导入时更新已有用例，不制造重复数据。

### 5.2 批次与比较

- `POST /runs`：创建后台评测批次；
- `GET /runs?datasetId=`：查询批次列表；
- `GET /runs/{id}`：查询批次、汇总和全部用例结果；
- `GET /runs/compare?baselineRunId=&candidateRunId=`：返回同一数据集两个批次的指标差值和逐用例状态变化。

创建批次请求必须明确 Agent、Agent 版本、RAG 策略和知识绑定。服务端复用 RAG 调试已有的资产归属、Active Release 和索引就绪校验。

## 6. Agent 契约调整

`customer-service-rag-debug-view/1` 保持版本号不变并新增可选 `citations` 数组。Java DTO 和前端 Schema 接受旧调试记录缺少该字段的情况；新的 Agent 调试调用必须返回渲染后的最终引用快照。

每条引用包含文档、文档版本、索引版本、父片段、引用类型、页码、原文和偏移。评测只读取这些冻结字段，不重新访问向量库推断历史引用。

## 7. 后台执行与失败处理

1. 创建批次时写入 `PENDING` 和冻结参数；
2. 后台单线程执行器将批次改为 `RUNNING`；
3. 对每条启用用例调用现有 `AiRagDebugService`；
4. 单条调用失败时保存真实异常码和耗时，继续下一条；
5. 每条完成后立即持久化结果，避免进程中断丢失已完成事实；
6. 全部完成后计算汇总并写入终态；
7. 全失败为 `FAILED`，部分失败为 `PARTIAL_FAILED`，全部执行成功时为 `SUCCEEDED`；用例质量不通过不会把批次执行状态改成接口失败。

日志必须包含 eval_run_id、case_id、debug_run_id、耗时、状态和错误码，不记录密钥和完整 Prompt。

## 8. 前端页面

AI 中心新增同级菜单“RAG 评测”，路径 `/ai-center/rag-evaluations`，不增加三级菜单。

### 8.1 数据集列表页

- 顶部：标题、说明、新建数据集按钮；
- 筛选：Agent、状态；
- 表格：名称、Agent、状态、用例数、最近运行、更新时间、操作；
- 操作：查看用例、发起评测、查看运行记录。

### 8.2 数据集详情页

- 头部：数据集名称、说明、状态、用例统计；
- 用例表格：编号、问题、预期模式、关键事实数、预期来源、标签、启用状态；
- 右侧抽屉：新增/编辑用例的完整字段；
- 批量导入弹窗：粘贴 JSON 数组，先展示解析数量，再提交；
- “发起评测”抽屉：选择 ACTIVE Release、RAG 策略和知识索引版本。

### 8.3 评测运行详情页

- 汇总区：状态、通过率、来源召回、引用合规率、模式准确率、P50/P95；
- 失败筛选：执行失败、模式错误、事实缺失、命中禁止事实、来源未命中、引用不合规、版本错误；
- 明细表：用例编号、问题、结果、回答模式、来源、耗时、错误；
- 详情抽屉：真实回答、引用、预期与实际逐项对照、Agent 调试 Run ID；
- 对比入口：选择同数据集另一个批次，展示指标差值和回归/改善用例。

## 9. 首轮真实数据与验收

首轮使用以下三份原始 DOCX，通过 Java 文件上传接口进入知识库，经过真实 COS、解析、父子切片、Embedding、索引发布和 Agent 检索：

- 《研发内部AI使用规范》；
- 《研发团队标准规范文档》；
- 《阿里多Agent》技术资料。

建立不少于 18 条人工标注用例，每份文档至少 6 条，覆盖直接事实、跨段归纳、禁止项、条件例外、操作步骤、故障排查和无依据问题。首轮功能验收要求：

- 三份文件真实上传、解析和发布成功；
- 18 条用例均产生真实调试记录或真实错误记录；
- 用例结果可从页面和接口复查；
- 引用能够定位到正确文档和版本；
- 运行日志无未处理异常；
- 任何不达标指标按真实结果报告，不修改数据伪造通过。

40 条以上、覆盖公司制度/业务流程/产品文档/技术文档的长期 Gold 集仍是发布门禁目标；本次三份资料不足以代表全部四类知识，因此不宣称完成全量质量门禁。
