## 2 方案选择

| 方案 | 优点 | 不足 | 判断 |
| --- | --- | --- | --- |
| 纯规则/关键词 | 可复算、低费用 | 无法稳定判断项目职责、复杂度和相关能力 | 保留用于客观事实，不独立承担全部匹配 |
| LLM直接报总分/推荐 | 初期实现少 | 权重漂移、证据不足误判、结果不可复算、难以审计 | 不采用 |
| LLM逐项语义判断＋Java冻结规则计分 | 兼顾语义理解、证据、复算与可控调用 | 需先定义评分锚点、输出契约、版本和复核制度 | 推荐，符合用户要求及现有产品结构 |

评分输出必须区分：材料符合岗位的程度、材料足以判断的程度、是否需人工核验。不会增加第二个Graph Runtime或自由互评Agent群。

## 3 三端职责

### Java业务真相

管理岗位/草稿/模板、硬软要求、五维权重、阈值、版本、词典、候选人/文件/事实快照、评估任务、分数/分档、人工操作与审计。确定性规则和评分聚合均在Java执行，不信任浏览器或模型提交的总分/规则内容。

首选独立HR业务域，包以`com.aiep`现有分层规范归属；新增Maven模块是否必要在实施计划中核对13模块依赖与ADR门禁后确定。本草案只确定逻辑域，不创建模块或调整现有依赖。HR通过平台文件能力保存私有文件，通过`AiInvokeFacade`调用Agent，不让HR直接依赖厂商SDK或Agent HTTP客户端。

涉及真实数据库时先检查已有表和迁移目录，展示SQL、影响及回滚；未获明确DDL授权不执行。逻辑对象如下，不提前固化旧项目表名：

| 对象 | 关键职责 |
| --- | --- |
| Position / PositionDraft | 稳定岗位ID、族/部门、草稿步骤与并发版本 |
| EvaluationConfigVersion | 已发布硬软规则、权重、阈值、映射、覆盖门禁、词典引用及不可变哈希 |
| PositionContextVersion | JD/名称/职级等上下文版本，不能隐含改变计分规则 |
| Candidate / ResumeVersion | 候选人、私有文件、哈希及版本；同文件复用有权限限制 |
| FactSnapshot / EvidenceBlock | 原始与确认事实、来源页段块、精度、脱敏与哈希 |
| SemanticAssessmentSnapshot | 逐项判断、证据、Prompt/模型/要求哈希、有效性与复核状态 |
| MatchingRun / MatchingResult | 一次运行、单题统一scope、配置/事实引用、完整值快照、分数/覆盖/状态/版本 |
| Override / CorrectionAudit | 原因、操作者、时间、前后值、新结果关联及撤销；不原地改历史 |

Java端对外入口拟定为`/api/hr/*`，沿用SUCCESS信封、分页/错误与traceId规范，前端不能调用旧项目`/v1`。具体路径及DTO在批准后的实施计划固化。

### Python Agent受控语义执行

只消费Java发来的服务器组装冻结规则及必要事实，不接收浏览器配置的规则或预算。按已有LangGraph运行时编排：事实解析→原子要求批评→证据/结构校验→输出语义快照或解释。不实现第二套总分引擎。

解析/语义/解释分别使用AI管理中已发布Prompt引用，缺失即明确拒绝；不把业务Prompt长文本写入新HR插件。模型路由由已发布模型策略决定，统一Provider与付费HTTP守卫。

优先同步返回结构化阶段产物到Java已有调用边界，运行进度/取消采用统一Run治理；是否流式展示解释不改变评分真相。各阶段必须有超时、终态、幂等及安全错误码，不能用前端轮询再次触发生成。

### Vue承接产品设计

保留H/positions、H/resumes、H/matching、H/interviews、H/talent、H/settings既有页面路径。按`pages→features→entities→shared`接入新的API/Schema，不在页面裸请求或保留与后端并行的评分真相。

继续沿用现有设计系统、匹配五维与证据布局、原文定位、权重快照、人工放行弹窗、过滤打捞与历史结果；不改成只有聊天框的HR产品。真实接入页去掉对应演示数据，尚未接入的页保持演示标识，不能混合真实/虚构统计。

新增待核验状态、全局规则页、明确的面试官视角/接口是现有设计的缺口，需先更新交互映射，不直接凭工程偏好扩大范围。当前生效样式受UI工程规范约束；旧PNG中的虚构身份/通知数字不复制成真数据。

## 4 数据与调用链

```text
HR配置岗位草稿 → Java完整校验 → 发布不可变规则版本
上传授权简历 → Java受控抽取/保存 → Agent提取事实与证据
Java校验/派生/人工修正 → 冻结事实快照
Java加载规则与事实 → 确定性硬条件/年限/证书判断
Agent有界批量语义判断 → 逐项ID/证据校验 → Java保存判断快照
Java标准分映射/五维聚合/覆盖门禁/分档 → 保存匹配快照
Agent按需生成有证据解释 → Vue展示/HR复核 → 面试准备
```

总体状态用运行状态与业务状态分离：运行可PENDING/RUNNING/SUCCEEDED/FAILED/CANCELLED/TIMED_OUT；业务结果可待确认、待核验、硬过滤、已评分、历史。硬过滤不是执行失败，待核验不是零分；执行失败也不能伪装成候选人“不达标”。

候选人列表以最新有效事实和目标配置版本读取；用户可主动查看历史。原子语义判断缓存键包含租户/数据范围、事实hash、语义要求锚点hash、词典/Prompt/模型版本。加权/阈值重算不收费，规则或事实变化才重评受影响内容。

候选人评估的一次任务统一承担解析、匹配、重试及解释实际请求的100元/60次/10分钟安全上限；如果产品流程暂停人工确认，则关闭当前任务，确认后的新动作有独立显式任务并仍受同一全局授权总账约束，不能通过拆子任务反复获得新额度。单逻辑操作最多3次HTTP，各层共享，不使用嵌套独立重试。

批量上传100份、预演50份属于产品规模要求，不等于允许一次无界收费。批次建立前声明最大工作单元，冻结批次总授权；样本不足和预算不足分别展示，不自动追加预算或另开账本。

## 6 验证与发布条件

1. 规则单测：权重/阈值/容差、缺证据、日期精度、各维公式、覆盖门禁、分档边界和历史冻结。
2. Agent契约：完整要求集合、错误证据、Prompt注入、未知字段/档位、有限修复、取消及重试共享额度。
3. Java→Agent离线HTTP：同一输入幂等、停后零新增发送、用量结算、模型失败不变成候选人负面判断。
4. Vue：向导真实保存/恢复、待确认/待核验/硬过滤/评分四类表现、原文跳转、理由必填、重算不覆盖历史；1440/1024/390设计验收。
5. 角色API/导出：面试官无评分字段、无排名及联系方式泄漏；只能访问被授权候选人。
6. 真实验收：用户授权简历与价格/预算，在固定总账下有限验证，先定向、异常即停；不将脱敏合成材料称真实候选人数据。
7. 校准：岗位负责人独立标注与仲裁，报告证据/档位/复核一致性和误过滤，不能仅用“总分接近”证明招聘有效性。
