# 问答Token硬预算与费用结算

- 状态：用户已授权制定计划并实施。
- 日期：2026-11-03；负责人：本轮实施者。
- 范围：既有本机付费总账、HTTP守卫、管理CLI及离线验证；保持服务停止，不发起外部付费请求。

## 数据与限制

在原次数、费用、时间和并发上限基础上，增加总批次与单问题的累计输入、输出、推理token上限。推理token包含于输出token，独立监控但不再加到输出或费用中。输入预留采用与完整请求字节及消息封装相关的保守上界，不能伪称精确厂商tokenizer；重排按query与每份文档的重复组合计入上界。输出预留取请求明确声明上限，DeepSeek推理预留等于该输出上限。无法确定上界时拒绝发送。

价格增加不可变版本、每百万token的CNY微元输入/缓存输入/输出费率与允许输入token上界，全部用整数运算，整体向上取整；缓存是输入子集，推理是输出子集。新授权须完整价格与token字段；旧授权、旧价格缺字段时保留历史用量，禁止恢复收费，不能自动填充无限额度或重置总账。

## 预留与结算

发送前SQLite同一事务预留费用和三类token，同时检查总/单问题限额；重试每次独立预留。单次最坏费用仍为保守预扣上界，并校验其至少覆盖本次按冻结费率计算的最坏成本。

新增PaidUsage(input_tokens, output_tokens, cached_tokens, reasoning_tokens)。只在完整成功的流或JSON响应得到可校验usage时结算。usage必须非负整数且cached<=input、reasoning<=output，不能用缺字段补0冒充实际。DeepSeek使用prompt/completion计数，推理details为子集；Embedding/重排使用其明确输入或total_tokens计数，输出为0；未知厂商格式继续保留预留。

流式只缓存有界单行与usage对象，不保存正文；[DONE]与完整终态、usage均有效才允许结算，重复usage必须一致。JSON仅在完整响应读完且成功标志合法时允许结算。异常、取消、失败HTTP、无usage、无终态、超大/损坏usage保留原预留且标记unknown，不释放未证实额度。结算幂等，事务将预留换为实际，跨进程并发不重复退款；结束、重启或崩溃不清零。厂商usage超过已预留上界时持久停用预算，记录异常与实际计数，不宣称能撤销已发生的外部费用。

状态与details只读展示批次、单问题、每次调用的预留、实际、未知金额/token、价格版本、停止原因，无prompt/key/正文。实际金额为usage乘核验费率的内部核算，不冒充供应商最终账单；价格/供应商偏差及外部程序仍需账户上限兜底。

## 兼容与实施选择

复用现有SQLite并做增量新增列，旧表/旧用量不删除、不自动退款。无需共享业务DDL、新依赖或模型切换。选择传输边界统一捕获usage，可覆盖生成、Embedding和重排，避免只在客服业务局部计数。CLI旧计划在preflight被明确拒绝，提供全0未授权模板。

已知本轮开始5173端口有前端进程，先识别后恢复用户要求的停止状态；测试仅MockTransport、ASGITransport和测试结束即关闭的loopback服务，不启动项目常驻服务、不授权真实非零预算、不提交推送。
