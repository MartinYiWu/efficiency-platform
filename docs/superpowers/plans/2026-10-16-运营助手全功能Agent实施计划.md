# 运营助手全功能 Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有运营助手从单 `system` 文件模板和通用交付物生成器升级为数据库版本化、多角色 Prompt 驱动的完整 Agent，并真实交付八个运营场景。

**Architecture:** Java 保持会话、消息、Run 和 Artifact 的业务真相源；Python Agent 负责意图、场景编排、Prompt 装配、研究工具循环、专业生成、校验和恢复。Agent MySQL `ai_efficiency_platform_agent` 保存 Prompt 与运行状态，PostgreSQL + pgvector 数据库 `vector` 保存检索内容，Redis 只做短期协调；前端只调用 Java。

**Tech Stack:** Java 21、Spring Boot 3.2、MyBatis-Plus、Python 3.12、FastAPI、Pydantic、SQLAlchemy AsyncIO、MySQL、PostgreSQL/pgvector、Redis、React 19、TypeScript 6、Ant Design、PowerShell 真实验收脚本。

## Global Constraints

- 八个场景必须全部完成：行业热点、多平台内容、品牌方案、IP 方案、活动方案、内容日历、增长实验、运营复盘。
- Intent & Planning Agent 是所有业务消息的第一入口；`revise`、`refresh`、`clarify`、`general_chat` 是控制动作，不是新场景。
- 每个场景和阶段加载独立 Prompt；Prompt 从 Agent MySQL 读取，运行时不得静默退回文件模板。
- `system`、`developer`、`user`、`assistant`、`tool` 在内部保持独立；实际 Provider 不支持的角色只能在 Adapter 边界确定性映射。
- Model Policy、Output Contract、Prompt Message 和 Prompt Variable 必须独立建模。
- 外部网页、用户输入、历史内容和工具结果不得进入可信 `system`/`developer` 变量。
- 公众号最终可见正文必须为 3000 至 4000 个中文字符；校验失败最多定向修订一次。
- 小红书、公众号、头条必须基于同一证据独立创作，禁止机械截断。
- 不实现登录，不自动发布到任何平台，不改造现有开发凭据管理。
- `ai-efficiency-platform/aiep-boot/src/main/resources/application.yml` 属于用户配置，任何提交均不得包含该文件。
- 当前工作树已有未提交实现；禁止 reset、checkout 或覆盖无关改动，每个提交只包含任务声明的文件。
- 测试类只作开发辅助；最终完成证明必须来自 Java 公共接口、真实 Agent、真实模型、真实数据、真实数据库和日志。
