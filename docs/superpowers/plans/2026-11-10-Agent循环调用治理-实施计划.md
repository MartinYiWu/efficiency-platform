# Agent循环调用治理实施计划

状态：本轮离线实施与验收完成；真实部署未执行。负责人：本轮执行代理。更新时间：2026-11-10（北京时间）。适用范围：客服Agent调用链、共用付费HTTP与SQLite单任务守卫。

**目标：** 消除重复执行与多层重试放大，任务终止后不再发送请求，单次任务费用上限100元。

**架构：** 保留现有有限阶段客服流程与SQLite统一总账。在core增加任务/逻辑操作执行控制，ContextVar传递给网关和HTTP守卫；任务内复用成功及在途操作，所有HTTP重试共享单操作3次额度。SQLite继续承担跨进程的次数、金额和时间保护，不新建真实账本。

**技术：** Python3.13、asyncio、HTTPX、SQLite、pytest；不新增依赖。

## 约束与方案依据

- 用户已批准上轮流程有界、重复去重、进展检测、统一重试、终止联动方案，并明确100元指单任务费用上限。此计划直接实施，不再重复请求设计批准。
- 本轮只做离线Fake/MockTransport验收，不开通或恢复真实预算、不启动常驻服务、不改价格、Release、Prompt、Java、前端或共享数据库DDL。
- 单任务最多60次付费HTTP、100000000微元、600000毫秒；既有授权更严格时取更严格值，绝不自动扩大旧授权。
- 单逻辑操作最多3次实际HTTP，网络/空响应/Schema修复共同计数。重试计数不因外层重新进入清零。业务校验失败不盲目再次调用已重试的网关。
- 成功/在途去重只限同任务、同阶段、同模型策略/输入/输出契约。不同证据或策略不能混用。相同已完成操作连续重复3次触发无进展；不同有效证据检查是进展，不按答案文字相同误判。
- 已停止状态不可恢复；取消在途和排队协程；单个共享等待者取消不影响其他等待者，但整个任务取消必须结束共享工作。SQLite历史占用不退款清零。
- 冲突核验先去重和核算任务数，超过60个检查单元时发送前明确拒绝；不省略必要证据对。保持已有批量契约开关；并发工作者最多8个，致命失败取消同组工作者。
- 发现局部Agent规则禁止Git操作：用实施前快照与逐文件差异审查，不执行提交/推送。保留工作区其他改动。
