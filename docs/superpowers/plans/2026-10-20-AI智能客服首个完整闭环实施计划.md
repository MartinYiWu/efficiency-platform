# AI 智能客服首个完整闭环 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 AI 效能平台中交付独立的内部 AI 智能客服，完成知识上传、版本发布、RAG 问答、引用、反馈、调试和运行回放的真实闭环。

**Architecture:** Java 继续作为知识、AI 资产和用户可见业务数据的控制面，Python Agent 作为文档摄取、RAG 和 CustomerServiceGraph 的执行面，`vector.datasource` 当前指向的 PostgreSQL 开发库 `jjcy_ai_vector` 保存知识 Chunk 与向量，Agent MySQL `ai_efficiency_platform_agent` 保存运行事实。前端只访问 Java；AI 中心为平台级管理入口，智能客服是其中一个独立 Agent。

**Tech Stack:** Java 21、Spring Boot 3.2.5、MyBatis-Plus 3.5.15、MySQL 8、Python 3.13、FastAPI、LangGraph、Pydantic 2、PostgreSQL + pgvector、Redis、腾讯云 COS、React 19、React Router 7、Ant Design 6、TanStack React Query、Zod、CSS Modules。

## Global Constraints

- 首期不实现登录；Java 固定注入 `tenantId=dev`、`userId=1`、`SYSTEM_ADMIN`，浏览器不得提交或覆盖可信身份。
- 智能客服 Agent Key 固定为 `customer-service`，不得引用 `agents/operation/` 的业务状态、Prompt、场景或契约。
- Prompt 正文由版本化 Prompt 资产和 Release Bundle 提供；代码只保留稳定的契约、枚举和安全门禁。
- 平台共享 Prompt 和 Agent 私有 Prompt 必须绑定确切版本；共享 Prompt 升级不得自动影响已发布 Agent。
- 模型策略和 RAG 策略必须带 `owner_agent_definition_id`，智能客服不得绑定其他 Agent 的私有策略。
- 公司事实只能来自冻结索引版本中的已发布证据；证据不足、过期或冲突必须返回 `INSUFFICIENT_EVIDENCE`。
- 通用知识只能出现在明确标注“通用建议，非公司制度”的独立区域。
- 前端导航固定为两级“AI 助手 → AI 智能客服”；AI 中心直接展开 Agent、Prompt、模型、RAG、调试、运行和反馈管理。
- 单文件最大 10 MiB；单批最多 50 个文件、总大小不超过 200 MiB；只支持 PDF、DOCX、Markdown、TXT、HTML。
- Embedding 固定为 `text-embedding-v4`、1024 维；向量距离使用 cosine。
- 单元测试、Mock、编译和静态检查仅作为开发辅助；完成结论必须来自真实数据库、真实文件、真实模型、真实 Embedding 和真实 HTTP/SSE 调用。
- 验收期间持续检查前端、Java、Agent、MySQL、PostgreSQL、Redis、对象存储和 Provider 日志；发现错误或结果不符合契约必须修复后重跑。
- 当前工作区存在其他未提交改动；每个任务只暂存本任务文件，禁止覆盖、清理或提交无关改动。
