# 智能客服父子切片与证据组装 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 智能客服以子片段精确检索、完整父条款回答，并在发布版本、上下文预算和引用边界内给出可靠的公司知识答复。

**Architecture:** 保留 Java 知识索引发布与 Agent Release 绑定；Agent PostgreSQL 增加父片段及子片段关系，沿现有向量/FTS→RRF→Rerank 链路扩展父片段，并让证据充分性和回答使用预算内的完整父原文。Java 仍是真相源，前端只读取 Java 提供的调试/回放视图。

**Tech Stack:** Python 3.13、FastAPI、PostgreSQL+pgvector、MySQL、Java/Spring、React/TypeScript、DashScope Embedding/Rerank。

## Global Constraints

- 依据 [设计](../specs/2026-10-22-智能客服父子切片与证据组装-设计.md)，仅改独立智能客服；不引入 LangChain/LlamaIndex 或第二 Graph Runtime。
- 保留文档版本、索引版本、Agent Release 和历史回放，不在原地重写已发布数据。
- PostgreSQL DDL 在只读预检后执行；用户已明确授权开发库 `jjcy_ai_vector` 迁移与新索引切换。其他环境不在授权范围。
- TDD 用于开发；验收必须另走真实 Java→Agent 接口、真实知识数据和日志，不用测试类结果冒充真实调用结果。
- 工作区已有 `ai-efficiency-platform/aiep-boot/src/main/resources/application.yml` 修改不得纳入本任务。

### Task 1: 父子切片与持久化契约

**Files:** `chunking.py`、`contracts.py`、`vector_repository.py`、上述 PostgreSQL 迁移文件；测试 `tests/unit/agents/customer_service/test_chunking.py` 和向量仓储测试。

**Interfaces:** 新增 `parent_child_document(document) -> tuple[ParentDraft, ...]`，保留现有 `chunk_document` 供旧索引与现有用例使用；`ParentDraft` 含完整 `content` 与 `children: tuple[ChunkDraft, ...]`；`DocumentChunkRepository.replace_version_chunks(..., parents, embeddings)` 将父与子同事务替换，Embedding 只对应子片段。

- [ ] 先在 `test_chunking.py` 增加编号条款含例外、跨段小节、表格行组、超长不可分条款的断言；运行 `uv run pytest tests/unit/agents/customer_service/test_chunking.py -q`，确认新增用例因缺少父子结构而失败。
- [ ] 在 `contracts.py` 定义 `ParentDraft(parent_no, section_path, page_start, page_end, content, content_hash, children)`；在 `chunking.py` 新增 `parent_child_document`，先按标题/编号条款/表格边界形成父片段，再仅在父片段内拆子片段。超长不可分原文抛出 `PARENT_CLAUSE_TOO_LONG`，不截断原文。
- [ ] 写仓储测试，要求父片段、子片段、位置映射同事务写入；运行定向测试确认旧仓储失败，再在 `vector_repository.py` 实现替换与关系验证。
- [ ] 迁移新增 `customer_service.document_parent`，为 `document_chunk` 增加 `parent_id`、`child_no`、原文位置；`03-verify.sql` 检查孤儿子片段、跨版本父子、子片段计数和非空内容；`04-down.sql` 只针对本迁移对象。执行仅限已授权的开发库 `jjcy_ai_vector`。
- [ ] 运行 `uv run pytest tests/unit/agents/customer_service/test_chunking.py -q` 和关联仓储测试；检查 SQL 与源码 diff。

### Task 2: 子片段检索与父片段证据组装

**Files:** `retrieval.py`、`vector_repository.py`、`state.py`；新建 `evidence_assembly.py`；测试 `tests/unit/agents/customer_service/test_parent_retrieval.py`、`test_evidence_assembly.py`。

**Interfaces:** `DocumentChunkRepository.get_parents(tenant_id, index_release_ids, parent_ids) -> tuple[ParentEvidence, ...]`；`assemble_evidence(children, parents, context_token_limit, fixed_prompt_tokens, output_reserve_tokens) -> EvidenceAssembly`。`EvidenceAssembly` 保留入选父原文、对应子命中、未采用原因和预算计数。

- [ ] 先写失败用例：两个命中子片段只展开一次父片段；跨索引/版本父片段被拒；相似但条件不同的父片段不得误删；预算不足时移除整段而非截字。
- [ ] 运行两个定向测试文件，确认失败原因是当前无父读取和组装接口。
- [ ] 保留现有向量/FTS/RRF/Rerank 子片段排序，在 Rerank 后批量读取父片段；按父 ID 去重，只在完整原文及版本完全相同时合并跨父副本。把预算计算与选择逻辑独立写入 `evidence_assembly.py`，不得以摘要替换制度原文。
- [ ] 重跑定向测试，并验证现有检索测试不退化。

### Task 3: 充分性、冲突与引用闭包

**Files:** `graph.py`、`sufficiency.py`、`citations.py`、`state.py`、`model_gateway.py`；测试 `test_answer_modes.py`、`test_citation_guard.py`。

**Interfaces:** `judge_sufficiency(gateway, question, assembly)` 与 `generate_answer(..., evidence=assembly.selected_parents, ...)` 接收同一份装配快照；引用保留 `chunk_id` 与父原文位置，不能引用被预算移除的证据。

- [ ] 先写失败用例：完整条款支持公司回答；只有被截断/预算移除的关键条款时返回 `INSUFFICIENT_EVIDENCE`；两份现行文档明确冲突时不得按得分挑选；引用位置必须落在原文内。
- [ ] 运行定向测试确认失败，再让 Graph 用同一份父证据快照执行充分性和回答；冲突结构化交给充分性阶段并在输出校验时拒绝冲突结论；保留通用建议的独立标注。
- [ ] 重跑定向测试及全部智能客服单元/API 测试；不把“引用 ID 合法”冒充“引用语义支持”。
