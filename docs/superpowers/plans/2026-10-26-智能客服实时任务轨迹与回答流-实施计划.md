# 智能客服实时任务轨迹与回答流 Implementation Plan

> 执行依据：[智能客服实时任务轨迹与回答流详细设计](../specs/2026-10-26-智能客服实时任务轨迹与回答流-详细设计.md)。实施时逐项勾选；本文件是开发计划，不代表代码或真实接口已验收。

| 适用范围 | 智能客服员工对话的实时进展、恢复与真实接口验收 |
| 更新日期 | 2026-10-26 |

**Goal:** 员工提交智能客服问题后，在对应助手消息中实时看到可恢复的真实任务轨迹，同时保留经证据校验的独立回答流。

**Architecture:** Agent 在 Graph 实际阶段边界发事件；Java 沿用现有 SSE 投影和运行步骤表，公开白名单进展并提供同事务时间线快照；前端按 Run 展示可折叠进展，从快照游标续订答案事件。无需新表、数据库迁移或新的模型推理输出。

**Tech Stack:** Python 3.13/FastAPI/Pydantic、Java 21/Spring/Reactor/JDBC、React 19/TypeScript/Zod/Ant Design、MySQL 现有运行步骤表、SSE。

## Global Constraints

- 只改独立智能客服的对话链路；运营助手、RAG 检索策略、Prompt、模型思考模式、知识索引和评测集保持现状。
- 公开阶段固定为 `intent`、`retrieval`、`verification`、`answer`；阶段状态仅 `STARTED`、`COMPLETED`；不发送模拟百分比或 LLM 原始推理。
- 进展不得进入助手正文、引用、后续对话历史或反馈正文；公开字段只允许阶段、阶段状态、固定文案、序号与时间。
- `answer.delta` 仍只发送完整且引用 ID 有效的内容；最终回答、引用闭包、版本与证据校验保持现状。
- 验收必须调用真实员工接口和实际 Agent/Java/模型/向量服务，记录首进展与首正文两个不同耗时，检查返回内容和日志；测试类不能代替真实验收。
- 当前隔离工作区为 `C:\Users\Administrator\.codex\worktrees\customer-service-evaluation\efficiency-platform`；主目录现有本地配置改动与未跟踪计划属于用户，实施期间不得覆盖。
