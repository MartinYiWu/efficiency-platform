# 问答Token硬预算与费用结算 Implementation Plan

> 用户明确要求制定详细计划并实施；按本计划在当前会话执行，独立账本与CLI任务并行，接口与集成顺序执行。

**Goal:** 为整批及一次问答提供累计输入/输出/推理token硬限制，并按冻结价格版本结算实际usage，未知用量保持保守占额。

**Architecture:** 保留core契约→SQLite事实→HTTP守卫→CLI的现有职责，所有预留/结算原子化。推理计数为输出子集，不双计。没有明确新预算和价格时禁止付费。

**Tech Stack:** Python3.13、SQLite、httpx、现有pytest/unittest/mypy/Ruff；无需新增依赖或共享DDL。

## Global Constraints

- 保持项目服务停止，禁止外部付费调用、真实预算授权、模型/知识索引切换。
- 保护此前未提交功能/格式化、application.yml与原未跟踪计划；不删除旧授权、账本或业务数据。
- 新旧授权兼容必须失败关闭，不能以默认大值代替缺失token上限。
- 证据写入忽略目录`.local-acceptance/token-accounting-20261103/`，不落prompt/key/业务正文。
- 金额整数CNY微元，费率按每百万token，统一向上取整；reasoning不重复计费。

## 文件职责与接口

- `efficiency-platform-agent/src/efficiency_platform_agent/core/paid_budget.py`：新增6个总/单题token上限、价格版本/费率/输入上限、PaidUsage、settle协议及成本整数计算。
- `.../persistence/paid_budget.py`：增量字段、原子预留/结算、异常熔断、批次/单题/调用明细只读接口。
- `.../providers/paid_usage.py`：有界usage解析和输入保守上界；不依赖API/持久化。
- `.../providers/paid_http.py`：传输前token预留、响应正常完成后结算、异常/取消保守finish。
- `scripts/acceptance/paid-budget/{manage.py,budget-plan.example.json,README.md}`：完整计划校验、只读details、全0模板、计费及恢复说明。
- 现有paid相关测试及新增token/usage结算测试：真实上游零调用。
