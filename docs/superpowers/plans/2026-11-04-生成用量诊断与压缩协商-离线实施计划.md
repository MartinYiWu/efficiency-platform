# 生成用量诊断与压缩协商离线实施计划

状态：本轮离线实施完成，真实生成用量结算仍待有效授权后验证。负责人：本轮执行代理。更新时间：2026-11-04。适用范围：Agent 付费 HTTP Provider；承接 2026-11-03 真实首题后续离线定位。

## 目标与设计

昨天公司知识题业务成功，但 14 次 Flash 用量未知。历史没有保留响应正文或采集器状态，不能从现有证据证明唯一根因。继续用户已批准的离线修复方向，不通过追加真实调用获取调试样本。

当前生成 Provider 使用 HTTPX 自有 SSE 解析并读取到 EOF，已有离线测试能结算完整合成响应；暂不修改其流生命周期。已复现 HTTPX 默认发送 `Accept-Encoding: gzip, deflate, zstd`，采集器却仅支持 identity/gzip/deflate。统一守卫应只协商自身可证明用量的编码。缺少推理用量、重复冲突、损坏响应等继续保留 unknown，不猜测为零。

在采集器增加固定枚举原因及布尔状态，在 HTTP 响应关闭后记录一次脱敏诊断，关联预留 ID；不记录请求、回答、Prompt、凭据、任意响应字段或任意头值。日志区分采集失败、未完整读取及关闭异常，不改变账本结算条件。

## 约束

- 本轮零付费外部调用；两个历史授权保持停止，固定 SQLite 总账只读核对。
- 不清零、不退款、不追溯结算历史 unknown，不续期或自动新授权。
- 不改 Java、前端、数据库 Schema、业务 Prompt 和模型策略，不重启用户 Java。
- 项目不是 Git 仓库；用实施前文件快照与文件级差异审查，禁止 Git 操作。
- 预算始终是上限；额度边界、失败与取消只通过临时 Fake 账本和 MockTransport 验证。
