## 目标与执行原则

完成相似片段安全去重、相邻父片段组装、旧版本隔离、相关度排序、可追溯原文节选、完整条款保护、Rerank 和分阶段 TopK 八项能力。复用现有父子切片、向量/全文召回、RRF、Rerank、Prompt 管理及发布流程；不引入第二套运行框架或检索服务。每个任务按“失败测试 → 最小实现 → 定向验证 → 文件级复核”执行。单元测试只验证契约，最终必须通过真实 Java→Agent 接口、真实数据及双端日志验收。

计划中的新增 SQL **只生成文件**；执行开发库 DDL、重建索引和发布切换前，先展示预检结果与影响，再单独取得明确授权。当前工作区的 `ai-efficiency-platform/aiep-boot/src/main/resources/application.yml` 已有他人改动，始终不修改、不暂存。Agent 和前端子目录不是独立 Git 仓库，不在子目录初始化 Git；若需要版本操作，只针对父仓库及本次文件白名单。

## 任务 3：检索排序、旧版隔离与安全相似去重

**文件**

- 修改：`efficiency-platform-agent/src/efficiency_platform_agent/agents/customer_service/{retrieval,vector_repository,model_gateway,state,graph}.py`。
- 新增：`efficiency-platform-agent/src/efficiency_platform_agent/agents/customer_service/equivalence.py`（仅承载同版本候选对选择、模型输出校验与分组）。
- 测试：`tests/unit/agents/customer_service/{test_parent_retrieval.py,test_equivalence.py}`；必要时扩展 API 查询契约测试。

**步骤**

1. 先写失败测试：激活 Release 的 `index_release_id` 之外候选不能进入 RRF；同一文档在绑定索引内出现两个版本应报发布契约错误；Rerank 失败不可伪装成功；相似但数字、否定、对象、时间或例外不同不得合并；跨版本/跨路径/跨文档不比较。
2. 沿用现有向量 TopK、全文 TopK、融合 TopK 与 Rerank TopK 顺序，并在 Rerank 后从已索引子向量中筛同版同路径候选对；按相似度取前 `similarity_pair_limit` 对。不为两两比较重复调用 Embedding。
3. 调用 `equivalence` Prompt；仅当候选 ID 对应输入、两处摘录逐字命中各自父原文、结论为 `EQUIVALENT` 且不同限制条件为空时合并。失败或 `UNCERTAIN` 时两项均保留并记录真实降级码；不删除索引数据。
4. 测试核对原始、RRF、Rerank 分数及名次都可进入调试事实；语义等价不覆盖原始候选事实。

**完成条件**：排序和筛选链路可追溯，模型不能仅凭相似度或无效摘录删证据。

## 任务 4：相邻组、最终 TopK 与跨文档冲突

**文件**

- 修改：`efficiency-platform-agent/src/efficiency_platform_agent/agents/customer_service/{evidence_assembly,vector_repository,state,graph,model_gateway,sufficiency}.py`。
- 新增：`efficiency-platform-agent/src/efficiency_platform_agent/agents/customer_service/conflict_screen.py`。
- 测试：`tests/unit/agents/customer_service/{test_evidence_assembly.py,test_conflict_screen.py,test_answer_modes.py}`。

**步骤**

1. 先写失败测试：只有同文档版本、连续 `parent_no`、同标题路径、双方 Rerank 命中且均为叙述段落或同表连续行，才能构成 `EvidenceGroup`；组上限生效；跨条款/标题/代码/版本不能拼接；组成员各占一个 `final_evidence_top_k` 名额。
2. 父片段批量展开、同父去重后形成有序组，组仅保留成员 ID/顺序，不新建合成父 ID。预算不足时完整父片段整体排除并记 `BUDGET_EXCLUDED`。
3. 对最终待装配集合里与问题相关的跨文档证据对运行 `conflict_screen`；逐对验证 ID、版本、索引成员及双方精确摘录。`CONFLICT`、关键 `UNCERTAIN` 或契约错误均阻断确定性公司事实回答；不得因分数或预算静默丢掉冲突另一侧。
4. 测试 `effective_date`、知识库 `priority` 不被当作跨文档制度效力排序。

**完成条件**：相邻合并是展示组而非新引用；冲突处理保留双方并可让回答转为证据不足。

2. 预算统一计入系统/用户 Prompt、问题、必要历史、输出预留、安全余量；不可只估算父文本。仅 `EXTRACTIVE_NARRATIVE` 的 `PARAGRAPH` 在完整父片段放不下时，按原序生成带偏移的完整句段，模型仅选择句段 ID；段本身无法完整送抽取模型则整段排除。
3. 代码逐段校验父原文、偏移、哈希与预算，按原顺序组合原文，不使用模型摘要。冻结不可变 `EvidencePack`：父/文档/版本/索引 ID、名次、原文哈希、`FULL_PARENT|EXTRACTED_SPANS`、实际入模文本、偏移、命中子 ID。充分性、冲突、回答、引用与回放共用同一快照。
4. Citation 增加引用类型与偏移。全文引用必须等于父原文；节选引用每段必须逐字命中原文对应区间并显示“原文节选”。校验失败停止公司事实回答，不生成貌似有效引用。

**完成条件**：无原文截断、无模型改写证据、无节选冒充全文；历史 Run 按当时冻结证据读取。

## 任务 7：真实迁移、索引切换与真实接口验收（独立授权闸门）

**步骤**

1. 固定真实、经人工标注的问题集，覆盖四种知识类型、条件不同的近似条款、相邻段落、新旧版本、跨文档冲突、长叙述、超长完整条款、无答案和中文关键词；每题先标注允许版本/父证据/关键条件/预期回答模式。无真实冲突或跨页 PDF 则明确标“未完成真实验收”，不得造样本。
2. 只读预检 `jjcy_ai_vector` 和 Java MySQL 的当前表结构、行数、索引与备份条件；展示具体 DDL/影响并取得本次新迁移的明确授权，再执行迁移及验证。失败时停止发布并按经确认的回滚 SQL 处理。新文档版本重建索引；验证当前索引版本唯一性；创建并激活新 Agent Release，不直接改旧快照。
3. 通过 Java→Agent 真实接口分别跑旧基线与新策略；保存实际 HTTP 状态、关键响应、运行 ID、Java/Agent 日志时间窗及错误分析。逐条核对 Recall@K、Rerank 后父证据覆盖率、错误合并率、节选原文一致率、引用支持率、冲突误答率、延迟和模型调用量；制度/流程由人工检查原文。
4. 发布阻断：旧版本进入新运行、条件不同被等价合并、受保护条款截断/压缩、节选与原文不一致、无证据公司事实回答、已确认冲突仍作确定结论，任一出现都修复并重测。正确父片段召回不得低于固定基线；延迟/调用量回归必须解释。中文全文零候选另列诊断，不把分词器改造暗含进本计划。

**完成条件**：验收报告只记真实调用与日志证据，失败项和未验证项如实保留；未经证据支持不得声称全量通过。

## 顺序和停点

执行顺序为 1 → 2 → 3 → 4 → 5 → 6 → 7。任务 1/2 可先用本地测试与未发布快照验证，但任务 7 的共享库 DDL、索引切换、Release 激活必须过独立授权闸门。每任务先审查文件白名单和现有改动；发现基线失败、契约不明或用户改动冲突时记录证据并暂停相关部分，不擅自扩大范围。最终交付逐项报告“已实现、已测试、已真实验证、未验证”，并核对本计划八项能力与设计文档无遗漏。
