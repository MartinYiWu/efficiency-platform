# 前端 Vue 整体重构实施计划

> 执行状态：用户已于 2026-11-03 明确批准全量实施，要求保留现有功能。按 executing-plans / subagent-driven-development 按模块实施与复核。

**目标：** 将当前整个 React 前端迁移为 Vue，复刻旧项目布局与视觉，保持当前业务、URL 和接口兼容。

**架构：** 提取旧版 Vue 应用壳与展示组件，在独立迁移工程中接入当前实体、API、SSE 和业务行为；逐模块迁移后切换正式前端入口。保留当前业务目录边界，不采用双框架混跑。

**技术：** Vue 3.5、TypeScript、Vue Router 4、Pinia 3、Ant Design Vue 4、Vite、pnpm、旧版样式与必要的 Tailwind 4、Zod、Vitest、Vue 组件测试、Playwright。

## 全局约束

- 设计依据：`docs/superpowers/specs/2026-11-03-前端整体布局与风格改版-设计.md`。
- 旧工程 `D:\work-place\jjcy-ai-platform\ai-platform-web` 只读；不修改其文件，不复制其环境凭证、node_modules、dist、历史业务和 npm 锁文件。
- 迁移阶段原前端目录为 `ai-efficiency-platform-ui`，候选目录为 `ai-efficiency-platform-ui-vue`。下文“原/新”为实施阶段称呼；现已完成切换，Vue位于正式 `ai-efficiency-platform-ui`，React位于回退副本。
- 保留已有未提交改动，不重置、不自动提交；遵守文件白名单与覆盖、移动、删除的安全规则。
- 用户要求的 Vue 技术栈替代现有 React 技术约束，其余数据、安全和离线门禁要求继续生效。
- 采用分工执行：知识、AI 管理、人事分别迁移并自查，主代理负责公共基础、客服/运营与集成门禁；共享目录写入按责任隔离。

- 单个阶段先做定向测试与视觉核验；修复后最终全量门禁一次，失败则仅围绕失败修复和复验。

## 难点、应对与进度判断

| 难点 | 依据 | 应对 |
| --- | --- | --- |
| 框架与生命周期变化 | useCustomerServiceChat/useOperationChat 依赖 Hooks、引用与卸载清理 | 保留协议和纯逻辑，composable 行为测试覆盖竞争、切换与取消 |
| 同名业务接口不兼容 | 旧 `/v1/ai/*`、数值响应码，对比当前 `/api/*`、SUCCESS 与 Zod | 当前 API 为唯一业务契约，旧页只复用展示部分 |
| 视觉复刻牵连历史样式 | 旧版同时存在 design-system、v1-*、Tailwind | 逐组件追踪实际样式依赖，以当前活跃路由为准做截图对照 |
| 旧版页面并不一一对应 | 当前岗位向导/知识版本/专业运营交付与旧版模型不同 | 建立完整映射，保留当前功能，复刻同类页面的视觉结构 |
| 测试迁移和类型覆盖 | 当前 55 个测试文件，旧版 tsconfig 排除了若干页面 | Vue 行为测试逐项替代，新工程不继承旧排除规则 |
| 工作区持续变化 | 当前已有大量未提交业务与安全改动 | 独立迁移目录、差异清单、切换前核对，不覆盖当前最新成果 |
