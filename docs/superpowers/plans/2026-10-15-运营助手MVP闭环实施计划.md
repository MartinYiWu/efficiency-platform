# 运营助手 MVP 闭环实施计划

> **执行要求：** 按任务顺序逐项实施。任何“完成”结论必须来自真实 Java HTTP 接口调用、真实 Agent/模型/数据源执行结果和 Java/Agent 日志检查；编译、静态检查、测试类只能作为辅助证据，不能代替端到端验收。

**目标：** 交付一个不含登录和自动发布能力的运营助手 MVP：用户在前端提出热点研究请求，系统识别意图、采集真实来源、返回排序后的热点；用户可继续要求生成微信公众号或小红书成稿，系统返回排版后的 Markdown、微信公众号 HTML 预览和下载文件。

**架构：** 浏览器只访问 Java。`aiep-biz-aihub` 持有会话、消息、运行任务和文章制品的业务真相；`aiep-platform-ai` 以类型化客户端调用 Agent 的会话、SSE 和取消接口；Agent 负责意图识别、研究、证据闭包、排序和成稿，并把运行状态/事件写入 `ai_efficiency_platform_agent`。向量文档继续存入 PostgreSQL + pgvector。开发期身份由 Java 固定注入 `userId=1`、`tenantId=dev`。

**技术栈：** Java 21、Spring Boot 3.2、MyBatis-Plus、MySQL、Redis、React 19、TypeScript、Vite、Python 3.13、FastAPI、LangGraph、SQLAlchemy async、MySQL async driver、PostgreSQL + pgvector、SSE。

---

## 全局完成门槛

以下条件必须同时满足：

1. 前端不再直接调用 Agent，所有业务请求均进入 Java `/api/operations/**`。
2. Java MySQL 中能查到本次真实验收产生的会话、用户消息、助手消息、运行任务和文章制品。
3. Agent MySQL 数据库 `ai_efficiency_platform_agent` 中能查到同一 `runId` 的运行记录和事件序列。
4. 热点结果来自实际启用的数据源，排序条目必须包含标题、摘要、时间、来源 URL；不得用 fixture、硬编码或伪造数据冒充。
5. 公众号成稿和小红书成稿都由上一步真实热点生成；普通回复只展示用户需要的结果，研究任务、引用闭包和内部版本保存在后台，不主动铺陈给用户。
6. 公众号文章能取得 Markdown 原文、可下载 `.md` 文件以及经过清洗的 HTML 预览；小红书文章具备标题、正文段落、话题标签和清晰换行。
7. 取消接口会使运行进入终态，并停止继续追加正常内容事件。
8. 验收期间同时捕获 Java 与 Agent 日志；出现 `ERROR`、`Traceback`、未处理异常或数据库错误时必须定位、修复并重新执行受影响场景。
9. 最终报告逐条列出真实请求、HTTP 状态、业务状态、关键返回语义、数据库证据和日志结论；不能把未执行、失败或结果不满足产品要求的调用写成成功。
