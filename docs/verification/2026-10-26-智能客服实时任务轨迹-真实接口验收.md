## 页面与受控故障补验

使用独立的本地 Chromium 实例访问员工页面，页面请求仍由运行中的真实 Java 和 Agent 处理，没有替换接口返回。实际提交“公司内部研发使用 AI 时，哪些资料不能发给公有模型？请给出依据。”时，助手气泡先展示 `正在理解问题`；完成后，刷新页面可看到用户提问在前、带引用的助手回答在后，处理过程默认收起且可展开，浏览器无页面异常。补验中发现同一轮用户和助手消息使用完全相同的创建时间，Java 的倒序查询在时间相等时返回顺序不稳定，前端原先直接倒序显示导致回答可能出现在提问上方。已改为按创建时间正序、同一时间用户消息优先排序，并用真实页面刷新复验两种数据库返回顺序。

另启动隔离验收服务 Agent `127.0.0.1:8091`、Java `127.0.0.1:8081`，只将该隔离 Agent 的模型端点临时设为本机不可连接地址，以制造**受控连接故障**；正常 `8090/8080` 服务及真实开发配置未改动。通过真实 Java API 提交 Run `0754b089-e40c-44a6-916a-e7ea3356be01`：0.344 s 收到 `run.progress` 和 `intent/STARTED`，4.375 s 收到 `run.failed`；时间线状态 `FAILED`，只保留 `intent/STARTED`，助手消息 `FAILED`，正文长度 0、引用 0。Agent 日志实际记录两次模型连接尝试、`PROVIDER_CONNECTION` 和 `customer_service_run_failed`；Java 日志记录序号 1、2、3 及失败终态。刷新员工页面后，提问位于失败气泡之前，气泡明确显示“本次回答未完成，请重试”，展开后只有实际发生的意图开始步骤，没有伪造完成。此故障是人为控制的不可连接端点，**不是外部模型服务真实宕机**。
