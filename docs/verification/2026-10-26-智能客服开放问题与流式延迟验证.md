## 问题来源与调用方式

开发环境的会话记录中没有可追溯的生产用户提问样本。本轮先基于《研发内部AI使用规范》《研发团队标准规范文档》《阿里多Agent》编写六个**未导入固定评测集**的自然问题，使用普通用户接口真实创建会话、提交问题、接收 SSE、读取运行回放与引用。它们是开放问法和真实网络调用，不能称为历史生产用户原话。

调用链为 `POST /api/customer-service/conversations` → `POST /api/customer-service/conversations/{id}/messages` → `GET /api/customer-service/runs/{id}/events` → `GET /api/aihub/runs/{id}/replay`。计时从提交消息开始，分别记录首个 SSE 事件、首个 `message.delta` 和终态。

## 发现、修复与回归

1. 原实现先等完整 Graph 和结构化模型返回，再把已完成的 Markdown 切成 SSE，导致首个正文片段长期延后。现改为模型返回完整且引用 ID 有效的段落后立即发送；最后仍校验完整答案、引用闭包与 SSE/回放前缀一致性。若后续模型输出失败，运行明确标为失败，已发送的部分内容可能留在失败消息中。
2. 查询改写后的向量与全文检索、不同证据对的冲突核验、可选等价核验原先有串行等待。改为有上限的并发；冲突核验最多 8 路，失败证据对最多重试一次，重试后仍无效继续拒答。
3. 实测发现模型会稳定将某对父证据的 `right_parent_id` 抄成 33 字符、仅 3 个连字符的无效 UUID，造成相关问题误拒。现在证据对身份由检索程序绑定，模型只给出冲突判断和两侧摘录；摘录仍必须逐字来自对应父原文，身份、索引成员、版本与引用闭包校验保持失败关闭。
4. 回答表述阶段启用模型官方支持的非思考模式以缩短正文等待；冲突和证据充分性判断保留默认思考。曾试将充分性判断降为低思考强度，完整评测实际降到 15/18，故撤回；随后还识别并修复了无效 UUID 误拒，不将中间失败运行写成成功。
5. Agent 日志增加意图、检索、证据包、充分性、回答阶段累计耗时，以及带运行 ID 的首段与完成耗时；结构校验错误只记录字段位置、错误类型与长度，不记录模型原文。最终六次普通问答及完整评测对应的 Agent 日志未发现 `run_failed`、`ERROR`、`Traceback` 或模型请求失败。

## 固定集真实接口回归

沿用原已发布的 18 题数据集及同一 Agent、RAG、知识索引发布版本，通过 `POST /api/aihub/rag-evaluations/runs` 发起，逐条从 `GET /api/aihub/rag-evaluations/runs/{id}` 读取实际回答、引用、质量指标和运行状态。最终运行 ID：`f9b244dd-0a55-4dd2-a23e-6d393bfd457d`。

- 运行 `SUCCEEDED`，18/18 题质量通过，0 条执行错误；回答模式、期望事实、来源、引用和版本指标均为 1.0，禁用事实命中率为 0.0。
- 本次 P50 为 12376 ms、P95 为 21849 ms；此前 18/18 运行分别为 11539 ms、52615 ms。P50 略增，P95 明显下降；两次运行的模型响应存在自然波动，不能把差额全部归因于代码改动。
- 逐条查看了 18 个实际回答及引用文档版本，包括 OpenClaw 配置、Cursor MAX 禁用、PR 要求、hotfix 合并方向、单元测试 80%/60% 和 OpenAPI 同步要求；内容与三份源文档的相应条款一致。

剩余问题：跨文档问答的首段实测仍为 19.188 s，其中 Agent 日志显示检索完成约 12.0 s、证据充分性判断完成约 17.8 s。SSE 连接很快，不等于正文首段很快。若要进一步压缩这类问题，需要在不削弱跨文档冲突校验的前提下减少运行时成对模型调用；本轮不以跳过校验来换取表面速度。
