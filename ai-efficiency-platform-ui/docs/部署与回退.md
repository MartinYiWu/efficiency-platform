# Vue 前端部署与回退

本项目输出静态 Vue SPA。生产构建不包含 Node 服务、后端密钥或测试 fixture。部署前需确认后端地址、上传大小限制及现有域名/TLS配置。

## 生成构建

```powershell
pnpm install --frozen-lockfile
pnpm format
pnpm lint
pnpm typecheck
pnpm test:coverage
pnpm build
pnpm test:e2e --workers=2
pnpm test:e2e:release
```

生产推荐使用同源 `/api`。运营浏览器请求可读取 `VITE_API_BASE_URL`，它是构建时配置，发布前必须核对；客服/知识/管理使用同源 `/api`。开发代理 `VITE_API_PROXY_TARGET` 不会进入 dist，也不能替代生产代理配置。

## 本机生产预览

```powershell
$env:RELEASE_PORT = '5193'
# 留空时 /api 明确返回503，不默认指向真实服务。
$env:RELEASE_API_TARGET = ''
pnpm preview:release
```

上面的 pnpm 命令在源码工程运行。若使用已解包的交付包，不需要安装依赖，也没有 package.json；在包根目录直接运行 `node scripts/serve-dist.mjs`，环境变量用法相同。浏览器实际使用包内的 dist。

`scripts/serve-dist.mjs` 只监听127.0.0.1，用于验证实际 dist。`RELEASE_DIST_DIR` 可指定解包后的 dist 绝对路径，`RELEASE_ASSETS_DIR` 可指定跨版本共享 assets 绝对目录（目录内直接存放hash资源）；配置 `RELEASE_API_TARGET` 时必须是无凭据的 HTTP(S) origin，如 `http://127.0.0.1:8080`，不带路径/查询。仅在操作人确认目标和预算边界后连接真实业务。

`pnpm test:e2e:release` 使用5193/5194/5198，启动独立测试后端，只验证探针，不调用真实生成。该套件与默认 browser fixture 套件隔离。

## Nginx 托管

参考 `deploy/nginx.conf`。将 root 指向解包后的版本目录中的 dist，`/api` upstream 指向 Java 服务；保留 `/api` 前缀和查询参数，不加会删除前缀的 proxy_pass 尾斜杠。SSE 路径关闭 buffering/cache，保持 HTTP/1.1；下载响应由后端透传。

- `/index.html` 与SPA fallback使用 no-cache，带内容指纹的 assets 使用 immutable。
- 缺失 `.js/.css` 等资源必须返回404，不回退HTML；业务深链接回退index.html。
- `/assets/` 从 `/srv/efficiency-platform/shared/assets` 服务。发布前将候选dist/assets追加复制到该目录，保留所有仍被允许回退版本的hash文件。仅保留前版版本目录但不保留其可访问assets不足以避免旧页面懒加载404。不得在发布时清空共享assets。
- `client_max_body_size 50m` 是模板值，发布时与Java multipart上限核实一致；不要用Nginx默认1MB限制截断文档上传。
- 在目标环境执行 `nginx -t`，再按现有流程 reload；保留已有TLS、日志和域名配置。本轮未执行任何服务器写入或reload。
- 当前本机无可运行Nginx/Docker服务，Node预览代理通过不等于该Nginx配置已在目标环境实测。

## 版本包与发布步骤

本轮本机交付包及SHA256清单见仓库根 `docs/verification/2026-11-03-ui-delivery/`。包内只含dist、部署模板、预览脚本和说明，不含.env、node_modules、测试数据或凭据。Git HEAD旁必须注明工作区有未提交改动，不能只凭HEAD复现当前构建；以发布清单和包哈希识别版本。

1. 在新的版本目录解包，按manifest核对每个文件SHA256与包SHA256。
2. 将API地址/上传限制/TLS等配置与目标环境确认，不在包内保存凭据。
3. 启动候选静态站，验证根页面、动态详情深链接刷新、缺失assets 404及API响应类型。
4. 验证上传、SSE、取消和下载；真实模型调用必须有项目守卫认可的独立预算。
5. 先将候选 `dist/assets` 追加复制到共享 `shared/assets`，逐个按清单校验；保留前版资源，不删除或覆盖同名但校验和不同的文件。然后保留前一版本，切换current指向候选目录并reload。回退时共享资源目录不变，确保已打开页面仍能获取旧hash资源。
6. 观察通过后记录发布人、版本标识与清单；此步骤尚未在真实服务器执行。

## 回退

将current切回保留的前一完整版本，检查配置后reload，验证根页面/深链接和index响应哈希。不回滚共享数据库、不重新授权预算、不清空付费账本。

本轮会在隔离本机目录演练“前版→候选→前版”，不会移动当前正式源码或删除React副本。React源码回退副本位于 `.local-acceptance/react-ui-before-vue-20261103`，与静态发布回退用途不同，不能用一次旧React构建冒充所有最新功能均可回退。

真实Java/Agent未启动、模型预算未授权或Nginx未实测时，交付记录必须保留这些未验收项。

本机配置示例：先创建共享目录并追加复制各保留版本的dist/assets，再设置 `$env:RELEASE_ASSETS_DIR` 指向该目录。版本包manifest只描述该版本文件；共享目录可以包含其他保留版本的文件，这些附加文件不可算作本版构建产物。
