# AI 效能平台前端架构设计

## 1. 目标与边界

本项目是一个面向现代浏览器的 React 单页应用（SPA）。它只负责前端呈现、浏览器交互、会话内状态与后端 HTTP 接口调用；不承担服务端渲染、后端业务规则、工作流编排或多应用运行时集成。

项目保持单仓库、单构建产物、单路由树和单套设计令牌。模块以路由和目录边界隔离，不采用微前端。

## 2. 技术基线

| 领域       | 选型                                           | 约束                                        |
| ---------- | ---------------------------------------------- | ------------------------------------------- |
| 运行时     | Node.js 20.18+、pnpm 10+                       | 以 `packageManager` 锁定 pnpm               |
| 框架       | React 19、TypeScript 严格模式                  | 不允许 JavaScript 源文件                    |
| 构建       | Vite 6、`@vitejs/plugin-react-swc`             | 输出静态 SPA 资源；当前 Node 20.18 环境兼容 |
| 路由       | React Router                                   | 路由配置集中在 `src/app/router`             |
| 基础组件   | Ant Design、`@ant-design/icons`                | 唯一通用 UI 与图标来源                      |
| 样式       | Ant Design Token、CSS Modules、CSS 自定义属性  | 不引入 Tailwind 或第二套 UI 样式体系        |
| 服务端状态 | TanStack Query                                 | 远端数据不可写入 Zustand                    |
| 客户端状态 | Zustand                                        | 仅会话、主题、导航折叠等浏览器状态          |
| HTTP       | Axios                                          | 仅 `src/shared/api` 创建与配置实例          |
| 表单/校验  | Ant Design Form、Zod                           | Zod 用于运行时数据边界校验                  |
| 图表       | Apache ECharts                                 | 仅通过 `shared/ui/Chart` 访问               |
| 测试       | Vitest、React Testing Library、MSW、Playwright | 单元、组件、接口模拟与端到端职责分离        |

## 3. 目录和依赖方向

```text
src/
  app/          # 启动、Provider、全局路由、全局样式
  pages/        # 路由页面组合
  widgets/      # 可在多个页面复用的业务区块
  features/     # 用户可触发的独立业务动作
  entities/     # 稳定业务实体与其展示、类型、查询定义
  shared/       # 不依赖业务的 API、UI、工具、类型、样式和配置
```

只允许 `pages → widgets → features → entities → shared` 的单向引用；同层目录之间不得用相对路径跨目录访问，必须通过各层对外 `index.ts` 导出。`app` 仅装配 Provider 和路由，不承载业务逻辑。

当前最小可运行路径以人事助手为主线：`app`、`pages/hr-assistant`、`widgets/hrAssistantShell`、`shared/config`、`shared/lib`、`shared/ui` 和测试目录。平台只保留一套应用壳与导航，避免按页面拆出互相独立的侧栏。

## 4. 应用装配和路由

`main.tsx` 只创建 React 根节点并渲染 `App`。`App` 从 `app/providers` 组合以下能力：

1. `QueryClientProvider`：统一查询重试、缓存时长与错误日志策略。
2. `ConfigProvider`：挂载 Ant Design 主题令牌与中文本地化。
3. `BrowserRouter`：承载路由和浏览器历史。
4. `AppErrorBoundary`：仅兜底渲染期异常，不吞掉接口异常。

根路径 `/` 重定向到 `/ai-assistants/hr/workbench`；人事助手的工作台、岗位管理、简历中心、匹配结果、面试准备、人才库与配置中心共用 `HrAssistantShell`。未来路由按领域在 `app/router/routes` 下拆分，并通过 `React.lazy` 进行页面级懒加载。鉴权、权限和菜单显示由未来独立的路由守卫和会话模块负责，不能散落到页面按钮判断中。

## 5. 状态与接口边界

### 5.1 服务端状态

API 请求函数放在实体或功能所属目录的 `api` 中；Query Key、查询和 Mutation Hook 放在其 `model` 中。组件只消费 Hook 返回的已声明状态，不直接调用 Axios。

Query Key 必须以实体名作为第一个元素，例如 `['user', userId]`。Mutation 成功后只失效相关 Query Key；不以页面刷新代替缓存同步。

### 5.2 客户端状态

Zustand Store 仅保存用户偏好、浏览器会话派生数据和临时布局状态。表单字段由 Ant Design Form 管理，列表接口数据由 TanStack Query 管理，URL 可表达的筛选条件由路由查询参数管理。

### 5.3 HTTP 和错误

`shared/api/http.ts` 是唯一 Axios 实例。它负责基础 URL、超时、请求标识、认证头注入、响应解包和统一错误模型；业务接口禁止注册各自的全局拦截器。接口 DTO 必须先经 Zod 解析，再转换成前端展示模型。

## 6. 组件和样式边界

Ant Design 直接提供标准控件。`shared/ui` 只沉淀跨业务且包含平台一致性规则的组合组件：页面容器、异步状态、确认操作弹窗和图表容器。禁止为了统一命名而包裹无额外行为的 Button、Input、Select。

样式先使用 Ant Design Token；页面级布局通过 CSS Modules 实现；只将可全局复用的颜色、间距和层级变量定义在 `app/styles/tokens.css`。不允许在 JSX 写静态样式对象，不允许直接使用未定义的色值、阴影或 z-index。

## 7. 依赖治理

生产依赖白名单：`react`、`react-dom`、`react-router`、`antd`、`@ant-design/icons`、`axios`、`@tanstack/react-query`、`zustand`、`zod`、`dayjs`、`echarts`、`classnames`。

开发依赖白名单：`vite`、`@vitejs/plugin-react-swc`、`typescript`、ESLint 及 React/TypeScript 插件、Prettier、Stylelint、Vitest、jsdom、React Testing Library、MSW、Playwright、Husky、lint-staged、Commitlint。

新增任何运行时依赖都必须说明：现有白名单为何不能解决、包体积影响、许可证、维护状态及移除成本。禁止引入第二 UI 库、第二状态库、Moment、Lodash、jQuery、Create React App、Tailwind、富文本/拖拽/Markdown/聊天组件库（未专项决策前）。

## 8. 质量门禁

本地必须提供 `lint`、`typecheck`、`test`、`test:coverage`、`build`、`test:e2e` 命令。提交前运行格式化校验、ESLint 与类型检查；CI 依次运行依赖安装、lint、typecheck、单元测试、构建与 Playwright 冒烟测试。

新函数必须先有可观察行为的失败测试；测试不验证框架内部实现。错误页、路由兜底、环境变量读取和共享工具是初始化阶段必须覆盖的最小行为。

## 9. 环境、安全与部署

浏览器可见环境变量仅使用 `VITE_` 前缀，机密不得写入前端环境文件。提交 `.env.example`，不提交 `.env.local`。部署采用静态资源服务器，并配置任意前端路由回退到 `index.html`。

令牌和权限不写入 URL、日志或错误提示；接口错误提示使用经统一错误模型清洗后的文案。任何富文本、外链、文件预览和下载能力在引入时单独制定安全策略。

## 10. 初始化验收标准

初始化完成后，项目必须具备：

1. `pnpm dev` 可启动首页；
2. `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 均可执行；
3. 首页、404 路由和环境配置工具有自动化测试；
4. Ant Design 主题和基础页面容器已经通过 Provider 生效；
5. 目录未预建空业务模块，且生产依赖不超出白名单。
