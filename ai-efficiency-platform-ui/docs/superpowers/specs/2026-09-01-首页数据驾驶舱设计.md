# 首页数据驾驶舱设计

## 1. 目标与范围

首页采用“数据驾驶舱”方向：用户进入平台后，先看到本周工作量、待办、AI 协作使用情况和效能趋势，再进入具体业务工作区。页面解决“今天有什么需要关注”的问题，不承担某个业务助手的操作入口。

本次实现范围是前端首页布局、通用页面壳、响应式样式、独立数据状态与浏览器烟测。首页保留进入 AI 助手、知识中心、数据分析和配置中心的导航入口，但不开发这些页面的业务内容。

不在本次范围：后端指标接口、鉴权与权限接口、真实统计口径、数据分析详情页、通知中心和可配置仪表盘。

## 2. 信息结构

```text
AppShell
├─ GlobalHeader
│  ├─ 平台标识
│  ├─ 帮助中心
│  └─ 用户入口（静态展示，未接会话）
├─ SideNavigation
│  ├─ 工作空间：首页概览、AI 助手、知识中心
│  └─ 管理：数据分析、配置中心
└─ DashboardPage (/)
   ├─ Breadcrumb + DashboardHeader
   ├─ TimeRangeControl（仅展示“本周”，暂不改变数据）
   ├─ MetricGrid（4 个指标卡）
   ├─ EfficiencyTrendPanel
   └─ MyTodosPanel
```

页面顶栏高度为 56px；展开侧栏宽度为 240px；主内容区底色为 `#F8FAFC`，内边距 24px，最大内容宽度为 1440px 并居中。页面标题区固定使用“面包屑 → 页面标题 → 辅助说明”的顺序。

## 3. 仪表盘模块

### 3.1 指标概览

首屏第一行展示四张等宽卡片：本周已处理任务、待完成事项、AI 协作次数、累计节省时间。每张卡片包含指标名、主值和同比/环比说明。颜色只用于表达趋势或状态，主值本身不以颜色传递语义。

初版使用 `DashboardOverviewViewModel` 本地演示数据，仅用于验证布局和交互。数据来源替换为后端接口时，展示组件不变，只替换实体层 Query Hook；不得把演示数据留作生产兜底。

### 3.2 工作效能趋势

趋势面板位于左侧，占内容区约 60%。初版显示按日的柱状趋势和“查看分析”入口；图表实现封装在 `shared/ui/Chart`，并按需加载 ECharts。图表加载时显示骨架，数据为空时显示“暂无可展示的趋势数据”，请求失败时只在卡片内提供重试入口。

### 3.3 我的待办

待办面板位于右侧，显示标题、待办事项、截止时间和来源标签。首期只做只读列表与“查看全部”占位入口；不在首页实现勾选完成、编辑或拖拽。没有待办时显示空状态，不使用零条目的空表格。

## 4. 组件边界

| 组件                        | 层级     | 职责                                      |
| --------------------------- | -------- | ----------------------------------------- |
| `AppShell`                  | widgets  | 组合顶栏、侧栏和路由内容区                |
| `GlobalHeader`              | widgets  | 平台标识与全局入口；不加载业务数据        |
| `SideNavigation`            | widgets  | 菜单呈现与当前路由高亮；不控制权限        |
| `DashboardPage`             | pages    | 组合首页模块，不直接调用 Axios            |
| `DashboardHeader`           | widgets  | 面包屑、标题、说明与时间范围展示          |
| `MetricGrid` / `MetricCard` | widgets  | 呈现概览指标与状态                        |
| `EfficiencyTrendPanel`      | widgets  | 管理图表的加载、空、错与正常状态          |
| `MyTodosPanel`              | widgets  | 管理待办的加载、空、错与正常状态          |
| `dashboardOverview`         | entities | 定义 ViewModel、Query Key 和未来 API 转换 |

页面层不直接依赖 ECharts、Axios 或 Ant Design 的全局配置。图表库只可经共享图表容器使用；卡片、布局、标签和空状态优先使用 Ant Design 组件与 Token。

## 5. 数据状态与接口预留

```ts
interface DashboardMetric {
  key: 'completedTasks' | 'pendingTasks' | 'aiCollaborations' | 'timeSaved';
  label: string;
  value: string;
  comparisonText: string;
  trend: 'up' | 'down' | 'neutral';
}

interface DashboardTodo {
  id: string;
  title: string;
  dueText: string;
  sourceLabel: string;
}

interface DashboardOverviewViewModel {
  rangeLabel: string;
  metrics: DashboardMetric[];
  trend: Array<{ dateLabel: string; value: number }>;
  todos: DashboardTodo[];
}
```

未来接口由 `entities/dashboardOverview/api` 定义，Query Hook 位于 `entities/dashboardOverview/model`，Query Key 固定以 `['dashboardOverview', range]` 开头。页面不保存远端数据到 Zustand；日期范围在可交互时写入 URL 查询参数，当前阶段只静态展示“本周”。

## 6. 响应式与可访问性

- `≥1280px`：侧栏展开，指标四列，趋势和待办按 3:2 横向排列。
- `1024–1279px`：侧栏收为 64px 图标栏，指标保持四列，内容区间距降为 20px。
- `768–1023px`：指标两列，趋势与待办上下排列；顶栏保留平台名和账户入口。
- `<768px`：侧栏变为抽屉菜单，指标单列，图表保持横向可读高度，不隐藏待办语义信息。

所有可点击导航项都可通过键盘聚焦；当前菜单使用文字、图标和背景共同标识；趋势颜色满足 WCAG AA 对比度要求；图表应给出等价的趋势摘要文本。

## 7. 视觉规范

- 主色：`#2563EB`；页面背景：`#F8FAFC`；卡片背景：`#FFFFFF`；边框：`#E2E8F0`。
- 标题：24px / 700；模块标题：16px / 600；正文最小为 14px；辅助文本最小为 12px。
- 卡片圆角 8px，边框 1px；阴影仅用于 hover，不产生位移。
- 采用 4px 间距体系；禁止渐变大背景、玻璃拟态、悬浮粒子、无限动画和未定义色值。

## 8. 验收与测试

组件测试覆盖：四项指标的语义渲染、趋势图加载/空/错误状态、待办正常/空/错误状态、当前路由的菜单高亮。

端到端烟测覆盖：访问 `/` 显示“工作概览”与四项指标；窄屏宽度下指标变为两列或一列；未知路由仍显示 404。

构建验收继续执行 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 和 `pnpm test:e2e`。

## 9. 实施顺序

1. 建立 `AppShell` 和首页路由布局，不触碰未开发的业务页面。
2. 以本地 ViewModel 建立指标、趋势和待办组件及其状态测试。
3. 接入响应式样式、图表容器和页面级烟测。
4. 后端接口就绪后，以实体层 Query Hook 替换演示数据并删除演示数据入口。
