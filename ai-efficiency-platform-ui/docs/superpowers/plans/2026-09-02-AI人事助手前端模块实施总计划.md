# AI 人事助手前端模块 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 React 单页应用中，以产品文档和高保真设计稿为唯一验收基线，逐页交付 AI 人事助手的 22 个页面及其设计规定的前端交互。

**Architecture:** 采用 `pages → widgets → features → entities → shared` 的现有单向分层。页面只组合领域组件；浏览器内交互由 `features` 管理；岗位、候选人、匹配、面试题和审计展示模型由 `entities` 管理。当前 Java 服务尚无人事领域接口，首轮仅用显式标识的本地展示模型驱动交互，禁止伪造已完成的接口联调。

**Tech Stack:** React 19、TypeScript 严格模式、React Router 7、Ant Design 6、CSS Modules、TanStack Query、Zod、Vitest、React Testing Library、Playwright。

## 全局强制约束

- 需求权威顺序：用户当轮要求 → `AGENTS.md` → [功能规格](../../../产品文档/02-需求规格/AI人事助手/2026-09-02-AI人事助手-功能规格.md) → [UI 设计规范](../../../产品文档/03-交互与UI规格/AI人事助手/2026-09-02-AI人事助手-UI设计规范.md) → [设计稿说明](../../../产品文档/05-设计稿/AI人事助手/设计稿说明.md) → 既有代码。
- 设计稿、功能规格和 UI 规范未出现的页面、字段、操作、颜色和业务结论一律不新增；冲突时停止实施并报告。
- 每次只实现一个 PAGE 编号。该页的失败测试、最小实现、桌面截图比对、交互验证和回归通过前，不得开始下一页。
- 页面仅使用具名 CSS Module 类控制布局；禁止无作用域 `main`、`header`、`aside`、`section` 选择器和静态 JSX `style`。
- 全部匹配分档固定为：强烈推荐面试 `#16A34A`、推荐面试 `#2563EB`、建议复核 `#F59E0B`、暂不推荐/被过滤 `#94A3B8`；不得以红色表示淘汰。
- 禁止实现自动淘汰、批量拒绝、候选人外发、面试安排、Offer、薪酬、候选人状态机、受保护特征字段或以 AI 代替录用判断。
- 证据必须可定位到简历原文；面试官页面必须不渲染分数、分档、维度分、排序位次、匹配亮点和能力缺口。
- 新增运行时依赖须单独获得用户确认；图标优先使用 `@ant-design/icons`，设计稿缺失的插画/图片才可生成并保存为本地素材。
- 当前目录不是 Git 仓库：不得初始化、提交、推送、重置或删除文件。

## 每页固定验收门禁

1. 读取该 PAGE 的功能规格段落、UI 规范段落、对应 PNG；列出该页允许的字段、按钮、弹窗和状态。
2. 新增一个只观察用户可见行为的失败组件或 E2E 测试，运行并确认因功能不存在而失败。
3. 编写最小实现；运行该页测试并确认通过。
4. 在 1440px 截图与同名设计稿逐项比对导航、标题、栅格、留白、颜色、文案、状态和弹窗。
5. 在 1024px 和 390px 验证连续响应式布局、无横向挤压、无文字遮挡和完整可访问名称。
6. 运行 `pnpm format`、`pnpm lint`、`pnpm typecheck` 和相关 Vitest；该页失败时不得进入下一页。
7. 在本计划中将该 PAGE 标记为完成，并登记实际路由、测试文件、截图路径和未联调项。
