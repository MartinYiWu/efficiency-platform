# 文档规则

> 状态：有效  
> 文档类型：项目强制规则  
> 适用范围：`md/`、`plan/`、`sql/`、`rule/`、`docs/` 与根说明文件  
> 最后更新：2026-09-01

## 1. 目录唯一职责

| 位置 | 唯一职责 | 禁止内容 |
|---|---|---|
| 根 `README.md` | 当前工程事实、构建入口和索引 | 完整规则正文、临时讨论记录 |
| `AGENTS.md` | 执行入口、优先级、工作区与授权底线 | 复制各规则的全部正文 |
| `rule/` | 当前有效且强制的持续规则 | 单次需求设计和计划 |
| `docs/` | 已确认的稳定架构基线和使用说明 | 过程性讨论和失效方案 |
| `md/` | 项目级设计、ADR、跨模块契约与实施结果 | 逐步执行清单 |
| `plan/active/` | 正在执行或待执行的实施计划 | 稳定架构事实 |
| `plan/archive/` | 完成、取消或被替代的计划 | 当前有效计划 |
| `sql/` | 本工程唯一 SQL 资产与其说明 | 密钥、真实生产数据、重复迁移 |

## 2. Markdown 规则

1. 规则、设计、计划和结果文档使用中文标题和正文；必要的类名、模块名、命令、协议字段和 SQL 关键字保留原技术名称。
2. 当前有效 Markdown 必须有唯一一级标题；规则、设计和计划在标题下标注状态、适用范围和最后更新日期。
3. 新设计使用 `YYYY-MM-DD-主题-详细设计.md`；ADR 使用 `ADR-<三位序号>-主题.md`；计划使用 `YYYY-MM-DD-主题-实施计划.md`；结果使用 `YYYY-MM-DD-主题-验证结果.md`。
4. 每个主题只允许一份当前有效主文档。被替代资料移入最近的 `archive/`，并写明原路径、归档日期、原因和替代文档。
5. 新增或归档文档后，必须同步同级 `README.md` 索引；不得保留失效相对链接。

## 3. SQL 规则

1. 正向迁移存放于 `sql/migration/`，文件名为 `V<版本>__<lower_snake_case说明>.sql`，例如 `V1.0.0__create_kb_document.sql`。
2. 回滚脚本存放于 `sql/rollback/`，文件名为 `R__V<版本>__<lower_snake_case说明>.sql`；回滚文件是人工受控资产，不得假设迁移框架自动执行。
3. 只读验证脚本存放于 `sql/verification/`，文件名为 `V<版本>__verify_<lower_snake_case说明>.sql`。
4. 人工脚本存放于 `sql/manual/`，文件名为 `M__<版本>__<lower_snake_case说明>.sql`，文件开头必须写明目标环境、影响范围、前置检查、授权要求、执行步骤与回滚方式。
5. 开发和测试种子数据存放于 `sql/seed/`；禁止放入生产数据、个人信息、密钥或生产连接信息。
6. 已在任何环境执行的版本化迁移不得修改、改名、删除或复用版本号；新迁移前先核验真实迁移历史。
7. 当前未启用 Flyway 自动执行。后续启用时必须仅选择一个权威迁移位置，并配置 `aiep-boot` 将该位置打包进 classpath；禁止同时维护与 `sql/migration/` 内容相同的 `resources/db/migration/` 副本。
