# 工作流规则

> 状态：有效  
> 文档类型：项目强制规则  
> 适用范围：所有设计、开发、评审、数据库和文档任务  
> 最后更新：2026-09-01

## 1. 任务分类与最低流程

| 任务类型 | 最低流程 |
|---|---|
| 咨询、评审 | 只读核验、证据、结论、风险 |
| 新需求 | 范围确认、设计、计划、测试基线、实施、验证、文档同步 |
| Bug 修复 | 复现、根因、回归测试、最小修复、验证 |
| 重构 | 等价基线、分阶段改造、契约核对、验证 |
| SQL 迁移 | DDL 核验、正向/回滚/验证脚本、明确授权、执行证据 |
| 文档治理 | 事实核对、唯一主文档、链接检查、归档关系 |

## 2. 授权边界

1. 用户要求“只读”“先分析”“先讨论”时，不得修改文件、配置、数据库或外部系统。
2. 数据库写入、迁移执行、部署、删除、真实模型调用、第三方配置和不可逆操作，必须获得明确授权。
3. 本地文件与代码修改属于实现授权范围，但必须限制于本次任务文件清单，不得顺带格式化、升级依赖或清理无关内容。

## 3. 风险与验证

1. 低风险文档或注释变更至少检查文件、标题、链接和差异格式。
2. 中风险代码、接口、配置或 SQL 查询变更，必须完成定向编译或测试，并核对调用方和异常路径。
3. 高风险架构、数据库、鉴权、AI、任务状态机和跨模块契约变更，必须先有设计和实施计划，说明影响、回滚与验证证据。
4. 无法验证时必须明确未验证原因和替代证据；不得把“已编写”表述为“已生效”。

## 4. 交付要求

交付结论必须包含：实际修改、验证命令及结果、未验证项、剩余风险。若工程尚未初始化 Git，说明无法执行分支检查、提交和 `git diff --check`，不得虚构 Git 证据。
