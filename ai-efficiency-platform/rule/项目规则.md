# 项目规则

> 状态：有效  
> 文档类型：项目强制规则  
> 适用范围：`ai-efficiency-platform` 全工程  
> 最后更新：2026-09-01  
> 事实来源：根 POM、模块 POM、架构基线与 ArchUnit 测试

## 1. 工程与模块边界

1. 服务名固定为 `ai-efficiency-platform`，根包固定为 `com.aiep`，Maven artifact 统一以 `aiep-` 开头。
2. 本工程是单体多模块应用：13 个 Maven 模块最终由 `aiep-boot` 打包为一个 Jar、运行于一个 Java 进程。禁止将任一模块当作独立 Java 微服务发布。
3. `aiep-platform-*` 属于 L0，只能依赖 `aiep-platform-core`；`aiep-identity` 属于 L1，只能依赖 L0；`aiep-biz-*` 属于 L2，只能依赖 L0、L1，且仅允许 `aiep-biz-aihub` 依赖 `aiep-biz-knowledge`；`aiep-agg-*` 属于 L3，可读取 L0、L1、L2，但不得被低层反向依赖。
4. `aiep-boot` 只负责组装、配置、运行与测试，不承载业务领域逻辑。
5. 跨模块调用只能依赖目标模块的 `api` 包与 `XxxFacade`，禁止依赖目标模块的 Controller、实现类、Domain、Repository、Mapper、PO、Entity 或 Config。

## 2. 技术选型与依赖

1. 基线版本为 Java 21、Spring Boot 3.2.5、MyBatis-Plus 3.5.15、Druid 1.2.21、MySQL Connector/J 8.3.0、Redisson 3.27.0、JJWT 0.12.5、Springdoc 2.3.0。
2. 公共组件版本只允许在根 `pom.xml` 管理；子模块不得覆写已纳入基线的公共版本。
3. 未经 ADR 批准，禁止引入 Spring Cloud、Nacos、OpenFeign、Kafka、XXL-Job、Spring AI、Sa-Token、Fastjson 或 Fastjson2。
4. 新增依赖必须说明使用场景、替代方案、许可证风险、模块归属和测试方式；不得为一次性调用引入大型基础设施。

## 3. 数据所有权

1. Java 拥有身份权限、业务实体、文件元数据、会话与消息持久化、任务业务状态和 AI 调用审计；Python Agent 不得成为这些数据的真相源。
2. 表前缀固定为：`pf_`（平台能力）、`org_`（身份）、`kb_`（知识库）、`as_`（资产）、`ai_`（AI Hub）、`sys_`（系统）。新增表必须归入已有所有者或先完成 ADR。
3. 一个本地事务只能写本模块拥有的表。跨模块写入使用本地状态、事件、补偿或对账闭环，禁止跨模块大事务。
4. 禁止跨模块写表、业务表物理外键和业务表 Join；仅 `org_user`、`org_dept` 可作为展示用途的只读关联。

## 4. 安全与架构底线

1. Java 到 `efficiency-platform-agent` 的调用严格单向；前端不得直接访问 Agent。
2. `aiep-platform-ai` 是唯一 AI 调用边界，其他模块只能使用 `AiInvokeFacade`。
3. 生产密钥、Token、私钥、证书、连接串、完整个人信息和未脱敏请求正文不得进入 Git、日志、响应、测试快照或示例配置。
4. 未经正式 ADR，不得改变模块层级、数据所有权、Agent 调用方向、公共响应契约或 SQL 唯一真相位置。
