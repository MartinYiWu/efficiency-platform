> 状态：有效  
> 适用范围：`ai-efficiency-platform` 整个仓库

本文件是进入本工程后的全局执行入口。工程事实、启动方式和目录入口见根 `README.md`；规则正文只维护在 `rule/`。

## 规则优先级

1. 用户当前明确指令。
2. 本文件 `AGENTS.md`。
3. `rule/项目规则.md`、`rule/开发规则.md`、`rule/工作流规则.md`、`rule/文档规则.md`。
4. 当前有效的设计文档、实施计划与架构基线。
5. 已归档资料和外部参考资料。

低层级资料不得降低高层级约束；事实与文档冲突时，先核对源码、POM、配置、DDL、接口契约和测试，再修正文档或提出变更方案。

## 任务开始前

1. 若仓库已初始化 Git，先检查分支、HEAD 与工作区差异；未初始化 Git 时明确记录该限制。
2. 判断任务是咨询评审、设计、开发、修复、重构、SQL、部署还是文档治理，并声明范围、非范围和风险级别。
3. 阅读涉及模块的 POM、接口、配置、迁移 SQL、测试和当前有效文档。
4. 现有工作区修改默认属于用户或其他工程师，禁止覆盖、回退、清理或混入无关变更。
5. 仓库存在 `.codegraph/` 时，定位和理解代码优先使用 CodeGraph；文档、配置和 SQL 使用 `rg` 与文件读取补充。

## 工程边界

- 服务名固定为 `ai-efficiency-platform`，Java 根包固定为 `com.aiep`，唯一可部署启动模块为 `aiep-boot`。
- 13 个 Maven 模块组成一个 Java 进程，模块不是独立微服务。
- Java 是身份权限、业务数据、任务状态、调用审计和会话持久化的真相源；Python Agent 是独立执行端。
- Java 只可单向调用 `efficiency-platform-agent`；前端不得绕过 Java 直接访问 Agent。
- 代码结构、模块依赖和 Agent 边界以 `docs/architecture/Java端架构与开发约束.md` 为准，并由 `aiep-boot` 中的 ArchUnit 测试守护。

## 目录入口

- `rule/`：持续有效的强制规则。
- `md/`：项目级设计、ADR、跨模块契约说明和实施结果。
- `plan/`：实施计划、执行记录、验证结果与归档。
- `sql/`：本工程唯一的 SQL 治理入口。
- `docs/`：已确认的稳定架构基线和使用说明。

目录职责、命名、状态、归档和 SQL 规则以 `rule/文档规则.md` 为准。
