# V1.2.20 有限候选与CPU确认

新增三张本模块表：批次按tenant/task唯一，来源版本按tenant/source/version唯一且不可删改，候选按原用户/顶层Agent/会话/字段归属。正文AES-GCM密文，元数据仅refs；每批至多16条、候选值含包装的保守UTF8字节界限512，依赖至多512，索引固定NOT_REQUESTED。

默认`aiep.memory.proposals-enabled=false`；需要现已发布`memory-policy/1`同时具备合法fields、artifacts.NOT_PROVISIONED及`proposals:{enabled:true,retentionSeconds:<1..15552000>,sourceTypes:["MESSAGE","CURRENT_USER_MESSAGE","USER_PREFERENCE_DECISION"]}`，只允许此数组的受信子集；实际全部输入源必须均在允许类型中。不自动插入策略、授权、预算或表。

顺序：独立授权环境只读precheck→审阅up/影响→迁移→verify；先隔离库演练，未经确认不触共享库。DDL隐式提交，失败保留现场人工检查；代码运行不会隐式DDL。回滚仅三表完全未使用、无PROPOSAL依赖时允许；任何使用后保留来源机会锚，不用清表/新task或策略版本绕过。

source epoch/retention收紧和FIELD/SOURCE suppression触发器在同事务擦候选密文；终态不复活，PENDING转STALE/SUPPRESSED。来源实际正文更正另由Java读取时重新核验，候选/已确认版本均保原安全依赖。确认复用Preference/Version/Decision权威链，按proposal和item双revision，次日不检查旧预算，不触发索引。当前先提供CPU用户候选持久接口；6201自动提炼的正式接线单独完成，迁移不代表自动生成已启用。

本任务未执行任何SQL或数据库连接；隔离迁移正/逆及并发真实验收仍由root统一门禁。
