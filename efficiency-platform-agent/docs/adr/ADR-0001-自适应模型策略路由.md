## 关联设计

P2 的 Provider 抽象和 P0～P5 的 Harnessed Hybrid Multi-Agent Architecture 继续有效。本 ADR 只替换 LLM 来源、模型路由和故障降级的具体裁决。

## 背景

单一、写死的 LLM 模型会在模型故障、限流或能力不匹配时中断任务，也无法让不同复杂度的 Agent 节点使用合适的推理能力。当前默认 LLM 选择 DeepSeek；未来可能接入其他厂商模型。旧 Java AIHub 配置不作为 Agent 侧 LLM 来源。

## 驱动因素

| 因素 | 重要性 | 证据或约束 |
|---|---|---|
| 连续执行 | 高 | 强模型故障时任务应尽量通过快模型继续，而不是立即终止 |
| 自适应质量与成本 | 高 | Agent 应结合当前任务和中间结果自主申请合适能力，不固定映射模型 |
| 可治理性 | 高 | 预算、时限、能力兼容和尝试次数不得被 Prompt 或单个 Agent 绕过 |
| 可演进性 | 高 | 新模型或未来代理模型池加入时不得修改业务 Agent、Prompt 或 Graph 契约 |
| 可审计性 | 高 | 每次选择、切换、降级和真实 Usage 必须关联 Run/Step/Invocation |

## 候选方案

| 方案 | 安全 | 成本 | 可维护性 | 兼容性 | 运行风险 | 证据 | 结论 |
|---|---|---|---|---|---|---|---|
| 固定任务类型到固定模型 | 预算易控 | 低 | 初期简单 | 差 | 单模型故障直接中断 | 不符合已确认的自主选择要求 | 不采用 |
| Agent 提议能力层级，Harness 自适应选择候选模型 | 受中心约束 | 可按实时预算优化 | 通过逻辑路由隔离模型 ID | 高 | 需实现健康、预算和降级治理 | 符合本 ADR 的批准证据 | 采用 |
| 每一步调用独立 LLM 裁判决定模型 | 需额外防护 | 高 | 复杂 | 中 | 增加调用链、成本和循环风险 | 当前没有必要性和验证证据 | 暂不采用 |

## 最终裁决

采用“**Agent 提议、Harness 约束、运行时自适应**”的模型策略路由。

1. Agent 节点只能产生版本化 `ModelDemand`：所需能力、任务复杂度、上下文规模、推理深度、结构化输出/工具需求、预估资源和当前置信度；不得直接写死厂商、模型 ID 或 Secret。
2. Harness 的 `ModelPolicyRouter` 以 `ModelDemand`、候选池实时健康度、剩余 Token/费用/时限、模型能力和租户策略形成最终 `ModelSelection`。模型能力采用逻辑层级 `fast`、`balanced`、`strong`，实际模型 ID 全部配置化。
3. 当前默认 Provider 为 `deepseek_direct`。旧 Java 的 AIHub 配置不迁移；未来模型池或其他厂商以独立 Provider 加入同一候选注册表，不改变上层契约。
4. 每个逻辑能力可配置有序候选模型。可重试的网络、连接、超时、限流和服务端故障允许重新选择候选；强模型不可用时允许降级到快模型，以尽量完成任务。
5. 降级前仍必须校验目标模型具备该步骤的硬能力；降级、原因、尝试、实际模型、耗时、Token、费用和结果质量状态必须写入受控 Invocation/Usage/Event 契约。不得把降级后的结果伪装为原强模型结果。
6. 取消、认证/授权失败、非法请求、输出契约不兼容、总预算耗尽和最大尝试次数耗尽不得无限切换。所有候选不可用时，保留 Checkpoint 和明确的可恢复失败状态，不伪造成功。

## 正面后果

- 简单步骤可以优先使用快模型，复杂推理可以请求强模型，选择可随任务执行过程调整；
- Provider 或模型短暂不可用时可继续任务，降低单模型故障的中断率；
- 新增模型、替换模型 ID 或引入未来模型池只影响受控配置与 Provider Adapter；
- 模型选择、降级和成本具有可审计依据。

## 负面后果

- 需要维护候选能力、健康状态、预算和降级状态；
- 降级可能降低输出质量，调用方必须能看到受控的降级/告警事实；
- 真实模型能力、价格和健康度只能在后续获批 PoC 中验证，不能在本 ADR 中假定。

## 风险与缓解

| 风险 | 触发条件 | 缓解措施 | 责任人 | 验证/复审条件 |
|---|---|---|---|---|
| Agent 任意切换高成本模型 | Prompt 或节点提出无界需求 | 只接受能力层级；Harness 强制预算、时限和最大尝试数 | Agent 平台负责人 | 单元/契约测试覆盖越权、超预算和循环切换 |
| 快模型不满足步骤硬能力 | 降级候选缺少所需能力或输出契约 | 按能力矩阵校验；不兼容即跳过候选并保留可恢复失败 | Provider 负责人 | 候选能力矩阵与降级契约测试 |
| 降级被用户误认为高质量完成 | 强模型失败后快模型返回结果 | Invocation/Event 记录降级原因与质量状态；上层按稳定契约呈现 | Harness 负责人 | 运行事件和 API 契约测试 |
| 所有候选同时不可用 | 网络、配额或 Provider 故障 | Checkpoint、稳定错误码、有限退避和恢复入口 | Runtime 负责人 | Worker 崩溃/重试/恢复 PoC |

## 复审条件

在首次配置模板和 Provider Adapter 实施前，以及出现以下任一事件时复审：新增第二厂商模型、引入企业模型代理池、候选模型能力/价格变化、连续故障触发熔断、降级质量不可接受，或 PoC 证明 DeepSeek 所需接口不兼容。
