## 1. 背景与驱动因素

用户明确要求意图识别及采集、过滤、整合、输出、补采使用已经实现的开源项目作为技术参考。现有实现存在时间约束中途丢失、仅来源声明、二值研究结果及关键路径静态匹配等限制，详见总览。

只修改 Prompt 无法形成来源执行事实、原文证据和可测试的补采策略。直接迁移整个平台又违反 LangGraph 唯一运行时和现有治理边界。

## 2. 候选方案

| 方案 | 安全与兼容 | 成本 | 可维护性 | 运行风险 | 结论 |
|---|---|---|---|---|---|
| 单 Provider 加强提示 | 网络面不增加，V1 兼容较易 | 低改造成本 | 受 Provider 来源能力限制 | 无独立原文和补采账本 | 保留兼容，不作为目标 |
| 引入完整 Dify/Coze/新闻平台 | 多运行时、权限和存储重复 | 迁移成本高 | 两套生命周期 | 接口及回滚复杂 | 不采用 |
| 成熟库 + 模块适配 + 受控研究子图 | 复用既有边界，新增网络面可限制 | 中等改造成本、可预算 | 各模块有开源参考和契约 | 需来源、证据和持久化验收 | 已采纳；按批准边界分阶段实施 |

## 3. 候选裁决

1. 自然语言采用语义模型解释、字段提取、多轮增量、确定性校验；注册 Schema 和能力是执行边界，不用关键词替代理解。
2. 研究采用已核实免费且可用的注册 API/RSS/静态公开网页；补采通过这些来源的查询、分页或替换来源完成。现有搜索 Provider 不是必选依赖，只有另行满足免费及可用性准入才可选用。新增 feedparser、Trafilatura、dateparser 需单独完成版本与依赖准入，HTTPX 作为直接运行依赖显式声明。
3. LangGraph 仍是唯一 Runtime，沿用中央 Supervisor。Graphon、Rasa、Coze、TrendRadar、Daybreak 仅作为模块/算法参考；不部署第二套平台。
4. 所有网络采集经 Tool Runtime 和 Provider；禁止专家直接出网，禁止绕过 SSRF、超时、结果大小、租户和日志治理。
5. 将 ResearchBrief、Evidence、ResearchOutcome 引入 V2；V1 继续冻结其原语义，不把 V1 `valid` 重定义为原文已核验。
6. 质量报告区分硬约束、覆盖缺口和软排序；模型提出补采动作，运行时校验权限、范围、预算和停止条件。
7. Run 四种终态不变；`COMPLETE / PARTIAL / NO_MATCHES / FAILED` 是研究领域结果，不新增 RunStatus。
8. 复用 PostgreSQL 和现有 Artifact Provider；逻辑数据模型的设计不授权执行任何共享 DDL。

## 4. 保持不变的边界

- 仅使用免费且经可用性验证的信息来源，不接入收费商业新闻、热点、舆情或搜索源；收费规则未知即拒绝。免费额度耗尽时硬停止或切换其他已准入免费来源，不自动计费、购买或升级。已有模型调用仍按既有授权和 Run 预算治理，开源不等于零运行成本。
- 不引入动态浏览器、自建搜索集群、定时全网采集、图数据库、第二向量模型或新监控平台作为首轮依赖。
- 只生成内容，不自动发布文章、发邮件或向第三方推送。
- ContextBuilder 是唯一上下文装配入口；Provider 不依赖业务 Agent；工具及插件仍显式注册。
- 不读取真实 `.env` 值，不新增凭据，不改变 Java 业务与权限事实。

## 5. 风险与补偿措施

| 风险 | 补偿措施 | 责任人 | 生效/复审条件 |
|---|---|---|---|
| 主动抓取带来 SSRF、恶意正文、资源消耗 | DNS/重定向/连接目标验证、正文限额、禁执行网页指令、工具白名单、注入测试 | Agent 端维护负责人 | 任何新来源或重定向策略变更时复审；安全门禁未过不得启用 |
| 许可或服务条款不匹配 | 固定提交、许可文件、NOTICE/归属记录；来源逐项准入；不绕过登录/付费墙 | Agent 端维护负责人，项目负责人批准 | 复制代码、升级依赖、变更发布方式前复审 |
| 模型误判证据充分 | 引用定位、数字/日期一致性检查、未决冲突保留、标注评测 | Agent 端维护负责人 | 门禁回归失败或误报即暂停灰度 |
| 补采无限循环或双重扣费 | 单一预算账本、有限轮次、无增益终止、幂等、取消传播 | Agent 端维护负责人 | 预算越界或重复调用证据出现即关闭补采 |
| V1/V2 回滚混用 | 按 Run 固定版本，V2 不降格解析；迁移和回放测试 | Agent 端维护负责人 | 灰度扩展或 Schema 升级前复审 |

## 6. 生效、替代与恢复

2026-09-16，项目负责人明确要求“根据这3份实施计划以及实施顺序进行逐个阶段的开发”，因此本 ADR 的 Agent 侧分阶段开发和离线依赖安装已获批准。批准不构成共享 DDL、真实来源启用、新增真实模型费用、部署、生产配置切换、Java/UI 修改或自动发布授权。

2026-09-16 已确认的局部要求：项目负责人明确提出“采集信息使用免费的可用的API、RSS和公开的信息来源。”此要求已经纳入来源准入硬约束；不将其扩大解释为本 ADR 全部裁决已获批准。确认范围不包括额外模型费用授权或运行配置切换。

用户此前要求依据完整设计制定实施级计划，形成[总体实施计划](../superpowers/plans/2026-09-16-Agent意图与研究闭环优化-实施计划.md)及其中链接的两部分子计划；此项是此前规划授权的历史事实。新增的逐阶段开发指令使本 ADR 的 Agent 侧实施裁决生效。旧组件/P4 文档保留原批准正文并增加局部替代说明；旧架构的安全和唯一 Runtime 约束持续生效。

新设计生效条件：项目负责人明确批准范围，来源和依赖准入完成，关键回归与安全用例通过。默认预算、保留期限、首批来源按详细设计审议；未获准项保持关闭。

回退时关闭新 Run 的 V2 入口和网络适配器；不删除 V2 证据与审计，不改变进行中 Run 的版本。回退不能重新启用未经免费准入的旧搜索来源；无合规来源时明确不可用。若安全/租户边界不再满足，立即停用相关来源而非扩大例外。

## 7. 预期收益与残余代价

收益以验收衡量：意图参数准确性、有效证据比例、误聚合率、部分交付保留、补采命中缺口和故障可解释性。尚无实测提升百分比。

代价：维护来源连接器、执行账本和证据存储；增加模型校验与网络调用；无法保证全网完整或绝对事实正确。必须持续保留已检索范围和不确定性说明。
