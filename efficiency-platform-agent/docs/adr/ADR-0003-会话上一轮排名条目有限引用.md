# 会话上一轮排名条目有限引用

状态：实现完成，真实 V2 正向验收待接线；负责人：Agent 平台维护者；更新时间：2026-09-17。
范围：纯 Agent Conversation、Scenario、Supervisor 与运营专家输入；关联：ADR-0002、纯 Agent 侧总体架构。

## 决策与安全边界

仅支持同租户、同用户、同 conversation 中上一条已提交 Run 的第 N 条改写。上一条必须已成功终态，且输出能通过严格 V2 Schema 与现有交付质量校验，包含唯一 ranked_digest。按 rank 选择一个条目，按 source_refs 取来源闭包并裁剪 supports_item_ids；禁止解析 V1 正文、传递完整会话历史、向更早 Run 回退或跨身份引用。

会话保留最近提交的 Run 身份指针，读取仍通过 Runtime 租户校验。引用在任何意图或内容模型调用前解析；不存在、未终态、输出无效、非排名摘要、越界均使用稳定请求错误拒绝。并发提交绑定提交时的前驱，晚到终态不得覆盖最近提交指针。该指针沿用会话 TTL，重启或过期后安全拒绝，不声称跨重启记忆能力。

显式类型 ReferencedRankedInput 只携带源 Run/交付物标识、一个 RankedItemV2、引用闭包及身份，由 ConversationService → ScenarioSubmission → ScenarioSupervisorRequest → ScenarioDispatch 传播。专家沿用 input_deliverables/citations 和现有预算、输出校验，不扩展工具权限。来源仍为不可信数据。

## 替代方案与风险

拒绝完整历史注入（数据面与注入面扩大）、V1 文本猜测（排名与来源不可验证）、搜索更早成功 Run（违反上一轮语义）。不引入长期记忆、数据库表或第二运行时。有限识别只消费明确的“改写/改成/写成第 N 条”指代；无平台时稳定提示补充平台。

## 2026-09-17 R2 独立复核补强

独立复核发现，引用解析曾先把 Citation 的 `supports_item_ids` 改写为所选条目，再构造 `ReferencedRankedInput`。这会把“所选条目引用 citation-1，但 citation-1 原始只支持 item-2”的坏闭包洗成合法输入并继续调用内容模型。

裁决补强为：必须先在原始 V2 交付物上完成条目 ID、Citation ID、所选 `source_refs` 的唯一性和存在性校验，并确认每个原始 Citation 的 `supports_item_ids` 包含所选 `item_id`；任何失败继续稳定返回 `CONVERSATION_REFERENCE_UNAVAILABLE`。只有全部校验通过后，才允许深复制所选条目和来源闭包，并把副本的 `supports_item_ids` 裁剪为所选条目。不得通过预先改写输入来满足闭包校验。

本次补强没有改变身份、上一轮、V2-only、平台、工具、存储或 UI 边界。RED/GREEN、相关 API、架构守卫、全量回归与 8080 重启重放证据追加在[进度账本](../implementation-ledger/2026-09-17-会话上一轮排名条目有限引用-进度账本.md)。
