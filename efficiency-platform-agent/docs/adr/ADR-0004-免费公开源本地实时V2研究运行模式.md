# ADR-0004 免费公开源本地实时 V2 研究运行模式

状态：实施方案待独立复核；负责人：Agent 端维护负责人；更新时间：2026-09-17。
适用范围：本机 Agent 会话、免费来源研究及 V2 交付接线。关联：ADR-0002、ADR-0003、[实施计划](../superpowers/plans/2026-09-17-免费公开源本地实时V2研究闭环-实施计划.md)。

## 背景和现状证据

正式入口 `main.py` 调用 `build_local_agent_application()`，默认研究仍是 `FreePublicResearchProvider` 与 V1 交付。现有 V2 工厂以 `production=not test_mode` 校验，缺少真实网络但内存状态的显式模式。`LangGraphResearchServiceV2` 已有子图端口，但正式 StageRunner、materializer 和按 Run 绑定预算的组合根尚待接线。`harness/live_research_v2.py` 是独立验收执行器，固定窗口、fixture 来源标识及跨调用缓存不构成正式运行实现。

ADR-0003 的上一轮排名引用已经具备严格 V2 和来源闭包校验；[其进度账本](../implementation-ledger/2026-09-17-会话上一轮排名条目有限引用-进度账本.md)记录真实 V1 第一轮会导致第二轮安全拒绝。此处记录历史证据，不把旧测试数量、进程 PID 或健康状态当作本次验收。

## 决策

1. 新增独立 `local_live` 运行模式：真实已授权模型、真实已准入免费来源、内存 Run/研究事实/Checkpoint，单进程且只绑定回环地址。另保留 `production` 模式及既有测试入口。`local_live` 不是生产状态，不通过 `test_mode=True` 启用，也不伪称 PostgreSQL 或通过传入 `production=False` 规避就绪门。
2. 运行模式、state_backend、研究和意图版本、租户白名单、来源白名单、策略版本在 Run 首次进入时冻结。`local_live` 必须显式配置非空租户白名单；白名单外的研究请求失败关闭，不自动回退另一研究链。普通对话仍按既有能力执行。
3. production 继续要求真实 PostgreSQL 组件及既有持久化/恢复证据；配置字符串不能充当验证。local_live 明确报告 `production_ready=false`、内存状态与重启丢失，不声称跨进程/重启恢复。
4. 采用同一 LangGraph 研究子图和正式 StageRunner/materializer，复用现有 Provider、VerifiedSourceRegistry、Tool Runtime、内容及质量组件。所有 discover/fetch 经 Tool Runtime；Provider 内部 HTTP 子请求亦逐次计费、限流和取消。不存在第二个研究执行循环。
5. 实际来源使用语义稳定 ID、逐来源 descriptor 和现有准入证据映射。旧 fixture 标识仅留在历史证据和测试，不直接改写历史记录。准入只覆盖已验证端点、用途、成本、域名、内容处理与保存范围；发现 URL 不自动授权访问其主机。
6. `content_scope` 严格保持 `none/summary/full/platform_text` 含义。RSS 摘要、arXiv abstract、HN 外链信息、GDELT 发现元数据不能升级成全文。文章级事实要求获准读取的原站正文与可定位证据；平台文本只支持该平台文本本身的归属声明。源允许 full 不代表将正文交付给用户，也不代表允许长期存储；全文按许可在隔离内存短暂处理，默认不落日志、事件或验收包。
7. 所有研究阶段共用当前 Run 的预算租约。来源免费不代表模型免费；模型费用未知按既有保守预算处理。HTTP、重试、分页、模型请求分别计数，配额与输出预留不可被内部循环耗尽。来源失败形成独立 attempt，不能伪装为零结果。
8. V2 outcome 经原文证据、质量、输出校验后投影至正式 `deliverable-set/2`。第一轮 ranked_digest 与第二轮有限改写沿用 ADR-0003：同身份、同会话、最近提交且成功的 Run，原始闭包先验后裁剪；不把 V1 文本转换成伪 V2。

## 代价、补偿与停止条件

内存状态设置 TTL、容量与每 Run 字节上限；终态预算和已提交交付在 TTL 内保留用于跨轮引用，临时全文完成后释放。重启后引用安全拒绝。短期来源不可证明历史覆盖完整，不能因“未找到”判定 NO_MATCHES。正文准入不足时输出 PARTIAL/FAILED；没有合格排名时真实正向改写验收为未完成，不能用测试样本替代。

本裁决只局部增加本地实时模式，不替代 ADR-0002 的生产持久化裁决，不授权共享数据库 DDL、新模型费用、Java/UI 修改或生产发布。不新增付费源，不自动调用旧厂商搜索兜底。保留来源失效、预算耗尽、硬截止、取消、来源内容限制及输出校验的稳定错误。

回滚先关闭新 Run 的 local_live V2 入口；进行中 Run 保持版本或明确取消，不重解释旧状态。凭文件白名单快照恢复本批源码/本地非敏感配置并重启确认所属的本机服务；不删除历史证据、不清理共享数据、不实施 Git 操作。停用后无合规研究能力时明确不可用。

### Task 2 组合层位置澄清（2026-09-17）

现有 AST 架构矩阵禁止 configuration 依赖 capabilities。Task 2 的描述符加载和静态校验仍放 configuration；
`build_local_source_registry(descriptors, *, now) -> VerifiedSourceRegistry` 放在新增
`harness/research_local_sources.py`，由组合层依赖配置、中立契约和现有来源能力。
这只是落实既有依赖方向的文件位置修订，不新增架构允许边，不以动态导入或 TYPE_CHECKING 规避守卫。
原因、红绿测试与文件白名单追加到进度账本；后续组合根按此位置导入。

### Task 2 独立复核 I1：启用来源历史证据组合门（2026-09-17）

独立复核确认，通用 `VerifiedSourceRegistry` 仅对 `latest_only` 在调用预约时检查
`history_verified` 与 `freshness_sla`；本地 loader/组合门却允许启用缺少历史核验、
freshness 或最大回看范围的 `queryable` / `archive` 来源，导致其能够构建并预约外部调用。

本地实时来源现追加失败关闭裁决：`latest_only`、`queryable`、`archive` 只有同时具备
`admission.history_verified=true`、非空 `freshness_sla` 和非空 `max_lookback` 时才可在
`enabled=true` 状态通过静态组合校验。任一事实缺失统一返回既有
`SOURCE_HISTORY_UNSUPPORTED`，在 Registry 构建、配额预约和任何网络调用之前停止。
禁用来源仍可保留未完成证据以供后续核验；`unknown` 继续沿用既有 Registry 失败关闭语义。

该补强只收紧 local_live 配置/组合根，不修改或放宽通用 Registry、来源准入 TTL、架构允许矩阵
及 Provider 边界。合法且已核验、有 freshness 与最大回看边界的三种历史模式保持可构建和预约。
