# S5 运营专业能力实施计划

> **执行要求：** 实施时必须使用 `subagent-driven-development`（推荐）或 `executing-plans` 逐任务执行，步骤使用复选框跟踪。项目永久不使用 Git；每个任务以实施前文件快照、文件级差异包、RED/GREEN 输出和进度账本代替提交步骤。

**目标：** 在 S1～S4 冻结契约之上，以四个可独立验收的批次实现研究/证据/质量审校、品牌/IP/产品、内容/渠道/活动、用户增长/社群/分析复盘专业能力，并且只使用 Fake Provider/Tool 和固定合成样本验证。

**架构：** 所有专业 Agent 实现 S1 `AgentPlugin`，由 S4 中央 Supervisor 通过能力 Registry 选择，且只消费 S3 运营值对象。Evidence Gate、PlatformProfile 解析和分析文件边界是确定性服务；QualityReviewAgent 只输出结构化审校和修订请求，修订计数、预算和循环仍由 S4 管理。业务 Prompt 与固定样本同版本治理，真实公共搜索、真实模型/文件 Provider 及真实质量验收留到 S7。

**技术栈：** Python 3.13、uv、S1 `AgentSpec/AgentPlugin/AgentRegistry/AgentFactory`、S2 Prompt/Context/Model/Tool Runtime 与 Fake Provider、S3 运营领域契约、S4 Operation Supervisor/LangGraph（唯一 Graph Runtime）、Pydantic v2（由 S2 引入后复用）、标准库 `csv/json`、`unittest`；Polars 1.x 和 fastexcel 仅保留窄端口，S7 前不接入真实适配器。

## 全局约束

- 只修改 `D:\efficiency-platform\efficiency-platform-agent` 的纯 Agent 侧文件，不设计或修改 Java、网关、部署拓扑、共享数据库 DDL 或外部平台接口。

- 新增行为必须测试先行；所有注释、Docstring、配置说明和测试意图使用中文。
- 项目永久不使用 Git；不执行、要求或声称初始化、提交、分支、推送或 Git 差异审查。

## 2. Specialist 创建裁决

架构要求“满足多数条件才创建 Specialist”：有独立业务子目标、多步专业判断、独立 Prompt/知识/Tool 范围、独立上下文切片、可独立失败/重试/降级、可返回结构化结果、可被多场景复用。

| 组件 | 形态裁决 | 决策依据 |
|---|---|---|
| ResearchInsightAgent | 独立 Specialist | 有研究目标、查询规划、证据结构、独立失败关闭和多场景复用，满足全部条件 |
| EvidenceGate | 确定性服务，不是 Agent | 只检查 Schema、URL 规范化、重复、时间窗和结论关联，不需要自主业务判断 |
| QualityReviewAgent | 独立 Specialist | 对多类交付物做跨产物语义审校，有独立 Prompt、上下文、结构化结果和失败语义，可复用 |
| BrandOperationAgent | 独立 Specialist | 定位、价值主张、信息体系、节奏和指标形成独立策略目标，可单独失败与验收 |
| IPOperationAgent | 独立 Specialist | 人设、受众、内容支柱和成长阶段需独立专业 Prompt 与 Profile，可复用 |
| ProductOperationAgent | 独立 Specialist | 发布、用户教育、卖点和冷启动需产品事实门禁和独立策略结果 |
| ContentAgent | 独立 Specialist | 选题、栏目、日历、草稿和复用是可单独验收的多步创作目标 |
| ChannelContentAgent | 独立参数化 Specialist | 每个平台独立创作并验收，共享 Brief/证据但不机械换格式，可按 PlatformProfile 并行实例化 |
| CampaignOperationAgent | 独立 Specialist | 目标、机制、节奏、资源、物料、风险和指标组成可独立失败的策划目标 |
| UserGrowthAgent | 独立 Specialist | 用户分层、生命周期、漏斗和实验需多步分析；按批准架构合并用户与增长，不拆成两个 Agent |
| CommunityAgent | 独立 Specialist | 社群定位、栏目、互动、激励和 SOP 有独立目标、Prompt 和可验收交付物 |
| AnalyticsReviewAgent | 独立 Specialist | 受控文件数据的趋势、异常、归因假设和行动计划是多步专业判断，可独立失败 |
| PlatformProfileResolver | 确定性服务，不是 Agent | 只校验和展开 S3 `ChannelProfile`的版本化规则，不产生平台策略 |
| AnalyticsFileReader | 窄端口 + 测试 Fixture 适配器，不是 Agent | 只做允许格式、大小、列、行、类型和摘要归一化，不做归因判断 |

### 4.1 Specialist 公共契约

`src/efficiency_platform_agent/agents/operation/specialists/contracts.py` 必须定义：

```python
@dataclass(frozen=True, slots=True)
class SpecialistExecutionInput:
    contract_version: Literal["operation-specialist-input/1"]
    task_id: str
    tenant_id: str

    evidence_pack: EvidencePack | None
    platform_profile: PlatformProfile | None
    analytics_dataset_reference: AnalyticsDatasetReference | None
    analytics_summary: AnalyticsSummary | None

@dataclass(frozen=True, slots=True)
class SpecialistExecutionResult:
    contract_version: Literal["operation-specialist-result/1"]
    task_id: str
    completed_scope: tuple[str, ...]
    missing_scope: tuple[str, ...]
    deliverable_bundle: DeliverableBundle | None
    evidence_pack: EvidencePack | None
    quality_report: OperationQualityReport | None

```

公共校验规则：`task_id/tenant_id` 必须与 `SupervisorTask` 和 S3 契约一致；输入为 tuple/frozenset；成功必须有 `completed_scope` 与交付物或证据/质量结果；失败必须有稳定 `error_code` 和 `missing_scope`；`analytics_dataset_reference` 与 `analytics_summary` 必须同时为空或引用同一 `dataset_id/tenant_id`，二者均不得含 `rows`；不返回原始 Prompt、模型文本、文件全文、异常 `repr` 或 Secret。

`decode_specialist_task(task: SupervisorTask) -> SpecialistExecutionInput` 只解码 S4 已裁剪的 `input_data/context_view`，并递归拒绝任意名为 `rows`、`raw_rows`、`dataframe` 的字段；`encode_specialist_result(result: SpecialistExecutionResult, parent_run_id: str) -> RunResult` 必须构造 S4 `SpecialistResultEnvelope`，逐字段映射 `contract_version="operation-specialist-result/1"`、`task_id`、`completed_scope`、`missing_scope`、`deliverable_bundle`、`evidence_pack`、`quality_report`、`assumptions`、`warnings`、`error_code`、`requested_capability`、`revision_request` 和 `usage`，再使用 S4 官方 codec 转为 `RunResult.output`。`result.evidence_pack` 必须原样放入类型化 `evidence_pack` 字段；S4 decoder 往返后必须恢复完整 `EvidencePack`，包括 `records/supports/duplicate_status`。如实际 S4 不能做到，Task 1 标记 `BLOCKED_BY_S4_EVIDENCE_ENVELOPE`，不得把 Evidence 塞进 pack_id、自由文本或未版本化扩展字典。

`EvidenceGate` 先调用 S3 `validate_evidence_pack`，再检查有效来源数、发布者数、时间窗和事实结论关联。URL 字段完整永远不等于网页原文已核验，因此 `source_content_verified` 在 S5 只能为 `False`。研究能力不可用返回 `RESEARCH_UNAVAILABLE`，证据数或时间窗不足返回 `RESEARCH_INSUFFICIENT`，无支撑结论返回 `EVIDENCE_INVALID`。

@runtime_checkable
class AnalyticsDatasetLease(Protocol):
    async def __aenter__(self) -> AnalyticsDataset:
        raise NotImplementedError("进入数据集临时读取边界")

        raise NotImplementedError("释放数据集临时读取边界")

    def open(self, request: AnalyticsFileReadRequest) -> AnalyticsDatasetLease:
        raise NotImplementedError

`AnalyticsDataset` 是仅存在于 `async with reader.open(request) as dataset:` 内部的瞬时对象，不得进入 `SpecialistExecutionInput`、`SupervisorTask.input_data/context_view`、S4 TaskGraph/Checkpoint/事件、Prompt、`SpecialistExecutionResult` 或日志。`AnalyticsSummary.aggregates` 的 key 只能是稳定指标 ID，value 只能是有界标量 `str/int/float/bool/None`，禁止嵌套对象、数组、样例行和原始单元格序列。Analytics Specialist 在运行边界内加载 rows，立即完成确定性聚合并生成 `AnalyticsSummary`，随后在模型调用前退出 lease；成功、Reader 异常、聚合异常、取消都必须执行 `__aexit__`，且不得缓存 rows。跨边界只传 `AnalyticsDatasetReference + AnalyticsSummary`。

## 7. S5 完成门禁

3. EvidenceGate、PlatformProfileResolver、AnalyticsFileReader 和有限修订决策保持确定性，没有被包装成无意义 Agent。

6. ChannelContentAgent 按单个 PlatformProfile 独立生成，三个固定平台产物不是正文复制，Profile 缺失不静默降级。
7. Research 的完整 `EvidencePack`（含 records/supports/duplicate_status）能通过 S4 `operation-specialist-result/1` 类型化 evidence 字段编码、解码、聚合和 assembly，不降级为 ID、字符串或未知字典。
