# 运营助手内联研究结果与成稿制品分流 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让资料收集与汇总任务在聊天区流式展示完整结果，只在用户明确要求推文、公众号文章或正式成稿时生成可下载制品。

**Architecture:** Agent 依据冻结的场景和输出要求产生 `inline` 或 `artifact` 展示模式；Harness 同时发布完整对话正文与带模式的结构化事件。Java 持久化两类结构化结果，但公开制品查询排除 `inline`；前端只将 `artifact` 事件加入制品视图。

**Tech Stack:** Python 3.13、FastAPI、Pydantic、pytest、Java 21、Spring Boot、MyBatis-Plus、JUnit 5、React、TypeScript、Vitest、SSE。

## Global Constraints

- 研究、汇总、资料整理和分析回答必须使用 `presentation_mode=inline`。
- 明确的推文、公众号文章、平台文案、正式成稿与导出请求使用 `presentation_mode=artifact`。
- 内联研究结果必须通过现有 `assistant_delta` 流式输出完整正文。
- 内联研究记录可以内部持久化，但不能出现在公开制品列表或下载 Markdown UI。
- 展示模式由服务端冻结意图决定，LLM 不得自行决定。
- `presentation_mode` 缺失时按 `artifact` 处理，保持历史协议兼容。
- 不修改研究采集、排序、引用闭包和事实核验算法，不修改数据库 DDL。
- 保留用户现有 `aiep-boot/src/main/resources/application.yml` 改动，不纳入本任务修改。
