# Agent 真实会话研究链路修复与十轮回归实施计划

## 目标

修复默认真实会话仍走不稳定厂商搜索、研究请求数量与时间窗丢失、待澄清状态污染新意图、续写上下文不完整、标签结构化校验误报，以及前端跨轮展示旧交付物的问题；完成自动化门禁后，在内置浏览器执行不少于 10 轮真实问答回归。

## 实施边界

- Agent 端复用现有 RSS/Atom、GDELT、arXiv、Hacker News 和安全 HTTP 传输适配器，不新增收费数据源或依赖。
- 研究结果只接纳公开来源 URL、标题、发布者和可验证时间；严格时间窗内数量不足时明确降级，不扩窗、不编造。
- 意图仍由模型进行语义识别；确定性代码只负责会话生命周期、澄清答案归并、数量/时间约束投影和安全兜底。
- 前端只修复已确认的跨轮旧交付物残留，不调整页面设计或其它交互。
- 本轮不引入 Git，也不修改或输出任何本地密钥。

## 测试驱动批次

1. 先补失败测试：免费源聚合与严格过滤、请求数量投影、澄清与新意图切换、上下文输入、正文标签结构化、跨轮交付物清理。
2. 实现免费公开源研究 Provider，并接入默认真实会话组合根。
3. 修复会话状态机与研究请求约束投影。
4. 修复交付物标签归一化和前端跨轮展示状态。
5. 运行 Agent 定向测试、全量测试、Ruff、Mypy、compileall；运行前端格式、Lint、类型、测试、构建。
6. 重启 Agent，保留前端开发服务，使用内置浏览器重新执行至少 10 轮测试并检查控制台。

## 通过标准

- 普通问答、新运营任务、澄清续写、意图切换互不污染。
- 研究请求按用户显式日期、相对时间、数量和来源约束执行；输出带公开链接，证据不足时明确说明。
- 小红书正文中的标签可被结构化为 `hashtags`，不再产生错误缺失告警。
- 新一轮不会继续显示上一轮交付物。
- 10 轮真实浏览器测试全部达到 PASS；允许“证据不足但明确说明”的受控 PARTIAL 作为符合产品约束的正常结果，但不允许接口失败、无关回答、扩窗或伪造来源。
