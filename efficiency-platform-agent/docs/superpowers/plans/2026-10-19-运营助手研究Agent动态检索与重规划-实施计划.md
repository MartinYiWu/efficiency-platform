## 1. 目标与完成定义

把当前“固定查询 × 固定来源一次抓取”的流程改为受治理的研究 Agent 闭环：

```text
动态意图参数
→ 研究任务账本
→ LLM 生成结构化检索动作
→ 确定性策略校验
→ 来源 Tool 执行
→ 证据记忆与质量评估
→ LLM 反思缺口并重规划
→ 满足目标或按预算/无增益条件停止
→ 证据闭包交付
```

完成必须同时满足：

1. “1 天、3 天、上周、2 周、明确日期”等时间范围继续由 Intent V2 解析，研究代码不得写死 7 天。
2. “前 5 条、前 10 条、尽可能多”等数量继续由 `CountPolicy` 控制，研究代码不得写死 Top10。
3. 来源的费用、许可、凭据、租户和 Tool 白名单仍在网络调用前失败关闭；来源静态 `max_lookback` 不再代替本次运行的真实覆盖证据。
4. LLM 可基于主题、时间范围、质量缺口、失败来源和历史查询提出检索词与来源选择；运行时负责校验来源、时间窗、动作类型、重复、预算和指纹，模型不能生成 URL、扩大时间范围或绕过准入。
5. 每轮保存已执行查询、失败查询、失败来源、候选、证据和质量缺口；重复动作或连续无增益必须停止或换源，不能无限循环。
6. Prompt 的可变规则从数据库 Prompt 资产读取；代码只保留稳定的 Prompt key、Schema 和安全校验。
7. 真实验收必须调用正式 Agent HTTP/SSE 接口，覆盖动态时间和数量矩阵，并同步检查 Agent 日志；不得用测试替身或 HTTP 200 冒充功能通过。

## 2. 实施任务

### Task 1：用回归测试固定原故障与动态边界

**修改文件**

- `tests/unit/capabilities/research_v2/test_source_registry.py`
- `tests/unit/capabilities/research_v2/test_model_decisions.py`
- `tests/orchestration/research_v2/test_live_stage_runner.py`
- `tests/unit/prompts/test_research_v2_templates.py`

**RED 用例**

1. 已准入 `latest_only` 来源面对大于描述符提示窗口的 Brief 时仍可进入执行候选，但不得宣称完整历史覆盖。
2. 规划模型能返回不同查询词的结构化动作提案，服务端生成动作指纹；模型伪造来源、缺口、动作类型、重复查询或时间范围时被拒绝。
3. 初轮与补采轮都经过模型规划；补采负载含已执行查询、失败来源、当前合格事件数和剩余目标数。
4. 连续相同查询或无增益达到策略上限后停止，且日志含稳定停止原因。
5. 数据库 Prompt 组装路径能分别提供 system/developer/user 消息和字段语义，不回退到业务代码中的可变大段提示词。

**验证命令**

### Task 2：拆分来源准入与时间覆盖

**修改文件**

- `src/efficiency_platform_agent/capabilities/research/v2/sources.py`
- `src/efficiency_platform_agent/contracts/research_sources_v2.py`
- `src/efficiency_platform_agent/providers/research/feed.py`

- `src/efficiency_platform_agent/providers/research/gdelt.py`

**实现**

1. `VerifiedSourceRegistry` 的可用性只判断准入、适用用途、凭据、免费配额、租户/请求白名单、语言和地区。
2. 新增结构化覆盖观测，记录来源声明能力、实际返回最早/最晚时间、截断/游标和 `complete/partial/unknown`，不根据静态天数伪造完整。
3. queryable/archive 来源只有在端点按请求时间过滤且未截断时可报告完整；feed/latest_only 默认报告 unknown/partial。
4. 质量层只在“零结果”判定时要求完整历史覆盖；已有足量合格证据时按真实条数交付。

### Task 3：把规划器升级为“LLM 提案、运行时裁决”

**修改文件**

- `src/efficiency_platform_agent/contracts/research_v2.py`
- `src/efficiency_platform_agent/capabilities/research/v2/model_decisions.py`
- `src/efficiency_platform_agent/orchestration/research_v2/planner.py`

**实现**

1. 增加结构化 `SearchActionProposal`：`gap_id`、`source_id`、`action_kind`、`query`、可选 `cursor`；模型不填写最终时间窗、revision、requirement 或动作指纹。
2. Prompt 明确每个字段的含义、可选来源能力、原时间范围、当前缺口、已尝试/失败项和剩余预算。
3. 运行时从原 Brief 注入时间窗与 revision，绑定 gap requirement，生成稳定指纹，再使用 `ActionValidator` 做最终裁决。
4. 初轮也由模型生成多查询；模型不可用时使用受控的主题/实体/维度组合降级，不生成外部事实。

### Task 4：补齐研究任务账本、反思与停机条件

**实现**

**日志事件**

### Task 7：离线门禁与真实接口验收

**离线命令**

```powershell
uv run pytest -q tests/unit/capabilities/research_v2 tests/orchestration/research_v2 tests/unit/prompts tests/unit/observability
uv run pytest -q
uv run ruff check src tests
uv run python -m compileall -q src
```

**真实调用矩阵**

通过前端实际使用的 Agent HTTP/SSE 入口依次调用并记录新的 run_id：

1. `收集今天 AI 热点，给出前 5 条`
2. `收集最近 3 天 AI 热点，给出前 8 条`
3. `收集上周 AI 热点，给出前 10 条`
4. `收集最近 2 周 AI 热点，最多 12 条`
5. `收集 2026-10-01 到 2026-10-07 的 AI 热点，按热度排序`

每个用例核对：

- Intent 的 resolved time window、count policy、ranking mode 与输入一致；
- 实际发生模型规划和至少一个真实来源请求，来源时间戳位于请求窗口；
- 返回条数不超过目标，exact 模式不足时不得伪造，必须给出可诊断缺口；
- 每条交付项存在来源引用闭包，不出现未采集事实；
- Agent 日志无未分析异常；429、超时或来源缺口必须触发换源/受控停止，而不是记录成功；
- Java 和前端无需因纯 Agent 改动重启，Agent 重启后再做最终矩阵。

若真实来源客观上不足以满足某个窗口/数量，用例状态记录为真实 `PARTIAL/FAILED`，继续分析来源、计划或质量门禁；不得修改断言、伪造候选或用测试样本替代。

## 3. 非目标与回滚

- 不引入 AutoGen、CrewAI、OpenManus 等第二运行时；只参考其 Task/Progress Ledger、反思、循环检测等模式，仍由现有 LangGraph 执行。
- 不新增付费商业搜索、新闻或舆情源，不自动发布到任何平台。
- 不修改共享数据库 DDL；Prompt 资产沿用现有表和幂等 seed/upsert 机制。
- 回滚时恢复本计划涉及的 Agent 文件并重启 Agent；不删除历史 Run、Prompt 快照、证据或审计数据。
