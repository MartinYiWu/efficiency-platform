# S6 运营场景包实施计划

> **执行要求：** 逐任务使用复选框跟踪；每个任务先产生可复现的 RED，再作最小 GREEN。项目永久不使用 Git，不执行初始化、提交、分支、推送、`git diff` 或基于 Git 的审查；每项任务改动前后保存文件快照、文件级差异包和命令输出摘要。

**目标：** 在不复制 S2 运行主链、S3 领域契约、S4 Supervisor 或 S5 Specialist 的前提下，将八个运营场景定义为可校验、语义版本化的 S3 `ScenarioPackManifest/PlanTemplateDefinition/ScenarioStepDefinition`，以不含期望结果的 `ScenarioSubmission` 作为唯一生产入口，并用测试专属固定样本验证可追溯交付物 bundle。

**架构：** S6 生产代码仅拥有场景声明、`ScenarioSubmission` 校验、S3 Profile 权威选择与 `compile_scenario_plan` 调用、场景级质量规则和对 S4 Supervisor 的窄请求适配。每个 Pack 的执行结构只存在于 S3 `plan_template.steps`，不维护第二份步骤表、目标 Agent 或状态枚举；实际 DAG、子预算、等待/恢复、`CompletionStatus`、Provider、Tool 和 Specialist 执行仍由 S2～S5 的注入端口负责。`ScenarioSample`、期望状态和脚本响应全部留在测试 helper，任何真实模型、网络、数据库、存储、文件解析、账号或发布操作都留给 S7。

**技术栈：** Python 3.13、标准库 `dataclass`/`Protocol`/`StrEnum`、S1 Registry 契约、S2 Fake Provider/Tool 契约、S3 运营领域不可变值对象、S4 Supervisor 结果契约、S5 Specialist 契约、`unittest`/`IsolatedAsyncioTestCase`、`uv`。不新增依赖，不修改 Java 侧、部署、持久化或公共运行时。

## 全局约束

- 只修改 `D:\efficiency-platform\efficiency-platform-agent`；本计划唯一新增的当前文件位于 `docs/superpowers/plans/`，执行本计划时的代码只能位于纯 Agent 工程。
- S6 的唯一场景标识固定为 `industry_digest`、`multi_platform_content`、`brand_operation_plan`、`ip_operation_plan`、`campaign_plan`、`content_calendar`、`growth_experiment`、`operation_review`；所有 Manifest 的 `contract_version` 固定为 `scenario-pack/1`，首版 `semantic_version` 固定为 `1.0.0`。
- 语义版本、场景 ID、能力 ID、Profile ID、质量检查 ID、固定样本 ID 和交付物 requirement ID 均遵循 S3 小写稳定 ID 规则；删字段、改变字段类型或改变同一字段语义必须新增主版本并新建样本，不得静默兼容或覆盖旧样本。
- S6 只加载并校验 S3 `ScenarioPackManifest`，不得重定义其字段、修改 S2 Harness/LangGraph 生命周期、增加第二 Graph Runtime，或在 Pack 中写 Graph、Provider 参数、厂商模型 ID、密钥、网络地址、平台账号或发布 Tool。
- 生产唯一入口固定为 `ScenarioPackService.run(submission: ScenarioSubmission)`；`ScenarioSample` 只允许定义在 `tests/support/s6_scenario_samples.py`，只能经 `submission_from_sample(sample)` 去除全部 expected 字段后进入生产入口。生产代码不得导入 Sample、sample ID 或任何期望状态/交付物/告警。
- 每个 Pack 只能在 S3 `ScenarioPackManifest.plan_template` 中声明 `PlanTemplateDefinition/ScenarioStepDefinition`；服务必须调用 S3 `compile_scenario_plan(manifest, task_spec, operation_context, plan_id)` 生成 `OperationPlan`，不得自建计划、运行时拼步骤、写目标 Agent ID 或按场景 ID 分支调度 Specialist。
- Pack 的 `required_capabilities` 必须从 S5 `agents.operation.definition.OperationSpecialistCapabilityId` 或 `operation_specialist_capability_ids()` 取得，精确复用 S5 冻结的 11 个完整 ID；禁止手写 `research.insight`、`content.strategy`、`brand.operation` 等相似短名。
- Profile 候选不能仅以 `ProfileReference` 直接进入 Supervisor。服务必须调用 S3 `select_profiles_for_task(task_spec, profile_candidates)` 形成 `OperationContext`，由该入口执行租户、事实状态、版本、过期和任务需求校验；失败时 Supervisor 零调用。S6 不新增第二 Profile 权威缓存或放宽规则。
- S6 只使用 S4 `CompletionStatus` 表达 COMPLETE/PARTIAL/WAITING_INPUT/FAILED/CANCELLED；不得定义 `ScenarioPackStatus`、字符串状态映射或第二完成状态权威。
- S5A（研究与质量）、S5B（品牌/IP/产品）、S5C（内容/渠道/活动）、S5D（增长/数据）必须各自提供稳定的 `AgentSpec`、能力注册、输入输出 Schema 和离线固定样本后，S6 才能把相应能力列入生产 Pack；本计划在前置阶段未落地时只允许 `tests/support/s6_scenario_fakes.py` 中同名的脚本化替身。
- 所有用户文本、Provider 返回、Tool 返回和 Specialist 返回均为不可信数据。场景层只能读取已结构化的 S3/S4/S5 值对象；不可信文本不得改变 Manifest、能力需求、预算、Tool 白名单、Profile 权威状态或等待/部分失败语义。
- 所有 Pack 均为“生成、预览、修改、导出交付物”的离线组合，不包含内容发布、发送消息、账号操作、报名、交易、用户触达、业务数据库直连、Text2SQL、付费商业热点/新闻/舆情数据源或主动网页正文读取。
- 关键条件缺失必须生成 S4 `WAITING_INPUT` 结果及稳定缺失项；非关键缺失只能形成 Manifest 允许的、带依据且可修改的 `OperationAssumption`。无有效 ChannelProfile 时不得声称平台适配完成。
- `PARTIAL` 必须保留 `completed_scope`、`missing_scope`、失败任务、告警和已完成交付物；只有所有必需交付物和质量门禁通过才可声称完整。场景层不得把部分结果改写为完整成功。
- 一个跨平台请求的共享层只能包含已确认的品牌/IP/产品/受众事实、同一研究 `EvidencePack`、统一内容 Brief、目标、禁用项、时间窗和已确认素材；每个平台必须对应独立 `ScenarioStepDefinition`，其 capability 固定为 S5 `OperationSpecialistCapabilityId.CHANNEL_CONTENT`，由 S4 按能力选择 Specialist。标题、开场、正文组织、互动引导、标签、排版和 `PlatformContent` 必须独立生成、独立质量校验并使用独立交付物 ID，严禁复制一段正文或在 S6 硬编码 Agent。
- 项目自行编写的注释、Docstring、示例说明和配置说明使用中文；代码标识符、标准技术术语和稳定 ID 可使用英文。

## 1. 前置门禁与接口冻结

### 1.1 进入 S6 前必须满足的事实

1. S1 的 `AgentRegistry`、`AgentFactory`、`AgentPlugin` 和 `CapabilityRequirement` 契约可用，且显式注册无动态扫描副作用。
2. S2 已冻结 `RunStatus`、`ExecutionBudget`、`GraphExecutionResult`、受治理 Tool Runtime 和 Model Provider 的 Fake 契约；本阶段不直接调用它们的生产实现。
3. S3 已冻结下列不可变类型/函数：`OperationTaskSpec`、`OperationContext`、`OperationPlan`、`OperationAssumption`、`EvidencePack`、`OperationDeliverable`、`DeliverableBundle`、`OperationQualityReport`、`ScenarioPackManifest`、`PlanTemplateDefinition`、`ScenarioStepDefinition`、`ClarificationPolicy`、`FailureBehavior`、`DeliverableRequirement`、`ProfileKind`、`select_profiles_for_task`、`compile_scenario_plan`。
4. S4 已冻结 `CompletionStatus`、`TaskExecutionStatus`、`SpecialistResultEnvelope`、`TaskOutcome`、等待恢复、取消、预算和部分失败的语义；`GraphExecutionResult.next_status` 必须能返回 `WAITING_INPUT`。
5. S5A～S5D 的各能力均以版本化 `AgentSpec` 注册，且 `agents.operation.definition.operation_specialist_capability_ids()` 与 `OperationSpecialistCapabilityId` 可用。S6 所有步骤 capability 必须是该函数返回集合的成员；若任一必需能力尚不可用，Pack 注册必须失败关闭。固定样本仅可验证 Fake 的接口形状，不能标记该 Pack 已完成。

### 1.2 S6 新增且冻结的窄接口

所有接口位于 `agents/operation/scenarios/`，只依赖 S1～S5 已冻结的领域和编排契约。不得向 S2/S3/S4 添加字段。

```python
from typing import TypeAlias

from efficiency_platform_agent.agents.operation.supervisor.contracts import (
    CompletionStatus,
)


ProfileCandidate: TypeAlias = (
    BrandProfile
    | IPProfile
    | ProductProfile
    | AudienceProfile
    | MetricProfile
    | ChannelProfile
    | CampaignProfile
)


@dataclass(frozen=True, slots=True)
class ScenarioSubmission:
    contract_version: str
    submission_id: str
    scenario_id: str
    manifest_semantic_version: str
    plan_id: str
    request: OperationRequest
    task_spec: OperationTaskSpec
    profile_candidates: tuple[ProfileCandidate, ...]
    evidence_pack: EvidencePack | None


@dataclass(frozen=True, slots=True)
class ScenarioSupervisorRequest:
    contract_version: str
    submission_id: str
    request: OperationRequest
    task_spec: OperationTaskSpec
    operation_context: OperationContext
    operation_plan: OperationPlan
    evidence_pack: EvidencePack | None


@dataclass(frozen=True, slots=True)
class ScenarioExecutionResult:
    scenario_id: str
    semantic_version: str
    completion_status: CompletionStatus
    deliverable_bundle: DeliverableBundle | None
    quality_report: OperationQualityReport | None
    missing_condition_ids: tuple[str, ...]
    completed_scope: tuple[str, ...]
    missing_scope: tuple[str, ...]
    warning_codes: frozenset[str]
    error_code: str | None


class ScenarioSupervisorPort(Protocol):
    async def execute_scenario(
        self,
        request: ScenarioSupervisorRequest,
    ) -> ScenarioExecutionResult:
        raise NotImplementedError


class ScenarioQualityGate(Protocol):
    def validate(
        self,
        manifest: ScenarioPackManifest,
        result: ScenarioExecutionResult,
    ) -> OperationQualityReport:
        raise NotImplementedError


class ScenarioPackRegistry(Protocol):
    def register(self, manifest: ScenarioPackManifest) -> None:
        raise NotImplementedError

    def get(self, scenario_id: str, semantic_version: str) -> ScenarioPackManifest:
        raise NotImplementedError

    def list(self) -> tuple[ScenarioPackManifest, ...]:
        raise NotImplementedError
```

`ScenarioSubmission` 是唯一生产入站，固定 `contract_version="scenario-submission/1"`，不含 Sample ID、expected 字段、Prompt、模型参数、Tool 参数、Agent ID 或预编译 Plan。`request/task_spec/profile_candidates` 的 tenant 与身份链必须一致；这些约束在调用 Supervisor 前失败关闭。服务必须先调用 S3 `select_profiles_for_task(submission.task_spec, submission.profile_candidates) -> OperationContext`，再调用 `compile_scenario_plan(manifest, submission.task_spec, operation_context, submission.plan_id) -> OperationPlan`，最后以 `contract_version/submission_id/request/task_spec/operation_context/operation_plan/evidence_pack` 七个完整字段构造 `ScenarioSupervisorRequest`。Profile/Plan 不能由调用方预填或只持有引用后跳过权威校验。

生产 Registry 直接存取 S3 `ScenarioPackManifest`，不定义 `ScenarioPackDefinition` 或第二份步骤/能力/状态配置。每个 Manifest 的 `plan_template` 是唯一执行结构声明；`shared_fact_ids` 只能通过 S3 `ScenarioStepDefinition.input_reference_ids` 表达，平台独立输出只能通过各 Step 的 `expected_deliverable_ids` 表达。S4 只接收编译后的 `OperationPlan`，并按 capability 选择 Agent；S6 任何运行时分支不得包含 Agent ID/类名。

`ScenarioSample` 不属于上述生产契约，只能在 `tests/support/s6_scenario_samples.py` 定义。它包含 `ScenarioSubmission` 所需输入和 expected 字段；同文件唯一转换函数 `submission_from_sample(sample: ScenarioSample) -> ScenarioSubmission` 必须逐字段新建对象，明确丢弃 `sample_id/expected_*`。契约测试以反射证明 `ScenarioPackService.run` 只接受 `submission`，生产 `src/**` 无 `ScenarioSample`、`expected_completion_status`、`expected_deliverable_ids` 或 `submission_from_sample`。

### 1.3 固定质量检查 ID

所有 Pack 只可引用本节的稳定检查 ID；S5 `QualityReviewAgent` 可以补充结构化建议，但不得改变这些检查的含义：

| 检查 ID | 确定性规则 |
|---|---|
| `q.required-deliverables/1` | 每个必需 requirement 的数量、类型、格式和独立 ID 与 Manifest 一致 |
| `q.evidence-linkage/1` | 事实型交付物的结论均能关联 `EvidencePack.supports`；无 Evidence 不宣称研究事实完整 |
| `q.profile-authority/1` | 使用的 Profile 引用与任务同租户、版本匹配且不是候选事实 |
| `q.assumption-disclosure/1` | 非关键缺失项均以可修改假设返回，关键缺失项不生成完整交付物 |
| `q.metrics-definition/1` | 只输出指标口径、目标与周期；没有用户数据时不得输出实际结果、ROI、转化或留存结论 |
| `q.partial-scope/1` | `PARTIAL` 同时包含完成范围、缺失范围、告警、失败或不可用能力 |
| `q.channel-independence/1` | 多平台每个平台一个独立交付物 ID，正文指纹、标题和结构键均不相同；共享事实不计作重复正文 |
| `q.no-publication/1` | bundle、Tool 记录和 Manifest 均不存在发布、账号、发送、写入或交易动作 |
| `q.review-round-limit/1` | 结果中的修订次数不大于 S4 的两轮硬上限，超限返回 `QUALITY_NOT_MET` |

| `IP_STRATEGY` | `operation.ip.strategy` |
| `PRODUCT_PLAN` | `operation.product.plan` |
| `CONTENT_CREATE` | `operation.content.create` |
| `CHANNEL_CONTENT` | `operation.channel.content` |
| `CAMPAIGN_PLAN` | `operation.campaign.plan` |

契约测试必须断言 `operation_specialist_capability_ids()` 恰好等于上述枚举 `.value` 的 tuple，并断言八个 Manifest 的每个 `ScenarioStepDefinition.required_capabilities` 都是该集合的子集；测试不得另写一份字符串 expected 清单，而应直接引用枚举成员。任何旧短名或未知 ID 在 Registry 注册阶段失败关闭。

## 2. 场景包清单、关键条件与样本

| Pack | 必需能力 | 用户关键条件 | 非关键默认假设 | 交付物 bundle | 等待/部分失败规则 |
|---|---|---|---|---|---|
| `industry_digest` | `operation.research.insight`、`operation.content.create`、`operation.quality.review` | 行业/主题、时间窗、读者、报告周期 | 未给栏目时按“动态、洞察、行动提示”三段组织 | `industry-report`、`source-index`、`editorial-summary` | 缺主题或时间窗等待；研究不可用或来源不足时无事实型完整报告，可返回标注资料不足的摘要 |
| `multi_platform_content` | `operation.content.create`、`operation.channel.content`、`operation.quality.review` | 主题或已有原稿、目标平台列表、目标受众 | 未给 CTA 时使用中性互动引导；未给长度只采用 Profile 结构，不臆造平台阈值 | `content-brief`、每平台一个 `platform-content`、`quality-summary` | 缺主题/原稿或平台列表等待；单平台失败返回其他平台独立成品与该平台缺失范围 |
