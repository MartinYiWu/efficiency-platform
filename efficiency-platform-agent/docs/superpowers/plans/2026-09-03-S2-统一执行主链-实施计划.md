# S2 统一执行主链实施计划

> **执行要求：** 实施时必须使用 `subagent-driven-development`（推荐）或 `executing-plans` 逐任务执行。步骤使用复选框跟踪。项目永久不使用 Git；每个任务使用实施前文件快照、文件级差异包、测试输出和项目内进度账本完成评审。

**目标：** 在 S1 稳定 Agent 契约之上建立统一 Harness、唯一且可注册的 LangGraph Runtime、策略路由、Prompt/Context/Tool/Model Runtime、BudgetGuard、Run/Checkpoint/恢复/取消/事件和 FastAPI/SSE 最小入口，使 Direct 与固定 Workflow 在全部外部依赖均为 Fake/InMemory 的条件下可端到端执行，并冻结 S4 只能消费的通用扩展契约。

**架构：** 入站 Pydantic 契约只调用薄 Harness；Harness 建立身份、单调预算、Run、事件和错误边界，经规则型 Strategy Router 产生 `StrategySelection`，再由同一个 Registry 驱动的 LangGraph Runtime 执行。Graph 节点只能通过 Prompt Runtime、Context Builder、Tool Runtime 和 Model Runtime 使用能力，并在节点前后检查预算和取消；恢复沿原 Run/Checkpoint/deadline 返回同一 Graph。模型由 `ModelPolicyRouter` 选择逻辑候选并有限降级，真实 Provider、网络、数据库、Redis 和监控平台均不进入本阶段。

**技术栈：** CPython `>=3.13,<3.14`、uv、LangGraph OSS 1.x、FastAPI `>=0.135,<1`、Pydantic v2、Jinja2、Uvicorn、pytest、pytest-asyncio、HTTPX TestClient、Ruff、mypy；生产能力之外只使用 Python 标准库和确定性 Fake/InMemory 适配器。

## 全局约束

- 只修改 `D:\efficiency-platform\efficiency-platform-agent` 纯 Agent 工程，不设计或修改 Java 侧接口、权限、网关、领域模型、数据架构或部署拓扑。
- 项目永久不是 Git 仓库；不得要求、执行或声称 Git 初始化、提交、分支、推送、Git diff 或基于 Git 的审查。
- 所有新增注释、Docstring、配置注释、测试说明和项目文档使用中文；标识符、协议字段、模型逻辑名、环境变量名和标准技术术语可保留英文。
- S1 的 `AgentSpec`、`AgentValidator`、`AgentRegistry`、`AgentFactory`、`AgentPlugin` 和现有 `core.run` 契约是前置基线；除本计划明确列出的兼容扩展外，不改变其语义。
- LangGraph `StateGraph` 是唯一 Graph Runtime；不得引入 full `langchain`、`langchain.create_agent`、预构建 ReAct Agent、AutoGen、CrewAI、LlamaIndex Workflow、Deep Agents 或第二运行生命周期。
- Graph State 使用 `TypedDict` 与 JSON/msgpack 兼容值；不得放入 Pydantic 对象、Provider SDK 对象、连接对象、异常对象或可执行回调。
- Pydantic 只用于 API、事件和版本化边界 Schema；`core` 保持 Python 标准库中立。
- 所有 Run 必须走 `CREATED → QUEUED → RUNNING` 主路径；Graph 只能受控返回 `WAITING_INPUT / SUCCEEDED / FAILED / CANCELLED / TIMED_OUT`，Direct/Workflow 本阶段不得返回 `WAITING_INPUT`。同状态事件幂等，非法跳转失败关闭，终态不可逆；恢复只能 `WAITING_INPUT → RUNNING`，取消不建立第二生命周期。
- 本阶段只注册 Direct 和固定 Workflow 两个可运行 Graph。ReAct、Plan-and-Execute、Multi-Agent 在未注册时返回 `STRATEGY_NOT_AVAILABLE_IN_S2`；S2 必须交付通用 Graph 注册、等待/恢复、协作取消、Checkpoint、事件和 `next_status` 扩展点，使 S4 以后只注册并消费 Multi-Agent builder，不反向修改 S2 生命周期或实现文件。
- `StrategySelection.mode` 是 Graph Runtime 使用 `StrategyMode` 的唯一来源；全计划只允许一个 `GraphRuntime.execute(selection: StrategySelection, initial_state: AgentGraphState)` 签名，不得再并存 `execute(strategy: StrategyMode, initial_state: AgentGraphState)` 或让 S4 绕过 Strategy Router 手工拼接模式。
- LangGraph 只能被 `src/efficiency_platform_agent/orchestration/**` 导入；Harness、Routing、Strategies、Agents、Workflows、Provider、Tool 和 API 均不得直接导入。S4 的 Multi-Agent LangGraph builder 必须新增在 `orchestration/builders/`，S4 策略目录只提供框架中立节点函数和条件函数。
- 所有模型调用必须经 `ModelRuntime` 和 `ModelProvider` 端口；只实现脚本化 `FakeModelProvider`，不得读取 `.env`、调用真实模型、HTTP API 或厂商 SDK。
- 模型节点只能提出 `ModelDemand` 逻辑能力；实际候选由 Harness 约束下的 `ModelPolicyRouter` 选择。可重试失败最多尝试两个候选，降级事实必须写入事件和结果元数据。
- 所有 Tool 调用必须经 `ToolRuntime`；本阶段只注册无网络、无数据库、无文件写入的 `SyntheticLookupTool`。任何副作用 Tool、越权 Tool、未注册 Tool 或参数不合法调用必须在执行前失败关闭。
- `ContextBuilder` 是唯一上下文装配入口。用户输入、元数据和 Tool 返回均标记为不可信数据；它们不得改变系统指令、策略、权限、模型候选或 Tool 白名单。
- Prompt 必须来自显式注册的版本化 Bundle，使用 Jinja2 `ImmutableSandboxedEnvironment` 与 `StrictUndefined`；不得在 Graph 节点或业务代码中散落 Prompt 正文。
- `InMemorySaver`、`InMemoryRunRepository` 和 `InMemoryRunEventStore` 只证明本阶段离线闭环，不得表述为生产持久化、跨进程恢复或 Redis SSE 已验证。
- 每个 Graph 节点、Provider 尝试和 Tool 尝试都必须在执行前、执行后调用统一 `BudgetGuard`；remaining budget 由父预算、可信 Runtime Usage、迭代数、Tool 次数和首次运行时确定的绝对 deadline 单调计算，恢复不得重置。任何维度不足或执行后超限统一失败关闭为 `BUDGET_EXHAUSTED`，不得继续节点、降级、重试或返回成功。
- 本阶段不引入 PostgreSQL、`AsyncPostgresSaver`、SQLAlchemy、Alembic、Psycopg、Redis、Taskiq、Outbox、MCP、RAG、OCR、对象存储、真实文件解析或任何 DDL。
- 本阶段不创建运营业务 Specialist、Operation Supervisor、业务 Workflow、业务 Prompt、Scenario Pack、ChannelProfile 或业务交付物。
- 本阶段不建设 OpenTelemetry、Prometheus、Grafana、LangSmith、Dashboard、告警、SLO 或性能平台；只保留结构化 Run、Checkpoint、Event、Tool Invocation、Model Attempt 和 Usage 事实。
- 新增行为必须严格执行有效 RED → 最小 GREEN → 相关回归。完成声明必须使用修改后的新鲜命令输出，并区分离线 Fake 验证与未执行的真实集成。

## 2. 冻结接口与行为

### 2.1 入站、结果和事件契约

`contracts/requests.py`：

```python
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field

from efficiency_platform_agent.core.enums import StrategyMode


class CreateRunRequestV1(BaseModel):
    """S2 创建并同步执行一个受治理 Run 的入站契约。"""

    model_config = ConfigDict(extra="forbid", frozen=True)

    contract_version: Literal["run.create/1"] = "run.create/1"
    request_id: str = Field(min_length=1, max_length=128)
    tenant_id: str = Field(min_length=1, max_length=128)
    user_id: str = Field(min_length=1, max_length=128)
    input_text: str = Field(min_length=1, max_length=20_000)

    workflow_id: str | None = Field(default=None, min_length=1, max_length=128)
    strategy_payload_schema_version: str = Field(
        default="strategy.none/1", min_length=1, max_length=128
    )
    strategy_payload: dict[str, JsonValue] = Field(default_factory=dict)


class RunQueryV1(BaseModel):
    """查询 Run 时由受信请求头归一化得到的身份。"""

    model_config = ConfigDict(extra="forbid", frozen=True)

    tenant_id: str = Field(min_length=1, max_length=128)

    """用原 Run 与精确 Checkpoint 恢复同一 Graph 的通用契约。"""

    model_config = ConfigDict(extra="forbid", frozen=True)

    contract_version: Literal["run.resume/1"] = "run.resume/1"
    tenant_id: str = Field(min_length=1, max_length=128)
    checkpoint_id: str = Field(min_length=1, max_length=256)

    contract_version: Literal["run.cancel/1"] = "run.cancel/1"

    reason_code: Literal["user_requested"] = "user_requested"
```

`strategy_payload` 与 `ResumeRunRequestV1.resume_value` 都只是版本化 JSON 信封。Pydantic 入站 dict 必须立即深拷贝为框架中立不可变 `JsonObject`：UTF-8 规范 JSON 最大 `65_536` 字节、嵌套深度最大 `8`、每层对象最多 `128` 个成员、键长最大 `128`；只允许有限 JSON 数值，不允许对象实例、回调或二进制。超限统一 `STRATEGY_PAYLOAD_INVALID`，且 Graph/Tool/Provider 零调用。

S2 在路由后必须通过当前 `GraphRegistration` 的 schema、顶层键白名单和 adapter 校验/归一化 payload；Direct/Workflow 固定 `strategy.none/1` 且只接受空 payload。payload 一律标记为不可信，只能表达当前 strategy 的领域输入，不能改变 `tenant_id/user_id/request_id`、`StrategySelection`、Run ID、预算/deadline、权限、Tool 白名单、模型候选、Checkpoint 或事件序号。S4 的 `OperationRequest`、`input_request_id`、`plan_revision` 等领域字段由 S4 自有 Pydantic 契约验证后适配为 `StrategyPayload`，不得要求修改 S2 请求模型，也不得让 API 预填 Graph State。

`RunRecord.transition(target, *, strategy=None, output=None, failure=None, checkpoint_id=None, usage=None, budget_state=None, degraded=None) -> RunRecord` 必须调用现有 `validate_run_status_transition`，令 `version + 1`，并强制：`SUCCEEDED` 有输出且无 failure；`FAILED/TIMED_OUT` 有 failure；`WAITING_INPUT/CANCELLED` 无成功 output；非终态无最终 output/failure；终态不可再改变。`budget_state` 只能单调增加消费且 `started_at_epoch_ms/deadline_epoch_ms` 不变。其方法体按以下逻辑实现：

```python
def transition(
    self,
    target: RunStatus,
    *,
    strategy: StrategyMode | None = None,
    output: JsonValue = None,
    failure: RunFailure | None = None,
    checkpoint_id: str | None = None,
    usage: UsageSnapshot | None = None,
    budget_state: BudgetState | None = None,
    degraded: bool | None = None,
) -> RunRecord:
    if target is self.status:
        return self
    validate_run_status_transition(self.status, target)
    if target is RunStatus.SUCCEEDED and (output is None or failure is not None):
        raise ValueError("成功终态必须包含输出且不得包含失败")
    if target in {RunStatus.FAILED, RunStatus.TIMED_OUT} and failure is None:
        raise ValueError("失败或超时终态必须包含归一化错误")
    if target not in {
        RunStatus.SUCCEEDED, RunStatus.FAILED, RunStatus.TIMED_OUT
    } and (
        output is not None or failure is not None
    ):
        raise ValueError("非终态不得携带最终输出或失败")
    return replace(
        self,
        status=target,
        strategy=self.strategy if strategy is None else strategy,
        output=output,
        failure=failure,
        checkpoint_id=self.checkpoint_id if checkpoint_id is None else checkpoint_id,
        usage=self.usage if usage is None else usage,
        budget_state=(
            self.budget_state if budget_state is None else budget_state
        ),
        degraded=self.degraded if degraded is None else degraded,
        version=self.version + 1,
    )
```

`UsageSnapshot` 全部计数非负；S2 的 Fake Usage 无论数值是否为零均令 `estimated=True`，不得伪装为真实计量或真实零费用。

`BudgetGuard.start()` 将绝对 deadline 固定为 `now_epoch_ms + budget.timeout_ms`。`remaining()` 逐字段计算 `limit - consumed`，不得把负数钳成零；任一为负或 `now_epoch_ms >= deadline_epoch_ms` 立即抛 `BudgetExhaustedError`，`reason_code` 只允许 `iteration_limit/tool_call_limit/input_token_limit/output_token_limit/cost_limit/absolute_timeout`。每个 Graph 节点的 `required.iterations` 固定为 `1`；Tool/Provider 尝试在调用前预留其最小可执行额度，完成或异常后都通过 `record_after_node()` 记实际可信消耗并再次检查。执行后超限时丢弃该节点业务输出、保存预算/Checkpoint 事实并以 `BUDGET_EXHAUSTED` 失败，绝不继续下一节点、重试或模型降级。

可信消耗只来自 Harness/Graph 自计数、`ToolRuntime` 的调用记录和 `ModelRuntime` 汇总的 Provider Usage，再由 `GraphExecutionResult.usage/facts` 对外读取。`RunResult.metadata`、用户输入、Tool 输出或未来 S4 `SpecialistResultEnvelope` 自报的 usage 不得进入 `BudgetState`；若未来 Specialist 未通过 S2 Graph Runtime 产生可信 Usage，S4 必须保守核销其已分配额度，不能依据自报值返还预算。恢复继续使用 Checkpoint 中的原 `BudgetState` 和绝对 deadline，不得调用 `start()` 重建。

### 2.4 策略、模型和 Provider Runtime

`StrategyRouter(available_modes: frozenset[StrategyMode]).select(request: CreateRunRequestV1) -> StrategySelection` 的规则固定为：

1. `workflow_id` 非空且 `requested_strategy` 为空或为 `WORKFLOW`：选择 `WORKFLOW`，`reason_code="explicit_workflow"`；
2. `workflow_id` 为空且 `requested_strategy` 为空或为 `DIRECT`：选择 `DIRECT`，`reason_code="simple_no_tool"`；
3. `requested_strategy` 为 `REACT`、`PLAN_EXECUTE` 或 `MULTI_AGENT`：只有该 mode 已存在于组合根从 `GraphRegistry` 得到的 `available_modes` 时才返回对应 `StrategySelection`，否则在任何 Graph/Tool/Provider 调用前抛出 `STRATEGY_NOT_AVAILABLE_IN_S2`；

LangGraph config 固定为 `configurable.thread_id=run_id` 与 registration 的 `checkpoint_ns`。S2 组合根只能注入 `InMemorySaver`；缺失 Checkpoint、`thread_id`、namespace、checkpoint ID 或 Strategy 绑定不匹配时失败关闭。`resume_binding` 只保存恢复校验必需的稳定控制字段（例如未来 S4 的 input request ID 与 plan revision），不得含用户补充正文；对外 `CheckpointViewV1` 仍只映射三个 ID，不公开该内部 binding。builder 返回的 `GraphProgram` 适配器在其 `resume()` 内部才允许把已验证的 `resume_value` 转为 LangGraph `Command(resume=resume_value)`；Runtime 以外调用方不得导入或构造 `Command`。公开返回只使用 `CheckpointView`，不暴露 LangGraph `StateSnapshot`。

`GraphExecutionResult.next_status` 只能是当前 registration 的 `allowed_next_statuses`，否则以 `GRAPH_NEXT_STATUS_FORBIDDEN` 失败关闭。结果不变量固定为：`SUCCEEDED` 必须有 output 且无 failure；`FAILED/TIMED_OUT` 必须有 failure 且不得有成功 output；`WAITING_INPUT/CANCELLED` 不得有成功 output/failure；所有结果必须包含已成功保存的 Checkpoint、单调 `BudgetState` 和可信 Usage。Runtime 在返回结果前完成 Checkpoint；Harness 不接受 Graph 自报的 Run 状态字符串。

`InMemoryCancellationSignal` 按 `run_id` 持有 `asyncio.Event`，`request()` 幂等置位，`is_requested()` 用于每个节点/尝试前后检查，`wait_requested()` 用于与正在等待的 Tool、Provider 或未来 Specialist 协程竞争并即时唤醒取消；它不强杀线程，也不创建第二状态机。ToolRuntime、ModelRuntime 和 Graph 节点的等待上限同时受 `remaining_budget.timeout_ms`、自身 timeout 与取消事件控制，取消胜出后不得启动重试或新节点。

```python
class AgentRuntimeService:
    async def create_and_execute(self, request: CreateRunRequestV1) -> RunViewV1:
        raise NotImplementedError

    async def get_run(self, run_id: str, tenant_id: str) -> RunViewV1:
        raise NotImplementedError

    async def resume_run(
        self, run_id: str, request: ResumeRunRequestV1
    ) -> RunViewV1:
        raise NotImplementedError

    async def cancel_run(
        self, run_id: str, request: CancelRunRequestV1
    ) -> RunViewV1:
        raise NotImplementedError

    async def list_events(
        self, run_id: str, tenant_id: str, after_sequence: int = 0

        raise NotImplementedError
```

`create_and_execute` 固定顺序为：验证入站 → 幂等查询 → 生成 Run ID → `BudgetGuard.start()` 一次性确定 deadline → 写 CREATED/事件 → 转 QUEUED/事件 → 路由 → 从当前 registration 取得 schema/白名单/adapter，把入站 dict 深拷贝为不可变 `JsonObject` 并校验/归一化为 `StrategyPayload` → 转 RUNNING/事件 → 由 Harness 把 payload 的 schema/data 写入完整初始 State → 以完整 `selection` 调用唯一 `GraphRuntime.execute()`。API/调用方不得传入或预填 `AgentGraphState`，payload adapter 失败时 Graph/Tool/Provider 调用计数必须为零。Strategy payload 在同一 Run 生命周期内冻结：Checkpoint 保存同一值，resume value 只能补充中断请求，不能替换 strategy payload；事件、错误和公开响应不得回显 payload 正文。Runtime 必须先成功保存 Checkpoint 再返回；Harness 校验 `next_status` 与 output/failure 不变量，将 `budget_state/usage/checkpoint_id` 和目标状态用 CAS 写为权威 Run，再按事实原顺序追加 `checkpoint_saved`、治理事件和 `run_waiting_input/run_succeeded/run_failed/run_cancelled/run_timed_out`。这条“Checkpoint 成功 → Run CAS → Event 对外可见”的顺序适用于成功、等待、预算失败、取消和超时，不允许先发终态/等待事件后补权威状态。

`resume_run` 固定顺序为：同租户读取 → 必须为 `WAITING_INPUT` → 根据 Run 中 strategy 重建同一 `StrategySelection` → 读取并精确匹配 request 的 checkpoint ID/namespace/thread → 调用 registration 的 `ResumeValueValidator`（S4 可在自己的 registration 提供领域校验）→ `BudgetGuard.remaining()` 检查原 deadline/消费 → CAS `WAITING_INPUT → RUNNING` → 写 `run_resumed` → 调用 `GraphRuntime.resume()` → 按上一段相同的 Checkpoint/CAS/Event 顺序落结果。校验失败保持原 `WAITING_INPUT` 且不发 `run_resumed`；恢复不得创建新 Run、切换 Graph、重置预算或直接操作 LangGraph Snapshot。

`cancel_run` 固定顺序为：同租户读取并拒绝终态 → `CancellationSignal.request()` 幂等置位 → 写一次 `run_cancel_requested`。若 Run 为 `WAITING_INPUT`，已有 Checkpoint 即为权威恢复点，Harness 直接 CAS 到 `CANCELLED` 后写 `run_cancelled`；若为 `RUNNING`，当前 Tool/Provider/未来 Specialist 通过 `wait_requested()` 被唤醒，Graph 在节点前后观察信号、保存 Checkpoint 并返回 `next_status=CANCELLED`，再由 Harness CAS 状态并写 `run_cancelled`。重复取消不重复事件，取消后不得启动新节点或采纳迟到结果。

任一步预算不足均归一化为 `RunFailure(code="BUDGET_EXHAUSTED", category="budget", retryable=False, safe_message="运行预算已耗尽")`；绝对 deadline 到期目标状态为 `TIMED_OUT`，其余预算维度为 `FAILED`，两者均先写 `budget_exhausted` 再写对应终态事件。其他异常按稳定错误边界处理；若 Run 尚未创建，直接向 API 抛安全 4xx 错误。入站请求不能直接授予权限、Tool、模型候选或预算消费。

FastAPI 路由固定为：

```text
POST /v1/runs                    201，S2 同步执行后返回 RunViewV1
POST /v1/runs/{run_id}/resume    200，恢复原 Run；非 WAITING_INPUT 或 Checkpoint 不匹配返回 409
POST /v1/runs/{run_id}/cancel    200/202；等待态立即取消，运行态接受协作取消
GET  /v1/runs/{run_id}           200；不存在或跨租户统一 404
GET  /v1/runs/{run_id}/events    200 text/event-stream；支持 Last-Event-ID
GET  /health/live                200 {"status":"ok","mode":"s2_fake_in_memory"}
```

三个 POST 都要求 `X-Tenant-ID` 与 body `tenant_id` 一致；查询和事件要求 `X-Tenant-ID`。`Last-Event-ID` 仅接受正整数字符串或缺失，非法值返回 400 `INVALID_EVENT_CURSOR`。SSE `id` 使用事件 `sequence`，`event` 使用 `event_type`，`data` 使用 `RunEventV1.model_dump_json()`；S2 事件端点回放游标后的现有事件并在终态或 `run_waiting_input` 后结束，不保持生产长连接。

## 3. 验收标准

1. `POST /v1/runs` 的 Direct 请求在 Fake Provider 下通过同一 Harness 和 LangGraph Runtime 完成，状态严格为 CREATED→QUEUED→RUNNING→SUCCEEDED。
2. 固定 `synthetic_review/1` Workflow 通过 Context Builder、三份受治理 Prompt、一次 Synthetic Tool、两次模型调用、结构校验和 Checkpoint 完成，不存在隐藏第二执行链。
3. API、Direct、Workflow、Graph 节点、Tool 和模型均不能绕过 Harness；API 不直接依赖 LangGraph、Provider、Tool 或 Store。
4. S2 默认 Registry/Router 只选择 Direct/Workflow；未注册的其他策略以 `STRATEGY_NOT_AVAILABLE_IN_S2` 零副作用失败。测试证明显式注册后同一个 Router 可产生相应 `StrategySelection`，无需修改 S2 源码。
5. Prompt 版本、变量、输出 Schema、模型层级和最大长度可机器读取；未定义变量、路径穿越、超长和二次模板解释测试通过。
6. Context Builder 是唯一上下文入口，身份一致、来源信任、Tool 白名单和估算 Token 预算均受验证；外部内容不能改变治理数据。
7. `BudgetGuard` 对每个节点、Tool 和 Provider 尝试执行前后检查，remaining iteration/tool/input token/output token/cost 和首次确定的 absolute timeout 均单调；六类耗尽统一 `BUDGET_EXHAUSTED`，恢复不重置且耗尽后零重试/降级/后继调用。
8. Tool Runtime 在调用前完成注册、Schema、白名单、权限、副作用和 remaining budget 检查，在调用中同时受绝对超时与取消唤醒控制，在调用后执行预算/结果/大小/审计治理；所有拒绝用例证明零调用。
9. ModelPolicyRouter 按 fast/balanced/strong 逻辑层级和硬能力选择；只对可重试临时错误且 remaining budget 允许时最多降级一次，并保留候选、原因、尝试、Usage 和降级事实。
10. Provider 返回与异常完全归一化，上层看不到厂商对象、厂商配置键或原始异常；S2 只有显式脚本化 FakeModelProvider。
11. Direct/Workflow 共用显式 `GraphRegistry` 和一个 `GraphRuntime`；唯一 execute 签名为 `execute(selection, initial_state)`，只从 `selection.mode` 取策略；State 只含 JSON/msgpack 兼容数据，Checkpoint 使用 `run_id + s2:<strategy>:<version>` 隔离。
12. `GraphExecutionResult.next_status` 受 registration 白名单和 output/failure 不变量控制；Synthetic suspendable builder 证明 WAITING_INPUT、原 Checkpoint 恢复、运行/等待取消、TIMED_OUT 均复用同一 Harness 生命周期。
13. `CancellationSignal.wait_requested()` 能唤醒等待中的 Fake 调用；取消后不启动新节点、不重试、不采纳迟到结果，且事件顺序为 request accepted → checkpoint/Run 权威状态 → cancelled visible。
14. 每个 Run 具有单调、可游标回放的版本化事件；`strategy_event` 只接受冻结 evidence payload 白名单，SSE `Last-Event-ID` 不重复已确认事件，非法游标稳定拒绝。
15. 跨租户查询统一 404，错误与事件不泄露 Prompt、用户正文、resume value、Tool 参数、Provider 脚本、Secret 或内部异常。
16. AST 守卫证明全源码只有 `orchestration/**` 导入 LangGraph，S4 builder 归 `orchestration/builders`；新增包依赖方向、唯一 Runtime、S1 Agent 契约与既有测试全部回归通过。
17. 六组端到端验收在任何 S2 生产实现前已有真实 RED，最终有新鲜 GREEN；pytest、unittest、Ruff、mypy、compileall、架构和治理命令均记录实际数量、失败、错误和跳过。
18. 新增注释、Docstring、配置注释和项目文档为中文；所有测试数据为合成数据。
19. 交付报告明确说明 Fake/InMemory 证据只证明 S2 离线纵向闭环和通用扩展契约，不等于真实 Provider、数据库、网络、跨进程恢复、生产 SSE、S4 Multi-Agent 或业务 Agent 完成。
