# S3 运营领域内核实施计划

> **执行要求：** 按任务顺序实施；每项先执行 RED，再写最小 GREEN 实现，最后复跑对应门禁。项目永久不使用 Git：不得初始化、提交、分支、推送或运行 Git 差异；每个任务以实施前文件快照、实施后文件级差异包及进度账本取代提交记录。

**目标：** 在不运行任何真实业务能力的前提下，冻结可被 S2 主链、S4 Supervisor 和未来运营 Specialist 共同使用的运营任务、Profile、计划、证据、交付物、质量、场景包和领域错误契约。

**架构：** 新增内容全部位于 `agents/operation/contracts`，只依赖既有 `core` 与 S1 的 `CapabilityRequirement`。领域内核是纯不可变值对象和确定性校验：它不解析自然语言、不选择模型、不执行 Graph、不调度 Specialist、不访问网络/数据库/文件/对象存储。S2 依赖以窄 Protocol 表达，并只由测试目录中的 Fake 实现；S3 不提供任何真实适配器。

**技术栈：** Python 3.13、标准库 `dataclasses`、`enum`、`typing`、`unittest`、现有 `uv` 执行环境；不得新增依赖、锁文件、配置、服务进程或数据迁移。

### 跨阶段接口与唯一所有者

| 消费阶段 | S3 提供的唯一接口 | 消费约束 |
|---|---|---|
| S1 Registry/AgentSpec | `OperationPlanStep.task_type`、`required_capabilities`、`input_schema_version`、`output_schema_version`、`required_permissions`、`allowed_tools` | S4 候选必须同时满足 `task_type in AgentSpec.supported_task_types`、S1 `CapabilityRequirement` 的 all_of/any_of 语义、两个 Schema 版本分别精确相等、`required_permissions <= AgentSpec.permissions`、`allowed_tools <= AgentSpec.allowed_tools`；任何字段缺失或不匹配均失败关闭，不得靠 Agent ID 或业务类名推断。 |
| S2 主链 | `S2OperationIntentPort.normalize(OperationRequest) -> OperationTaskSpec`、`S2OperationPlanningPort.build_plan(OperationTaskSpec, OperationContext) -> OperationPlan`、`S2OperationAssemblyPort.assemble(OperationTaskSpec, OperationPlan, EvidencePack) -> DeliverableBundle` | S3 只拥有 Protocol 和测试 Fake；S2 才拥有真实适配器。身份链必须保留 `tenant_id/user_id/session_id/task_id/parent_task_id/operation_id`。 |
| S4 Supervisor | `OperationPlan`、`OperationPlanStep`、`FailureBehavior`、`EvidencePack`、`DeliverableBundle`、`OperationQualityReport` | S4 只编译、选择、派发、聚合，不复制或扩展这些领域字段；`required=False` 仅可与 `SKIP_WITH_WARNING` 配合，其他失败行为均为必需步骤。 |

def compile_scenario_plan(
    manifest: ScenarioPackManifest,
    task: OperationTaskSpec,
    context: OperationContext,
    plan_id: str,
) -> OperationPlan:
    """把已校验的场景步骤逐字段编译为不可执行计划。"""
    validate_scenario_pack(manifest)
    plan = OperationPlan(
        contract_version="operation-plan/1",
        plan_id=plan_id,
        task_id=task.task_id,
        strategy=manifest.recommended_strategy,
        source_template_id=manifest.plan_template.template_id,
        source_template_version=manifest.plan_template.semantic_version,
        success_conditions=manifest.plan_template.success_conditions,
        steps=tuple(
            OperationPlanStep(
                step_id=step.step_id,
                task_type=step.task_type,
                depends_on_step_ids=step.depends_on_step_ids,
                required_capabilities=step.required_capabilities,
                input_schema_version=step.input_schema_version,
                output_schema_version=step.output_schema_version,
                input_reference_ids=step.input_reference_ids,
                context=context,
                allowed_tools=step.allowed_tools,
                required_permissions=step.required_permissions,
                budget=step.budget,
                expected_deliverable_ids=step.expected_deliverable_ids,
                quality_check_ids=step.quality_check_ids,
                required=step.required,
                failure_behavior=step.failure_behavior,
            )
            for step in manifest.plan_template.steps
        ),
        total_budget=manifest.budget,

    )
    validate_operation_plan(plan)
