# S7 真实集成与验收实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 在 S1～S6 已完成并通过阶段门禁的前提下，把运营 Agent 的离线 Fake/InMemory 证明扩展为可选择、可授权、可清理、可审计的真实集成验证，并用固定离线回归、真实 Provider/基础设施 Gate、质量回归和人工验收共同给出不越界的 S7 结论。

**架构：** 离线回归始终是无网络、无 Secret、无外部副作用的必跑基线；真实 DeepSeek、服务端 `web_search`、PostgreSQL/pgvector、Redis/Taskiq、COS 及上传文件链路分别放入默认关闭的独立 Gate。每个 Gate 必须先完成纯本地静态配置预检；任何 PING、握手、HEAD、连接或模型请求都属于网络动作，必须再取得独立、低预算的探测授权；写入或可能计费的调用另取动作级授权。所有授权以唯一 `run_stamp` 隔离资源，运行后先清理再形成脱敏证据；任一真实 Gate 不可用都不能阻断离线回归，也不能由 Mock 结果代替真实结论。

**技术栈：** CPython `>=3.13,<3.14`、uv、pytest、Pydantic v2、pydantic-settings、OpenAI Python SDK/HTTPX、DeepSeek OpenAI-compatible Responses API、SQLAlchemy 2 async、Psycopg 3、PostgreSQL/pgvector、LangGraph PostgreSQL Checkpoint、redis-py async、Taskiq/Taskiq Redis、腾讯云 `cos-python-sdk-v5`、FastAPI multipart、Docling 2.x、pypdf/pypdfium2、Pillow、PaddleOCR/PaddlePaddle 3.x、PP-StructureV3、Polars、JSONL；只引入已批准组件，补丁版本以 Windows + Python 3.13 实际解析后写入 `uv.lock`。

### 1.3 结果口径

S7 总体状态与单 Gate 结果分开记录：

- `IMPLEMENTATION_READY`：Task 1～11 的实现、配置、SQL/fixture/文档治理、G0 离线回归和静态门禁均通过；允许所有真实 Gate 尚未执行，但绝不能写成“真实验收完成”。
- `REAL_ACCEPTANCE_COMPLETE`：在 `selected_real_gates` 非空的前提下，所有被选择的真实 Gate 都已取得对应探测及写入/计费授权、实际通过且清理回读为零；任一所选 Gate 为部分通过、失败、未执行或阻断都不能达到此状态。所有真实 Gate 全部跳过时最高只能是 `IMPLEMENTATION_READY`。

| 状态 | 精确定义 | 报告要求 |
|---|---|---|
| 通过 | Gate 已获授权并实际执行；全部必需断言通过；外部资源清理通过；证据清单完整 | 记录命令、退出码、测试数、非敏感版本、调用/写入计数、清理状态 |
| 部分通过 | Gate 已执行且一部分能力通过，但存在明确缺失范围；该 Gate 不视为放行 | 列出通过子项、失败子项、对业务结果的影响和是否已清理 |
| 失败 | Gate 已执行且必需断言、隔离、安全或清理任一失败 | 停止依赖该 Gate 的后续步骤，保留脱敏错误和人工处置责任 |
| 未执行 | 前置、配置键、授权、费用确认或资源不可用；从未发起外部动作 | 写明准确原因；不得写成失败、通过或“Mock 已验证真实能力” |
| 阻断 | S1～S6 契约不一致、出现越权/泄密/跨租户/业务库风险或无法安全清理 | 停止全部相关 Gate，先走架构/安全/数据治理评审 |

任何 `PARTIAL` 业务输出必须同时包含 `completed_scope`、`missing_scope`、`warning_codes` 和稳定错误；不得以 HTTP 200、模型有文本、任务出队或对象存在作为业务成功。

即使 G0～G7 全部通过，S7 也只能声明“在本次授权、合成/脱敏数据、指定 Windows + Python 3.13 环境和调用上限内，选中的真实集成与代表场景通过”。以下仍不得声明：

- 长时间运行、并发、吞吐、容量、压力、SLO、告警或成本预测；
- DeepSeek、搜索、模型 ID、价格、配额或响应格式的长期稳定性；
- 模型返回 URL 的网页正文已读取、交叉核验或互联网事实绝对真实；
- 所有 PDF/Office/图片版式均可正确解析，或无恶意文件扫描器时文件已安全；
- 用户正式数据、个人信息、受限数据或生产 Bucket/数据库已获准处理；
- 运营内容已发布、消息已发送、账号已操作或效果指标已经发生；
- 付费商业数据源、网页爬虫、Text2SQL、业务库直连、云 OCR、MCP Server、监控平台已实现；
- 人工评审通过等于法律、品牌、合规或最终业务批准。

## 7. 停止与回滚条件

出现以下任一情况立即停止相关 Gate，并执行该 Gate 已批准的清理：

1. S1～S6 实际接口与计划无法加法兼容，或需要修改公共生命周期/状态语义；
2. `.env` 值、Secret、连接串、签名 URL、Bucket/Region、模型值或用户正文进入输出、日志、异常、测试快照或证据；
3. 目标资源无法证明是 Agent 自有逻辑范围，或数据库查询将触及业务 Schema；
4. `vector` 未安装且需要 `CREATE EXTENSION`，或 S7 SQL 超出已展示脚本；
5. Redis/COS/PostgreSQL 前缀/Schema 无法精确限定，或清理回读不为零；
6. DeepSeek/web_search 费用、配额、合同或数据处理边界未知，或实际调用数将超过授权；
7. 需要打开网页、引入付费搜索/商业数据、切换云 OCR、添加第二解析/OCR/Graph Runtime；
8. 文件签名/MIME/扩展冲突、文件超限、解析器执行主动内容、用户文件未经同意；
9. 真实测试出现跨租户读取、越权 Tool、模型 SQL、平台发布或外部消息副作用；
10. 为通过测试需要降低既有安全/质量阈值、无限重试、扩大超时或隐藏失败。

回滚只能使用实施前文件快照、受审 SQL `04-rollback.sql`、精确 Redis/COS 前缀和本地隔离目录清理；不得使用 Git，也不得执行数据库/缓存全局清理。回滚后必须复跑 G0，若 G0 不能恢复为全绿，S7 状态保持失败或阻断。

## 8. 双状态完成定义

S7 必须分别判定，禁止用一个模糊“完成”覆盖实现就绪和真实验收：

1. Task 1～11 都有有效 RED/GREEN、文件清单、文件级审查和本次新鲜证据；
2. S1～S6 实际交付和版本对照完成，所有离线回归、静态、依赖和治理门禁通过；
3. 每个真实 Gate 都被准确标成通过、部分通过、失败、未执行或阻断，不存在含糊的“可用”结论；所有真实 Gate 未选择/未执行时只能达到 `IMPLEMENTATION_READY`；
4. 实际执行的 Gate 均有本次授权、调用/写入上限、运行证据和清理回读；
5. 固定质量集和至少四类人工业务样本有结果，失败与部分范围没有被隐藏；
6. `.env` 和用户文件的值/正文从未进入实现变更或证据；
7. 生产边界、停用手册、回滚步骤、未验证项和明确非目标完整；
8. 最终报告的结论不超过证据，并由项目负责人决定是否批准下一阶段或生产专项；`REAL_ACCEPTANCE_COMPLETE` 还要求 `selected_real_gates` 非空且每项均通过、清理回读为零，否则不得设置。

计划获批、`IMPLEMENTATION_READY`、`REAL_ACCEPTANCE_COMPLETE`、单个真实 Gate 通过、人工样本通过和生产可用是六个不同状态。任何 S7 状态都不自动改变生产配置，所有真实 Gate 在验收结束后继续保持关闭。
