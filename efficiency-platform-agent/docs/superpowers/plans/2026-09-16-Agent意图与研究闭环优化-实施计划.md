## Global Constraints

- Python >=3.13,<3.14；不调整构建后端、现有向量模型、维度和命名空间。
- LangGraph 是唯一 Graph Runtime；跨专家只能由中央 Supervisor 调度。
- ContextBuilder 是唯一上下文入口；模型只能通过 ModelRuntime；出网必须经过 Tool Runtime 和 Provider。
- core 仅用标准库；contracts 不依赖编排；Provider/Persistence 不反向依赖 Agent、Harness 或 Orchestration。
- 只使用免费且经可用性验证的 API、RSS/Atom、公开页面；paid/unknown/额度无法保证零收费一律拒绝。
- 免费额度耗尽停止或换已准入免费来源；禁止付费兜底、自动注册、绑定支付、绕过访问控制。
- 模型调用费用单独计账，复用现有授权；研究、解释、生成共享 Run 总预算，禁止各自重新满额。
- 不读写真实 .env，不输出连接串或凭据；不执行共享 DDL，不自动发布内容。
- V1 契约和 RunStatus 保持语义；COMPLETE/PARTIAL/NO_MATCHES/FAILED 仅为研究领域状态。
- 自维护注释、Docstring、配置说明使用中文；插件显式注册，不动态导入。
- 原计划编写轮次只有文档交付；2026-09-16 后续明确指令授权逐阶段执行。任务仅以进度账本和实际测试证据为完成记录。

## 3. 执行约定与测试组织

每个任务按“红灯测试 → 最小实现 → 绿灯回归 → 文件级评审 → 证据账本”执行。代码块是任务的关键测试/算法切片，完整字段规则以 C02 契约清单和关联设计为准；不得把示例常量作为业务实现。

- 每个勾选步骤内按单个测试用例或函数推进，约 2—5 分钟一小步；大型任务禁止先写完整模块再补测试。
- 红灯必须是目标行为不满足，不能以导入失败作为唯一红灯证据；新模块可先验证导入失败，然后补签名，再保留行为失败。
- 新增包只加无副作用 `__init__.py`；测试使用根 `tests/conftest.py` 显式加载公共 fixtures。
- 新增 `tests/support/research_v2_cases.py` 提供 `run_case(case_id: str) -> CaseResult`，fixture 名 `v2_case`。它驱动真实被测组件，外部模型/HTTP/Clock/Repository 才用 Fake；禁止读取 expected 生成 actual。
- CaseResult 是测试专用只读对象：`intent`、`outcome`、`errors`、`source_attempts`、`requests`、`usage`、`events`、`calls`。每个任务须在自己的测试文件明确输入、Fake 返回及断言；禁止把业务逻辑藏进 fixture。
- `tests/support/intent_v2_cases.py` 提供 `intent_case(case_id: str) -> IntentCaseResult`；结果包含 frame、decision、brief、provider_calls、tool_calls、safe_error、snapshots。案例名称及输入由意图子计划规定。
- 固定外网夹具使用保留域 `news.example`，测试 transport 不进行 DNS/真实连接；安全测试单独用可控 resolver/connector。普通 pytest 默认 0 外网调用。
- 每任务将实际文件、红绿命令、退出码、风险、未验证项记录到新增 `docs/superpowers/sdd/intent-research-v2/实施进度账本.md`，状态只可为未开始/进行中/离线通过/集成通过/真实验收通过/阻塞。
- 本轮及后续计划不自动提交或推送。阶段使用文件快照/差异包评审；需要 Git 交付时另按用户授权、精确文件白名单执行，绝不批量纳入父目录 Java/UI/产品资料。
