## 2. Task 4 修改文件与验证范围

- `tests/api/test_run_sse_integration.py`：通过实际 Conversation API、意图解释器、ModelRuntime、DIRECT LangGraph、Harness 和 HTTP SSE 路由验证本地和模型对话。只替换外部 Provider；没有替换被测内部事件发布逻辑。
- `tests/governance/test_operation_chat_acceptance.py`：通过完整版本化 HTTP/SSE 响应验证现有验收脚本接受 DIRECT 普通正文，交付物与引用计数均为零，摘要不回显正文。
- 本进度文档与对应实施计划：同步证据、勾选及未验证边界。

成功协议断言包括：`run_started` 先于 `assistant_started`，后者先于 `assistant_delta`，`stream_done` 唯一且为最后事件；序号连续、Run 身份一致、拼接正文与权威输出相等；输出仅有 `content`，无 `deliverable` 或澄清事件；终态游标续传在限定时间内返回空响应。

取消协议从 HTTP 入口受理取消后释放受控模型，确认内部取消请求先于取消终态，公开 SSE 不包含 assistant 正文、交付物或成功结果，最后为 `stream_done(status=cancelled)`。这是迟到结果抑制验证，不宣称强制中断厂商在途网络请求已实现。

## 3. 测试先行与故障检测证据

### 3.1 首轮测试编排修正

新增三个完整 HTTP/SSE 用例后运行：

```powershell
uv run pytest tests/api/test_run_sse_integration.py -k conversation_direct -q
```

结果：退出码 1，`3 failed, 14 deselected in 2.19s`。

失败属于测试编排错误：将内部 `run_succeeded`、`run_cancel_requested`、`run_cancelled` 当作公开 SSE 名称。既有 `RunStreamEventV1` 不包含这些名称，Harness 将终态映射为 `stream_done`。修正后分别验证内部事件顺序与公开 SSE 顺序，没有改生产代码，也不把这次编排错误算作有效产品 RED。

### 3.2 不落盘故障注入

Task 4 不新增生产行为，已有实现正常时新增回归直接通过。按测试规范允许的等价故障注入，在独立 Python 进程内替换 `EventHub.publish_next`：吞掉正常 `assistant_delta`，并在取消的 `stream_done` 前注入迟到正文。实际文件不变，进程退出后注入自动失效。

可重现命令：

```powershell
$task4Probe = @'
import pytest
from efficiency_platform_agent.runtime.event_hub import EventHub
original = EventHub.publish_next
async def faulty_publish(self, run_id, event, payload=None):
    if event == 'assistant_delta':
        return None
    if event == 'stream_done' and payload and payload.get('status') == 'cancelled':
        await original(self, run_id, 'assistant_delta', {'delta': 'injected-late-content'})
    return await original(self, run_id, event, payload)
EventHub.publish_next = faulty_publish
raise SystemExit(pytest.main(['tests/api/test_run_sse_integration.py', '-k', 'conversation_direct', '-q', '--tb=short']))
'@
uv run python -c $task4Probe
```

结果：退出码 1，`3 failed, 14 deselected in 2.65s`。本地/模型用例均检出缺失 `assistant_delta`，取消用例检出不允许的迟到 `assistant_delta`。该结果证明新增断言可以发现这两类协议回归，不表示正常生产实现存在这些缺陷。

1. 最终 Agent 全量离线命令 `uv run pytest -m "not real_external" -q` 退出码 0：`867 passed, 266 subtests passed`。两条 warning 分别来自 Starlette TestClient 的 AnyIO 别名弃用提示与 Polars Excel 未来返回类型提示，不是本次回归。

3. 前端全量 Vitest 为 26 个文件、71 项测试通过；专项 23 项、typecheck、lint 和生产构建均通过。新增回归覆盖“新请求已提交但新 Run 尚未绑定”窗口，旧 Run 的迟到 SSE 不再污染新轮。构建只有既有大分包提示，不在当前性能阶段处理。
4. 真实 DeepSeek 普通问答为 `succeeded/direct`、`degraded=false`，共收到 41 个正文 delta；首片早于 `stream_done` 约 160ms，拼接正文与保存正文一致。
5. 浏览器联调实际观察到无文字三点动效、首片后部分正文逐字出现、最终 Markdown 正文和零控制台错误/警告。
6. 真实联网研究成功仍未通过：明确研究请求正确进入 `multi_agent`，但现有能力返回 `RESEARCH_UNAVAILABLE`。失败透明且没有伪正文、交付物或引用。
7. 内存提交、进程内 EventHub 与 Checkpoint 不等同于跨进程持久化恢复；生产部署、容量治理、性能压测、监控和长期稳定性按既定裁决后置。
8. 第二模型候选尚未配置，因此真实自动降级仍未验证。
9. 旧的非 DIRECT 结果呈现器在自定义输出流中断后的补偿分支可能重复已展示前缀；当前 DIRECT 真实流不经过该分支，后续若将它用于生产增量展示，必须先改为后缀补偿并补协议测试。
