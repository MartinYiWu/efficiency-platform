# Intent / Research V2 发布与回滚手册

| 属性 | 内容 |
|---|---|
| 状态 | 离线演练版；禁止用于生产切换 |
| 更新时间 | 2026-09-17 |
| 适用范围 | Agent 侧 Intent V2 / Research V2 新会话灰度与安全回退 |
| 不包含 | Java/UI、部署、共享 DDL、账户注册、真实来源开启、自动发布 |

## 一、发布前硬条件

以下条件必须全部满足，否则保持 `config/research_pipeline.toml` 的 V1、memory、零租户状态：

1. X01 隔离 PostgreSQL 双连接、进程重启、租户隔离、保留期和 `UNKNOWN_OUTCOME` 策略通过，且生产 DDL 另获授权。
2. X04 至少三次固定模型/Prompt 评测达到指标；五类真实请求完成；来源费用、权限、Schema、限流、历史范围和存储边界逐项 VERIFIED。
3. 服务端 `BudgetLease` 与本次批准预算原子绑定；失败、超时、迟到结果也进入 Usage，不能只在 CLI 报告中写预算数字。
4. 真实安全连接器满足 IP 固定、TLS SNI、证书验证、禁环境代理、逐跳重定向授权与字节/次数限制。
5. 明确一个测试租户、观察负责人、开始/结束时间、模型预算、来源配额和回滚责任人；不得用 `rollout_mode=all` 做首次生产灰度。

当前第 3 条已有默认不挂载的内部入口和任务级租约继承离线证据；测试内存 Binder 会被生产工厂拒绝，因此仍需 X01 持久化 Binder、跨进程恢复和 `UNKNOWN_OUTCOME` 验收，不能据此放行。

## 二、配置与版本冻结

仓库默认配置：

```toml
[pipeline]
intent_pipeline_version = "intent-v1"
research_pipeline_version = "research-v1"
research_replan_enabled = false
research_source_allowlist = []
research_policy_version = "research-policy/disabled"
state_backend = "memory"
rollout_mode = "tenant_allowlist"
rollout_tenant_allowlist = []
```

真实灰度时必须同时切换 Intent/Research 版本、postgres 状态后端、已批准来源、策略版本和单租户白名单；单边 V2 仍视为 V1。`tenant_allowlist` 模式启用 V2 时空名单会配置失败，重复/空租户 ID 也会失败。

适配器在会话首次进入协调器时同时冻结启用和禁用决策：

- 已冻结 V2 的会话在全局关闭后仍使用原 V2 快照，不交给 V1 checkpoint。
- 关闭期间冻结为 V1 的会话在重新开启后仍保持 V1，不自动升级或重解释。
- 租户不在灰度名单时冻结为 V1；之后扩大名单只影响尚未冻结的新会话。
- `research_replan_enabled` 修改只影响新会话；既有会话语义版本不被运维开关改写。

当前冻结表仅为进程内状态。X01 已证明 PostgreSQL 事实可跨连接/新进程恢复，但会话版本表本身仍未部署为多副本共享配置；不能仅据此生产发布。

## 三、灰度步骤

1. **预检**：运行 X04 三个默认安全命令，确认真实执行仍由授权控制；检查批准记录、来源目录、模型/Prompt 版本和预算租约。
2. **单租户启用**：只加入一个测试租户，来源 allowlist 只含已 VERIFIED 项；不得同时启用旧 DeepSeek Web Search gate。
3. **意图影子**：如另获模型预算，只比较 Intent V1/V2 结构化结果；影子分支不得创建 Run、调用来源、写 checkpoint 或生成用户输出。
4. **有效请求观察**：至少 20 个有效请求并覆盖“昨天 AI 新闻、上周指定主题、精确 5 条、基于前文改写、普通聊天”五类。20 只是观察下限，不替代质量指标。
5. **逐项审计**：每个请求记录版本快照、时间窗、来源尝试、补采原因、状态、Usage、引用覆盖、错误事件合并与人工复核。
6. **扩大范围**：只有本窗口零硬停止事件且 X04 指标维持门槛，才能提出下一租户批准；本手册不自动扩大。

## 四、立即停止条件

出现任一条件立即禁止新 V2 会话并保留全部证据：

- 跨租户读取/写入、越权工具或未准入来源调用；
- 收费未知、超免费配额后计费或预算超发；
- 不同事件错误合并，或正式事实没有可定位引用；
- V2 checkpoint 被交给 V1 解释、证据被删除或时间窗被擅自扩大；
- 取消/硬截止被投影成成功，或未知结果被重复执行。

只有纯性能问题且没有正确性/安全问题时，才可先对**新会话**关闭补采。既有会话仍按冻结快照运行；若必须中止，则使用正常取消路径并保留 checkpoint/evidence，而不是篡改版本。

## 五、回滚顺序

| 级别 | 动作 | 新会话 | 已冻结会话 | 证据 |
|---|---|---|---|---|
| R1 性能降级 | `research_replan_enabled=false` | 不再补采 | 保持原快照；必要时显式取消 | 保留 |
| R2 关闭 V2 | 两个 pipeline version 同时切回 V1 | 走 V1；无合法旧来源时明确研究不可用 | V2 继续完成/等待/取消，不交给 V1 | 保留 |
| R3 来源隔离 | 从新版本来源 allowlist 移除问题源并撤销来源授权 | 禁止新调用 | 已发起调用按预算/迟到规则结算，不重复执行 | 保留 |
| R4 全面停止 | 停止新增灰度租户并取消受影响运行 | 不创建新 V2 Run | 正常取消，标记 UNKNOWN_OUTCOME 时等待人工决策 | 保留 |

回滚后不删除 checkpoint、Brief、Attempt、Evidence、Usage 或授权记录。恢复时只对新会话使用新配置；旧会话仍按原版本继续或由用户重新发起。

## 六、演练结果

`tests/acceptance/test_research_v2_rollout.py` 已覆盖：V2 关闭后活动快照与证据不变、V1 冻结会话不被重新开启升级、补采开关按新会话生效、单租户白名单，以及运行中的 V2 成功、等待补充、协作取消三条真实 Run 状态分支；三条分支均保持 V1 解释器/Checkpoint 读取为 0，并保留 Checkpoint、Run 事件和 Evidence。`test_factory_research_gate_off_fails_without_model_fallback` 证明 V2 与合法旧研究路径都不可用时明确返回 `RESEARCH_UNAVAILABLE`，不以普通模型伪造在线研究。

真实单租户灰度另执行 20 个请求、五类各 4 次；来源只采集一次。未准入来源停止探针触发后，新 dispatch 被拒绝且 PostgreSQL 调用数保持 35→35。X01/X04/X05 前置均已通过，Agent 侧阶段关闭；生产配置切换和部署仍需独立流程。
