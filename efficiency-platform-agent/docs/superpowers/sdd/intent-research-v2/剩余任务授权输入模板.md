# 剩余任务授权输入模板

本文件用于项目负责人提供明确授权，不是授权记录本身。尖括号占位符使示例故意无效，不能直接传给脚本；不要在仓库中填写数据库连接串、API Key、模型密钥或其他凭据。

## 一、X01 隔离 PostgreSQL 与策略授权

请以文字确认以下字段：

```text
authorization_scope: X01 isolated PostgreSQL integration only
approved_by: <项目负责人标识>
approved_at: <带时区时间>
expires_at: <带时区失效时间>
database_environment: <明确的临时隔离环境名称；连接凭据通过既有密钥通道提供>
agent_schema_name: <Agent 独立 Schema 名>
migration_directory: sql/changes/20260916_001_意图与研究V2/
allowed_actions: [precheck, create_agent_schema_objects, migrate, verify, rollback_test]
retention_policy: {html_days: <是否批准 7>, excerpt_days: <是否批准 30>, metadata_days: <是否批准 90>}
unknown_outcome_policy: <保守计费；Provider 可查询时按 action fingerprint 恢复；不可查询时是否允许策略控制重试>
shared_schema_access: false
production_access: false
```

缺少任一范围字段时不执行 DDL。连接信息不得写入本文件、任务报告、命令输出或 Git 管理文件。

## 二、X04 来源只读探测授权

脚本接受 `x04-source-read-authorization/1`。项目负责人应确认来源 ID、时间窗和动作；实际 JSON 只放入受控本地授权路径，不提交仓库。

```json
{
  "version": "x04-source-read-authorization/1",
  "authorization_id": "<唯一授权ID>",
  "approved_by": "<项目负责人标识>",
  "approved_at": "<ISO-8601带时区时间>",
  "expires_at": "<ISO-8601带时区时间>",
  "allowed_actions": ["source_read"],
  "allowed_source_ids": ["<从五个候选中明确选择的source_id>"]
}
```

可选候选仅为：`fixture_official_feed`、`fixture_arxiv`、`fixture_gdelt`、`fixture_github_releases`、`fixture_hacker_news`。授权不会自动把来源改为 VERIFIED；仍须先补齐实时 Schema、时间、限制和存储边界记录，再显式开启配置。

## 三、X04 真实模型/五类链路授权

真实验收使用 `x04-live-authorization/1`，要求正预算、固定租户和冻结用例。模型密钥由既有服务端密钥机制读取，不出现在授权 JSON 或客户端请求中。

```json
{
  "version": "x04-live-authorization/1",
  "authorization_id": "<唯一授权ID>",
  "approved_by": "<项目负责人标识>",
  "approved_at": "<ISO-8601带时区时间>",
  "expires_at": "<ISO-8601带时区时间>",
  "allowed_actions": ["model_evaluation", "source_read"],
  "allowed_case_ids": [
    "yesterday_ai",
    "last_week_topic",
    "exact_five",
    "rewrite_wechat",
    "ordinary_chat"
  ],
  "allowed_tenant_ids": ["<测试租户ID>"],
  "max_budget_microunits": "<项目负责人批准的正整数>"
}
```

还需文字冻结：`model_id`、`prompt_versions`、`dataset_version=2026-09-16.1`、三轮独立运行要求、失败调用是否计费、验收服务本机环回地址及端口。客户端只能发送授权 ID、用例 ID 和申请预算，不能发送授权正文。

## 四、X05 单租户灰度授权

```text
authorization_scope: X05 single-tenant canary only
approved_by: <项目负责人标识>
approved_at: <带时区时间>
expires_at: <带时区失效时间>
tenant_id: <与X04一致的单个测试租户>
deployment_window: <开始和结束时间>
minimum_valid_requests: 20
required_case_coverage: [yesterday_ai, last_week_topic, exact_five, rewrite_wechat, ordinary_chat]
shadow_intent_only: true
shadow_research_collection: false
observer: <观察负责人>
rollback_owner: <回滚负责人>
hard_stop_authority: <可关闭新V2会话并正常取消受影响运行的负责人>
allowed_production_changes: <精确配置或部署范围>
```

X01 和 X04 未通过时，该授权不得执行。首次灰度不得使用 `rollout_mode=all`；影子分支不得重复采集、创建 Run、写 checkpoint 或产生用户输出。

## 五、授权后的执行顺序

1. 先验证授权格式、范围、有效期和秘密隔离；不合格则零外部 I/O 退出。
2. X01 在隔离数据库完成预检、迁移、双连接/重启测试、验证和回滚演练。
3. X04 先逐源有限只读探测并完成准入，再执行三轮模型评测和五类真实链路。
4. X05 最后执行单租户灰度、20 请求观察、硬停止演练和阶段关闭审查。

任何一步失败都不自动扩大来源、预算、租户、数据库或部署权限。
