# R06 事件聚合、来源独立性与排序任务简报

| 属性 | 内容 |
|---|---|
| 任务 | R06 |
| 状态 | 离线通过 |
| 依赖 | R05 离线通过 |
| 范围 | Agent 侧事件候选聚合、来源家族解析、importance/heat/recency 可解释排序 |

## 不变量

1. 文档相似不等于事件等价；先按可信实体提示、相邻日期和显式产品版本形成最多 30 条的有界桶，再由语义判别提出事件成员。
2. 模型只提出成员 ID、事件类型、产品版本、实体和合并依据；程序验证 brief/hash/Prompt 版本、未知 ID、重复分配、集合完整性以及类型/版本冲突。
3. 类型或版本冲突、语义不确定、没有被合法提案覆盖的文档均保持为独立 singleton，不为凑数量或排名硬合并。
4. 每个输入文档必须且只能进入一个最终事件；stable event_id 由 Brief 与成员事实确定，不依赖模型自由文本或输入顺序。
5. 来源家族根据已知 ownership_group、同发布者、同规范 URL、同文通稿和 primary 原始来源合并；不同域名不自动视为独立，UNKNOWN 不满足独立佐证门槛。
6. importance 只接受枚举等级与解释码；recency 只用事件时间；相同值以 stable event_id 排序。
7. heat 只使用带平台、指标与观测时间的实测值，按平台与指标分别归一化；缺失是 UNKNOWN，不等于 0，不直接相加为“全网热度”。
8. 没有至少两个可比时间点不得生成涨幅/趋势标签；当前快照只能标记为“当前平台归一化热度”。
9. 本任务不抽取 Claim、不接受 Evidence、不宣布 COMPLETE，也不启用真实模型或公网来源。
