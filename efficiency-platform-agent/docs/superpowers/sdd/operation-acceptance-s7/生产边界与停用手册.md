# S7 生产边界与停用/回滚手册

## 人工验收评价维度（十项）

1. 需求理解与范围完整性
2. 输出 Schema 与必填字段
3. 事实来源关联与可追溯性
4. 多平台成品独立性
5. 内容质量与可读性
6. 部分失败范围披露
7. 预算、Tool 与权限边界
8. 租户隔离与数据最小化
9. 敏感信息与提示注入防护
10. 清理回读与证据完整性

每项只能填写“通过”“需修改”或“拒绝”三态，固定记录验收人、时间、输入摘要和稳定 issue_id。每个交付物最多两轮修订；第二轮仍不合格则返回 `QUALITY_NOT_MET` 或明确部分结果，不扩大权限和费用。

## 生产边界

S7 只证明指定 Windows + Python 3.13、合成/脱敏数据和本次授权上限内的行为。不得据此声明生产部署、高可用、性能容量、业务库访问、平台发布、消息发送、付费数据源或法律合规批准。所有真实 Gate 验收后保持关闭。

## 停用与回滚顺序

1. 停止接收新任务并标记 Gate 为关闭。
2. 取消或等待在途 Run，保存脱敏证据。
3. 关闭模型、搜索、数据库、Redis、COS 客户端和 Worker。
4. 使用 `04-rollback.sql` 删除精确的 S7 Schema，禁止全库操作。
5. 按 `s7:{run_stamp}:` 精确前缀清理 Redis 并回读为零，不得执行 FLUSHDB/FLUSHALL。
6. 按 `s7/{run_stamp}/` 精确前缀删除 COS 对象并回读为零。
7. 删除本地隔离文件和临时目录，核对无用户正文残留。
8. 记录每一步执行者、时间、结果和失败原因。
9. 发现残留、跨租户或未授权副作用时立即阻断后续 Gate。
10. 回滚后复跑 G0 离线回归，未全绿则保持失败/阻断状态。

## 恢复边界

回滚只允许使用实施前快照、精确 SQL 和资源前缀清理；不得使用 Git、全局缓存清理或未经批准的替代 Provider。
