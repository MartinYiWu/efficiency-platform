# S4 依赖对照表

> 本表记录 S4 实施前对 S2、S3 实际接口的只读核验结果。项目永久不使用 Git；本表以文件路径、公开类型和离线测试作为证据。

| S4 计划假设 | 当前实际接口 | 适配位置 | 结论 |
|---|---|---|---|
| S2 统一执行入口为 `GraphRuntime.execute(selection, initial_state)` | `src/efficiency_platform_agent/orchestration/runtime.py` 提供 `GraphRuntime.execute(selection, initial_state)`，并返回 `GraphExecutionResult` | S4 Task 7 的唯一 LangGraph Builder/Runtime 注册 | 通过 |
| S2 提供 Graph 注册 | `src/efficiency_platform_agent/orchestration/registry.py` 提供 `GraphRegistration`、`GraphRegistry.register`、`GraphRegistry.get` | S4 组合根注册 `MULTI_AGENT` | 通过 |
| S2 提供恢复与取消端口 | `src/efficiency_platform_agent/orchestration/contracts.py`、`cancellation.py`、`checkpoint.py` 提供恢复、Checkpoint 和取消相关契约 | S4 只消费，不复制生命周期 | 通过，真实持久化未验收 |
| S2 提供运行结果和可信 Usage | `src/efficiency_platform_agent/orchestration/contracts.py` 的 `GraphExecutionResult` 携带 `usage`；`core/runtime.py` 提供 `UsageSnapshot` | S4 预算账本仅接受运行时事实 | 通过，真实 Provider Usage 未验收 |
| S3 Step 含任务类型、Schema、权限、工具、required 和 failure behavior | `src/efficiency_platform_agent/agents/operation/contracts/planning.py` 的 `OperationPlanStep` 已提供上述字段 | `agents/operation/supervisor/planning.py` 无损编译为 `TaskNode` | 通过 |
| S3 提供任务、上下文、证据、交付物和场景契约 | `agents/operation/contracts/task.py`、`profiles.py`、`evidence.py`、`deliverables.py`、`scenarios.py` 已冻结值对象 | S4 仅引用并组合，不复制字段 | 通过 |
| S3 提供 intent/planning/assembly 端口 | `agents/operation/contracts/ports.py` 定义对应 Protocol | S4 SupervisorDependencies 注入端口 | 通过，当前仅 Fake 离线验证 |
| S1 Agent 入口保持稳定 | `core/ports.py` 的 `AgentPlugin.run(task: SupervisorTask) -> RunResult`；`core/run.py` 提供 `SupervisorTask` | `TaskDispatch` 只做不可变包装 | 通过 |
| S4 核心层不得引入上层或框架 | `core/multi_agent.py` 仅依赖标准库和 `core` 既有契约 | 架构测试 `test_core_contracts.py` | 通过 |

## 门禁结论

- S2、S3 的离线契约均已存在，未发现需要反向修改前序阶段的阻断项。
- S4 可以开始实现核心 DAG、预算和 Supervisor 组件。
- 真实模型、网络、数据库、Redis、COS、生产 Checkpoint 和部署行为仍不在 S4 离线实施范围内。
