## 2. 需求到测试追踪

| 需求 | 主要实现 | 测试证据 | 结论 |
|---|---|---|---|
| 中央 Supervisor 独占调度 | `selection`、`dispatch`、`scheduler`、Supervisor nodes | 架构守卫、调度单元测试 | 离线通过 |
| Specialist 禁止点对点调用 | S1 `SupervisorTask` 边界、目录守卫 | 多 Agent 架构测试 | 离线通过 |
| 入站只提交 OperationRequest | payload adapter、请求解码节点 | 节点测试、验收预填拒绝 | 离线通过 |
| 计划由 S3 三端口构造 | intent/context/planning/assembly 节点 | Fake 三端口闭环 | 离线通过 |
| DAG、预算和并发受平台上限约束 | planning、budget、scheduler | 对应单元测试 | 离线通过 |
| 六维 Specialist 匹配 | `SpecialistSelector` | selection 单元测试 | 离线通过 |
| 部分失败不伪装成功 | aggregation、executor | 聚合与状态测试 | 离线通过 |
| EvidencePack 无损传递 | dispatch decoder、aggregation | dispatch/aggregation 测试 | 离线通过 |
| LangGraph 只有 orchestration 入口 | 唯一 Builder、策略层框架中立 | AST 架构守卫 | 离线通过 |
| 等待、恢复、取消和可信 Usage | S2 委托与策略节点接口 | 当前仅结构/Fake 覆盖 | 真实验收待后续 |
| 真实模型、网络和持久化 | 不属于 S4 | 无真实基础设施测试 | 明确排除 |

## 3. 交付审查结论

S4 可作为后续业务 Agent 接入的框架中立底座，但当前交付等级为“离线契约与 Fake 验收通过”。在真实基础设施、生产恢复/取消和真实 Usage 完成专项验收前，不得标记为生产可用。
