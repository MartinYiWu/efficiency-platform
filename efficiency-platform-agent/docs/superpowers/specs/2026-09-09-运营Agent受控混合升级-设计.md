## 1. 目标

把当前“意图模型先行、研究与生成共享预算、研究结果直接串接平台生成”的运营 Agent，升级为受控混合执行模式，使普通对话、明确联网研究、多平台内容生成、运营策划和多轮追问都能通过同一套对话入口稳定运行。

本次升级必须支持真实输入：

> 收集下周 AI 行业热点，整理成公众号、小红书和头条三种版本。

该请求必须真实调用已配置的 DeepSeek Responses API `web_search` 能力；不能用普通模型回答伪装联网结果，不能展示内部 Prompt、工具调用细节或隐藏推理过程。

## 2. 非目标

- 不接入 Java 侧接口、业务权限或业务数据库；
- 不引入 LangChain、第二套 Graph Runtime、爬虫、浏览器搜索或付费商业热点数据源；
- 不建设监控平台、Trace、Metrics、告警和性能压测体系；
- 不新增 ASR、TTS、视觉 LLM、内容审核和 Text2SQL；
- 不主动向公众号、小红书或今日头条发布内容；
- 不把模型隐藏推理过程发送给前端。

## 3. 方案裁决

采用 **方案 C：受控混合运营 Agent**：

```text
用户输入
  → 确定性请求预判
     ├─ 普通聊天 → 通用对话 Agent
     ├─ 明确联网研究 → 研究快速通道
     └─ 模糊/复杂任务 → LLM 意图解析
  → Supervisor 场景编排
  → 研究 EvidencePack（需要时）
  → 并行平台 Specialist
  → 证据、结构、平台格式和交付质量校验
  → 统一摘要、多平台成品和来源
  → SSE 事件流
```

Prompt 负责理解、判断、提炼和生成；运行时负责工具调用、预算、超时、重试、模型降级、Schema 校验、状态恢复和用户可见事件。不可把运行时可靠性寄托在 Prompt 上。

## 4. 关键改造

### 4.1 联网意图快速通道

增加无外部 I/O 的确定性快速预判器。用户消息同时满足研究词、时效词或来源词时，先构造 `IntentEnvelopeV1` 的最小合法骨架；明确平台词、时间窗口和研究主题从消息中提取，仍缺少主题或必要条件时进入澄清，不再先等待一次可能超时的意图模型。

快速通道只允许生成受控字段，不能识别到的字段保持空值；复杂品牌、活动、增长和复盘任务仍走模型意图解析。快速通道生成的意图必须与既有 `ScenarioResolver`、`ConversationSubmissionStore` 和 `OperationStrategyPayload` 兼容。

### 4.2 分阶段预算与模型策略

将单一 Run 预算拆成意图、研究、平台生成和汇总校验四个阶段。每阶段保留独立 timeout、Token、成本和迭代边界，并向 `Run` 事件写入阶段名称、实际耗时、模型候选、降级标记和使用量。

默认策略：普通聊天优先快模型；意图解析优先快模型；联网研究优先均衡模型，来源不足时允许强模型重试；平台生成优先均衡模型并行执行；强模型不可用时自动降级快模型，同时设置 `degraded=true`。

### 4.3 研究与平台生成解耦

研究 Specialist 只返回 `ResearchResult` 和 `EvidencePack`，不生成平台正文。平台 Specialist 只读取已治理的 EvidencePack 和用户约束，分别输出公众号、小红书、今日头条独立 `DeliverableV1`。一次研究结果最多复用一次，不为每个平台重复联网。

某一个平台生成失败时，Supervisor 返回其余成功成品，并在 `missing_scope` 和质量报告中标识缺失平台；研究阶段失败时不得生成声称“最新已核验”的内容。

### 4.4 统一交付与 SSE

保持当前后端版本化契约，同时补充运营阶段事件：`intent_detected`、`research_started`、`research_completed`、`content_generation_started`、`content_generation_completed`、`quality_checked`、`stream_done`。事件只包含阶段、状态、数量、耗时和安全摘要，不包含 Prompt、模型原始响应、内部推理或密钥。

最终 `deliverable_set` 必须能表达任务摘要、研究来源、每个平台独立正文、质量状态、降级和警告；前端按既有 SSE 协议显示阶段动效和最终成品。

## 5. 真实验收矩阵

| 编号 | 输入类型 | 验收重点 |
|---|---|---|
| R01 | 普通身份/能力对话 | 不联网、不误进入运营流程、直接回答 |
| R02 | 无需联网的多平台文案 | 三个平台独立成品、平台规则不串台 |
| R03 | 收集下周 AI 行业热点并生成三平台版本 | 真实联网、时间窗、来源、并行生成、统一交付 |
| R04 | 最近 7 天 AI 动态公众号周报 | 研究证据、周报结构、引用完整性 |
| R05 | 品牌/IP/活动策划 | 复杂意图解析、缺失条件澄清、结构化方案 |
| R06 | 内容日历/选题规划 | 时间范围、批量任务、结构化输出 |
| R07 | 多轮追问和内容修改 | 上下文继承、保留已确认约束、只补缺失字段 |
| R08 | 研究源不足、超时或模型降级 | 失败关闭、用户级错误、SSE 终态、降级标记 |

每个用例必须记录原始输入、Run ID、SSE 事件序列、最终状态、实际模型、Token、来源数量、成品数量、质量结果、错误码和用户可见正文。真实用例 R03、R04 至少一次使用真实 DeepSeek Web Search；R08 可以通过真实配置的能力关闭或受控故障注入验证失败边界，不得伪造“联网成功”。

## 6. 质量门禁

- 普通对话不得出现 `RESEARCH_UNAVAILABLE`、工具名或内部能力说明；
- 研究成功必须有有效来源、时间范围和可关联引用；
- 多平台任务每个目标平台最多一个独立成品，平台字段必须匹配；
- 内容生成只可引用 EvidencePack 来源，禁止模型自行编造 URL；
- 任何内部异常映射为固定错误码，日志保留关联 ID 和安全错误位置；
- SSE 事件序列必须单调、可重放、最终只出现一个终态；
- 真实研究失败不得回退到无来源普通回答冒充完成。

## 7. 变更边界

代码变更只允许发生在 `conversation`、`orchestration`、`agents/operation`、`capabilities/research`、`contracts`、`tests` 和本次设计/验收文档范围内。所有注释、Docstring、测试说明和配置项说明使用中文。项目永久不是 Git 仓库，使用文件快照、源码编译、测试输出和 `docs/superpowers/sdd/operation-hybrid-upgrade/进度账本.md` 作为审查证据。
