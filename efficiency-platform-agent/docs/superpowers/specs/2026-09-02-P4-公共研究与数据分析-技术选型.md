## 1. 目标与约束

P4 只补齐两类通用技术能力：

1. 让 Agent 在公共互联网范围内发现信息，并由 LLM 按约定 Schema 返回带来源的结构化结果；
2. 读取 CSV、JSON、Parquet 和 XLSX，在 Agent 进程内完成表格清洗、筛选、聚合和统计。

硬约束如下：

- 不建设自有搜索引擎、爬虫平台或浏览器集群；
- 不采购商业热点、舆情、新闻或搜索数据源；
- 不引入 Text2SQL，不允许模型生成或执行 SQL，不直连业务数据库分析；
- 不生成 Excel、图表或其他报表文件，输出生成等具体业务场景出现后再评估；
- 不因“可能有用”引入需要额外部署、运维或付费的数据组件；
- 所有外部内容与模型输出均视为不可信数据，不能成为指令、权限或 Tool 调用依据。

## 2. 最终架构

```text
公共信息研究
  Agent / Workflow Node
      ↓
  Jinja2 受控 Prompt
      ↓
  P2 ModelProviderPort
      ↓
  DeepSeek Responses API
    ├─ server-side web_search
    └─ JSON Schema structured output
      ↓
  Pydantic v2 校验
      ↓
  来源证据检查 / URL 规范化 / 去重 / 格式封装

表格数据处理
  CSV / JSON / Parquet ───────────────→ Polars 1.x
  XLSX ─→ fastexcel（calamine）──────→ Polars 1.x
                                               ↓
                                     Pydantic 结构化结果
```

公共信息研究和表格分析是两个独立能力端口。上层 Agent 可以分别调用或在工作流中组合，但不得让 Polars、fastexcel 或厂商响应对象泄漏到 Graph State 和业务契约。

## 3. 公共互联网研究

### 3.1 组件裁决

| 能力 | 最终选型 | 是否新增依赖 | 说明 |
|---|---|---|---|
| 联网搜索与信息处理 | DeepSeek Responses API 服务端 `web_search_2025_08_26`（兼容 `web_search`） | 否 | 复用 P2 LLM Provider，不建设本地搜索服务；强制新版工具并要求正文提供完整来源 URL |
| 结构化输出 | DeepSeek `json_schema` + Pydantic v2 | 否 | Provider 约束输出，Agent 再做本地严格校验 |
| Prompt | P2 Jinja2 安全模板 | 否 | Agent 负责研究目标、范围、时间窗、来源与输出 Schema |
| Provider 客户端 | P2 OpenAI Python SDK；必要时由既有 HTTPX Adapter 处理兼容差异 | 否 | 厂商对象、错误、配置键不得进入上层 |
| URL 规范化与轻量去重 | Python 标准库 | 否 | 只处理返回结果，不抓取网页正文 |
| 运行、Token 与耗时事实 | P1 Run/Step/Invocation/Usage 契约 | 否 | PostgreSQL 是权威事实层，P4 不新增统计库 |

DeepSeek 官方 Responses API 当前声明支持服务端 `web_search`、`web_search_call` 和 `json_schema`：[Responses API](https://api-docs.deepseek.com/api/create-response/)、[Responses API 使用指南](https://api-docs.deepseek.com/guides/responses_api/)。这里的“全网搜索”表示在 Provider 可覆盖的公共互联网范围内发现信息，不表示全量索引、穷尽检索或搜索结果完整性保证。

### 3.2 结构化来源证据

研究输出必须使用版本化 Pydantic Schema，并至少能够表达：

- 结论或事实的稳定标识；
- 来源标题、发布者和 URL；
- 来源发布时间（无法确认时显式为空）和本次检索时间；
- 来源支持的结论标识；
- 简短证据摘要，不保存或大段复制受版权保护的网页正文；
- Provider、模型逻辑名、Prompt 版本、请求/响应关联标识和用量事实。

Schema 合法只证明结构合法，不证明来源真实。Agent 必须拒绝缺少来源的事实型输出，并对重复 URL、非法协议、字段超限和无法对应结论的来源给出明确质量状态。当前不主动访问返回 URL，因此不新增网页抓取或 SSRF 客户端；未来若需要打开、验证或下载 URL，必须复用统一 SSRF Policy，并重新评审抓取、版权和站点条款边界。

### 3.3 强制准入门禁

现有企业 AIHub/DeepSeek endpoint、凭据和模型配置可以复用，但“配置可用”不等于以下能力已验证：

1. endpoint 实际开放 `/responses`；
2. 目标模型同时支持 `web_search_2025_08_26`（或兼容 `web_search`）和 `json_schema`；
3. 搜索响应能提供可提取、可对应、可复核的真实来源；
4. 搜索没有独立付费数据源或搜索附加费用；
5. Token、超时、错误、流式事件和搜索调用可以被 Provider 正确归一化。

这些条件必须在总体选型完成并取得实施授权后通过真实 PoC 验证。Provider 先读取结构化来源字段；DeepSeek 当前部分响应仅在正文中返回 URL，适配器只提取正文明确出现的 HTTPS URL，不访问 URL、不把正文当作证据。任一条件不满足时，P4 联网搜索能力必须失败关闭；当前不自动引入自建搜索、GitHub Skill 或其他付费搜索 API 兜底。

## 4. 表格数据处理

### 4.1 组件裁决

| 输入或能力 | 最终选型 | 说明 |
|---|---|---|
| CSV、JSON、Parquet | Polars 1.x 原生读取 | 不引入 Pandas 或 PyArrow 作为直接依赖 |
| XLSX | fastexcel（calamine 引擎） | 只读；具体兼容版本由 Python 3.13 PoC 后的 `uv.lock` 固化 |
| 清洗与类型转换 | Polars 1.x | 列选择、空值处理、类型转换、排序和去重 |
| 聚合与统计 | Polars 1.x | 分组、连接、窗口和惰性计算 |
| 输出契约 | Pydantic v2 | 只返回受大小、类型和字段约束的结构化结果 |

Polars 官方说明 Excel 读取通过外部引擎完成，并推荐基于 calamine 的 fastexcel：[Polars Excel](https://docs.pola.rs/user-guide/io/excel/)。fastexcel 可直接与 Polars 交换数据而不要求 PyArrow 依赖，并声明 Python API 可用于生产：[fastexcel](https://github.com/ToucanToco/fastexcel)。

### 4.2 与 P3 Docling 的边界

- P3 Docling 将 XLSX 作为办公文档解析，目标是 Document AST、知识入库、RAG、页/表结构与来源关系；
- P4 Polars + fastexcel 将 XLSX 作为表格数据读取，目标是列类型、清洗、筛选、连接、聚合和统计；
- 同一请求必须先由能力路由选择一种主路径，不能无条件双解析；
- Excel 公式只按文件中可读取的缓存值或引擎能力处理，不执行宏、外链、脚本或公式计算；需要高保真公式、样式、编辑或导出时必须重新选型。

## 5. 不选方案

| 不选项 | 裁决理由 |
|---|---|
| SearXNG | 需要单独部署、搜索源维护和运维，不符合当前最小化目标 |
| Playwright | 浏览器运行时和页面自动化当前没有必要 |
| Trafilatura、BeautifulSoup4、lxml | 当前不抓取和解析网页正文 |
| feedparser | 当前由 LLM 服务端联网搜索，不建设 RSS/Atom 采集链 |
| 第三方 GitHub Skill | 可作为未来 Prompt/流程参考，不作为可靠数据源或运行时依赖 |
| DuckDB | 当前没有分析 SQL、隔离 SQL 引擎或本地数据仓库需求 |
| SQLGlot | 当前不做 Text2SQL，也不允许模型生成 SQL |
| PyArrow 直接依赖 | Polars 原生处理当前格式；fastexcel 可不经 PyArrow 对接 Polars |
| openpyxl、xlsxwriter | 当前只读 XLSX，不做兼容兜底、编辑或生成 |
| Altair、vl-convert-python | 当前不生成图表或静态图片 |
| 商业热点/搜索 API | 任何额外收费的数据源均不接入 |

## 6. 费用边界

- Polars 与 fastexcel 不产生按次 API 调用费，但仍消耗本机或服务器 CPU、内存和磁盘；
- DeepSeek 模型调用按现有模型合同或官方规则计费；
- 当前官方价格页面列出模型 Token 费用，但未单列 `web_search` 费用：[DeepSeek Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/)；
- 后续必须核实企业 endpoint 的实际合同。若 `web_search` 存在独立搜索费用或隐含收费商业数据源，则按项目裁决关闭，不自动转付费；
- P4 不新增数据库、搜索服务、浏览器集群或其他部署资源。

## 7. 错误与降级边界

| 情况 | 处理原则 |
|---|---|
| Provider 不支持 Responses、web_search 或 json_schema | 明确返回能力不可用，不以普通 Chat 响应伪装成功 |
| 模型输出不满足 Schema | 本地校验失败；可在预算内做有限重试，仍失败则终止 |
| 来源缺失、无法对应结论或疑似虚构 | 标记不可发布或需要复核，不把结果当作已验证事实 |
| 搜索超时、限流或预算耗尽 | 按 Provider 分类错误返回，不切换付费数据源 |
| 表格格式、类型或体积超限 | 明确拒绝或要求缩小输入，不无限加载内存 |
| XLSX 兼容性不足 | 返回不支持；不静默安装 openpyxl 兜底 |

## 8. 后续 PoC 与验收边界

P4 实施获批后至少验证：

1. Windows + CPython 3.13 下 Polars 与 fastexcel 的 wheel、导入和基础读取；
2. CSV、JSON、Parquet、单/多 Sheet XLSX 的类型、空值、日期和大表内存边界；
3. 企业 DeepSeek endpoint 的 Responses、web_search、json_schema、流式事件、来源字段和 usage；
4. 对缺失来源、虚构 URL、重复来源、非法 URL、截断 JSON 和超限输出的失败关闭；
5. 费用与配额确认，证明没有违反“禁止付费商业热点/搜索数据源”的裁决。

通过标准、样本和具体版本必须在 PoC 前确定。本文批准不表示上述验证已经执行或通过。

## 9. 最终裁决

P4 新增组件仅为：

```text
Polars 1.x
fastexcel（calamine 引擎，只读 XLSX）
```

公共互联网研究复用 P2 DeepSeek/OpenAI-compatible Provider、OpenAI Python SDK、HTTPX、Jinja2 和 Pydantic v2；运行与用量事实复用 P1 契约。除上述两项外，P4 不新增搜索、抓取、浏览器、数据库、SQL、图表或导出组件。

P4 技术组件、边界及其跨阶段关系已经批准。当前仍禁止依赖安装、功能实现、真实 API/数据库连接、PoC、DDL 和部署动作，直至项目负责人另行明确授权具体实施范围。
