## 1. 背景与目标

项目后续新增或修改的注释必须使用中文，且每个项目自维护配置项必须有紧邻的中文说明。当前 DeepSeek 直连 Provider 需要补全可公开的网关地址和模型标识，API Key 仍由使用者在本机忽略文件中注入。

本设计不实现 Provider、模型路由器或真实模型调用，不改变既有基础设施 Secret，不发起任何外部连接。

## 2. 方案比较与结论

| 方案 | 做法 | 结论 |
|---|---|---|
| 方案一：仅在代码评审中约定 | 不修改规范和测试 | 不采用；无法阻止后续遗漏 |
| 方案二：规范、逐项注释和自动检查 | 将规则写入项目规范，补齐当前自维护配置，并由测试校验 | 采用；规则可见且可持续验证 |
| 方案三：将说明集中到独立文档 | 配置项不保留就近说明 | 不采用；维护者容易在配置与说明之间失配 |

## 3. 中文注释与配置说明规则

### 3.1 代码、SQL 与文档内技术注释

- 项目自行编写的 Python 代码注释、Docstring、SQL 注释和配置注释 MUST 使用中文。
- 代码标识符、协议字段、环境变量、Provider 名称、模型 ID、文件格式关键字以及标准技术术语保持其既定英文形式；中文注释可以引用这些英文标识。
- 注释 MUST 解释职责、原因、边界、格式、单位、风险或缺失后的行为，MUST NOT 复述字段或代码字面量。

### 3.2 配置项逐项说明

- 项目自维护且支持注释语法的配置文件中，每个有效配置项 MUST 具有紧邻上方的中文注释。
- 注释至少说明该项的用途；涉及输入格式、单位、敏感性、默认值、启用条件、缺失行为或兼容边界时，MUST 一并说明。
- `.env` 与 `.env.example` 中每个环境变量 MUST 使用紧邻上方的中文注释；注释 MUST NOT 包含真实密钥、密码、连接串或个人数据。
- 不支持注释语法的格式，或由工具自动生成的锁文件，不直接插入注释；其配置语义 MUST 在紧邻的人工维护配置、Schema 或说明文档中逐项描述。`uv.lock` 属于自动生成锁文件，不得人工加入注释。

## 4. DeepSeek 默认配置

当前采用 DeepSeek 官方 OpenAI 兼容端点 `https://api.deepseek.com`。三个逻辑能力层与物理模型的映射如下：

| 逻辑层 | 环境变量 | 配置值 | 原因 |
|---|---|---|---|
| 快模型 | `AGENT_LLM_DEEPSEEK_FAST_MODEL` | `deepseek-v4-flash` | 官方当前的高响应速度、低成本模型 |
| 平衡模型 | `AGENT_LLM_DEEPSEEK_BALANCED_MODEL` | `deepseek-v4-flash` | 当前直连 Provider 仅有两档稳定模型；保持独立逻辑层，后续可无业务代码改动地改为新模型或模型池候选 |
| 强模型 | `AGENT_LLM_DEEPSEEK_STRONG_MODEL` | `deepseek-v4-pro` | 官方当前的高能力模型 |

`AGENT_LLM_DEEPSEEK_API_KEY` 保持空值，必须仅由使用者在本机根目录 `.env` 或受信任 Secret 注入中填写。`AGENT_LLM_MODEL_POOL_*` 保持空值，未来 Provider 契约批准后再启用。

## 5. 变更范围与验证

### 5.1 修改范围

- 修改 `docs/standards/01-工程与目录规范.md`，固化配置逐项中文注释规则；
- 修改 `docs/standards/03-Python编码与注释规范.md`，将中文注释由可选收紧为必须；
- 修改 `.env.example`、本机 `.env` 与 `config/llm-routing.toml`，补齐逐项中文注释；
- 在本机 `.env` 中填入 DeepSeek 网关和模型 ID，保留 API Key 与未来模型池值为空；
- 扩展 `tests/config/test_llm_configuration_template.py`，验证 DeepSeek 映射和配置说明完整性；
- 如 `pyproject.toml` 存在项目自维护配置项，同步补齐中文说明；不修改自动生成的 `uv.lock`。

### 5.2 验证

- 先新增配置注释与 DeepSeek 映射的失败测试；
- 执行该测试，确认它因缺少规则或配置值失败；
- 完成最小修改后重跑该测试和全量 `unittest`；
- 仅验证配置文本、格式解析和本机忽略规则，不调用 DeepSeek 或任何外部基础设施。
