## 1. 设计目标与阅读顺序

本次解决两个有明确接口的子系统，而非重建 Agent 平台：

1. **语义意图与多轮理解**：把自然语言转换为可追溯的需求快照，明确做什么、研究什么、何时、来源范围、交付方式及本轮修改。
2. **多源采集与研究交付闭环**：根据需求选择来源，采集和归并证据，判断缺口，有限补采，输出合格结果或明确不足。

先读本文掌握边界和开源依据，再读两份详细设计，最后审查 ADR。详细设计中的类型、文件、配置和阈值除“现状”章节外均为拟议目标，不能按已存在能力使用。

验收原则：理解正确但采集失败、采集成功但证据不足、证据合格但输出不合格是三个不同问题，必须分别记录和处理。

### 1.1 已确认的采集费用边界

2026-09-16，项目负责人明确要求：“采集信息使用免费的可用的API、RSS和公开的信息来源。”本要求作为本设计的强制约束，不再使用“优先免费、必要时付费”的解释。

- 信息采集仅准入免费且经可用性验证的 API、RSS/Atom 和公开页面；免费来源可以需要免费注册或 Token，但不得自动注册、购买、绑定支付或创建凭据。
- 按量收费、收费订阅及收费规则未知的来源不得进入新采集链。免费额度型接口只有能保证额度内零收费并在耗尽前硬停止时才可准入；禁止自动升级或付费兜底。
- LLM 仍负责理解、筛选、整合与补采决策，费用沿用既有模型授权及总预算，不把模型运行描述为免费。
- 现有服务端 web_search 不作为新方案的必选依赖；费用或可用性未验证时排除，不因“已经写了适配器”而自动启用。
- 本次确认仅限来源费用和可用性边界，不代表全部设计、预算、依赖或 DDL 已获实施批准。

## 4. 候选方案与推荐

| 方案 | 优点 | 代价/风险 | 结论 |
|---|---|---|---|
| 继续关键词快路径 + 单搜索 Provider | 修改少 | 意图、时间、来源完整性和补采仍不可解释 | 不作为目标方案，仅保留受控兼容路径 |
| 整体迁移到 Dify/Coze/Rasa 或完整新闻平台 | 可复用大量界面和运行功能 | 与现有唯一 LangGraph、Provider、权限和状态治理冲突 | 不采用 |
| 成熟组件直接依赖 + 开源模块机制适配 + 本项目契约与质量策略 | 复用既有实现，保持治理边界，可分阶段测试 | 仍需完成语义契约、来源准入和中文评测 | 推荐 |

用户的“不要写死”指自然语言表达和判断不依赖固定关键词，不表示工具权限、Schema 和质量下限可以由模型任意修改。

## 5. 总体数据流与依赖

```text
受信任：请求身份、会话状态、能力注册、来源策略、预算
                         │
用户文本（不可信）→ ContextBuilder → 语义解释 → 多轮增量合并 → 时间/约束校验
                         │
             IntentFrameV2 + DecisionRecord
                         │
       能力绑定 → Strategy Router → 现有 Supervisor / LangGraph
                         │
              ResearchBriefV2（两部分唯一需求接口）
                         │
        来源规划 → Tool Runtime → Provider → 外网（不可信）
                         │
         安全解析 → 文档去重 → 事件聚合 → Claim / Evidence
                         │
                    QualityReportV2
                    ├─ 达标 → 生成 → 输出检查 → 交付
                    ├─ 有缺口且有预算 → 定向补采 → 重新检查
                    └─ 无法继续 → 部分/空结果/失败 + 具体原因

PostgreSQL：版本、任务、证据元数据、事件与决策事实；Checkpoint：节点恢复
受控 Artifact：必要正文或摘录；Redis：缓存/限流，不作权威状态
```

模型只能提出结构化候选，不得直接设置权限、任意 URL、动态 Python 导入、成功终态或追加预算。研究来源内容不能回写用户意图。

## 6. 两部分共享契约

`ResearchBriefV2` 由意图侧产生，研究侧只能读取，禁止自行改写需求：

| 字段 | 类型/约束 |
|---|---|
| `schema_version` | 固定 `research-brief/2` |
| `tenant_id, run_id, task_id` | 来自受信任运行上下文，模型不得生成或覆盖 |
| `intent_revision` | 正整数，关联不可变意图快照 |
| `topic, entities, required_facets` | 主题、实体、用户明确要求或透明默认的覆盖维度 |
| `time_window` | UTC 起止、IANA 时区、左闭右开、时间口径、原始表达、基准时刻 |
| `source_constraints` | 允许/排除来源、语言、地区、是否仅一手；不得扩大注册权限 |
| `count_policy` | `exact / at_most / best_effort`、目标数量、最小可交付数量 |
| `ranking_mode` | `importance / heat / recency`；默认重要性，不能伪造热度 |
| `output_requirements` | 类型、语言、交付平台、格式、引用要求 |
| `quality_policy_id, policy_version` | 与当前运行绑定的不可变策略快照 |
| `budget_lease_id` | 引用 Harness 分配预算，不接受模型生成额度 |

每个下游步骤及缓存条目必须关联 brief 摘要、intent_revision 和策略版本。用户修改需求时新建 revision，重新判断可复用证据，禁止混用旧范围。

## 8. 风险、回滚和评审项

- **误识别**：V2 影子解析仅比较结果，不执行第二次工具；真实模型双跑仍消耗预算，须显式启用。先固定离线语料，再按租户灰度。
- **网络扩大**：只开放注册来源和经安全验证的公开文章页；动态浏览器默认不启用。
- **证据质量**：结构校验不证明真伪，模型支持判断也可能错误；通过原文定位、保守排除和人工标注集衡量风险。
- **成本**：研究、解释、输出使用子预算，但总和与预留必须受同一 Run 总预算约束，禁止分阶段“重新满额”。
- **回滚**：关掉 V2 新请求入口，不把进行中的 V2 状态反序列化为 V1；保留结果、决策和版本。旧路径不能展示“原文已核验”。
- **已确认约束与待评审决策**：免费且可用的数据源边界已确认；主动采集的具体安全实现、默认质量/模型预算档位、逐源准入及正文保留期限仍需评审。未准入来源保持关闭，不影响本次设计完成。
