## 1. 目标与约束

P5 只补齐三类底层技术能力：

1. 以标准协议接入经过批准的外部工具、资源或 Prompt；
2. 用可复现的离线数据集和确定性指标验证 Agent、Tool 与 RAG 契约；
3. 用轻量开发工具验证复杂状态边界，并检查锁定依赖的已知漏洞。

硬约束如下：

- MCP 只作为外部能力协议，不替代 LangGraph、多 Agent Supervisor 或内部 Tool Runtime；
- P5 只建设 MCP Client，不建设 MCP Server；
- 动态发现不能自动扩大 Tool、Resource 或 Prompt 的允许清单；
- 评测默认不依赖 LLM Judge，不因评测产生额外模型费用；
- 不引入新的数据库、服务端、监控平台、压测平台或独立安全扫描平台；
- 所有外部 MCP 描述、返回内容和错误均视为不可信输入；
- 当前仍不考虑业务 Agent、业务指标和业务验收集。

## 2. 最终组件基线

| 技术域 | 最终选型 | 依赖类型 | 当前裁决 |
|---|---|---|---|
| MCP 协议 | 官方 MCP Python SDK 2.x，包名 `mcp` | 运行依赖 | 新增；只使用 Client 能力，不安装 `mcp[cli]` |
| 常规评测运行器 | pytest | 开发依赖 | 复用 P0 |
| 评测契约 | Pydantic v2 | 运行/开发复用 | 复用 P0，定义版本化 Case、Expected、Actual、Metric、Result |
| 小型回归集 | JSONL | 文件格式 | 使用人工评审、可版本管理的数据集 |
| 大型评测集和聚合 | Parquet + Polars 1.x | 文件格式/运行依赖复用 | 复用 P4，不新增评测数据库 |
| 性质测试 | Hypothesis 6.x | 开发依赖 | 新增；仅测试底层不变量 |
| 依赖漏洞检查 | `uv audit --frozen` | 复用现有 uv | 新增门禁命令，不新增 Python 包 |

具体补丁版本必须在获批实施阶段通过 Windows、CPython 3.13 兼容性验证，并由 `uv.lock` 固化；本文不提前写死未经验证的补丁版本。

P5 实际新增依赖仅为：

```text
运行依赖：mcp 2.x
开发依赖：Hypothesis 6.x
不新增依赖：pytest、Pydantic、Polars、uv audit 均复用既有技术栈
```

## 3. MCP Client 架构

### 3.1 调用链

```text
Agent / Workflow / Specialist Subgraph
                  ↓
          内部 Tool Contract
                  ↓
             Tool Runtime
  Schema / Tenant / Allowlist / Budget / Approval
  Timeout / Retry / Idempotency / Audit / Result Limit
                  ↓
          MCP Client Adapter Port
                  ↓
       官方 MCP Python SDK 2.x Client
                  ↓
        已批准的外部 MCP Server
                  ↓
       不可信响应 → 归一化 → 内部 Tool Result
```

上层只能依赖 Agent 自有的 Tool Request/Result 契约，不能依赖 MCP SDK 对象。这样可以替换协议、Server 或传输方式，而不改变 Graph State、Supervisor 和业务 Agent。

### 3.2 Client-only 边界

- 当前只允许通过 MCP Client 消费外部能力；
- 不暴露任何 Agent 内部 Tool、Prompt、Resource 或 Graph 为 MCP Server；
- 未来只有出现明确的跨系统复用需求时，才对 MCP Server 单独选型、威胁建模和授权；
- 安装普通 `mcp` 运行包，不引入仅用于命令行开发工具的 `mcp[cli]` extra；
- MCP 不是 Agent 间通信总线。内部多 Agent 协作继续由 LangGraph Supervisor Graph 和 Specialist Subgraph 完成。

### 3.3 传输方式

| 传输 | 裁决 | 使用边界 |
|---|---|---|
| Streamable HTTP | 主选 | 连接受信任的远程 MCP Server；必须经过 URL、TLS、认证、超时和响应大小治理 |
| stdio | 受限可用 | 仅连接明确批准的本地进程；命令、参数、工作目录和环境变量必须为静态允许项 |
| SSE | 兼容模式 | 仅兼容遗留 Server，不建设新的 SSE MCP 接入 |

官方 SDK 文档说明 v2 是当前稳定版本线，要求 Python 3.10+，并提供 Client 与上述传输能力：[MCP Python SDK 安装](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/get-started/installation.md)、[Client Transports](https://github.com/modelcontextprotocol/python-sdk/blob/main/docs/client/transports.md)。

### 3.4 发现与准入

MCP Server 返回的 Tool、Resource 和 Prompt 列表只用于发现，不构成执行授权。每个外部能力必须完成以下映射后才可被 Agent 使用：

1. 外部 Server 标识映射到内部 Provider/Tool 标识；
2. 外部输入 Schema 映射并收紧为内部 Pydantic Schema；
3. 明确租户、角色、Agent、环境和数据范围允许清单；
4. 明确超时、重试、预算、结果大小、幂等和是否需要人工批准；
5. 外部结果归一化、标记来源并经过输出边界检查；
6. 记录发现版本、调用事实和最终状态，但不记录明文密钥或敏感正文。

Server 新增或变更能力时默认不可用，必须重新评审允许清单。不得因为 `list_tools`、`list_resources` 或 `list_prompts` 返回成功，就把新能力自动暴露给模型。

## 4. 确定性离线评测

### 4.1 评测架构

```text
版本化 JSONL / Parquet Dataset
                ↓
       Pydantic EvalCase 校验
                ↓
     pytest 运行目标 Agent/Node/Tool/RAG
                ↓
       Pydantic EvalResult 校验
                ↓
    项目内确定性 Metric Functions
                ↓
   JSON/Parquet 明细 + Polars 聚合摘要
```

小型、需要代码评审的回归集使用 JSONL；达到批量分析规模后才使用 Parquet。评测数据和结果是文件制品，不引入独立评测服务或数据库。

### 4.2 基础指标

| 对象 | 基础确定性指标 |
|---|---|
| Schema/Contract | Schema 通过率、必填字段完整率、枚举与大小边界通过率 |
| Tool | Tool 选择准确率、参数精确匹配/字段匹配、允许轨迹匹配、终止状态 |
| Graph/Multi-Agent | 状态转换合法率、最大步数/预算遵守率、路由与终止条件 |
| RAG | Recall@K、MRR、nDCG、引用完整率、引用与 Chunk 标识可关联率 |
| 公共研究 | 来源字段完整率、结论与来源关联率、重复来源率、时间窗符合率 |
| 运行事实 | 端到端耗时、节点耗时、模型调用次数、输入/输出/总 Token；只使用真实记录值 |

业务正确率、具体阈值和业务样本不在 P5 预设。真实业务出现后，由对应业务设计定义数据集、指标阈值、责任人与发布门禁。

### 4.3 LLM Judge 边界

LLM Judge 不是默认评测路径，也不进入常规 CI。只有语义质量无法由确定性指标覆盖且业务明确需要时，才能通过 P2 Provider Port 作为可选评测器，并必须固定模型逻辑名、Prompt 版本、采样参数、预算、样本与人工校准集。未单独批准前不得产生评测模型费用。

## 5. Hypothesis 性质测试

Hypothesis 只用于传统样例难以完整覆盖的底层不变量：

- LangGraph 状态转换、合法终态和最大步数；
- Run/Step/Invocation 状态与预算上下界；
- Pydantic Schema、序列化和反序列化往返；
- 重试、幂等键、重复消息和取消的组合边界；
- Tool 参数、结果大小、URL、路径和标识符的边界组合。

禁止把 Hypothesis 用于随机调用真实 LLM、OCR、COS、数据库或远程 MCP Server，也不用于负载测试。失败样例必须可重放；持续集成使用受控 profile，开发人员可在本地扩大生成样例数。Hypothesis 是免费开源的 Python 开发工具，无独立服务和 API 费用：[Hypothesis on PyPI](https://pypi.org/project/hypothesis/)。

## 6. 依赖漏洞检查

依赖检查复用项目现有 uv：

```powershell
uv audit --frozen
```

`--frozen` 要求从已有 `uv.lock` 审计且不重新锁定依赖。官方 CLI 文档说明 `uv audit` 检查已知漏洞及不良包状态，并支持按漏洞 ID 忽略：[uv audit](https://docs.astral.sh/uv/reference/cli/#uv-audit)。

忽略规则必须同时记录漏洞 ID、影响判断、负责人、批准人和失效日期。无修复版本时可以在明确批准后使用 `--ignore-until-fixed`；出现修复版本后必须重新报告。P5 不重复引入 `pip-audit`。

`uv audit` 是当前 uv 版本中的能力，获批实施时必须先验证固定的 uv 版本支持该命令；若命令在后续 uv 版本发生变化，只替换审计命令或重新评审，不因此引入安全平台。

## 7. 基础安全边界

P5 不建设安全扫描平台，但下列现有架构约束继续强制生效：

- 所有外部 MCP 内容、网页内容、文件内容和模型输出均为不可信数据；
- Tool Runtime 统一执行租户权限、能力允许清单、预算、超时、审批和审计；
- 远程 URL 必须经过协议、域名、DNS、IP 和重定向检查，禁止访问内网和元数据地址；
- stdio 只能启动静态允许的程序，不允许模型拼接命令、参数或环境变量；
- Secret 只从受控配置注入，不进入仓库、Prompt、Graph State、日志或评测集；
- 模型不能生成或直接执行 SQL；Agent 自有持久化只能经过受控 Repository；
- 文件继续执行 P3 的签名、类型、容器、大小、页数、压缩比和主动内容预检；
- MCP 响应必须限制内容类型、条目数、单项大小、总大小和保存范围。

这些是实现约束，不等价于已经安装或运行安全扫描工具。

## 8. 明确不选与后置项

| 组件或能力 | 当前裁决 | 重新评审触发条件 |
|---|---|---|
| MCP Server | 不选 | 出现明确的外部系统复用 Agent 能力需求 |
| `mcp[cli]` | 不选 | 确有 MCP Server 本地开发或 Inspector 常态化需求 |
| Ragas | 不选 | RAG 业务评测规模和语义指标证明项目内确定性方案不足 |
| DeepEval | 不选 | 需要成体系的 LLM Judge、对话评测或独立评测运行平台 |
| Locust、k6、JMeter、pytest-benchmark | 后置 | 业务功能完成后启动性能与容量专项 |
| OpenTelemetry、OTLP、Prometheus、Grafana、Dashboard、告警 | 后置 | 业务完成后启动可观测性专项 |
| Bandit、Semgrep、额外 Ruff 安全规则集 | 后置 | 实际代码、CI 和风险面形成后启动源代码安全专项 |
| ClamAV 或恶意文件扫描服务 | 后置 | 外部文件接入风险和运行环境能够支持独立扫描能力 |
| 独立 Secret Scanner | 后置 | 进入共享仓库/CI，且现有凭证管理约束不足 |
| LLM Judge 默认流水线 | 不选 | 业务语义质量无法用确定性指标覆盖并单独批准费用 |

后置表示当前不安装、不配置、不验收，也不能写成“已经支持”。

## 9. 跨阶段边界

| 阶段 | P5 复用内容 | P5 不改变的边界 |
|---|---|---|
| P0 | Python 3.13、uv、pytest、Pydantic | 不改变基础运行时和依赖管理方式 |
| P1 | LangGraph、Tool Runtime、Run/Step/Usage 事实 | MCP 不成为编排内核；评测不成为运行时依赖 |
| P2 | Provider Port、RAG 契约、引用与 Token 数据 | LLM Judge 只能未来复用 Provider，不绕开模型治理 |
| P3 | 文件安全与 Document AST | MCP 文件结果仍必须经过 P3 安全边界 |
| P4 | Polars、Parquet、公共研究来源契约 | P5 不新增搜索、爬虫、Text2SQL 或分析数据库 |

## 10. 费用边界

- MCP SDK、Hypothesis、pytest、Pydantic、Polars 和 uv 均为免费开源组件；
- P5 不新增必须付费的 API、SaaS、数据源或独立服务；
- 外部 MCP Server 自身可能收费，只有完成费用核验和单独批准后才能进入允许清单；
- 默认确定性评测不调用付费模型；LLM Judge 未批准前保持关闭；
- 免费软件仍会消耗本机或后续运行环境的 CPU、内存、磁盘和网络资源，但本阶段不做容量或部署设计。

## 11. 后续 PoC 与验收边界

只有再次获得项目负责人对 P5 具体实施范围的明确授权后，P5 才能进入以下验证：

1. Windows + CPython 3.13 下 `mcp` 与 Hypothesis 的解析、安装、导入和最小测试；
2. Streamable HTTP Client 的发现、调用、超时、认证、错误映射和响应大小限制；
3. stdio 静态允许清单、最小环境变量和进程终止行为；
4. MCP 动态新增能力默认不可用；
5. JSONL/Parquet 数据集、确定性指标和结果聚合可重复；
6. Hypothesis 失败样例可重放且不访问真实外部服务；
7. `uv audit --frozen` 对 `uv.lock` 的审计行为和忽略治理规则。

本文批准不表示上述 PoC 已经执行或通过。

## 12. 最终裁决与实施门禁

P5 最终基线为：

```text
MCP Client：官方 MCP Python SDK 2.x，普通 mcp 运行依赖
评测：pytest + Pydantic + JSONL/Parquet + Polars + 项目内确定性指标
性质测试：Hypothesis 6.x，开发依赖
依赖审计：uv audit --frozen，复用现有 uv
```

Ragas、DeepEval、Locust、完整性能工具、监控平台和额外安全扫描工具均不属于当前 P5。P5 及其跨阶段关系已获项目负责人批准；当前仍禁止依赖安装、代码实施、真实连接、PoC、数据库变更和部署动作。
