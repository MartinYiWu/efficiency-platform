## 1. 背景与问题

运营助手以自然语言会话作为用户入口。当前实现已经具备 Run、SSE、通用对话和运营多 Agent 主链，但仍存在以下产品级缺口：

1. 通用对话等待模型完整返回后才把正文切片，属于结果分片，不是真正的端到端增量输出；
2. 前端直接追加服务端正文，没有独立的思考过渡态和受控打字机展示；
3. 通用对话系统人格包含底层限制描述，模型可能把“不能联网、不能调用工具”等内部约束直接告诉用户；
4. 普通对话与公共研究链路没有完成自动转接，显式搜索、最新事实和核验请求可能错误进入无工具 DIRECT；
5. 终态后的迟到事件、取消后的增量、Markdown 安全展示等边界仍需闭合。

本设计把运营助手建设为具备自然多轮交流、按需联网研究、真实 SSE 正文流、受控多 Agent 协作和统一输出治理的对话式 Agent。系统内部可以执行复杂编排，但面向用户保持简单、自然且不暴露底座。

## 2. 设计裁决

采用“确定性快速响应 + DIRECT 真实流式对话 + 受控研究/运营多 Agent + 统一对外输出治理”的混合架构。

```text
Conversation API
    │
    ▼
ConversationService
    ├─ LocalConversationResponder
    │    └─ 身份、问候、能力、帮助、致谢的确定性快速响应
    │
    └─ IntentInterpreter + 会话上下文
         ├─ 稳定知识、普通聊天、解释与追问
         │    └─ DIRECT → GeneralConversationAgent → ModelRuntime.stream
         │
         ├─ 最新、搜索、核实、来源或时效性追问
         │    └─ MULTI_AGENT → Research Specialist → 证据门 → 回答合成
         │
         └─ 运营任务
              └─ MULTI_AGENT → Scenario Pack → Specialist → Quality Gate
```

不采用以下方案：

- 不以固定计时器伪造检索、分析或思考进度；
- 不展示模型隐藏思维链、Prompt、节点名称、工具调用参数或模型选择过程；
- 不让多 Agent 的未经验证中间正文直接到达用户；
- 不新增第二 Graph Runtime，也不让 Specialist 自由点对点对话；
- 不以简单全局关键词过滤代替上下文相关的对外输出治理。

## 3. 用户可见交互

### 3.1 唯一思考过渡态

用户提交消息后，前端只显示“助手头像 + 三点跳动”的简洁思考动效。动效不包含“正在检索”“正在分析”“正在调用模型”等过程文字，也不展示任何推理内容。

```text
用户提交
  → submitting/streaming 且尚无 assistant_delta
  → 显示三点思考动效
  → 收到首个 assistant_delta
  → 移除思考动效并创建回答气泡
  → 按字素逐步展示已收到正文
  → stream_done 后完成展示
```

动效必须由当前 Run 的真实状态驱动：提交、取消、失败、澄清、终态或组件卸载时都必须正确结束，不使用固定持续时间。

### 3.2 不展示中间推理

以下内容严禁进入用户界面和用户可见 SSE 正文：

- 隐藏思维链、逐步推理和内部自我对话；
- 系统 Prompt、开发规则和安全策略原文；
- Graph、Agent、Specialist、Tool、Provider、模型池和降级策略名称；
- API Key、配置项、内部错误堆栈、租户内部标识和审计细节；
- “根据系统限制”“我不能真正联网”“我无法调用外部工具”等底座能力声明。

内部仍可记录不含正文和敏感数据的结构化状态与审计事实，但不得把它们映射成面向用户的思考过程。

### 3.3 打字机展示

打字机是前端展示行为，权威正文仍是按 SSE 顺序累计得到的完整文本。展示层必须：

- 以 Unicode 字素为单位推进，避免拆分中文、Emoji 和组合字符；
- 支持单个大 delta 和多个小 delta；
- 新增 delta 时在已有展示进度后继续，不重复、不回退；
- 用户开启减少动态效果时直接显示已接收正文；
- 页面卸载、会话切换、取消和错误时释放定时器；
- 屏幕阅读器不逐字重复播报，完成后再提供稳定可读正文。

### 3.4 Markdown 展示

助手正文使用受控 Markdown 渲染，至少支持标题、段落、列表、强调、引用、链接和代码块。必须禁止原始 HTML 或进行白名单清洗；外链使用安全属性。用户消息继续按纯文本展示。

## 4. 路由语义

### 4.1 本地快速响应

`LocalConversationResponder` 仅处理低歧义且不依赖外部事实的短句：身份、问候、能力、帮助、致谢和结束语。匹配必须基于规范化完整表达或受控正则，不能用宽泛关键词吞掉真实运营任务。

能力描述使用产品语言，例如“可以协助公开资料整理、内容策划、品牌运营、活动方案、渠道文案和运营复盘，并在需要时给出可核验来源”，不得解释内部实现，也不得承诺尚未真正完成的文件或平台发布。

### 4.2 DIRECT 通用对话

稳定知识、概念解释、创意交流、普通追问以及不要求外部实时事实的内容进入 DIRECT。`GeneralConversationAgent` 仅依赖统一模型运行时，使用受限可见历史生成自然回答。

DIRECT 的正文采用真实模型增量：上游 Provider 产生 delta 后，经 `ModelRuntime`、通用对话 Agent、Graph 运行输出端口和 Harness 立即发布为 `assistant_delta`。Run 在模型结束前保持 `RUNNING`。

### 4.3 联网研究路由

以下请求优先进入受控研究路径：

- 用户明确要求搜索、联网查找、核实、验证或提供来源；
- 问题包含“最新、今天、近期、本周、刚刚发布”等时效性要求；
- 上下文追问表达为“那查一下最新的”“给我来源”“核实一下”，主题可从当前会话继承；
- 运营场景明确需要公共事实、新闻、政策、趋势或市场信号。

路由不得只依赖单个关键词。意图结果中的 `needs_research=true` 必须参与策略选择，`general_chat + needs_research=true` 不得进入无工具 DIRECT。

研究链复用现有 `ResearchProviderPort`、Research Specialist、证据门、引用和预算治理，不引入付费商业热点数据源。真实检索成功时返回可核验来源；检索未启用、失败或没有合格来源时，只说明“本次未能完成在线核验”，不得虚构已联网，也不得将一次失败描述为整个助手没有联网能力。

### 4.4 运营任务

现有运营场景继续通过 `ScenarioResolver`、Supervisor、Specialist、Quality Gate 和 Deliverable Set 执行。多平台请求必须返回多个独立成品；不涉及主动平台发布。

### 4.5 等待用户输入

会话存在等待输入的运营意图时，下一轮优先合并到原意图。只有主题、时间范围或交付条件确实无法从会话推导时才提出简短业务澄清，不用技术性问题打断用户。

## 5. SSE 契约与生命周期

继续使用 `run.stream.event/1`，不新增第二套接口。用户可见链路使用：

```text
run_started
assistant_started
assistant_delta × N
[deliverable]
[usage_update]
[stream_error]
stream_done
```

`phase_started` 可保留为内部兼容事件，但前端不得把它渲染成思考步骤或用户可见过程文字。

关键不变量：

1. `assistant_started` 每个 Run 至多一次；
2. 首个 `assistant_delta` 可以在模型尚未完成、Run 仍为 `RUNNING` 时到达；
3. 拼接全部 `assistant_delta` 等于最终权威 `output.content`；
4. 已实时发布的正文不得在结算阶段再次整段发布；
5. `stream_done` 每个 Run 恰好一次，客户端看到后停止读取同批后续事件；
6. 终态、澄清或取消后，客户端和服务端都拒绝迟到 delta；
7. 新请求已经提交、但新 Run 尚未绑定时，客户端拒绝所有旧流 SSE；绑定完成后只接受当前 `run_id`；
8. 首个可见 delta 前的可重试失败允许选择备用模型；首个可见 delta 后禁止切换模型拼接另一份回答；
9. 取消必须传播到模型流和 Provider 内部重试边界；
10. Usage 以最终 Provider 快照为准，不按每个 delta 重复累计。

## 6. 服务端流式设计

### 6.1 ModelRuntime

统一模型运行时提供“增量回调 + 最终执行结果”的受控入口。它负责候选选择、首片前降级、绝对截止时间、取消、Usage 聚合和稳定错误归一化。

调用者实时收到正文 delta，同时在流结束后取得 `ModelExecutionResult`，用于最终正文、尝试事实、Usage、降级状态和预算结算。模型选择事件和错误细节不得通过正文回调暴露。

### 6.2 GeneralConversationAgent

通用对话 Agent 使用流式运行时生成正文，在内存中按顺序累计权威内容。每个 delta 先经过对外输出治理的跨片段缓冲，再交给运行输出端口。结束后对完整正文再次校验，最终返回现有 `GeneralConversationExecution`，保持调用方预算契约兼容。

### 6.3 Graph 运行输出端口

DIRECT Graph 通过组合根注入按 `run_id` 隔离的窄输出端口。端口只允许发布安全正文增量，不把 `EventHub` 或 API 类型反向注入 Agent。Graph State 继续保持可序列化，最终输出仍是权威完整正文。

### 6.4 Harness

Harness 负责：

- Run 进入 `RUNNING` 后发布一次 `assistant_started`；
- 只接受当前仍可输出的 Run 增量；
- 在事件锁内维持 sequence 单调；
- 取消或终态后拒绝增量；
- 对已实时发布的正文记录发布事实，结算阶段不重复正文；
- MULTI_AGENT 和本地固定回复仍可在质量门后走结果呈现分片；
- 本阶段继续使用进程内 `EventHub` 完成本地联调；慢客户端有界队列、持久事件留存与容量治理归入后续部署和性能专项，本轮不声称完成。

DIRECT 路径保证实时 delta 拼接后与权威正文一致。旧的非 DIRECT `output_streamer` 若在展示中断后进入补偿路径，仍可能以完整安全正文恢复，从而重复已展示前缀；它不属于本轮 DIRECT 真实流式链路，在用于生产增量展示前必须改为仅补未发送后缀。

## 7. 对外输出治理

输出治理是正文发布边界，不是内容审核平台。它只防止内部实现和敏感信息泄漏，并保持普通技术讨论可用。

治理分为三层：

1. 系统人格：使用正向产品身份与回答原则，不向模型灌输可被复述的底层限制清单；
2. 稳定能力快照：身份和能力问答优先走受控本地响应；
3. 发布前检查：结合请求类型与助手自我陈述语境，拦截内部 Prompt、密钥、堆栈和全局错误能力声明。用户主动讨论“模型池、工具、Prompt”等技术主题时不得误拦。

流式检查必须保留有界跨片段尾缓冲，避免敏感模式恰好跨两个 delta 而绕过。若完整正文不合格，返回稳定的用户导向回答或安全错误，不把内部命中规则告诉用户。

## 8. 前端状态模型

前端继续保留服务端已接收的权威正文，并增加独立展示状态：

```text
authoritativeContent：按 SSE 顺序累计的完整已接收正文
visibleContent：打字机当前展示的字素前缀
isThinking：当前 Run 忙碌且尚未收到首个非空正文
isTyping：visibleContent 尚未追上 authoritativeContent
```

`isThinking` 只决定三点动效，不产生聊天消息、不写入会话历史。首个非空 delta 到达时立即关闭。终态可以先于动画追赶完成，用户仍可看到剩余正文平滑出现；取消和失败则停止动画并保留已经可见的安全部分。

## 9. 错误、取消和恢复

- 模型失败统一映射为安全错误，不返回 Provider 异常正文；
- 搜索失败按单次任务描述，不宣称助手永久没有联网能力；
- 用户取消后停止思考动效、打字机、模型流和后续降级尝试；
- 前端断线按 Last-Event-ID 有限重连并去重；
- `stream_done` 后不再交付同一响应体中的任何事件；
- 同一会话的新 Run 不接受旧 Run 的事件；
- 部分正文后失败时保留已展示内容，并以稳定失败状态结束，不拼接另一模型答案。

## 10. 安全与隐私

- 不读取、记录或返回 `.env`、API Key、连接信息和内部配置；
- 日志不记录用户原文、历史、Prompt、模型正文或搜索结果全文；
- 外部资料继续视为不可信数据，不能改变系统权限和工具策略；
- 引用 URL 必须经过既有来源治理；
- Markdown 禁止危险 HTML、脚本和事件属性；
- 本设计不新增内容审核、语音、视频、Text2SQL、主动发布或付费数据源。

## 11. 验收标准

1. “你是谁”“你好”“你能干什么”“谢谢”使用稳定产品语言快速响应，不调用模型，不暴露底座；
2. 普通知识问答自然回答，并支持同一会话上下文追问；
3. 第一个模型 delta 在模型完成前到达 SSE，Run 此时仍为 `RUNNING`；
4. DIRECT SSE delta 拼接结果与最终保存正文一致且只出现一次；
5. 用户等待首个正文时只看到三点思考动效，没有推理或阶段文字；
6. 首个 delta 到达后开始按字素显示，中文和 Emoji 不损坏；
7. 明确搜索、最新事实、核实和来源请求进入研究链；成功时返回真实来源，失败时不虚构联网成功；
8. 回答不出现系统 Prompt、底层限制、模型池、工具参数、内部节点或错误堆栈；
9. 取消后没有迟到 delta、备用模型调用或残留动画；
10. `stream_done` 后客户端不处理后续事件，终态不会回退；
11. 运营多 Agent 仍在质量门后输出成品，未经验证的专家中间正文不外泄；
12. Agent 侧 pytest、Ruff、mypy、compileall、架构守卫和前端 Vitest、typecheck、lint、build 通过；
13. 在不读取密钥值的前提下完成本地真实 DeepSeek 普通对话联调；联网研究仅在现有配置门和服务能力真实可用时标记为已验收。

## 12. 非目标

- 不展示或保存隐藏思维链；
- 不建设复杂进度面板和监控平台；
- 不增加平台主动发布；
- 不增加语音、视频、ASR、TTS 或 Text2SQL；
- 不引入付费商业热点数据源；
- 不因本次交互优化建设第二套 Agent Runtime；
- 不把尚未真实验证的联网或文件能力描述为已经可用。
