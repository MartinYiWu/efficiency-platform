## 1. 总体裁决

Agent 侧采用 **Harnessed Hybrid Multi-Agent Architecture（受控混合多 Agent 架构）**：

1. Thin Agent Harness 统一治理身份、租户、权限、幂等、预算、超时、取消、审计和错误；
2. Strategy Router 在 Direct、Workflow、ReAct、Plan-and-Execute 和 Multi-Agent 之间选择执行方式；
3. LangGraph OSS 1.x `StateGraph` 是唯一 Graph Runtime；
4. Multi-Agent 使用中央 Supervisor Graph 调度 Specialist Subgraph，禁止专家 Agent 自由互聊；
5. 所有执行策略共享 Context、Tool、四层记忆、Provider、Persistence、Security 和 Evaluation 契约；
6. 上层只依赖 Agent 自有稳定端口，第三方 SDK 对象不得进入 Graph State、API 或业务契约。

本次总体复核未发现必须继续新增的第三方技术组件。新增能力优先复用已选组件和标准库；未来需求不能以“可能有用”为由自动扩大基线。

## 3. 分阶段组件基线

### 3.1 P0 工程与接入基础

| 技术域 | 选型 | 边界 |
|---|---|---|
| Python | CPython 3.13.x | 项目解释器由 uv 管理；不修改系统 Python |
| 项目与依赖 | uv、`pyproject.toml`、`.python-version`、`.venv`、`uv.lock` | 直接依赖分组，锁文件固定完整解析结果 |
| 构建 | `uv_build` | 纯 Python `src/` 布局 |
| API | FastAPI + Uvicorn | Run、流式事件、恢复/输入、取消和元信息入口 |
| Schema/配置 | Pydantic v2 + pydantic-settings | API、事件、Provider、Tool 和配置边界 |
| HTTP | HTTPX | 普通 Provider 与 HTTP Tool 的异步客户端 |
| JSON | Python stdlib `json` | 无性能证据前不引入 `orjson` |
| 基础测试 | pytest、pytest-asyncio、pytest-cov、respx、Ruff、mypy | 实施后形成质量门禁 |

### 3.2 P1 Agent Runtime

| 技术域 | 选型 | 边界 |
|---|---|---|
| Graph Runtime | LangGraph OSS 1.x `StateGraph` | 唯一编排内核，承载所有执行策略和多 Agent 子图 |
| Checkpoint | `langgraph-checkpoint-postgres` `AsyncPostgresSaver` | 工作记忆、暂停和恢复；不替代运行事实 |
| 异步任务 | Taskiq + `taskiq-redis` `RedisStreamBroker` | API/Worker 解耦、ACK 和重投递；Windows 强制 PoC |
| 临时基础设施 | Redis asyncio + Redis Streams | Broker、短期 Run Event、取消信号、缓存和锁；非权威数据 |
| 关系数据 | SQLAlchemy 2.x async + Psycopg 3 | Agent 自有 Run、Step、Invocation、Usage、Event、Outbox 和记忆数据 |
| 迁移 | Alembic | 只管理 Agent 自有表，不接管 LangGraph 官方 Checkpoint 表 |
| 日志 | structlog + stdlib logging | 结构化日志、关联字段和集中脱敏；监控平台后置 |

### 3.5 P4 公共研究与数据分析

| 技术域 | 选型 | 边界 |
|---|---|---|
| 公共研究 | DeepSeek Responses API `web_search` + JSON Schema | 复用 P2 Model Provider，不建设搜索、爬虫或浏览器服务 |
| 来源 | Pydantic 版本化来源证据契约 | 结论与来源可关联；Schema 合法不代表事实已验证 |
| 表格分析 | Polars 1.x | 读取 CSV、JSON、Parquet，执行确定性清洗和聚合 |
| XLSX | fastexcel/calamine | 只读，不编辑、不生成、不执行宏或公式 |

P4 不做 Text2SQL、模型生成 SQL、业务数据库直连分析、Excel/图表生成或付费商业数据接入。

### 3.6 P5 MCP、评测与基础质量保障

| 技术域 | 选型 | 边界 |
|---|---|---|
| MCP | 官方 MCP Python SDK 2.x，普通 `mcp` 包 | 只建设 Client；不安装 `mcp[cli]`，不建设 MCP Server |
| MCP 传输 | Streamable HTTP；受限 stdio；SSE 仅遗留兼容 | 动态发现不得自动扩大允许清单 |
| 离线评测 | pytest + Pydantic + JSONL/Parquet + Polars | 项目内确定性指标，不新增评测平台或数据库 |
| 性质测试 | Hypothesis 6.x | 开发依赖，只验证底层不变量，不调用真实外部服务 |
| 依赖漏洞检查 | `uv audit --frozen` | 复用 uv，不引入 `pip-audit` |

## 4. 四层记忆架构

四层是数据语义分层，不是四套数据库或四个独立服务：

| 记忆层 | 内容 | 生命周期 | 技术落点 |
|---|---|---|---|
| 工作记忆 | 当前 Run 的 Graph State、当前步骤、中间结果和 Tool 状态 | 单次 Run | LangGraph State + AsyncPostgresSaver |
| 短期记忆 | 当前会话最近消息、补充输入和连续上下文 | 会话级，可跨 Run | PostgreSQL 权威存储；Redis 只作热点缓存 |
| 情景记忆 | 历史任务、关键决策、执行结果、失败经验、时间和来源 | 长期、事件化 | PostgreSQL 结构化记录；需要语义召回时进入 pgvector |
| 语义记忆 | 稳定知识、制度、文档、事实、概念和规则 | 长期、知识化 | PostgreSQL 元数据 + pgvector + PostgreSQL FTS |

所有记忆统一通过 Agent `Memory Port` 访问并执行租户、用户、Agent、权限、来源和保留期限隔离。Specialist Agent 不维护绕开治理的私有记忆库。

Run Event 是运行审计事实，不自动等于情景记忆；只有经过策略筛选、脱敏、结构化且允许长期保存的信息才能进入情景记忆。会话原文也不能自动全部提升为长期记忆。

不引入 Mem0、Zep、Letta 或独立向量/记忆服务。

## 5. MCP HTTP 客户端例外

P0/P2 的普通 HTTP 客户端仍是 `httpx.AsyncClient`。官方 MCP SDK 2.x 的 Streamable HTTP Client 使用 SDK 自带的 `httpx2.AsyncClient`，因此批准以下窄范围例外：

```text
普通 Provider、Rerank、外部 HTTP Tool → httpx.AsyncClient
MCP Streamable HTTP                   → mcp SDK → httpx2.AsyncClient
```

- `httpx2` 只能存在于 `tools/mcp` Adapter 内；
- 项目其他模块不得把 `httpx2` 当作通用客户端；
- 不使用普通 HTTPX 自行实现 MCP 协议；
- `mcp` 携带的 Server 侧传递依赖不构成 MCP Server 建设授权；
- 全部传递依赖进入 `uv.lock` 和 `uv audit`；
- 如果未来官方 SDK 消除该差异，通过普通依赖升级收敛，不改变上层 Tool 契约。

## 6. 数据与持久化边界

| 存储 | 权威数据 | 禁止事项 |
|---|---|---|
| Agent Runtime PostgreSQL | Run、Step/Invocation、Usage、长期 Run Event、Outbox、会话/情景记忆和 Agent 自有技术事实 | 不写 Java 业务表，不保存未经治理的业务数据副本 |
| LangGraph Checkpoint PostgreSQL | Graph State、工作记忆、暂停/恢复快照 | 不替代 Run、Usage、业务结果或完整长期记忆 |
| Agent Vector PostgreSQL | Document、Chunk、Embedding、语义记忆、向量索引和 FTS | 不混写不同模型、维度或距离空间 |
| Redis | Broker、短期事件、取消信号、缓存和锁 | 不保存权威 Run、Checkpoint、Usage 或长期记忆 |
| Tencent COS | 原始文件和批准保存的大型/派生产物 | 不保存权威状态，不绕过租户权限和审计 |
| JSONL/Parquet | 版本化离线评测数据和结果制品 | 不作为在线运行事实库或业务数据库 |

两个 PostgreSQL 逻辑数据源是否映射为同一实例、不同 database/schema 或不同实例属于部署设计，本阶段不裁决。

## 7. 统一执行与错误链路

```text
Inbound Contract
  → Harness 建立 RunContext
  → Strategy Router 选择执行策略
  → LangGraph 执行 Graph/Subgraph
  → Context/Memory/Tool/Capability 经稳定端口协作
  → Provider/Persistence Adapter 调用第三方技术组件
  → PostgreSQL 写权威状态与事件
  → Redis 提供短期交付和取消快信号
  → 统一 Result/Citation/Artifact/RunEvent 返回
```

所有 Provider、OCR、MCP、检索和对象存储错误必须转换为 Agent 错误契约。任何降级必须显式记录，不得用普通 Chat 伪装联网搜索、用未批准 OCR 伪装解析成功、用内存 Checkpoint 伪装可恢复或用 Redis 临时状态伪装权威事实。

## 8. 费用边界

### 8.1 免费开源组件

Python、uv、FastAPI、LangGraph、Taskiq、Redis Client、SQLAlchemy、Psycopg、Alembic、structlog、OpenAI SDK、HTTPX、pgvector Python、Jinja2、Docling、PaddleOCR、PaddlePaddle、pypdfium2、Polars、fastexcel、MCP SDK、pytest、Hypothesis 等软件本身无按次 API 调用费，但会产生计算、存储、网络和维护成本。

### 8.2 沿用的云费用

- LLM、Embedding 和 Rerank 按现有企业接口、合同、配额或当期云规则执行；
- 腾讯云 COS 继续产生存储、请求和流量费用；
- 云 OCR 当前关闭；
- DeepSeek `web_search` 若存在独立搜索附加费或付费商业数据源则关闭；
- 外部 MCP Server 自身若收费，未单独批准前不得进入允许清单。

### 8.3 明确禁止

不采购商业热点、舆情、新闻、搜索或内容审核数据源；免费额度用尽不能自动转为按量付费。

## 9. 环境与准入门禁

项目基线保持 Windows + CPython 3.13。包元数据只证明候选兼容，不代替真实运行。取得实施授权后必须依次验证：

1. uv 能在 Python 3.13 下解析、锁定并审计全部直接和传递依赖；
2. FastAPI、LangGraph、Checkpoint、SQLAlchemy/Psycopg 和 Redis 生命周期；
3. Taskiq/RedisStreamBroker 的 ACK、重投递、崩溃恢复和 Windows Worker 停止；
4. LLM、Embedding、Rerank、pgvector/FTS 和 COS 的真实兼容性；
5. Docling、PaddleOCR、PaddlePaddle、pypdfium2 和切片器的组合运行；
6. DeepSeek Responses 的 `web_search`、JSON Schema、来源字段和费用；
7. MCP Streamable HTTP、stdio、认证、超时、动态允许清单和结果限制；
8. 四层记忆的租户隔离、生命周期、来源、删除和提升规则；
9. 确定性评测可重复，Hypothesis 失败样例可重放，`uv audit --frozen` 可执行。

任何强制 PoC 失败时，只针对失败项重新评审。禁止未经批准降级 Python、增加常驻服务、切换收费 API、安装备用框架或引入第二套 Graph Runtime。

| 性能与容量 | 业务功能完成并形成真实链路、数据规模和并发目标 |
| 可观测平台 | 业务完成后形成排障、SLO、容量和告警需求 |
| 安全工具 | 实际代码、CI、外部文件和 Tool 风险面形成 |
| LLM Judge/高级评测 | 确定性指标无法覆盖真实业务语义质量 |

后置项目必须重新完成组件比较、费用、兼容性和范围评审，不能自动继承为必选项。

## 12. 完成声明与冻结状态

当前可以声明：

- P0～P5 技术组件已经逐项讨论并获得项目负责人批准；
- 四层记忆模型、MCP `httpx2` 隔离例外和兼容性/费用处理原则已经批准；
- P0～P5 跨阶段架构、职责、数据、依赖和费用一致性复核通过；
- 当前没有遗漏的必选第三方技术组件。

当前不能声明：

- 全部依赖已经安装或写入 `uv.lock`；
- P1～P5 运行代码已经实现；
- Provider、Redis、PostgreSQL、COS、OCR 或 MCP 已连接；
- PoC、真实质量、性能、监控、安全平台或生产验收已经完成；
- 数据库 DDL 已授权或执行；
- 系统可运行或可生产使用。

下一阶段只能在项目负责人再次明确授权后开始。授权时必须明确是编写实施计划、执行某个 PoC，还是实施某个阶段；总体设计批准本身不授权任何上述动作。
