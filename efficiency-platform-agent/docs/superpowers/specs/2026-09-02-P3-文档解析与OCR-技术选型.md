## 1. 目标与范围

P3 为上层 Agent 提供统一、可替换、可审计的文档摄取能力：对受支持文件先执行安全预检，再选择原生解析或 OCR 路径，最终转换为 Agent 自有、版本化的 `Document AST`。后续 RAG 只消费该稳定契约，不直接依赖 Docling、PaddleOCR 或厂商返回对象。

P3 包含：

- 文件签名、扩展名和 MIME 联合识别；
- 容器、XML、HTML、图片和 PDF 的解析前安全检查；
- PDF、OOXML Office、轻量文本和常见图片的统一解析；
- 扫描 PDF 与图片的本地 OCR；
- 复杂版面和表格的按需结构化识别；
- Agent 自有 `Document AST`、确定性质量判定和结构优先切片；
- 与 P2 Artifact、Embedding、pgvector 和 PostgreSQL FTS 的边界。

P3 不包含：

- 具体业务文档语义、字段抽取、业务 Agent、工作流和 Prompt；
- Java 侧接口、部署、容量规划、监控平台和数据库 DDL；
- ASR、TTS、音频或视频输入输出；
- 内容审核、商业文档解析服务和任何付费 OCR 兜底；
- 对公式、印章、图表等专项能力的默认启用；
- 代码语义切片框架。

## 2. 硬约束

1. P3 必须在 Windows 与 Python 3.13 目标环境完成准入 PoC，具体补丁版本通过 `uv.lock` 固化；本文不以文档推断替代真实兼容验证。
2. Docling 和 PaddleOCR 只能存在于 `capabilities/document`、`capabilities/ocr` 或 `providers/ocr` 适配边界，禁止其对象进入 Graph State、API 契约和 P2 检索契约。
3. 文件必须先完成类型、大小、页数/对象数和容器安全检查，再进入解析器；无法确认安全边界时失败关闭。
4. OCR 结果、文档正文、元数据和解析器输出均属于不可信数据，不得成为权限、Tool、SQL 或编排控制指令。
5. JSON 形式的 Agent `Document AST` 是唯一权威解析结果；Markdown、纯文本和 Chunk 都是可重建派生物。
6. 不使用视觉 LLM；文本 LLM 不能补写图片中未被可靠识别的内容，也不能覆盖确定性质量结论。
7. 本地免费组件是当前唯一活动 OCR 路径；云 OCR 只保留可选 Provider 接口，默认关闭且不参与验收。
8. P3 不新增常驻服务、商业组件或付费依赖，不讨论部署方式。

## 3. 支持格式边界

| 类别 | P3 当前支持 | 处理说明 |
|---|---|---|
| PDF | 文本型、扫描型、混合型 PDF | 先尝试 Docling；扫描页或需 OCR 页由 `pypdfium2` 栅格化后进入 PaddleOCR |
| Office | DOCX、XLSX、PPTX | 由 Docling 统一解析，不再并行维护一套必选原生 Office 解析栈 |
| 轻量文本 | TXT、Markdown、CSV、HTML | 编码先由 `charset-normalizer` 识别并统一为 UTF-8；HTML 先清洗后解析 |
| 图片 | PNG、JPEG、TIFF、WebP | Pillow 做安全读取和规格校验，PaddleOCR 提取文本；复杂布局按需进入 PP-StructureV3 |

下列格式暂缓：DOC、XLS、PPT、邮件、压缩归档作为用户文档、EPUB、RTF、音频和视频。Docling 能支持某种格式不代表 P3 自动开放；新增格式必须重新评审其依赖、安全、质量和退出成本。

## 4. 最终组件基线

| 技术域 | 最终选型 | 责任边界 | 当前状态 |
|---|---|---|---|
| 文件类型识别 | `puremagic 2.x` + Python `mimetypes` | 文件签名为主，扩展名和 MIME 交叉验证；不单独决定可信性 | 已确认，未引入 |
| 容器安全 | Python `zipfile` | 检查 OOXML 容器成员、嵌套、数量、解压总量、压缩比和路径 | 已确认，标准库能力未实现 |
| PDF 预检 | `pypdf` | 页数、加密状态、基本对象和文本密度辅助判定；不承担页面渲染 | 已确认，未引入 |
| 图片预检 | Pillow | 尺寸、像素量、帧数、格式和解压炸弹防护 | 已确认，未引入 |
| XML 安全 | `defusedxml` | OOXML/XML 安全解析，阻断危险实体和相关攻击面 | 已确认，未引入 |
| HTML 清洗 | `nh3` | 清除脚本、危险标签/属性和不受控链接语义 | 已确认，未引入 |
| 文本编码 | `charset-normalizer 3.x` | TXT/CSV/Markdown/HTML 字节编码识别并规范为 UTF-8 | 已确认，未引入 |
| 主文档解析 | `Docling 2.x` | PDF、DOCX、XLSX、PPTX、Markdown、CSV、HTML 的统一结构化解析 | 已确认，未引入 |
| PDF 页面渲染 | `pypdfium2 5.x` | 仅对需 OCR 的 PDF 页面做本地栅格化 | 已确认，未引入 |
| 本地 OCR | `PaddleOCR 3.x` + `PaddlePaddle 3.x` | 图片和扫描页的中英文文本识别；当前唯一活动 OCR 路径 | 已确认，未引入 |
| 复杂版面/表格 | PP-StructureV3 | 仅在确定性路由判定为复杂布局或表格时启用；属于 PaddleOCR 同一生态 | 已确认，按需启用，未引入 |
| 规范文档模型 | Pydantic v2 Agent `Document AST` | 对上层提供稳定、版本化、厂商无关的 JSON 契约 | 已确认，未实现 |
| 质量判定 | Agent 自有确定性规则 | 输出质量状态、原因码、告警和缺失范围；不由 LLM 主观裁决 | 已确认，未实现 |
| 文档切片 | Agent 结构优先切片器 | 按标题、段落、列表、表格、页码和来源边界切片 | 已确认，未实现 |
| 超长叶节点切分 | `semantic-text-splitter 0.32.x` | 只切分无法继续按结构拆分的超长纯文本叶节点 | 已确认，未引入 |
| 云 OCR 接口 | 阿里云 `qwen3.5-ocr` Adapter Port | 仅保留未来可选接口；默认关闭，无可接受免费额度时不得启用 | 可选、停用，不属于活动链路 |

上述主版本是选型约束，不是补丁版本承诺。实施获准后必须通过 Windows + Python 3.13 兼容性 PoC 决定补丁版本并写入 `uv.lock`。Docling 官方支持统一文档表示与 PDF、DOCX、XLSX、PPTX、Markdown、HTML、CSV 和图片等格式；P3 仍使用显式允许清单，而不开放全部格式：[Docling 支持格式](https://docling-project.github.io/docling/usage/supported_formats/)。PP-StructureV3 可按模块处理布局、表格和阅读顺序，但其可选公式、印章与图表模块不在当前基线：[PP-StructureV3](https://www.paddleocr.ai/latest/en/version3.x/pipeline_usage/PP-StructureV3.html)。

## 6. 解析与 OCR 路由

路由必须由文件事实和确定性指标决定，不由 LLM 自主决定：

1. 预检失败：返回 `REJECTED`，不得把文件交给 Docling 或 OCR。
2. 受支持的 Office、HTML、Markdown、CSV：进入 Docling；轻量文本先完成编码规范化，HTML 先完成清洗。
3. 文本型 PDF：优先使用 Docling 的结构结果。
4. 扫描型或混合型 PDF：仅将缺少有效文本的页面通过 `pypdfium2` 栅格化后送入 PaddleOCR，避免整份文档无条件 OCR。
5. 普通图片：进入 PaddleOCR 基础识别路径。
6. 复杂多栏、表格或阅读顺序无法可靠恢复时：按需启用 PP-StructureV3。
7. 解析完成后统一规范化为 Agent `Document AST`，再执行确定性质量检查。

“需 OCR 页面”“复杂布局”和“质量不足”的具体阈值必须由后续代表性脱敏语料 PoC 得出，不能在未验证时写死。模型规格使用可配置 profile；当前不裁决 server/mobile 或其他模型档位。

## 7. 解析前安全组件与规则

P3 必须落实[安全与数据治理规范](../../standards/07-安全与数据治理规范.md)中的文件边界：

| 检查阶段 | 组件/机制 | 失败处理 |
|---|---|---|
| 基础身份 | `puremagic`、`mimetypes`、扩展名、内容哈希 | 签名/扩展/MIME 冲突、未知类型或不在允许清单时拒绝或隔离 |
| 资源上限 | 文件字节、页数、对象数、图片像素和帧数上限 | 超限立即停止，不尝试以 OCR 或其他解析器兜底 |
| 容器检查 | `zipfile` | 超嵌套、超成员数、超解压总量、异常压缩比拒绝 |
| 路径检查 | 路径规范化、隔离根目录约束 | 绝对路径、设备路径、`..`、符号链接逃逸拒绝 |
| 主动内容 | 宏、脚本、公式外链、嵌入对象 | 永不执行；无法安全忽略时拒绝 |
| XML | `defusedxml` | 外部实体、危险声明或解析异常失败关闭 |
| HTML | `nh3` + 受控允许清单 | 清除脚本和危险结构后才进入解析；清洗失败拒绝 |
| PDF | `pypdf` | 加密、页数或对象策略不满足时拒绝或要求受控处理 |
| 图片 | Pillow | 解码异常、尺寸/像素/帧数超限或炸弹告警时拒绝 |

ClamAV 或其他恶意文件扫描器只保留未来 Adapter 边界，不是 P3 基线组件，也不是当前验收依赖。没有扫描器不代表文件可信；预检、隔离和资源限制仍然必须执行。

## 8. Agent Document AST 契约

`Document AST` 由 Agent 侧拥有并使用 Pydantic v2 定义。至少表达：

```text
Document
├─ schema_version
├─ document_id / tenant_id
├─ source
│  ├─ artifact_id / filename / media_type
│  ├─ content_hash
│  └─ parser / parser_version / ocr_profile
├─ metadata
├─ pages[]
├─ nodes[]
│  ├─ node_id / parent_id / order
│  ├─ type: heading | paragraph | list | table | image | caption | other
│  ├─ text / cells / attributes
│  ├─ page_number / bounding_box
│  └─ provenance / confidence / warnings
└─ quality
   ├─ status / reason_codes
   └─ missing_ranges / warnings / metrics
```

契约要求：

- `schema_version`、节点类型、质量状态和原因码必须版本化；未知字段按边界策略处理，不能静默改变语义。
- 页码、坐标、解析器、OCR profile、来源哈希和节点关系必须尽可能保留，以支持证据引用和问题定位。
- Docling/PaddleOCR 原始 JSON 可作为受控诊断 Artifact 按需保留，但不是上层权威契约。
- Markdown、纯文本和 Chunk 必须可由同一 AST 重新生成，不得各自形成不一致的权威版本。
- AST 内容仍是不可信数据；结构化不等于安全或事实正确。

## 9. 质量判定

P3 使用以下统一状态：

| 状态 | 语义 | 下游边界 |
|---|---|---|
| `ACCEPTED` | 必需结构和内容通过确定性规则，无阻断告警 | 可进入切片与 P2 索引 |
| `ACCEPTED_WITH_WARNINGS` | 主体内容可用，但存在可定位的非阻断缺失或低置信内容 | 可进入下游，但必须携带告警和来源范围 |
| `REVIEW_REQUIRED` | 无法证明内容足够完整，自动索引可能误导 | 不得自动成为高置信知识；进入人工复核边界 |
| `REJECTED` | 安全、格式、资源、解析或最低完整性要求失败 | 停止处理，不生成可检索知识 |

质量规则可以组合文本覆盖率、页面覆盖率、空页比例、乱码率、OCR 置信区间、表格结构完整性、阅读顺序异常、截断和解析告警。规则必须可复现、输出原因码，并由代表性语料验证。LLM 可以在未来业务层理解已成功提取的文本，但不能将 `REVIEW_REQUIRED` 或 `REJECTED` 自行改判为已通过。

## 10. 结构优先切片

P3 不引入 LangChain TextSplitter、LlamaIndex、Agno、cAST 或 ChunkHive。切片顺序固定为：

1. 先按 Document AST 的标题层级、段落、列表、表格、页码和来源边界形成候选块；
2. 相邻短节点可在同一语义父节点内合并，不跨租户、文档或不可解释的结构边界；
3. 表格按表头和行组切分，每块重复必要表头并保留表/页定位；
4. 只有超长纯文本叶节点才调用 `semantic-text-splitter 0.32.x`；
5. 每个 Chunk 保存 `document_id`、AST 节点范围、页码、来源、内容哈希、切片器版本和质量信息；
6. Chunk 尺寸和重叠阈值由后续 Embedding/RAG 代表性语料 PoC 决定，不在 P3 选型阶段臆定。

这是通用文档切片，不是代码 AST 切片。若未来出现代码知识库需求，应独立评估语言解析器和代码专用切片方案，不复用本次文档切片裁决强行覆盖。

## 11. P2 接入边界

```text
P3 owns: File → Safe Parse → Document AST → Quality → Chunk
P2 owns: Chunk → Embedding → pgvector/FTS → Retrieve → Rerank → Context
COS owns: raw file and approved large/diagnostic artifacts through ArtifactProviderPort
```

- P3 只向 P2 提供 Agent 自有 Chunk 契约，不暴露 Docling/PaddleOCR 类型。
- `ACCEPTED` 和策略允许的 `ACCEPTED_WITH_WARNINGS` 才能自动提交索引；其他状态必须显式阻断。
- P2 的 `text-embedding-v4 + 1024 + cosine` 向量空间、原生 FTS、Rerank 和索引版本规则保持不变。
- 原始文件和大型派生产物通过 P2 已选 `cos-python-sdk-v5` Adapter 保存；Run/Document/Chunk 元数据进入 Agent PostgreSQL 的具体表设计属于后续实施。
- 重新解析或模型升级必须创建解析/切片版本，禁止静默覆盖现有索引来源。

## 12. 成本、许可证与生态

| 项目 | 费用结论 | 约束 |
|---|---|---|
| Docling、pypdf、pypdfium2、Pillow、defusedxml、nh3、charset-normalizer、puremagic、semantic-text-splitter | 无软件调用费 | 仍有本机/服务器 CPU、内存、磁盘、网络和维护成本；许可证清单在实施前由供应链流程锁定并复核 |
| PaddleOCR、PaddlePaddle、PP-StructureV3 | 无 OCR API 调用费 | 模型下载和本地推理消耗计算资源；不得因此宣称零总成本 |
| 阿里云 `qwen3.5-ocr` | 当前不启用、不进入预算 | 只有存在可接受免费额度且另行批准时才可启用；免费额度用尽后必须停止，不能自动转按量付费 |
| COS | 沿用 P2 费用边界 | 存储、请求和流量可能计费，不属于 P3 新软件授权费 |

本阶段未执行正式许可证法律复核，也未测算自建资源成本。组件实施前必须生成锁定版本的软件物料清单并复核许可证、模型权重许可、数据处理边界和供应链来源。

## 13. Windows 与 Python 3.13 兼容门禁

文档或包元数据只能作为候选证据，不能替代本机验证。实施获准后至少验证：

- uv 在 Windows 上能解析并锁定全部 P3 依赖，无互斥的 Paddle/Docling/原生轮子冲突；
- Python 3.13 下 Docling、PaddlePaddle、PaddleOCR、pypdfium2 和 `semantic-text-splitter` 可导入并完成最小调用；
- CPU 基线路径可运行，且不会隐式要求 CUDA、Poppler、LibreOffice、Tika Server 或其他常驻服务；
- TXT、PDF、DOCX、XLSX、PPTX、HTML、CSV 和四种图片格式分别有最小样例；
- 扫描 PDF、混合 PDF、复杂表格、乱码、加密文件、损坏文件和超限文件覆盖成功与失败路径；
- 质量状态、来源定位、Chunk 可重建性和 P2 契约一致性通过测试。

如果核心组件无法满足 Windows + Python 3.13，先记录阻断证据并重新评审组件或进程边界，不能静默降级 Python 基线、额外部署服务或引入收费 API。

## 14. 明确不选择

| 不选项 | 裁决原因 |
|---|---|
| Apache Tika | Docling 已覆盖当前开放格式；Tika Server 会增加第二解析栈和额外运行边界 |
| Office 原生解析栈作为必选项 | 不同时强制引入 `python-docx`、`openpyxl`、`python-pptx` 等重复解析路径；专项编辑/导出需求出现后再评估 |
| RapidOCR | PaddleOCR 是本地 OCR 主路径，不并存第二套 OCR Runtime |
| `python-magic` / libmagic | Windows 需处理额外原生库；当前选择纯 Python、跨平台的 `puremagic` |
| PyMuPDF | 当前 PDF 预检和渲染分别由 `pypdf`、`pypdfium2` 承担，不增加重叠组件 |
| `pdf2image` / Poppler | 避免额外系统可执行依赖；PDF 栅格化使用 `pypdfium2` |
| ClamAV 必选 | 不新增部署组件；只保留未来恶意文件扫描 Adapter |
| 完整 LangChain / LangChain TextSplitter | P2/P3 契约和切片由 Agent 自有实现，不引入高层框架依赖 |
| LlamaIndex / Agno | 不引入第二套 RAG、Agent 或数据处理抽象 |
| cAST / ChunkHive | 面向代码语义切片，不匹配当前通用办公文档和图片范围 |
| 视觉 LLM | 当前没有视觉模型，且不以付费模型替代可验证解析/OCR 链路 |
| 商业 OCR/文档解析服务 | 与“免费优先、无付费兜底”的当前裁决冲突 |

## 15. 降级与退出策略

- Docling 失败不能自动改用未批准的解析器；返回明确失败或复核状态并保留受控诊断信息。
- PP-StructureV3 不可用时，可按质量规则保留基础 PaddleOCR 结果并标记告警或要求复核，不能伪装成完整结构化解析。
- 云 OCR Adapter 始终支持配置关闭；关闭后主链路和验收必须仍然成立。
- 组件替换只需在 Adapter 内转换为相同 `Document AST`，并以同一代表性语料回归质量、来源和安全契约。
- `Document AST`、原始文件、派生物和 Chunk 必须具备解析器/模型/切片器版本，以支持并行重建和回退；不得原地不可追溯覆盖。

## 17. 当前冻结边界

P3 技术组件和边界及其跨阶段关系已经批准。当前仍禁止：

- 修改 `pyproject.toml` 或 `uv.lock` 引入 P3 依赖；
- 下载 OCR 模型或调用云 OCR；
- 编写 P3 业务/运行代码或数据库迁移；
- 连接真实文档、COS、PostgreSQL 或模型服务做 PoC；
- 把计划能力描述成已实现、已验证或可生产运行。

只有再次获得项目负责人对 P3 具体实施范围的明确授权后，才能进入 P3 实施设计与兼容性验证。
