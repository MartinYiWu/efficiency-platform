## 1. 目标与技术取舍

输入为不可变 `ResearchBriefV2`，输出为带研究状态、证据引用和缺口说明的 `ResearchOutcomeV2`。既要能回答“找到了什么”，也要能回答“为什么选它、还缺什么、为什么继续或停止”。

确定采集方向：仅使用已核实免费且可用的 API、RSS/Atom 和公开页面，按需采集并复用已有证据；通过免费来源的查询/分页、来源切换和公开原文获取完成补采。LLM 提出查询与补采动作，不要求使用模型厂商的联网搜索服务。纯 RSS 无法覆盖任意历史需求；纯搜索缺乏稳定来源和执行账本；全量周期爬虫不是首轮必要前提。

2026-09-16，用户先明确确认上述免费可用来源边界，随后又明确要求依据三份实施计划逐阶段开发，因此本设计的 Agent 侧离线实现和分阶段开发已经获批。真实来源逐项启用、新增模型费用、共享 DDL、部署和生产运行配置变更仍须按实施计划的独立闸门验收与授权。

首轮范围：日/周 AI 行业简报、用户指定主题和来源约束、带证据的后续内容生成。接口可扩展到其他行业，但不声称已有全球全行业来源。

非目标：收费商业数据源、绕过登录/付费墙、全网穷尽保证、事实绝对正确保证、历史热度回填、自动外部推送、浏览器抓取服务、图数据库和监控平台。

## 3. 数据源策略：来源有角色，不按数量堆砌

### 3.1 首批候选来源清单

下表是准入顺序，不是已上线清单；候选入口不能直接进入生产配置。实施时验证公开访问、API/Feed 地址、返回 Schema、时间字段、授权条件及历史覆盖，再登记精确入口。

| 优先级 | 候选源/入口 | 建议接入 | 角色及限制 |
|---|---|---|---|
| P0 | [OpenAI News](https://openai.com/news/)、[Anthropic News](https://www.anthropic.com/news)、[Google DeepMind](https://deepmind.google/discover/blog/) | 官方 Feed 可用时用 Feed，否则允许的静态公告页/搜索定位后打开 | 一手发布；“宣布效果”与效果客观成立分开 |
| P0 | [Qwen 官方仓库](https://github.com/QwenLM)、[DeepSeek 官方仓库](https://github.com/deepseek-ai)、[Hugging Face Blog](https://huggingface.co/blog) | 指定仓库 Releases/API、官方文章 | 模型/开源发布，不把每次 commit 都当行业新闻 |
| P0 | [GitHub Releases API](https://docs.github.com/en/rest/releases/releases) | 登记 owner/repo 的版本发布查询 | 只采允许清单；需要分页/速率处理；密钥来自配置注入 |
| P0 | [arXiv API](https://info.arxiv.org/help/api/index.html) | AI/ML 指定分类，提交/更新分别处理 | 研究线索；预印本不是已验证行业结论 |
| P0 | [Hacker News API](https://github.com/HackerNews/API) | 官方 item/top/new 数据 | 发现和社区热度；分数/评论仅表示该平台关注 |
| P1 | [36 氪](https://36kr.com/)、[机器之心](https://www.jiqizhixin.com/)、[量子位](https://www.qbitai.com/)、[TechCrunch](https://techcrunch.com/) | 官方 Feed/允许网页；参考 Daybreak RSS/36Kr 适配 | 报道、发现、背景；版权和可访问范围逐项确认 |
| P1 | [GDELT](https://www.gdeltproject.org/) | DOC API，参考 O8 的窗口和错误映射 | 新闻发现及覆盖补充；搜索结果仍需取原文，不承诺完整覆盖 |
| 非必选，默认不纳入 | 现有服务端 web_search | 仅保留兼容代码，不因存在配置就进入新方案 | 未证明采集服务免费且可用时禁止启用；即使后续准入，模型 Token 仍单独计账；URL 不等于已打开页面 |
| P2 | 国内热榜、Reddit、Product Hunt、RSSHub 生成源 | 通过逐源准入后才启用 | 可选发现信号；接口、许可、登录或稳定性不满足则不接入 |

首轮离线和真实冒烟的最小组合为：一个免费官方公告 Feed/页面、一个免费指定仓库 Releases API、一个免费 HN/媒体发现源。支持按条件检索的免费 API 通过准入后用于补采；现有服务端搜索不再是必选项。来源准入失败时报告阻塞或换已批准免费候选，不把表中全部源默认启用。

国外厂商来源不自动等于“海外事件”；中文媒体不自动等于“国内事件”。地区筛选按 brief 的事件地区口径执行。

### 3.2 SourceDescriptor

显式注册 Schema：`source_id, adapter_id, config_version, role, topics, languages, regions, publisher_id, ownership_group, allowed_hosts, access_mode, history_mode, max_lookback, pagination, freshness_sla, rate_policy, content_policy, cost_policy, admission_record_id, enabled`。

- `role`：primary/reporting/discovery/heat，可多选；来源角色不等于事实可靠性分数。
- `history_mode`：queryable/archive/latest_only/unknown，unknown 不用于证明历史覆盖。
- `content_policy`：允许存储内容、是否仅摘录、保留期限、访问限制和准入记录 ID。
- `adapter_id` 只绑定组合根显式注册代码；配置不得包含可执行模块路径。
- 运行时健康独立于静态描述，记录最近错误、成功时刻、熔断截止，不由 LLM 改写。

来源选择先做硬过滤（权限、时间覆盖、用户限制、启用状态），再按角色和覆盖需求选择。软优先级依次考虑主题匹配、补足空白、一手优先、健康和预计成本；同条件按稳定 source_id 排序，保证回放一致。

费用与可用性是前述硬过滤的组成部分，具体规则如下：

- `cost_policy.mode` 为 `free / free_quota / paid / unknown`；只接受 free，或经证明可在零收费范围内硬停止的 free_quota。
- 记录收费依据、核验时间、适用用途、免费配额/重置周期、是否需要免费认证、超额行为及本地硬停止方式。需要付费账户才能访问的接口不因边际费用为零就认定为免费。
- 对免费配额型接口，在派发前预留额度、完成后结算；不确定剩余额度、无法保证零收费、试用过期或费用规则变化时禁用。免费是数据访问边界，不是通过拆分账号绕过限流。
- 可用性验证不仅检查 HTTP 200，还要验证实际数据 Schema、目标主题、发布时间字段、正文/原文链接、历史范围和限流；空壳响应或只适合别的用途的接口不准入。
- 每个来源保留 `VERIFIED / UNVERIFIED / BLOCKED` 的准入状态和 `last_verified_at`；首次接入必须实测，接口、权限、价格或用途变化时重新核验。候选名单不得冒充已验证名单。
- 已准入来源失败或额度耗尽，只切换另一个已准入免费来源，或输出 PARTIAL/FAILED 及缺口；禁止自动转付费 API、购买套餐或绑定支付。

### 3.3 历史数据与增量

按需采集也保存合法的已取证据及抓取游标；后续请求优先复用满足时间、版本、权限和 freshness 的缓存。首次启动没有历史库，必须明示历史覆盖受限。

RSS 最新列表只能证明已返回条目的情况，不能证明整天没有新闻。只有来源支持完整分页、对应历史查询，或自有存档覆盖时间窗，才可将该检查标记 COMPLETE。

常规采用 ETag/Last-Modified 条件请求；304 只有在本地存在对应可用缓存对象时才能算缓存命中。分页达到上限标记 TRUNCATED，不等同空结果。

## 4. 总体执行图

```text
validate_brief → plan_sources → discover_candidates → acquire_documents
                                                        ↓
                                  normalize → filter → deduplicate_documents
                                                        ↓
                                    cluster_events → extract_claims
                                                        ↓
                                             evaluate_quality
                                  ┌─────────────────────┼───────────────────┐
                                达标              可补缺口且有预算        不可继续
                                  ↓                     ↓                    ↓
                              compose          plan_targeted_collection   finalize_outcome
                                  ↓                     │                    │
                             verify_output      受控回到发现/取文/核验        │
                           ┌──────┴──────┐                                   │
                         通过       表达错误/证据缺口                          │
                           ↓        有界修复或补采                            │
                         render ────────────────────────────────→ deliver
```

这是现有 LangGraph 中的研究子图，不新增顶层 Runtime。普通简报可由单研究 Specialist 执行子图；确需多任务分工时只由现有中央 Supervisor 调度。Provider 及确定性过滤函数不是每个都要做成“一个 Agent”。

`ResearchGraphState` 仅保存 brief/policy/revision、来源执行 ID、文档/事件/证据 ID、质量报告 ID、补采动作和预算引用。正文放受控 Artifact，按需经 ContextBuilder 裁剪，不把整站 HTML 塞入 State 或检查点。

所有新契约均在中立 `contracts/research_v2.py` 及相关子模块；Provider 不引用 `agents.operation` 的业务类型。第一期不搬迁整个 V1 模型，采用 V1 Adapter 保持边界。

## 6. 采集与正文取得

1. **发现**：API、Feed、搜索返回候选，保存来源执行事实和原始时间证据。
2. **安全预检**：方案/主机/解析 IP/端口/响应类型准入；重定向逐跳再验。
3. **抓取**：API 或 Feed 完整正文可直接形成内容记录；摘要 Feed 和搜索片段需要回源。已有 Provider 返回的真实 open_page 内容也可利用，但须保留可识别的内容与来源关联。
4. **提取**：Feed 字节交给 feedparser；已安全取得的 HTML 交给 Trafilatura。不使用解析库附带联网函数绕过安全层。
5. **失败处理**：正文不可达可换合法公开原文；禁止通过网页存档/代理绕过付费墙；只有片段的候选仍可用于发现，不计入严格事实门禁。
6. **记录**：保存实际 URL、重定向后 URL、获取时刻、状态码、MIME、hash、正文/摘录存储引用和解析版本。

默认 HTML/Feed 解压后单响应上限建议 2 MiB、最多 3 跳重定向、连接超时 3 秒、单请求 10 秒；实际取较严格的来源策略和剩余预算。首轮不下载视频、可执行文件、图片和 PDF 全文；论文使用元数据/摘要只支持摘要范围内的主张，全文论证不足则说明缺口。

HTTP 429 尊重 Retry-After；408/部分 5xx/网络抖动可有限重试；401/403、无效 Schema、禁止地址不自动重试。重试同样消费请求数和截止时间，不额外开新预算。

## 7. 时间、过滤和质量分层

### 7.1 统一时间语义

来源必须分别保存 `published_at, updated_at, event_at, first_seen_at, fetched_at` 及来源、精度。仅有日期时保存覆盖区间，严格时间窗默认要求该日期区间完全在目标窗口内；部分重叠标记歧义，不能伪造精确时刻。

事件资格默认按最早可确认的首发发布时间，昨天的转载不能让旧事件变成新事件。实质性更新作为关联的新事件或新版本，须有支持该更新的证据。

`within_time_window` 必须由时间字段与 brief 计算；未知为 UNKNOWN，不再默认 True。外部搜索的时间参数只帮助缩小候选，不能替代逐条校验。

### 7.2 分级过滤

- F0 资源与安全：不合规 URL、MIME、大小、注入企图；危险对象拒绝并记录原因。
- F1 可判定条件：时间、来源/地区/语言限制、排除项、空内容、重复文档。
- F2 语义相关：模型根据 brief 返回 `relevant / irrelevant / uncertain`、对应 requirement_ids 和依据短摘录。先用轻量规则作召回，不能仅因缺少关键词排除同义表达。
- F3 事实支持：提取 Claim 并验证摘录定位、主体、数字、时间与引用；语义支持判断属于模型辅助结论，不等于确定性真伪证明。
- F4 集合质量：事件数、用户明确维度、来源独立性、冲突和覆盖范围。

各阶段保留拒绝原因；不要让“没有内容”隐藏它是被日期、主题、安全还是证据门禁过滤。

## 8. 去重与事件整合算法

### 8.1 文档层

优先匹配 `(source_id, source_item_id)`，再匹配安全规范 URL，最后匹配清洗正文 hash。只移除已知跟踪参数和 fragment；保留文章 ID、版本等有意义参数。相同 URL 的不同内容 hash 作为版本，不覆盖旧引用。

可借鉴 Daybreak 的跨源内容合并，但各来源正文、发布时间、作者及转载关系单独保存，不将它们糊成没有出处的文本。

### 8.2 事件层

首轮采用 Daybreak 的模型事件分组思路：候选按实体、日期邻近和产品版本分桶，模型返回成员 ID 与合并依据；代码校验 ID 存在、不重复分配、版本/事件类型不冲突。一个桶建议最多 30 条，超出拆批并复查代表事件。

不按“都提到某公司”聚合。示例：同一模型发布的 8 篇报道可以合并；同模型发布与安全事件分开；发布 v1 与 v2 分开。不确定则保留分开并降低重复率置信，不为凑条数拆分同一事件。

数据量证明确有瓶颈后，才用已有 embedding 空间召回相似候选，再做事件判别；首轮不新增向量索引或固定余弦阈值冒充事件准确率。

### 8.3 独立来源与冲突

用原始引用链接、稿件相似度、publisher/ownership、通稿标记识别来源族；两个域名不自动独立。独立性未知时标记 UNKNOWN，不能满足“双独立来源”的门槛。

Claim 类型建议：`announcement / reported_fact / measured_result / opinion / inference`。官方公告可证明宣布，效果指标保留“发布方称”；论文结论注明研究报告属性；评论和推断不混入已核验事实。

冲突记录双方主张及证据，优先寻找原始材料。无法消解时从关键事实中排除，或明确按“存在争议”输出两方归属；不能通过多数转载投票决定真相。

## 9. 排序与覆盖

资格筛选先于排序；再高的热度不能弥补没有证据或时间不符。

默认 `importance` 使用可解释等级（重大产品/研究/产业变化、明确影响、一般更新），模型提供等级及证据依据；同等级优先用户关注维度和新近事件，稳定 event_id 作为末位排序。不输出未经校准的精确“真实性 98%”。

`heat` 只使用实测平台排名、分数、评论及观察时间；各平台按各自尺度归一化，缺失不是 0，不直接把 stars 与评论相加。有足够多次同口径观测后才计算变化速度。没有历史观测就不能回答“昨天涨得最快”。

覆盖通过 `CoverageMatrix[requirement_id]` 表达：需求、合格事件/Claim、来源检查状态、剩余缺口。覆盖维度仅来自明确请求或公开默认策略，不强制每份 AI 简报必须有融资、政策、模型和硬件各一条。

## 10. 允许输出的标准

### 10.1 事件级硬门禁

| 编号 | 条件 | 不通过处理 |
|---|---|---|
| H1 | 相关、时间及用户限制符合要求 | 排除或补充时间/实体证据 |
| H2 | 至少取得支持关键事实的完整正文、完整 Feed/API 内容或可定位原始记录 | 片段只作线索，继续取原文 |
| H3 | 每个输出事实都有 EvidenceRef；hash/摘录区间有效，关键实体数字日期一致 | 修正表达或补证据；禁止无引用事实 |
| H4 | 非重复事件；各来源关联保留 | 合并事件，不用重复填数量 |
| H5 | 没有被当作确定事实输出的未决关键冲突 | 去掉结论、明确争议或继续核验 |
| H6 | 来源使用/访问/保留策略允许，来源内容未扩大工具权限 | 拒绝相关材料 |

H2/H3 证明有可追溯支持，不保证事实绝对正确。普通公告一个真实一手记录即可支持“发布方宣布”；争议或高影响效果类结论要求独立佐证或保留明确归属，不能强行统一成“每条新闻必须两家媒体”。

### 10.2 交付级门禁

- 所有正式条目通过事件级硬门禁；事实引用覆盖率 100%（按已识别事实单元计算，另做人工遗漏抽检）。
- 用户指定的硬维度满足；软偏好未满足可告知但不自动变 FAILED。
- `exact N`：N 条不同合格事件才 COMPLETE；不足但至少 1 条可 PARTIAL，明确不足。`at_most N`：1..N 条且覆盖要求满足可 COMPLETE。`best_effort`：建议目标 5、最低 1；少于 5 本身不强制 PARTIAL，但有未解决关键覆盖缺口则 PARTIAL。
- 未指定来源数量时不强制“至少三家”；必须核对来源独立性与声明强度，避免为数量引入低质量来源。
- 最终文章不能引入证据包之外的数字、因果或排名。只修语法与格式失败，重新渲染；新增事实缺证据，先删除/改写，仍为用户必需项时才补采。

### 10.3 结果语义

| ResearchOutcome | 进入条件 | 对用户表达 |
|---|---|---|
| COMPLETE | 全部硬要求满足，至少一个合格事件，输出检查通过 | 交付并说明范围和必要限制 |
| PARTIAL | 有可用事件，但硬数量/覆盖/核验仍有缺口，已无法继续或到软停止点 | 交付可用部分 + 未满足项 + 停止原因 |
| NO_MATCHES | 无合格事件，约定检查计划完整执行，无关键失败/截断/未知历史覆盖 | “在已检查的这些来源和时间范围内未找到”，不声称全网没有 |
| FAILED | 无可交付事件且故障、预算或覆盖不足使研究无法有效完成，或致命完整性错误 | 说明失败阶段和原因，允许用户重新触发 |

成功空、失败空、限流空和被过滤为空分别记录。单一来源失败不会自动让整个任务失败；若其他来源满足硬要求，可 COMPLETE 并附警告。致命租户/安全完整性错误不得继续交付潜在污染结果。

## 11. 补采决策与停止算法

### 11.1 缺口到动作的映射

| 缺口码 | 动作 | 必须保持的不变量 |
|---|---|---|
| INSUFFICIENT_EVENTS | 换同义表达、英文/中文查询、未覆盖来源；排除已有事件 | 不扩大日期、地区或被排除主题 |
| MISSING_REQUIRED_FACET | 针对缺失 requirement_id 查询 | 不重复采已经覆盖的子主题 |
| PRIMARY_SOURCE_MISSING | 用事件实体/版本定向官方站点、论文/发布记录 | 不把二手转载当一手 |
| CONTENT_UNAVAILABLE | 获取完整 Feed/API、原始公告或合法公开替代来源 | 不绕过认证/付费墙 |
| TIME_UNKNOWN | 提取时间元数据、核对原始公告/记录 | 不用 fetched_at 回填 published_at |
| CONFLICT_UNRESOLVED | 查原始材料和独立来源 | 不把转载数量当投票 |
| HEAT_UNSUPPORTED | 查已批准且同时间窗的热度记录 | 不自动改成重要性榜；允许说明缺口 |
| SOURCE_TEMPORARY_FAILURE | 在时限内按策略重试，或换同角色免费来源 | 重试同样计入请求配额；涉及模型的调用另计 Token |
| FREE_QUOTA_EXHAUSTED | 停止该源请求，切换其他已准入免费来源 | 不超额计费，不自动购买/升级 |
| SOURCE_COST_UNVERIFIED | 阻止调用并记录准入缺口 | 不用一次真实计费调用来试探是否免费 |
| HISTORY_COVERAGE_UNKNOWN | 换支持历史查询的来源/已有存档 | 无法补足时标记范围受限 |
| OUTPUT_FORMAT_INVALID | 仅重渲染 | 不触发新的采集 |

计划由模型或确定性策略提出 `action_type, gap_ids, source_ids, query, expected_evidence_kind`。代码根据权限、硬约束、已执行动作和剩余预算裁决；缺口不存在或 source_id 未注册即拒绝。

### 11.2 选择优先级与信息增益

不使用未经训练的“预期收益概率”假装优化算法。首轮采用可解释顺序：阻断性事实/时间缺口 → 用户硬维度 → 条数缺口 → 软丰富度；同等级优先未试过的一手来源、健康来源、低成本动作。

动作指纹由 brief revision、gap、source、规范化 query、cursor 组成。除明确暂态故障的有限重试外，同指纹不再次派发。

每轮完成计算增益：新增合格事件数、由不支持转为支持的必要 Claim 数、被关闭硬缺口数。仅新增重复文章或更多字数为零增益。连续 2 个完整补采轮次零增益时停止；单个来源正在退避不单独视为一轮。

### 11.3 裁决伪代码

```text
检查取消、致命安全错误、Harness 硬截止；命中则立即终止派发
quality = evaluate(brief, current_evidence, policy)
若交付级门禁通过：进入 compose/verify_output
若有预算且未达轮次/无增益上限：
    actions = 按缺口生成并验证动作
    actions = 删除越权、重复、超预算和范围扩大的动作
    若仍有 actions：预留预算，执行，归并事实，重新 evaluate
若没有合格事件且完整检查证明无匹配：NO_MATCHES
否则若有合格事件：PARTIAL
否则：FAILED
```

`ResearchComplete` 只提出结束建议，必须再经过 evaluate。模型没有工具调用、输出解析失败、到达循环上限，都不能绕过门禁进入 COMPLETE。

## 12. 预算、超时和取消

以下为首轮建议的 `standard_digest_v1` 上限，待真实验收校准，不是性能承诺：

| 项 | 建议上限 | 含义 |
|---|---|---|
| 总 Run 时间 | 180 秒或更严格的现有 Harness 上限 | 用户/租户策略可更小 |
| 研究软截止 | Run 剩余时间扣除输出预留 35 秒 | 到软截止仍可交付已有部分 |
| 初采 + 补采 | 1 次初采，最多 2 轮补采 | 输出校验导致补采也占这 2 轮，不重新计数 |
| 搜索请求 | 总计 8 次 | 含重试、查询改写和补采 |
| 外部 HTTP 请求 | 总计 60 次，其中正文至多 30 次 | 分页、重试均计入，不能用 Provider 内部循环绕过 |
| 并发 | 全局 4，同主机 1 | 来源约束更严时取更严值 |
| 暂态重试 | 每动作最多 2 次额外尝试 | 总调用上限和截止优先 |
| 输出修复 | 最多 1 次 | 只修格式/措辞，不无限重写 |
| 模型预算 | 继承现有 Run Token/费用上限 | 输出预留建议至少 25%；费率不明不得假设零成本 |

配额为最大值，不要求耗尽。无来源完整度需求的小任务可提前完成。

Harness 为解释/研究/生成发放子预算租约，共享一份总账：派发前原子预留、完成后结算、未使用部分释放；超时但可能已计费的外部调用记录 unknown/estimated，保守占用预算。API 请求数与模型费用分开记录。

软研究截止产生领域 PARTIAL/FAILED；Harness 硬截止产生 TIMED_OUT，不能为写完文章越过截止。硬超时或取消时，已持久化的部分证据仍可查，但 Run 不可宣称成功。

取消信号传播至正在等待的 HTTP/模型任务，停止新派发；取消后迟到结果只记账/审计，不发送新的成功交付。

## 13. 输出契约及生成方式

`DeliveryPackV2` 是事实权威输入，渲染为 JSON/Markdown；面向公众号/小红书的后续生成继续由现有内容 Specialist 处理，不在采集节点顺便写营销稿。

每个事件输出：标题、发生/发布时间口径、核心事实、意义（标为分析）、引用列表、来源角色、核验/争议标签、重要性或热度依据。整包输出：准确时间窗、实际条数、研究状态、已覆盖范围、未满足项和停止原因。

生成阶段仅允许选择 DeliveryPack 中的 evidence_id，URL 由服务端引用表注入，防止模型编造网址。校验事实单元与引用映射、摘录支持、数字/主体、无重复、数量与平台结构；模型辅助支持判定不作为唯一程序准入条件。

若内容生成失败但结构化研究包合格，可降级为确定性 Markdown 简报；若用户明确要求特殊成稿而未满足，任务展示为 degraded，而不能把简报伪装成完整成稿。

PARTIAL 示例表达：“已核对 3 条符合指定日期的新闻；原要求 5 条，另 2 条线索发布时间无法确认，补采达到本次预算，因此未收录。”不能只显示通用“请稍后重试”，也不能暴露内部异常或凭据。

## 14. Run 状态与协议兼容

领域结果不改变现有 RunStatus：

| 领域结果/原因 | Run 终态 | 既有展示状态 |
|---|---|---|
| COMPLETE 且交付符合用户格式 | SUCCEEDED | succeeded |
| PARTIAL 且形成明确标记的可用交付 | SUCCEEDED | degraded_succeeded |
| NO_MATCHES 且计划完整检查 | SUCCEEDED | succeeded，正文明确已检查范围内无匹配 |
| FAILED | FAILED | failed |
| Harness 硬截止/用户取消 | TIMED_OUT/CANCELLED | 沿用既有错误/取消映射；不新增 V1 枚举 |

V1 ResearchProviderPort 不直接返回 V2 类型。新增 `ResearchServiceV2` 中立端口，V1Adapter 只把旧观察转成候选，不能把 `valid` 变为内容已核验。旧运行路径可继续消费原 V1。

现有 SSE 使用 `research_started/research_completed/quality_checked/phase_started` 等名称，不能向 V1 硬塞新的事件枚举。详细来源和补采事件先进入内部 `RunEventV1.strategy_event` 的版本化 payload；V2 输出仅对显式支持的消费者开放。

V1 对话可先交付已有允许的文本/产物及 degraded 展示；新增字段须通过契约测试验证，无法无损表达时提供保守文本说明，不静默升级对端协议。本设计不修改 Java/UI 消费方。

## 15. 持久化、幂等和恢复

### 15.1 逻辑数据模型

| 逻辑记录 | 主键/唯一约束建议 | 保存内容 |
|---|---|---|
| research_run | tenant_id + research_id | brief、revision、策略/Schema、领域结果、停止原因 |
| research_action | tenant_id + research_id + action_fingerprint | 状态、尝试、租约、预算预留/结算、Provider 请求关联 |
| source_attempt | tenant_id + attempt_id | 成功/空/失败/截断、时间、计数、限流/错误 |
| source_document | tenant_id + source_id + source_item_key + content_hash | 来源、时间、正文引用、许可/保留策略 |
| research_event | tenant_id + research_id + event_id | 事件聚类版本、成员、代表材料 |
| research_claim/evidence_ref | tenant_id + claim/evidence_id | 事实、支持区间、冲突和审核版本 |
| research_quality_decision | tenant_id + research_id + decision_sequence | 质量快照、缺口、动作和停止依据 |

可以用少量带版本 JSONB 的表承载以上逻辑对象，不要求一对象一表；实施前复用现有 Repository，避免重复建模。全文不写 RunEvent 或日志。共享 DDL 必须单独提交预检/迁移/回滚包并获授权。

默认建议：原始 HTML 最长 7 天；允许保留的正文摘录/证据 30 天；脱敏决策元数据 90 天，来源限制或租户政策更短时取较短值。删除正文后引用标记 artifact_expired，不宣称仍可按原文复核；仍保留许可允许的 hash/URL/时间事实。

### 15.2 恢复语义

Checkpoint 保存节点位置和对象 ID，Repository 保存已确认事实，两者不假设共享事务。节点恢复先以动作指纹查询已完成结果，幂等复用，再推进 State；事件用 outbox/单调序号去重。

远程只读 HTTP/LLM 不可能仅靠本地幂等键保证 exactly-once：调用完成但提交前崩溃时结果可能未知。标记 UNKNOWN_OUTCOME，先利用 Provider 请求查询能力（若存在）；没有则按策略决定是否再次调用并保守计费，不宣称绝无重复成本。

已提交结果可幂等消费；进行中租约到期允许安全认领；取消/终态不恢复运行。相同请求的重复消息不得重复交付或重复记账同一已知 invocation。

当前真实工厂仍有内存接线，切换前必须完成 PostgreSQL Repository 和 Checkpoint 的重启验收。存在持久化代码不等于已经验收。

## 16. 安全与来源准入

- 仅 HTTPS 公开来源，默认禁止 userinfo、非批准端口、本地/私网/链路本地/云元数据地址。DNS 校验和实际连接目标一致，重定向每跳重验，防 DNS rebinding。
- 新 `security/url_policy.py` 必须经测试准入；当前不能假设已有完整主动抓取 SSRF 实现。
- 严格限制压缩前后大小、重定向、解析时间、嵌套 XML 和正文长度；不加载脚本，不把网页中的工具调用示例当指令。
- 外部内容经 ContextBuilder 标记为不可信数据；不得覆盖 system、来源策略、预算、租户或交付要求。
- 用户提供 URL 仍需授权来源/公开网页策略检查；不得把任意 URL 交给搜索或抓取工具无条件执行。
- 缓存、文档、向量和证据查询均带 tenant_id；首轮不做跨租户公共内容共享缓存，避免查询和来源授权泄漏。
- 访问条款、robots 及内容使用限制作为来源准入条件；robots 不是版权授权。禁止为了提高成功率更换代理绕过访问控制。
- Secret 使用已有配置注入，日志只记录 source_id、脱敏域名、错误码和 hash；查询中的敏感业务内容不原样输出。

## 17. 观测与错误模型

内部事件建议：`source_planned/source_attempted/document_acquired/document_rejected/event_clustered/evidence_checked/research_gap_detected/research_replanned/research_stopped/output_verified`，作为现有 strategy_event 的受控子类型。

每次决策记录：run/task/revision、策略版本、阶段、合格事件数、支持 Claim 数、gap_ids、来源执行状态、预算余量、下一动作或 stop_reason。只记录可审计的结论依据，不存模型隐藏思维。

错误码：`SOURCE_TIMEOUT / SOURCE_RATE_LIMITED / SOURCE_AUTH_REQUIRED / SOURCE_FORBIDDEN / SOURCE_SCHEMA_INVALID / SOURCE_TRUNCATED / SOURCE_HISTORY_UNSUPPORTED / FREE_QUOTA_EXHAUSTED / SOURCE_COST_UNVERIFIED / CONTENT_UNAVAILABLE / CONTENT_REJECTED / EVIDENCE_UNSUPPORTED / EVIDENCE_CONFLICT / RESEARCH_NO_GAIN / RESEARCH_BUDGET_EXHAUSTED / OUTPUT_INVALID`。Provider 原异常留在脱敏诊断边界，不统一压成一个 RESEARCH_UNAVAILABLE 后丢失。

停止原因：`QUALITY_MET / PLAN_EXHAUSTED / NO_GAIN / ROUND_LIMIT / SOFT_DEADLINE / BUDGET_LIMIT / USER_CANCELLED / HARD_DEADLINE / FATAL_ERROR`。质量状态和停止原因是两个字段。

## 19. 测试与验收

### 19.1 固定回放集

建议 100 篇合法脱敏固定文档，标注至少 30 个真实事件；覆盖同稿转载、多语言同事件、同产品不同版本、发布时间未知、旧闻重发、相互矛盾、纯片段、403/429/5xx/分页截断等。文本与预期值固定，不使用实时搜索作为单元测试数据。

其中开发集与冻结集按事件划分，避免同一事件转载跨集合。事件匹配报告 pairwise precision/recall；首轮建议 precision 至少 98%、recall 至少 90%，并单独列出误合并事件，不以去重数量越多越好。

### 19.2 关键验收矩阵

| 编号 | 场景 | 预期 |
|---|---|---|
| R01 | 昨天任务经过 Specialist/Provider | 每层完全相同时间范围，绝不改成今天/24 小时 |
| R02 | 同公告 10 份转载 | 一个事件，一个原始来源族，不算 10 条/10 独立证据 |
| R03 | 同产品发布和安全事故 | 两个事件，不能误合并 |
| R04 | URL 参数包含不同文章 ID | 不能规范化成同一文档 |
| R05 | 只有搜索摘要/无法取正文 | 不满足内容证据门禁，触发补采或不足 |
| R06 | 来源全部超时 | FAILED，不是 NO_MATCHES |
| R07 | 完整计划各源正常且确无匹配 | NO_MATCHES，限定已检查范围 |
| R08 | 只有最新 RSS，用户要上周 | 历史覆盖未知，不允许 NO_MATCHES |
| R09 | exact 5 仅找到 3 条合格 | 定向补采后可 PARTIAL，不凑数、不拓宽日期 |
| R10 | 两个补采轮次只返回重复内容 | NO_GAIN 停止，保留原证据 |
| R11 | 429、分页截断、日期缺失 | 分别记录，不折叠为空 |
| R12 | 官方效果声明缺独立证明 | 归属表达，不写成已证实领先 |
| R13 | 引用存在但摘录不支持数字 | 输出门禁拒绝，修复或补证据 |
| R14 | 非法 URL、重定向至私网、DNS 变化 | 连接前/每跳阻断，0 次私网请求 |
| R15 | 网页注入要求换主题/扩大预算 | 无效，原 brief 与权限不变 |
| R16 | 并发任务预留预算、重试和迟到响应 | 总预算不超发，unknown 调用成本不当作零 |
| R17 | 调用后提交前崩溃 | UNKNOWN_OUTCOME，不宣称 exactly-once |
| R18 | 已持久化动作后重启 | 幂等复用，输出事件序号不重复 |
| R19 | 取消或硬截止 | 停止派发，保持 CANCELLED/TIMED_OUT，不转成功 |
| R20 | V1/V2 并存和回滚 | 不重解释 V1 valid，不用 V1 读 V2 checkpoint |
| R21 | 收费未知、付费或免费试用到期的来源 | 准入拒绝，0 次来源调用，不自动购买 |
| R22 | 免费配额不足及并发额度竞争 | 派发前硬停止，切换免费来源或明确不足，不越额 |
| R23 | HTTP 200 但无效 Schema/不具备所需时间覆盖 | 不标记可用，不用于证明完整采集 |

### 19.3 验收层次

1. 单元/契约：Mock HTTP、固定时钟、结构化模型 Fake，以上关键不变量必须全部通过。
2. 集成：临时隔离 PostgreSQL/受控 Artifact；状态、租户、恢复和预算竞态；不接共享库默认执行。
3. 真实来源：逐项记录可达性、Schema、时间字段、历史分页、限流和正文可用性；源失败不能用其他测试替代它的准入。
4. 真实模型：标注集评估相关性、聚类、事实遗漏、误支持与无效引用；人工复核冻结样本，不让 LLM Judge 成为唯一验收人。
5. 端到端：真实“昨天 AI 新闻”请求能交付可追溯结果；若当天无足够事实必须正确部分/空交付。没有结果不能预设为测试失败，也不能让故障空通过。

拟新增测试位置：`tests/unit/capabilities/research_v2/`、`tests/contract/providers/research_v2/`、`tests/integration/research_v2/`、`tests/acceptance/test_research_v2_closed_loop.py`。实施后回归既有研究、EvidenceGate、conversation 和 architecture 用例；本轮不宣称新路径存在或测试通过。

## 20. 迁移顺序、回滚与发布条件

1. 批准 ADR，冻结 Brief/Outcome 与来源契约；新增离线样本和失败用例。
2. 显式装配 V2 契约、免费 API/Feed、公开网页提取器和来源准入；同时通过免费/可用性及安全门禁后才开放出网，不要求接入现有服务端搜索。
3. 接入事件/Claim/证据和质量门禁；先无补采运行，确认结果状态可靠。
4. 加入有限补采和预算租约；用故障/无增益用例验证停止。
5. 接入持久化恢复、输出兼容和真实来源/模型验收；再灰度。

建议配置 `research_pipeline_version`、`research_source_allowlist`、`research_policy_version` 和 `research_replan_enabled`。新 Run 固定版本；实施切换时新旧链路都必须遵守免费准入，现有搜索若费用/可用性未知则关闭，不因保留旧代码而默认启用。可以先关补采保留单轮证据获取，再完全关闭 V2；无合规来源时明确不可用，不能用普通 Chat 冒充联网研究。本轮仅修改设计，尚未改变现有运行配置。

回滚不删除证据/审计，不把领域 PARTIAL 改成 COMPLETE。进行中的 V2 Run 保持版本或明确取消；迁移保留旧读能力，禁止回滚时 DROP 新记录。

准入批准人是项目负责人；Agent 端维护负责人提供依赖、来源、契约、安全、恢复及质量证据。预算/保留期限采用本文建议作为评审起点；不确定来源保持禁用，禁止为“完成进度”虚报生产可用。

## 21. 端到端决策样例

以下为固定回放样例，数字仅用于说明决策，不是本次真实采集结果。

用户要求：“收集昨天 AI 行业新闻，选 5 条，优先官方来源。”采用意图设计中的固定时钟，`exact=5`、Asia/Shanghai 昨日日历窗。

| 阶段 | 输入/结果 | 裁决 |
|---|---|---|
| 意图解释 | topic=AI 行业、时间明确、数量 5、官方优先但非仅官方 | READY；无需再询问主题 |
| 初次发现 | 4 个已批准来源返回 36 个候选；一个额外来源限流 | 限流单独记录，不中断成功来源 |
| 过滤/归并 | 去掉 12 个窗外/未知日期、8 个无关、10 个重复文章，余 6 个不同事件候选 | 不能把 36 个 URL 报成 36 条新闻 |
| 证据检查 | 3 个事件有可定位原文，2 个仅摘要，1 个存在关键日期冲突 | 暂有 3 个合格，形成正文和时间缺口 |
| 补采第一轮 | 仅查询那 3 个缺口的原始材料；补足 1 个事件，另 2 个仍不足 | 4 条合格；不重搜已通过的 3 条 |
| 补采第二轮 | 无新增合格事件，剩余 1 个必需条数缺口，轮次耗尽 | ROUND_LIMIT；PARTIAL；不是模型自行说“完成” |
| 输出 | 4 条新闻，每条有事实与引用；说明原要求 5 条及未收录原因 | degraded_succeeded，不引入今天旧闻补到 5 条 |
| 后续“改成上周” | 新 revision，时间重新解析；旧证据按新窗口重新判定 | 重新规划，不能只换标题里的日期 |
| 后续“把这 4 条写成公众号” | 引用已交付证据包，新生成目标 | 若没有新增事实需求，仅生成并核验，不再次全网采集 |

该回放必须同时断言 SourceAttempt、CoverageMatrix、预算消耗、stop_reason 与最终状态，不能只对比成稿文本。
