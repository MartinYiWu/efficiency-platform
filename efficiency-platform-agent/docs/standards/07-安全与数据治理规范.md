## 1. 信任模型与默认拒绝

身份、权限、系统规则和受控配置 MAY 作为经验证控制数据；用户文本、网页、文件、检索片段、OCR 结果、Memory 内容、Tool/MCP 输出和模型输出 MUST 视为不可信数据。任何解析、策略或授权步骤无法确定安全结果时 MUST 默认拒绝，MUST NOT 依赖模型自称安全、已授权或已完成。

安全决策 MUST 产生稳定结果、原因码和脱敏审计证据。测试 MUST 同时证明允许路径可用、拒绝路径无外部副作用，并 MUST 覆盖编码、嵌套、重定向、并发和重放等绕过尝试。

## 2. 身份、租户与授权传播

`tenant_id`、`user_id`、主体类型、角色/能力、授权范围和审计上下文 MUST 由受信任入站身份或受控服务建立，并 MUST 由 Harness 传播。模型、Prompt、外部文件和 Tool 返回 MUST NOT 构造、替换或提升这些字段。

- Context、Memory、Tool、Provider、Persistence、检索和 Artifact MUST 按租户与主体执行最小权限；
- 跨租户访问 MUST 默认拒绝；受控例外 MUST 绑定明确策略、目标租户、用途、期限和审计证据；
- 子任务和 Specialist MUST 只获得完成任务所需的权限与裁剪上下文，MUST NOT 自动继承父 Run 的全部能力；
- 授权凭证、审批和能力票据 MUST 绑定主体、租户、资源、动作、参数摘要、有效期和防重放标识；
- 下游无法验证授权传播或资源所有权时 MUST 拒绝，MUST NOT 使用默认租户或全局管理员兜底。

授权测试 MUST 覆盖同租户允许、跨租户拒绝、缺失/伪造上下文、权限缩减、并发和过期票据。

## 3. Prompt Injection 与不可信内容

系统指令、开发规则、Tool 策略和不可信数据 MUST 在结构与渲染上分区。外部内容中的“忽略规则”“调用工具”“泄露系统提示”等文本 MUST 保留为数据，MUST NOT 转换为权限、路由、SQL、Tool 或持久化控制指令。

Context Builder MUST 标记来源、信任级别、数据分级和引用，并 MUST 按预算裁剪。不可信内容需要触发 Tool 时，Harness/Tool Runtime MUST 重新校验当前主体、允许清单、参数 Schema、审批和预算；模型建议 MUST NOT 代替这些检查。

系统/开发 Prompt、策略、Secret 或内部错误信息 MUST NOT 因外部内容请求而回显。安全测试 MUST 使用直接、间接、编码、跨文档、Tool 输出和 Memory 污染样例验证边界。

## 4. SSRF 与网络访问

每次外部 URL 请求及每一跳重定向 MUST 在建立连接前执行完整 SSRF Policy：

1. 协议 MUST 来自封闭允许清单，用户信息段、模糊编码和解析歧义 MUST 拒绝；
2. 域名 MUST 规范化并匹配允许规则，IP 字面量和解析结果 MUST 独立校验；
3. DNS 的全部 A/AAAA 结果 MUST 校验，连接目标 MUST 与已校验结果绑定，并 MUST 在重试/重新解析时复查以防 DNS 重绑定；
4. 回环、私网、链路本地、云元数据、保留地址、组播和策略禁止的地址/端口 MUST 拒绝；
5. 重定向 MUST 逐跳限制次数，并对新协议、域名、端口、DNS/IP 和授权重新校验；
6. 客户端 MUST 设置连接/读取/总超时、响应字节上限、解压后上限、限速和取消；
7. 代理、环境代理和自定义 DNS MUST 受配置治理，MUST NOT 允许请求参数绕过策略。

校验失败、DNS 变化、响应超限或策略无法解析时 MUST 终止读取并记录安全拒绝。测试 MUST 覆盖 IPv4/IPv6 变体、编码地址、CNAME/多 IP、DNS 重绑定、公开地址跳私网和压缩响应膨胀。

## 5. 文件与文档安全

文件进入解析器前 MUST 校验文件签名、声明扩展名、MIME、大小、页数/对象数和允许类型；三者不一致或类型未知时 MUST 拒绝或进入隔离。归档和容器格式 MUST 限制嵌套深度、文件数量、单文件/总解压大小和压缩比，以防解压炸弹。

文件名和归档成员路径 MUST 规范化并限制在隔离目录，绝对路径、设备路径、符号链接逃逸和 `..` 路径穿越 MUST 拒绝。不可信文件、宏、脚本、公式外链、嵌入对象和可执行内容 MUST NOT 直接执行；解析器 SHOULD 在隔离、最小权限和资源限制下运行。

XML MUST 使用安全解析；HTML MUST 清洗；上传场景 SHOULD 通过恶意文件扫描适配器。扫描结果未知或扫描器不可用时，风险策略 MUST 决定拒绝或保持隔离，MUST NOT 自动转为可信。文件正文、OCR 文本和元数据 MUST 遵守敏感数据、上下文预算和日志禁止项。

## 6. Text2SQL 与业务数据访问非目标

当前 MUST NOT 引入 Text2SQL、模型生成 SQL 或面向业务数据库的直接分析。模型文本、Prompt、结构化输出、网页内容和 Tool/MCP 返回 MUST NOT 被拼接、解释或转换为可执行 SQL；模型也 MUST NOT 持有业务数据库凭据。

Agent 自有运行数据只能通过受控 Repository 或数据访问端口查询，值 MUST 参数化，动态标识符 MUST 来自封闭映射，并继续执行身份、租户、权限、超时、行数与结果大小限制。未来若要改变该边界，必须先重新完成组件选型、威胁建模和明确批准，MUST NOT 从当前规范推断存在默认 Text2SQL 实现。

## 7. Secret 与配置

密钥、令牌、密码、连接串、Cookie、私有端点和签名材料 MUST 通过环境或受控 Secret 引用注入。它们 MUST NOT 进入代码、Prompt、SQL、测试样本、日志、Trace、Metric、Audit 正文、Artifact、错误或文档。

配置对象 MUST 保存 Secret 引用而非值，并 MUST 声明所有者、用途、权限和轮换策略。Provider MAY 在最靠近调用边界的受控进程解析引用，但 MUST NOT 向上层返回真实值。

发现泄漏时，责任人 MUST 停止扩大影响、使凭据失效/轮换、核对访问和审计记录、清理可恢复副本并验证新凭据；MUST NOT 只删除当前文件后继续使用旧凭据。测试和示例 MUST 使用显然无效且不似真实凭据的占位值。

## 8. 模型输出与下游编码

结构化模型输出 MUST 在进入 Graph State、Tool、SQL、Persistence 或 Artifact 前通过版本化 Schema 校验，并 MUST 应用字段长度、数组数量、嵌套深度、枚举、数值范围和总字节限制。未知字段、截断 JSON、类型强制歧义和超限输出 MUST 拒绝或返回明确错误。

输出进入 HTML、Markdown、CSV、文件名、URL、SQL 或其他解释器时 MUST 使用目标上下文的安全编码或封闭映射。模型声称内容已转义、来源可信或具有权限 MUST NOT 跳过下游校验。自由文本 MAY 作为受限展示内容，但 MUST NOT 直接驱动控制流或可执行上下文。

## 9. 高风险 Tool 与审批

写入、删除、外发、权限变化、付费调用、不可逆操作或能影响外部主体的 Tool MUST 按高风险治理。审批请求 MUST 包含主体/租户、Tool 和版本、规范化参数摘要、目标资源、预计副作用、幂等键、预算、有效期和可验证审批者。

审批凭证 MUST 与上述对象绑定、一次性消费或原子防重放，并 MUST 在执行前复查当前策略。审批拒绝、过期、参数变化、主体变化、重复消费或状态未知时 MUST 默认拒绝。历史审批、模型判断、相似参数或 Tool 自报成功 MUST NOT 代替本次审批。

执行后 MUST 记录脱敏审计、实际副作用、幂等结果和验证结论。重试 MUST 证明同一幂等键不会重复副作用；无法证明时 MUST NOT 自动重试。

## 10. Artifact 访问

Artifact MUST 绑定租户、主体或受控共享范围、数据分级、所有者、来源、生命周期和内容哈希。下载/预览 MUST 使用短期签名 URL；URL MUST 限定对象、动作、过期时间和最小访问范围，MUST NOT 暴露长期凭据或允许目录枚举。

签名 URL 生成和下载 MUST 进行租户/权限校验并产生审计。转发、过期、撤销、对象替换和猜测路径 MUST 有拒绝测试。Artifact 到期、删除或访问撤销后，缓存和派生链接 MUST 按策略失效。

## 11. 数据分级与生命周期

数据 MUST 至少按公开、内部、敏感、受限进行分级，并 MUST 为来源、用途、允许处理、存储位置、共享范围、留存期和删除方式指定策略。系统 MUST 最少收集完成任务所需数据，MUST NOT 因未来可能使用而无限保存原始 Prompt、响应、文档或用户标识。

敏感和受限数据 MUST 在传输、存储、检索、备份、Artifact 和评测样本中执行相应访问控制与脱敏。日志和 Trace MUST NOT 记录原始敏感 Prompt/响应、完整文档、Secret 或未经脱敏个人数据；需要关联时 SHOULD 使用受控或不可逆标识。

留存到期或合法删除请求触发时，数据及受治理派生物 MUST 按可验证流程删除或不可逆匿名化，并 MUST 记录范围、时间、责任人和结果。备份、索引、缓存和 Artifact 的延迟删除边界 MUST 明确，MUST NOT 以删除主记录声称全部清除。

## 12. 审计与证据

授权、审批、Tool 执行、数据访问、跨租户拒绝、Prompt/Provider/配置变化、Artifact 访问、删除和安全拒绝 MUST 形成追加式审计事件。事件 MUST 包含稳定事件名、时间、主体/租户受控标识、资源、动作、策略版本、结果、原因码和关联 `run_id`/`trace_id`；正文和参数 MUST 脱敏。

安全证据 MUST 有保留和访问边界。业务日志、Trace 和审计 MUST 各自承担职责，MUST NOT 用可采样日志替代不可缺失的审计记录。

## 13. 当前非目标与例外

当前不建设内容审核能力。该裁决只排除内容分类/审核模型和流程，MUST NOT 放宽身份、租户、Prompt Injection、SSRF、文件、SQL、Secret、模型输出、Tool、Artifact 和数据生命周期基线。

对本规范 `MUST` 或 `MUST NOT` 的例外 MUST 按[工程规范索引](00-规范索引.md)记录。跨租户默认拒绝、Secret 禁止落库/日志、禁止模型生成/执行 SQL、高风险审批和不可信输入边界 MUST NOT 通过普通例外降低。
