## 1. 稳定命名原则

文档文件名 MUST 使用稳定日期、类型或 ADR 编号和清晰中文主题表达所有权，MUST NOT 依赖“新”“最后”等相对时间词。主题 MUST 使用项目统一术语，并 MUST NOT 包含真实客户、Secret、环境凭据或个人信息。

日期 MUST 使用文档首次建立或该独立版本生效的公历日期 `YYYY-MM-DD`，MUST NOT 因日常编辑改变。ADR 编号 MUST 在仓库内唯一、四位左补零且单调分配；废弃或删除的编号 MUST NOT 复用。

## 2. 文件名格式与示例

### 2.1 架构/模块设计

格式：`YYYY-MM-DD-主题-设计.md`

- 合法：`2026-09-01-Agent运行治理-设计.md`
- 合法：`2026-09-01-统一上下文构建器-设计.md`
- 非法：`Agent设计最终版.md`（缺日期且含不可追溯版本词）
- 非法：`2026_09_01_agent_design.md`（日期与主题格式不合规）

### 2.2 实施计划

格式：`YYYY-MM-DD-主题-实施计划.md`

- 合法：`2026-09-01-Agent运行治理-实施计划.md`
- 非法：`2026-09-01-Agent运行治理-plan.md`（类型后缀不合规）
- 非法：`new-实施计划.md`（缺日期、主题且含相对版本词）

### 2.3 ADR

格式：`ADR-NNNN-短标题.md`

- 合法：`ADR-0001-LangGraph作为唯一运行时.md`
- 非法：`ADR-1-LangGraph.md`（编号未使用四位格式）
- 非法：`ADR-0001-final.md`（标题不可追溯且含禁止版本词）

### 2.4 技术选型

格式：`YYYY-MM-DD-主题-技术选型.md`

- 合法：`2026-09-01-Agent可观测性-技术选型.md`
- 非法：`2026-09-01-Agent可观测性-最新版.md`（缺文档类型且含禁止版本词）
- 非法：`技术选型.md`（缺日期和主题）

### 2.5 评审报告

格式：`YYYY-MM-DD-主题-评审报告.md`

- 合法：`2026-09-01-Agent工程规范-评审报告.md`
- 非法：`Agent工程规范-review.md`（缺日期且类型后缀不合规）
- 非法：`2026-09-01-Agent工程规范-final.md`（缺类型且含禁止版本词）

目录 README、编号规范和受控模板 MAY 采用其治理结构约定的稳定名称。例外名称 MUST 在目录索引声明理由和所有者，MUST NOT 用例外规避设计/计划/选型/报告格式。

## 3. 禁止命名

文件名、标题版本后缀和目录名 MUST NOT 使用“最终版”“最新版”“new”“final”或同义的不可追溯词表达版本。文档版本 MUST 通过日期、ADR 编号、状态、替代关系和版本历史表达。

非法示例只用于评审识别，MUST NOT 复制为真实文件。临时草稿如需协作也 MUST 使用正式格式并标记状态为 `草案`，MUST NOT 以 `copy`、`副本` 或个人姓名区分版本。

## 4. 文档头必填元数据

每份受治理文档 MUST 在标题后提供可见的元数据表，且 MUST 包含：

| 字段 | 约束 |
|---|---|
| 标题 | MUST 与文档主标题和主题一致 |
| 状态 | MUST 是 `草案`、`评审中`、`已批准`、`已废弃` 之一 |
| 作者/负责人 | MUST 是可追责角色或人员，MUST NOT 只写模型名 |
| 创建日期 | MUST 使用 `YYYY-MM-DD` 且首次创建后保持稳定 |
| 最后更新日期 | MUST 使用 `YYYY-MM-DD` 并与实质变更同步 |
| 评审人/批准人 | MUST 区分评审和批准责任；未发生时 MUST 明确写 `未指定` 或 `尚未批准`，MUST NOT 虚构姓名或批准 |
| 关联 ADR/设计/计划 | MUST 使用相对链接；无关联时 MUST 写明 `无` 并说明范围 |
| 替代关系 | MUST 标明“无”、替代/被替代文档及双向链接 |
| 适用范围 | MUST 明确模块、阶段和不适用边界 |

文档 MAY 增加风险、数据分级、版本、所有者团队等字段，但 MUST NOT 删除上述字段。元数据变化 MUST 与正文和索引保持一致。

## 5. 状态与迁移

状态语义如下：

| 状态 | 语义 | 使用边界 |
|---|---|---|
| `草案` | 作者正在形成内容，尚未进入正式评审 | MUST NOT 作为批准决策或实施授权 |
| `评审中` | 范围和内容已可评审，结论尚未批准 | MAY 用于收集意见，MUST NOT 声称已批准 |
| `已批准` | 指定批准人已按范围批准且证据已记录 | MAY 成为后续实施和评审基线 |
| `已废弃` | 已被替代、撤销或不再适用 | MUST 保留原因、日期和替代链接，MUST NOT 作为新实施依据 |

合法迁移为：

```text
草案 → 评审中 → 已批准 → 已废弃
  ↑       │          │
  └───────┘          └─→ 新文档/新 ADR 进入草案或评审中
```

评审发现实质缺口时，`评审中` MAY 回到 `草案`。只修正不改变裁决的排版或链接时，`已批准` MAY 保持状态，但 MUST 记录变更；任何改变决策、范围、契约、安全基线或兼容性的修改 MUST 创建替代文档/ADR，MUST NOT 原地覆盖。

进入 `已批准` MUST 记录批准人、批准日期、批准范围、评审结论和可追溯证据引用。作者自述、自动测试通过、聊天中的模糊同意或文件名包含“批准” MUST NOT 代替批准证据。`已废弃` MUST 记录废弃原因、日期、责任人和替代关系。

## 6. ADR 触发条件

以下任一变化 MUST 在实施前创建并批准 ADR：

- 架构边界、依赖方向、顶层模块或所有权变化；
- Graph Runtime、Agent 编排范式、Run 生命周期或 Checkpoint 边界变化；
- 外部/内部协议、稳定契约、错误模型或版本兼容策略变化；
- 核心数据模型、权威状态、租户隔离或持久化边界变化；
- 安全基线、审批、权限、Secret、SQL 或数据生命周期边界变化；
- 引入或替换不可逆、迁移复杂、高退出成本或平台锁定显著的技术组件。

局部重构在不改变上述裁决时 MAY 不创建 ADR，但 MUST 在设计或变更说明中记录验证范围。是否触发存在争议时 MUST 先按触发处理并由架构负责人裁决，MUST NOT 先实施后补记录。

## 7. 已批准文档的替代与版本历史

已批准决策 MUST 通过新 ADR、新日期版本或明确的新设计替代，MUST NOT 原地覆盖、删除历史正文或重写批准证据。新旧文档 MUST 建立双向相对链接：新文档记录“替代”，旧文档记录“被替代”，并在旧文档标记 `已废弃`、原因和日期。

替代前，新文档 MUST 说明兼容窗口、迁移、风险、回滚和未解决项；仅有新文件名 MUST NOT 构成替代生效。历史修正如涉及事实错误，也 MUST 以勘误记录保留原证据和修正原因，MUST NOT 静默改写审计事实。

文档 SHOULD 维护简明版本历史，包含日期、作者、变更摘要和关联评审/ADR。Git 历史 MAY 提供辅助证据，但 MUST NOT 代替正文状态和替代关系。

## 8. 链接、索引与归档

仓库内链接 MUST 使用相对路径，并 MUST 指向实际文件或明确标记的规划目标。移动、重命名、替代或废弃文档时，变更者 MUST 更新所有已知入站链接、目录索引和替代关系，并 MUST 执行链接有效性测试。

每类正式文档 MUST 在所属目录 README 或权威索引可发现；规范与模板 MUST 进入[工程规范索引](00-规范索引.md)。孤立文件、只依赖聊天消息定位的文档和不可解析的本地绝对链接 MUST NOT 作为交付基线。

已废弃文档 MUST 保留在原路径或受控归档目录，并 MUST 保持可读、带废弃原因和替代链接。归档移动导致链接断裂时 MUST 提供稳定重定向说明或同步所有引用；MUST NOT 为“目录整洁”删除历史裁决。

## 9. 例外记录

对规范规则的例外记录 MUST 恰当包含以下六项：

1. 例外规则：文档、章节和具体 `MUST`/`MUST NOT`；
2. 业务/技术原因：目标、约束和已评估备选方案；
3. 风险评估：安全、数据、兼容、运行、成本和影响范围；
4. 补偿措施：控制、监测、验证和恢复动作；
5. 责任人：实施、风险接受和批准责任；
6. 到期时间与复审条件：明确日期、触发条件和恢复合规标准。

六项任一缺失时例外 MUST 视为未获批准。口头约定、聊天摘要、代码注释、Issue 标题或永久无期限豁免 MUST NOT 代替正式记录。例外到期或复审条件触发时，责任人 MUST 重新评估并选择恢复合规、批准新期限或停止相关能力。

## 10. 评审与自动检查

文档交付 MUST 检查文件名格式、元数据字段、状态、相对链接、索引、替代关系、禁止版本词和说明性占位内容。自动检查通过 MUST NOT 代替语义、批准证据、安全边界和实际实现评审。

评审报告 MUST 区分文档存在、链接有效、内容评审、批准、实施和运行验证。未经批准的 `草案`/`评审中`文档 MUST NOT 被报告为已批准基线。
