## 1. 核心原则

新增或改变行为 MUST 遵循测试先行，并提供本次执行的新鲜证据。测试通过只证明其覆盖的性质，MUST NOT 被扩大解释为未执行的兼容性、真实 Provider、数据库、网络、设备、质量或生产验收。

修复实现以让测试通过时，测试本身 MUST 表达稳定需求，MUST NOT 把当前实现细节固化为无意义断言。无法自动化的验收项 MUST 明确责任人、步骤、输入、预期结果和未验证原因。

## 2. 测试分层

### 2.1 单元测试

单元测试 MUST 验证纯函数、值对象、状态转换、路由规则、预算、错误映射和单一模块行为。它 MUST 快速、隔离、可重复，并 MUST NOT 访问真实网络、数据库、缓存、对象存储或模型。

关键边界值、空输入、非法状态、超时计算、预算耗尽和异常路径 MUST 与主路径同时覆盖。

### 2.2 契约测试

契约测试 MUST 验证请求、响应、事件、错误、Protocol、Tool Schema、Provider Adapter、Persistence Port 和版本兼容性。契约用例 MUST 对所有同类实现复用同一断言；厂商字段 MUST 在 Provider 边界归一化后验证，MUST NOT 泄露到上层快照。

新增端口或破坏性 Schema 变更 MUST 先增加能证明兼容或明确失败的契约测试，并提供版本或迁移策略。

### 2.3 架构与治理测试

架构测试 MUST 验证包结构、依赖方向、Core 隔离、Provider/Persistence 反向依赖、执行策略和扩展槽。治理测试 MUST 验证必需文档、相对链接、核心章节、SQL 授权词和命名规则不会被误删。

AST 守卫通过 MUST NOT 被解释为运行期动态依赖、职责边界或 Graph Runtime 唯一性全部通过；未被编码的规则仍 MUST 在评审中检查，并 SHOULD 逐步转成自动化。

### 2.4 Graph 测试

Graph、Node 和 Strategy 测试 MUST 覆盖：

- 初始状态、合法与非法状态转换；
- Node 输入状态和最小输出增量，不丢失无关字段；
- Direct/Workflow/ReAct/Plan-and-Execute/Multi-Agent 的路由与终止条件；
- 最大步骤、Token、时间、费用和 Tool 白名单预算；
- Checkpoint 写入、暂停、恢复、补充输入、审批、取消和超时；
- 同一 `run_id + checkpoint` 的重放与幂等；
- Node/Tool/Provider 的失败、重试、降级和部分结果；
- Supervisor 上下文裁剪、并发上限、Specialist 隔离、冲突与结构化汇总。

Graph 测试 MUST 使用确定的时钟、ID、随机源和测试 Checkpointer；MUST NOT 通过真实等待或无界循环验证超时与终止。

### 2.5 Provider 集成测试

Provider 集成测试 MUST 验证真实适配边界的请求映射、认证注入位置、连接池、显式超时、限流、错误归一化、用量字段、重试和降级。测试 MUST 区分：

- 离线契约：MUST 使用受控协议假体验证映射，MAY 在无真实 Secret 的环境执行；
- 本地集成：连接临时数据库、缓存或受控服务；
- 真实冒烟：MUST 仅在明确配置、授权和费用边界下调用真实 Provider。

真实冒烟未执行时 MUST 标为“未验证”，MUST NOT 由 Mock 或 HTTP 200 替代。涉及付费模型的测试 MUST 有调用上限和费用保护。

### 2.6 RAG 与 OCR 固定数据集

RAG/OCR 质量测试 MUST 使用版本化、合成或脱敏的固定数据集，并记录数据集版本、解析器/模型逻辑名、Prompt/配置版本和阈值。

RAG SHOULD 验证召回率、排序、引用覆盖、证据一致性、租户隔离和空结果；OCR SHOULD 验证文本、页码/坐标、表格/阅读顺序、置信度、扫描件与失败兜底。指标阈值 MUST 基于基线或业务验收定义，MUST NOT 因一次失败临时降低而不留评审记录。

### 2.7 安全测试

安全测试 MUST 覆盖与改动相关的租户/用户隔离、最小权限、审批、Prompt Injection、模型输出 Schema、SSRF（含重定向和 DNS/IP 变化）、文件类型/大小/恶意内容、只读 SQL、日志脱敏、Secret 和高风险 Tool 幂等。

安全拒绝路径 MUST 验证稳定错误和审计事件，同时确认外部副作用未发生。测试数据 MUST NOT 使用真实密钥、个人信息或生产文档。

### 2.8 验收测试

验收测试 MUST 从稳定入站契约出发，验证 Run 创建、事件流、策略选择、Graph 执行、Tool/Provider 治理、Checkpoint、恢复/取消以及结果、证据、引用和 Artifact。验收 MUST 同时核对最终内容与关键中间治理证据，MUST NOT 只断言 HTTP 200 或进程存在。

依赖真实基础设施的验收 MUST 记录环境、数据范围、进程身份和清理结果。临时服务验证完成后 MUST 停止并确认资源释放。

## 3. TDD：RED / GREEN / REFACTOR

每个新增行为或缺陷修复 MUST 遵循：

1. **RED**：先写最小测试，执行并确认它因缺少目标行为而正确失败；编译错误、路径错误或无关环境失败不算有效 RED。
2. **GREEN**：写满足该测试的最小实现，执行相关测试并确认通过；MUST NOT 顺手扩张范围。
3. **REFACTOR**：在行为受保护后整理命名、职责和重复，重新执行相关测试和受影响门禁。

缺陷回归测试 SHOULD 在修复前复现原症状。若修复已经存在，验证者 MAY 暂时回退最小修复或使用等价故障注入确认测试确实会失败，但 MUST 保护工作区并恢复后再次验证。

仅文档或模板变更也 MUST 先执行相关文档契约以建立基线，再实现最小修改并复跑；不能自动化的语义一致性 MUST 进入评审清单。

## 4. Mock 与测试替身

Mock、Stub、Fake 和协议模拟 MUST 只放在外部边界或时间、随机、ID 等非确定性端口，例如 Provider HTTP、数据库端口、对象存储、Tool 外部调用、时钟和 Checkpointer。

内部纯函数、领域状态转换、Strategy Router 和 Graph Node 之间 SHOULD 使用真实实现或轻量 Fake 端口，MUST NOT 通过逐调用 Mock 固化内部步骤。测试断言 SHOULD 聚焦输入输出、状态、事件、副作用和错误契约，而不是私有方法调用次数。

测试替身 MUST 模拟协议的重要失败语义，如超时、限流、部分响应、非法 Schema、取消和重试；只返回成功数据的万能 Mock 不足以验收外部边界。

## 5. 非确定性输出验证

LLM、RAG、OCR、排序和并发输出 MUST 使用结构、属性、固定样本和容差验证，MUST NOT 依赖整段自然语言逐字相等。

可接受的断言包括：

- 输出通过 Schema，必填字段、枚举和引用关系正确；
- 结果 MUST 只使用允许的 Tool/Provider，步数、Token、时间和成本 MUST NOT 越界；
- 引用能回指固定来源，关键主张有证据覆盖；
- 固定数据集指标达到评审确定的阈值；
- 并发结果按稳定键归一化后集合相等；
- 时间、浮点和置信度使用有依据的容差；
- 随机行为固定种子，并在报告中记录种子与样本版本。

快照 MAY 用于稳定结构或协议，但 MUST 审查差异；MUST NOT 通过无条件刷新快照批准未知行为变化。LLM Judge MAY 作为补充，MUST NOT 是安全、权限和确定性契约的唯一判定者。

## 6. 失败、跳过与噪声处理

- 测试失败 MUST 先分类为产品缺陷、测试缺陷、环境缺失、外部不稳定或已知未交付依赖；报告 MUST 给出准确的 failure、error、skip 数量和测试名。
- 失败测试 MUST NOT 通过扩大超时、重复运行到偶然通过、降低断言或静默跳过来掩盖。
- Flaky 测试 MUST 记录复现证据、责任人、影响、临时隔离方式和移除期限；安全、契约和架构测试 MUST NOT 长期隔离。
- 跳过测试 MUST 有可检查的前置条件和原因；“本机不行”或捕获所有异常后跳过 MUST NOT 使用。
- 日志、警告和资源泄漏噪声 SHOULD 作为缺陷处理。预期警告 MUST 精确匹配类别和内容，MUST NOT 全局屏蔽。
- 外部服务不可用时，离线单元/契约/架构测试 MUST 继续可运行；真实集成状态 MUST 单独报告为未验证或阻塞。
- 已批准分阶段计划中，完整套件因后续任务尚未创建的文件保持 RED MAY 被接受，但报告 MUST 证明当前任务的目标文件已存在、相关子集通过且没有既有架构回归。

## 7. 当前真实门禁

当前骨架只依赖 Python 标准库。以下命令是当前可执行门禁，交付前 MUST 从项目根目录运行并记录解释器版本、退出码和结果：

### 7.1 完整标准库测试发现

```powershell
python -m unittest discover -s tests -v
```

该命令执行当前架构和治理契约。分阶段落地时若因明确尚未交付的治理文件失败，MUST 准确报告 failure/error 及缺失文件；MUST NOT 报告“全量通过”。

### 7.2 源码编译

```powershell
python -m compileall -q src
```

退出码为零只证明源码可由当前解释器编译，MUST NOT 证明第三方依赖、Python 3.12 或运行集成已验收。

### 7.3 AST 依赖守卫

```powershell
python -m unittest tests.architecture.test_dependency_rules -v
```

该命令 MUST 在新增或移动包、改变 import、Provider/Persistence/Core/Contracts 或执行层时运行。当前守卫覆盖范围和局限以[架构与依赖规范](02-架构与依赖规范.md)为准。

### 7.4 变更相关子集

执行者 MUST 额外运行与变更直接对应的测试模块或测试方法，以证明目标契约通过。子集通过 MUST 与完整套件状态同时报告，MUST NOT 用子集替代完整发现命令。

## 8. 组件引入后的目标门禁

以下工具是已批准的目标能力，但在其写入 `pyproject.toml`、锁定、安装并有新鲜命令证据前，MUST NOT 声称已经安装、执行或形成当前门禁。

| 目标工具 | 启用条件与目标用途 |
|---|---|
| `pytest` | 组件引入后 MUST 作为统一测试运行器，并 MUST 继续兼容现有 `unittest` |
| `pytest-asyncio` | 异步 API、Graph、Tool 与 Provider 测试 MUST 启用明确事件循环模式 |
| Ruff | MUST 在 `pyproject.toml` 固定规则后执行格式检查与基础缺陷检查 |
| mypy | SHOULD 为公共边界和 Core/Contracts 渐进启用 strict；例外 MUST 局部且有原因 |
| `respx` | MAY 用于 HTTPX Provider/Tool 外部边界协议模拟；MUST NOT 替代真实冒烟 |
| Hypothesis | SHOULD 用于核心状态机、Schema、序列化和边界组合的性质测试 |
| `uv audit --frozen` | MUST 在正式启用依赖漏洞门禁后审计锁文件；漏洞忽略 MUST 记录 ID、理由、负责人、批准人和失效日期 |

工具启用后 MUST 同步 `pyproject.toml`、`uv.lock`、`CONTRIBUTING.md`、本规范和 CI/本地命令。目标门禁未执行时报告 MUST 写“未执行/未安装/未启用”，MUST NOT 写“通过”。

Ragas、DeepEval 和默认 LLM Judge 不属于当前评测基线；Locust、k6、JMeter、pytest-benchmark 等性能工具在业务功能完成后另行评审；Bandit、Semgrep、独立 Secret Scanner 和恶意文件扫描服务也在实际代码、CI 或外部输入风险形成后另行评审。后置工具在重新批准前 MUST NOT 写入当前门禁或声称已启用。

## 9. 变更与门禁映射

| 变更类型 | MUST 执行的最低附加验证 |
|---|---|
| Core/Contracts/枚举/状态 | 单元 + 契约 + AST 架构守卫 + 完整发现 |
| 包结构或 import | 架构 + Scaffold + 完整发现 + 源码编译 |
| Graph/Strategy/Supervisor | 单元 + Graph + Checkpoint/取消/终止 + 架构 + 完整发现 |
| Tool | Schema + 权限 + 幂等 + 超时/重试 + 审计 + 安全 |
| Provider | 共享契约 + 错误映射 + 超时/限流/降级 + 受控集成 |
| RAG/OCR/模型 | 契约 + 固定数据集 + 引用/Schema + 成本边界 + 真实冒烟状态 |
| Persistence/SQL | 契约 + 临时集成 + 并发/回滚 + SQL 预检/授权/验证证据 |
| 安全策略 | 正向 + 拒绝 + 绕过尝试 + 审计 + 无副作用证明 |
| 文档/模板/治理 | 文档契约 + 链接/元数据/占位扫描 + 完整发现 |

风险更高或跨层的变更 MUST 增加验证，MUST NOT 把本表当作上限。

## 10. 完成证据格式

任何“完成”“修复”“通过”“兼容”声明 MUST 附带本次运行的证据，至少包含：

```text
范围：<本次变更与明确非目标>
环境：<工作目录、解释器/工具版本、关键非敏感配置>
命令：<从项目根执行的完整命令>
结果：<退出码；tests/runs；passed/failures/errors/skipped；关键输出>
覆盖：<该命令实际证明的性质>
未验证：<真实 Provider/数据库/网络/性能/Python 3.12 等未执行项>
剩余失败：<测试名、原因、缺失依赖和责任任务>
```

- 每条命令 MUST 原样记录，结果 MUST 来自本次修改后的新鲜执行。
- 完整套件 RED 时 MUST 给出准确 failure/error 数、失败测试名和剩余缺失文件，MUST NOT 用“预期失败”省略细节。
- 多个门禁结果 MUST 分开陈述；一个命令退出码为零 MUST NOT 覆盖另一个命令的失败。
- Mock、离线契约和真实集成 MUST 分开标注。未运行、环境缺失、授权缺失和范围外 MUST 使用不同状态。
- 评审者 MUST 能仅凭证据重现命令并判断声明边界，否则完成声明不合规。
