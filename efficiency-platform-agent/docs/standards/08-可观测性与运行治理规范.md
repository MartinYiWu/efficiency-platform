## 1. 证据边界

可观测性 MUST 描述真实发生的运行事实，并 MUST 与业务结果、审计和费用账单区分。Span/日志存在、HTTP 成功或队列完成 MUST NOT 单独证明业务结果正确；Metric 未上报 MUST NOT 被解释为值为零。

本文定义的是准入契约，MUST NOT 被表述为监控、告警、SLO 或导出端点已经配置。只有代码、配置、当前运行输出和告警测试均有新鲜证据时 MAY 声明对应能力已启用。

阶段边界：P1 只实现结构化日志、`run_id`/`task_id`/`correlation_id` 传播、运行事件和可观测扩展端口。本文的 Trace、Metric、Exporter、SLO 与告警条款是后续专项的准入规范，不要求 P1 安装 OpenTelemetry、Prometheus、Grafana、LangSmith 或建设监控平台。

## 2. Trace 层级与传播

一个入站请求/Run MUST 建立根 Span，并按实际调用形成以下父子关系：

```text
agent.run
├─ agent.strategy.select
├─ agent.graph.execute / agent.workflow.execute
│  ├─ agent.agent.execute
│  ├─ agent.llm.invoke
│  ├─ agent.tool.invoke
│  ├─ agent.retrieval.search
│  └─ agent.checkpoint.write|load
└─ agent.run.finalize
```

Workflow、Graph、Agent、LLM、Tool、RAG/检索和 Checkpoint Span MUST 是当前 Run 或当前父步骤的子 Span。并行分支 MUST 共享同一 Trace，并 MUST 通过 Span Link 或明确父子关系表达扇出/汇聚；MUST NOT 为每个 Specialist 建立无法关联的新根 Trace。

在 Trace 专项启用后，跨线程、Taskiq 异步消息、MCP、HTTP 和 Checkpoint 恢复 MUST 传播标准 Trace Context 与受控 Baggage。P1 在 API 到 Worker 的进程边界必须显式传播 `run_id`、`task_id` 与 `correlation_id`。恢复 MUST 关联原 `run_id`；启用 Trace 后 MAY 建立新的 Trace 表达新的执行尝试，但 MUST 使用 Link 指向原 Trace/Checkpoint，MUST NOT 伪造连续单进程调用。

未信任的入站 Trace/Baggage MUST 校验长度和允许字段，MUST NOT 覆盖权威身份、租户、权限或采样策略。

## 3. Span 命名与公共属性

Span 名称 MUST 使用稳定、低基数的 `agent.<component>.<operation>`，MUST NOT 包含 `run_id`、用户文本、动态 URL、文件名、SQL、Prompt 或错误正文。可接受示例为 `agent.tool.invoke`、`agent.llm.invoke`、`agent.checkpoint.load`；`agent.tool.invoke.fetch-<url>` MUST NOT 使用。

与场景相关时，Span SHOULD 使用以下公共属性：

| 属性 | 约束 |
|---|---|
| `agent.run.id`、`agent.task.id` | 只用于 Trace/Log 关联，MUST NOT 作为默认 Metric Label |
| `agent.strategy.name`、`agent.graph.name`、`agent.node.name` | MUST 使用注册表稳定值，MUST NOT 使用自由文本 |
| `agent.agent.name`、`agent.tool.name` | MUST 使用受控逻辑名 |
| `gen_ai.provider.name`、`gen_ai.request.model` | MUST 使用逻辑 Provider/模型名，厂商实例细节 MAY 在 Provider Span 的受控属性记录 |
| `agent.prompt.id`、`agent.prompt.version` | MUST 记录稳定 ID/版本，MUST NOT 记录 Prompt 正文 |
| `agent.status`、`error.type` | MUST 使用有限枚举或稳定错误分类，MUST NOT 使用异常正文 |
| `agent.retry.attempt`、`agent.budget.*` | 只在真实可得时记录，单位 MUST 明确 |

租户和用户标识只 MAY 在有明确排障/审计目的、访问控制与留存策略时进入 Trace，并 MUST 使用不可逆哈希、受控映射 ID 或最小化标识。原始 `user_id`、邮箱、手机号和其他可识别信息 MUST NOT 进入 Span 属性。

## 4. Metric 契约

Metric 名称 MUST 使用小写点分层级 `agent.<subsystem>.<measure>`，单位 MUST 使用 OpenTelemetry 约定的基本单位（如 `s`、`By`、`{request}`、`{token}`、`{call}`、货币代码另以属性表达），并 MUST 在注册表中声明描述、类型、单位、允许 Label、所有者和基数预算。

| 示例 Metric | 类型 | 单位 | 用途 |
|---|---|---|---|
| `agent.run.count` | Counter | `{run}` | 按稳定状态统计 Run |
| `agent.run.duration` | Histogram | `s` | Run 端到端延迟 |
| `agent.llm.token.usage` | Counter | `{token}` | 按输入/输出类别统计真实 Token |
| `agent.tool.call.count` | Counter | `{call}` | Tool 调用与稳定结果分类 |
| `agent.checkpoint.operation.duration` | Histogram | `s` | Checkpoint 读写延迟 |
| `agent.budget.utilization` | Histogram | `1` | 预算占用比例 |
| `agent.retry.count` | Counter | `{retry}` | 受控重试次数 |

Metric Label MUST 来自白名单：`service.name`、`environment`、`strategy`、`graph`、`agent_name`、`tool_name`、`provider`、`model`、`operation`、`status`、`error_type`、`token_type`、`currency`。每个 Metric MUST 选择完成分析所需的最小子集，MUST NOT 默认添加全部字段。

每个 Metric MUST 定义单 Label 值上限和组合时间序列基数预算。新增 Label 或扩大注册值集合 MUST 提供样本基数、内存/出口成本和查询用途证据；超预算时 MUST 聚合、下沉到 Trace/Log 或拒绝发布。

以下值 MUST NOT 作为 Metric Label：

- `user_id`、原始或可逆租户/用户个人标识；
- 原始 Prompt、模型响应、Tool 参数、SQL、文件名/正文；
- 完整 URL 或查询参数；
- `run_id`、`trace_id`、`request_id`、Artifact ID；
- 异常正文、堆栈、自由文本错误、动态时间戳及其他无界值。

## 5. 结构化日志

日志 MUST 是结构化事件，并 SHOULD 包含 `timestamp`、`level`、`event_name`、`run_id`、`trace_id`、`span_id`、稳定组件/操作、`status`、`error_code`、`duration_ms` 和重试次数等适用字段。字段 MUST 使用统一名称和类型，MUST NOT 依赖拼接文本做告警或统计。

级别 MUST 按结果表达：`DEBUG` 用于受控开发诊断，`INFO` 用于正常生命周期，`WARNING` 用于已处理退化或接近预算，`ERROR` 用于当前操作失败，`CRITICAL` 只用于广泛不可用或安全边界严重失效。正常拒绝、取消和用户输入错误 MUST NOT 全部记录为系统错误。

Secret、认证头/Cookie、连接串、原始敏感 Prompt/响应、完整文件/SQL/Tool 参数和未经脱敏个人数据 MUST NOT 进入日志。异常正文和堆栈只 MAY 在受控内部日志经敏感检查后记录；面向用户的错误 MUST 使用稳定安全消息。

高频 Token、流事件和循环步骤 SHOULD 聚合或采样。采样策略 MUST 保留错误、安全拒绝和关键状态转换所需证据，MUST NOT 采样掉依法或策略要求的审计事件。

## 6. Trace、Log 与 Audit 分工

| 载体 | 主要职责 | MUST NOT 替代 |
|---|---|---|
| Trace | 单次执行调用关系、耗时、错误位置和异步关联 | 权威业务状态、不可缺失审计 |
| Log | 运行事件、诊断、错误和资源异常 | Metric 聚合、审批/授权事实 |
| Audit | 谁在何时以何权限对什么资源执行何动作及结果 | 高频调试日志、完整敏感正文 |

审计事件 MUST 至少覆盖：身份/授权允许与拒绝、高风险 Tool 审批和执行、数据/Artifact 访问、跨租户拒绝、配置/Prompt/Provider 版本变更、人工介入、恢复/取消以及安全拒绝。事件 MUST 追加记录稳定事件名、主体/租户受控标识、资源、动作、策略/版本、结果、原因码、时间和 `run_id`/`trace_id` 关联。

Audit 写入失败且事件属于高风险 Tool、授权、数据访问或配置变更时，操作 MUST 默认失败关闭或进入经批准的安全降级，MUST NOT 静默继续。

## 7. Token、费用与预算口径

LLM Token MUST 按 Provider 返回或经批准 tokenizer 的真实输入、输出、缓存和推理类别记录，并 MUST 标注计量来源。估算值 MUST 标记 `estimated`，MUST NOT 与厂商结算值混算。

模型费用和 Tool 费用 MUST 由版本化价格表、币种、计价单位、有效期和真实用量计算。未知价格、缺失用量或免费额度状态未知时，费用 MUST 标记未知，MUST NOT 伪造为零。账单对账 MAY 修正估算，但 MUST 保留原计量和修正证据。

Run 预算 MUST 分别记录配额、已用、预留、剩余和不可计算项。Supervisor 分配子预算时 MUST 防止总和超过 Run 剩余预算；重试和降级调用也 MUST 消耗预算。结算口径变化 MUST 版本化并记录生效时间，MUST NOT 静默回算历史数据。

## 8. 重试、退避、熔断与降级

重试 MUST 只处理明确分类的临时错误，并 MUST 受最大次数、指数退避、抖动、总截止时间、预算和取消约束。认证、权限、Schema、安全拒绝、预算耗尽和确定性输入错误 MUST NOT 自动重试。

外部写或高风险副作用只有在同一幂等键可证明不会重复效果时 MAY 自动重试；状态未知时 MUST 停止并进入人工核对或受控恢复。重试尝试 MUST 在 Trace/Log/Audit 中关联原操作，并 MUST NOT 重置总预算。

熔断器 MUST 按稳定 Provider/Tool 端点和错误类别定义窗口、阈值、半开探测与恢复证据。降级 MUST 声明触发条件、能力损失、数据/安全边界和用户可见语义；MUST NOT 通过切换 Provider 放宽 Schema、权限或隐私规则。

## 9. 取消、Checkpoint 与恢复

取消 MUST 从 Harness 传播到 Graph、Agent、Tool、Provider 和 I/O，并 MUST 区分用户取消、超时和系统失败。资源清理完成后取消语义 MUST 继续传播，MUST NOT 被转换为成功。

Checkpoint MUST 在外部副作用前后、等待输入/审批、长步骤和终态保存一致状态、版本、预算、幂等和关联上下文。恢复 MUST 使用原 `run_id + checkpoint`，校验调用主体、租户、权限、代码/Prompt/Provider 兼容性和副作用状态；无法确认时 MUST 失败关闭。

恢复测试 MUST 覆盖中断点、重复事件、部分副作用、版本不兼容、审批过期、预算不足和审计失败，MUST NOT 只测试正常序列化/反序列化。

## 10. SLI、SLO 与告警

每个上线能力 SHOULD 定义与用户结果相关的 SLI，例如成功率、端到端延迟、等待恢复成功率、Tool/Provider 可用率、预算拒绝率、引用覆盖或安全拒绝处理。SLI MUST 声明事件来源、分母/分子、排除条件、窗口和数据完整性要求。

SLO、告警阈值和观察窗口 MUST 来自容量测试、历史基线、用户目标或经批准风险预算，并 MUST 记录负责人和生效版本。缺少来源时 MUST 标记待评审，MUST NOT 虚构行业默认值为已批准阈值。

告警 MUST 具有稳定指纹、分组/去重、抑制、恢复条件、责任人、处置步骤和证据链接。重复重试、同一根因的多层 Span 错误和并行 Specialist 失败 SHOULD 合并为可处置事件，MUST NOT 形成无界告警风暴。

告警验收 MUST 使用受控故障或规则测试证明触发、去重、通知、处置和恢复；仅存在配置文件 MUST NOT 表述为告警有效。

## 11. 验证与完成声明

新增埋点 MUST 有字段/类型/单位/脱敏测试；Metric MUST 有 Label 白名单和基数测试；Trace MUST 有父子/Link 与异步传播测试；Audit MUST 有成功、拒绝和写入失败测试；重试/恢复 MUST 有无重复副作用测试。

报告 MUST 区分“规范已定义”“代码已埋点”“Exporter 已配置”“数据已接收”“查询/告警已验证”和“SLO 已批准”。任一层未验证时 MUST 明确标记，MUST NOT 推断后续层完成。

## 12. 例外

对本规范 `MUST` 或 `MUST NOT` 的例外 MUST 按[工程规范索引](00-规范索引.md)记录。Metric 高基数禁止项、敏感数据禁止项、未知费用禁止伪造、高风险副作用禁止重复和审计失败关闭 MUST NOT 通过普通例外降低。
