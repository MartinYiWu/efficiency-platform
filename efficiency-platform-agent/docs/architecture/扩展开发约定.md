## 1. 扩展原则

新增能力优先通过端口和注册机制扩展，不修改统一 Harness 和 Graph Runtime 的公共生命周期。业务代码不得直接依赖具体厂商 SDK，厂商差异必须收敛到 `providers/`。

## 1.1 S1 新 Agent 接入顺序

新 Agent 必须严格按以下顺序接入，前一步未通过不得进入下一步：

```text
定义 AgentSpec
→ 定义稳定输入输出 Schema
→ 实现 AgentPlugin
→ AgentValidator 本地校验
→ AgentRegistry 显式注册
→ AgentFactory 装配
→ 运行准入契约测试
→ 才能被 Supervisor 按能力匹配
```

其中 `AgentSpec` 必须完整表达 Agent 类型、能力、任务、输入输出 Schema、策略、Prompt、工具、知识、记忆、模型、质量、权限和终止条件；能力要求使用 `CapabilityRequirement` 表达。`AgentValidator` 必须对缺失、冲突和实例不一致失败关闭。`AgentRegistry` 只接受显式注册并提供稳定能力匹配，`AgentFactory` 负责安全装配和实例归一化。

接入过程禁止以下行为：

必须明确禁止动态导入和注册副作用。

- 业务 Agent 修改 Harness 或 Graph Runtime 的公共生命周期；
- 业务 Agent 直接调用 Provider SDK；
- 动态扫描、动态导入插件或动态注册；
- 通过 `__init__.py` 导入副作用完成注册；
- 绕过 `AgentValidator`、`AgentRegistry` 或 `AgentFactory` 直接构造并交给 Supervisor。

S1 只固化定义、校验、显式注册、能力匹配和装配契约；不因此声明真实 LangGraph、Harness、Provider、网络、数据库或其他外部运行时已经接入。

截至 2026-09-03，S1 离线回归记录为 79/79 通过且源码编译通过；最终代码修复仍在并行进行，S1 仍待终审，未获批准。配置治理与 Agent 功能分离：本机 `.env` 仅校验结构和中文注释，不校验真实可调用值；模板和路由继续严格校验。本约定不授权读取或写入任何 Key、令牌或 `.env` 值。

## 2. 新增专家 Agent

1. 在 `agents/` 下建立独立插件包；
2. 实现 `core.ports.AgentPlugin`；
3. 声明名称、能力集合、输入输出 Schema、允许工具和预算；
4. 通过 Agent Registry 注册；
5. 只接受 Supervisor 分配的结构化子任务和裁剪后的上下文；
6. 返回结构化结果、证据、引用和错误，不直接调用其他专家 Agent。

### 2.1 S5 运营 Specialist 交接约束

S5 已在离线范围显式注册 11 个运营 Specialist。新增或消费这些能力时，必须从
`agents.operation.definition.OperationSpecialistCapabilityId` 或
`operation_specialist_capability_ids()` 导入能力标识，不得在业务模块、场景包或测试中复制字符串目录。
研究能力只能依赖 `ResearchProviderPort`，分析能力只能依赖
`AnalyticsFileReader.open(request) -> AnalyticsDatasetLease`；原始分析 rows 不得进入 SupervisorTask、Graph State、Prompt、结果或日志。
注册只能由组合根显式调用 `register_operation_specialists()`，不得通过包导入副作用完成。
本节的 Specialist 和 Provider 仍只完成固定 Fake/离线验证，不代表真实网络、模型、文件上传或生产环境已接入。

## 3. 新增执行策略

1. 在 `strategies/` 建立独立策略包；
2. 实现 `StrategyExecutor`；
3. 声明适用条件、最大步骤、预算、暂停点和终止条件；
4. 在 Strategy Router 注册；
5. 复用统一 Context、Tool Runtime、Checkpoint 和事件协议。

## 4. 新增 Tool

1. 根据归属放入 `tools/internal`、`tools/external` 或 `tools/mcp`；
2. 实现 `Tool` 端口，提供稳定名称、描述和参数 Schema；
3. 所有调用必须经过 `tools/runtime` 的 Schema 校验、权限、超时、重试、审计和结果归一化；
4. Tool 不得读取不属于当前租户或用户的资源；
5. 高风险写操作必须声明审批策略和幂等键。

## 5. 新增 Provider

1. 放入对应的 `providers/<type>/`；
2. 对上实现内部端口，对下封装厂商 SDK 或 HTTP API；
3. 不向上泄露厂商响应对象、异常类型和配置键；
4. 必须定义超时、重试、限流、错误映射和可观测字段；
5. 相同能力至少保留主 Provider 与可选降级 Provider 的配置空间。

## 6. 新增 Capability

Capability 是可复用的技术能力，不等于业务用例。它可以组合 Provider、Tool、Context 和 Persistence，但不得包含某个业务部门的流程判断。

示例：文档解析、OCR、混合检索、重排、引用校验属于 Capability；“简历筛选”“会议待办分配”属于后续业务 Agent 或 Workflow。

## 7. 强制依赖规则

- `core` 只依赖自身和 Python 标准库；
- `contracts` 不依赖 API、Harness、编排或策略；
- 内部任何层不得依赖 `api`；
- `providers`、`persistence` 不得依赖 Harness、Routing、Orchestration、Strategies、Agents、Workflows；
- Agent 不直接实例化厂商 SDK；
- 专家 Agent 不点对点调用其他专家 Agent；
- 业务 Prompt、业务工具授权和业务数据访问策略与各业务插件同仓位管理。

执行以下命令校验：

```powershell
python -m unittest tests.architecture.test_dependency_rules -v
```

## 8. 新增代码的最低测试要求

- 新端口：契约测试；
- 新 Provider：适配器契约、超时、错误映射和降级测试；
- 新 Tool：Schema、权限、幂等、超时和审计测试；
- 新策略：路由、终止条件、预算、Checkpoint 和失败恢复测试；
- 新 Agent：输入输出 Schema、工具白名单、上下文隔离和 Supervisor 集成测试；
- 新 RAG/OCR 能力：固定数据集上的质量回归测试。
