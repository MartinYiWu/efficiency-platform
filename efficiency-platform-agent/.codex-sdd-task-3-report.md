## 实现结果

- 会话无待补充运营意图时，先执行有限本地响应；身份问题直接进入 DIRECT，意图解释器和模型均不调用，经既有 HTTP Conversation API 与 Run SSE 输出身份正文。
- 非本地消息经现有意图解释器解析；`general_chat` 生成空策略 payload 的 DIRECT 提交，八种运营任务继续使用原 MULTI_AGENT 提交。
- `pending_intent` 存在时跳过本地响应；后续被识别为普通聊天或其他任务类型时保留原待补充运营意图，同类型继续按缺失字段合并。
- DIRECT 提交复用已裁剪的 ConversationContext 快照；当前用户消息只追加一次，成功正文由既有终态监听写回会话历史。
- DIRECT 提交预算从 Run 准备阶段快照扣除意图阶段实际迭代、Token、费用及准备耗时，复用 BudgetGuard 校验，不建立第二个权威 Run 账本。准备失败仍附带可信用量、降级及消耗事实。
- 成功、失败、取消、超时四种终态都清理 Direct Submission；保存提交与活动 Run 检查共用会话锁，防止取消后迟到写入。
- 真实组合根和显式 test_mode 都注册 DIRECT Conversation Graph 与 MULTI_AGENT Operation Graph；共同使用既有 ModelRuntime、Run 预算、取消信号、GraphRuntime 与 SSE。

## Important 复核修复

独立复核发现初次交付存在两个实质缺陷，已按测试先行修复。本节替代上文“未改 Task 1/2 源码”以及取消仅抑制迟到输出的范围描述；公共 Harness 和 ModelRuntime 生命周期仍未修改。

### 根因与修改

1. DIRECT 正文的 ModelExecutionResult 用量虽进入 Run.usage，但 GeneralConversationExecution 丢弃了模型 attempts。GraphRuntime 的预算归一化只接受 BudgetState；DIRECT 程序原样留下输入字典，导致 Harness 恢复原预算，漏计正文消耗。现在冻结执行结果与安全异常都透传不可变 attempts；DIRECT 程序在 LangGraph 调用返回后把 JSON 预算映射归一化为 BudgetState，累加正文实际 iterations、input/output tokens、cost，严格保留传入 Run 的 started_at 与 deadline。Graph 内状态仍保持 JSON，预算对象归一化位于 GraphProgram 边界。
2. 共享 ModelRuntime 原先未接入 Run 取消探针；取消首调用后若返回可重试错误，仍会启动第二候选。现在组合根以 ContextVar 维护每个异步调用链的 Run 标识，通过 DIRECT Builder 注入的调用作用域绑定；ModelRuntime 复用既有前后取消检查，阻止取消后的新 fallback。相同模型实例、候选池与 Provider 注册表继续共用，没有创建第二个 ModelRuntime，也没有把单个 Run 的状态放入共享可变属性。
3. 补充并发隔离回归：A、B 同时进入首模型调用，取消 A 后返回可重试失败；A 总调用数为 1、终态 CANCELLED，B 可降级调用第二候选并成功。作用域退出时恢复原 ContextVar 值。
