## 2. 架构边界修正

原计划把 `DirectConversationSubmission` 与 `GeneralConversationExecution` 隐含放在 `conversation` / `agents` 实现层。若 `GeneralConversationAgent` 直接依赖 `conversation`，会形成 `conversation -> agents` 与 `agents -> conversation` 的层级双向依赖。

按架构检查点裁决，新增 `contracts/direct_conversation.py` 持有跨层冻结值契约：

- `agents` 只依赖 `contracts` 与 `core`；
- `conversation/direct_submission.py` 只实现 Store，并依赖 `contracts`；
- `orchestration/builders/conversation_direct.py` 组合 Agent、Store 错误与跨层契约；
- 未放宽 AST 依赖矩阵。

这是对已批准计划文件清单的必要最小修正，不改变 Task 2 的接口与行为目标。

## 6. 需求自审

- 统一模型入口：Agent 构造器要求 `complete(demand, request, *, remaining_budget)`，拒绝旧 Provider 直连签名。
- 可见历史：冻结契约只允许 `user` / `assistant` 字符串正文，最多 8 条、总计最多 12000 字符；系统与 Tool 消息不能伪装成会话历史。
- 本地响应：Graph 优先返回 `local_response`，测试证明模型调用次数为 0。
- 输出面：`GeneralConversationExecution` 只有 `content`、`usage`、`degraded` 三个字段；Graph 业务 `output` 只有 `content`，usage/degraded 走既有运行事实字段，不返回交付物。
- 身份：Store 同时校验 tenant、user、request 三个标识；失败不消费正确提交。
- 错误：Provider error、空正文、无效角色、无效运行时结果和运行时异常统一收敛为 `GENERAL_CONVERSATION_MODEL_FAILED`，不包含厂商错误正文。
- 策略 payload：注册使用 `strategy.none/1` 和空键白名单，模型输入/输出均不进入策略 payload。
- Graph：使用 LangGraph `StateGraph` 并注册到现有 `GraphRegistration` / `GraphRuntime`，checkpoint namespace 为 `s2:direct:1`。
- 注释：新增模块、公共类型和关键内部边界均使用中文 Docstring/注释。
